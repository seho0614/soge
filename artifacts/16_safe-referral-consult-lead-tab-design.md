# 소개뱅크 안심소개 상담 축 통합 설계서 v1.3 (소개리드 폐지 · 확정 · 화면 처분표)

Oct 1, 2026 · @박세호

## 1. 최종 결론

**소개리드 관을 없애고, 리드 업무(보험·의료·렌탈 등 상담 신청)를 안심소개의 세 번째 축 「생활·금융 상담」으로 옮깁니다.** 안심소개는 인증받은 업체만 등록되는 관이 되고, 업체 등록·서비스 입력·리드 처리는 제휴 파트너센터와 별도로 운영하는 「안심소개 파트너센터」에서, 관리자 검수는 기존 관리자 파트너 메뉴에서 합니다.

### v1.0 에서 바뀐 점 (2026-10-01 대표 지시)

| --- | --- | --- |

### 먼저 알아 두실 점 3가지

1. **법무 회신 재확인 필요** — 보험·의료 허용 회신은 "리드관 적용"으로 받았습니다. 리드 업무가 안심소개(인증 거래 관)로 옮겨 가면 같은 결론이 유지되는지 확인해야 합니다. 보험·의료를 뺀 업종은 먼저 진행할 수 있습니다.
2. **대원칙과의 관계** — 2026-09-15 대원칙은 "돈이 도는 방식이 다르면 같은 체계에 두지 않는다"였습니다. 안심소개 안에 "회원 ↔ 회원"과 "플랫폼 → 업체" 두 흐름이 함께 생기므로, 규칙을 **축 단위로 갈라** 지킵니다(§2).
3. **파트너센터는 두 곳을 별도로 둡니다** — 머리 메뉴의 제휴 파트너센터(/partners, 소개링크·수익)와 기존 리드 파트너(/partner, 서비스 등록·리드 목록)입니다. 합치지 않고, 기존 리드 파트너를 「안심소개 파트너센터」로 이름만 바꿔 씁니다(§3).

## 2. 판단 근거 — 체계는 7개에서 6개로, 안심소개 안에서 규칙을 축별로 가릅니다

소개리드가 사라지면 관 사이 분리 원칙(INV-SEP1\~4)은 그대로 지켜집니다. 대신 안심소개 내부에 성격이 다른 두 흐름이 생기므로, 리드 전용 규칙은 **상담 축에만** 걸리게 합니다.

### 2-1. 체계 재편

| 체계 | 현재 | 변경 후 |
| --- | --- | --- |
| MAL 안심소개 | 기계·설비·시설 · 부동산 (회원 ↔ 회원) | + **생활·금융 상담 축** (플랫폼 → 인증업체) |
| LED 소개리드 | partner. · 라우트 16 · 역할 2 | **폐지** — 라우트·역할·데이터를 MAL 로 이관 |
| 파트너센터 | 제휴(/partners) · 리드(/partner) 따로 | 별도 운영 — 리드 파트너를 「안심소개 파트너센터」로 (§3) |

### 2-4. 주의할 충돌 지점

1. **법무** — 허용 근거였던 "사업 알선(차단) vs 소비자가 스스로 신청한 연락처 전달(허용)" 구분이 이제 같은 관 안의 축 구분이 됩니다. 실질은 같지만 관 이름이 "안심소개"라 플랫폼 보증으로 읽힐 수 있어 재확인이 필요합니다(보험업법 제83조, 의료법 제27조 제3항·제57조).
2. **화면 문구** — 현재 상단의 「소개하기 · 소개받고 싶어요 · 소개받기」는 상담 축에 맞지 않아 축별로 바꿉니다.
3. **중고차** — 같은 관 안에 축B(상용차·특장차 매물)와 상담 축(소비자 매입·판매 상담)이 함께 있게 됩니다.

## 3. 파트너센터 — 두 곳을 별도로 운영 (2026-10-01 확정)

제휴 파트너센터와 안심소개 파트너센터를 합치지 않고 따로 둡니다. 기존 리드 파트너 화면(/partner)을 「안심소개 파트너센터」로 이름을 바꿔 그대로 쓰므로, 화면 이전 작업이 없습니다.

| 항목 | 제휴 파트너센터 | **안심소개 파트너센터** |
| --- | --- | --- |
| 주소 | /partners (현행) | /partner (현행 유지) |
| 대상 | 소개링크로 상품을 알리는 제휴 회원 | **안심소개 전 축 인증업체** — 기계·설비·시설 · 부동산(중개사) · 태양광 · 상담(보험·의료·렌탈 등) |
| 주요 메뉴 | 대시보드 · 소개링크 · 주문 · 수익 · 정산 · 추천상품 · 자료실 · 공지 · 문의 · 가이드 | 입점 신청·축별 자격 서류 · **매물 등록·관리** · 서비스 등록·단가(상담) · 매물 문의 · 리드 목록·이의신청(상담) · 노출료 결제(부동산, A-07) · 성과 · 소개캐시 · 의료 심의 |
| 소유 체계 | 현행 그대로 | MAL |
| 역할 | 현행 그대로 | MAL\_PARTNER (+ 부동산은 MAL\_BROKER) |
| 관리자 메뉴 | 현행 그대로 | SB-ADM-PTN-020 · 030 · 050 · 060 · 070 · 080 + 중개사 인증 심사 |

### 들어가는 길 (제안)

1. **머리 메뉴** — 「파트너센터」는 제휴 파트너센터로 두고, MAL\_PARTNER 로 로그인한 업체에게만 「안심소개 파트너센터」를 함께 보여 줍니다.
2. **안심소개 상담 탭** — 「인증업체 등록」 버튼 → 안심소개 파트너센터 입점 신청.
3. **나의공간** — 「내 업체 관리」 → 안심소개 파트너센터.

두 센터에 모두 가입한 회원은 두 메뉴가 다 보이며, 정산·소개캐시 기록은 센터별로 따로 남습니다.

### 기존 매물 등록 회원 이관 규칙 (확정)

| 대상 | 처리 | 기존 매물 |
| --- | --- | --- |
| 사업자 인증 통과 + 기계·설비 매물 | **기계·설비 축 일괄 입점 승인** → MAL\_PARTNER 부여 | 그대로 노출 |
| 사업자 인증 통과 + 부동산·태양광 매물 | 해당 축은 **재심사** (부동산은 중개사 인증) — 일괄 승인은 기계·설비만 | 승인 전 비공개 |
| 사업자 인증 미통과 | **재심사** (입점 신청 안내 발송) | 승인 전 비공개 |

- 일괄 승인 기준인 "사업자 인증 통과"는 **국세청 실연동 조회 결과**만 인정합니다. 국세청 연동이 아직 시험 중이므로, 시험 단계에서 통과 처리된 기록은 실연동 후 다시 조회합니다.
- 이관은 오픈 직전 1회 실행하고, 대상 회원에게 결과(승인 / 재심사 필요)를 알림으로 보냅니다. 기록은 축별 입점 승인 이력에 "일괄 이관" 사유로 남깁니다.

### 4-3. 업무 흐름

1. **업체 등록 (전 축)** — 업체가 안심소개 파트너센터에서 입점 신청 + 축(기계·설비 / 부동산 / 태양광 / 상담)·업종 선택 + 축별 자격 서류 제출.
2. **입점 승인 (전 축)** — 관리자 입점 신청 승인(SB-ADM-PTN-020). 부동산은 중개사 인증 심사, 보험·의료는 규제 카테고리 자격 심사(SB-ADM-PTN-070) 추가.
3. **게시물 입력 (전 축)** — 매물(기계·설비·부동산·태양광) 또는 서비스·단가(상담)를 안심소개 파트너센터에서 입력.
4. **검수 (전 축)** — 관리자 검수 승인(SB-ADM-PTN-030) → 해당 축에 노출. 부동산은 노출료(A-07) 결제 후 노출, 보험·의료는 문구 검수, 의료는 심의필 확인.
5. **상담 신청 (상담 축)** — 소비자가 상담 축에서 신청 + 개인정보 제공 동의 + 휴대폰 확인.
6. **리드 배분 (상담 축)** — 1리드 = 1업체. 보험·의료는 리드 건별 검수 후 배분.
7. **리드 처리 (상담 축)** — 업체가 리드 목록에서 열람(소개캐시 1회 차감) · 상담 진행.
8. **이의신청 (상담 축)** — 업체가 반려 신청 → 관리자 반려 인정/기각(SB-ADM-PTN-050).

기계·설비·부동산·태양광의 소개·성사·정산 흐름(귀속 90일, 양측 확인)은 현행 그대로입니다.

**서버 반영 시 정정 (2026-10-01, 마이그레이션 D005)** — 카드·금융·통신사 대리점은 서버(C993)에 이미 GATED(자격 확인 후 게시)로 들어가 있어 그대로 유지했습니다. 위 표의 OPEN·숨김 표기보다 이 기준이 우선합니다. 업종 코드는 서버와 같게 CSL\_INSURANCE·CSL\_MEDICAL·CSL\_CARD·CSL\_FINANCE·CSL\_TELCO·CSL\_RENTAL·CSL\_MOVING·CSL\_USEDCAR·CSL\_RENTCAR 입니다.

**업종 개편 확정 (2026-10-01 대표 결정 · 서버 D006)** — 위 9종 표를 아래로 대체합니다.

| 구분 | 업종 | 서버 상태 |
| --- | --- | --- |
| 자격 확인 후 게시 (GATED) 10 | 보험 · 의료 · 이사짐 · 인테리어 · 건설·시공 · 자동차(정비·렌트) · 여행·항공 · 교육·학원 · 물류·운송 · 통신사 대리점 | 공개. 보험·의료는 법무 재확인 전 "준비 중" 표시 |
| 사업자 인증만 5 | 청소 · 웨딩 · 이벤트·행사 · 렌탈 · 중고차 | 공개 |
| 준비 중 2 | 법률(변호사·법무사) · 세무·회계(세무사·회계사) | 법무 확인 전 — 상담 신청을 받지 않음 |
| 보관 2 | 카드 · 금융 | 목록 제외 (지난 기록 때문에 지우지 않음) |

렌터카는 「자동차(정비·렌트)」로 합쳤고, 이사짐은 허가증 확인(GATED)으로 강화했습니다. 광고·마케팅 · 디자인 · IT · 제조 · 유통은 소개장터, 부동산은 안심소개 부동산 축, 공공·기관은 제외입니다. 업종별 법률 근거는 운영 전 법무 확인이 필요합니다.

**업종 추가 (2026-10-02 대표 결정 · 서버 D007)** — 공공·기관을 뺀 나머지 전문 업종도 안심소개에 넣습니다. 광고·마케팅 · 디자인 · IT·소프트웨어 · 제조·생산 · 유통·무역은 사업자 인증만 보는 일반 업종입니다. 상담 축은 **공개 20 · 준비 중 2(법률 · 세무) · 보관 2(카드 · 금융)** 입니다. 법률 · 세무는 추천대로 법무 확인 전까지 준비 중을 유지합니다.

### 5-2. 관리자 업무 규칙

| 업무 | 누가 | 규칙 |
| --- | --- | --- |

### 6-2. 테이블 이관과 업종 마스터 (PostgreSQL 예시)

```sql
-- 1) LED 스키마 대신 MAL 스키마에 상담 축 테이블 생성 (100_lead 를 재작성)
CREATE TABLE mal.consult_category (
  code          VARCHAR(10) PRIMARY KEY,
  name          VARCHAR(50) NOT NULL,
  publish_mode  VARCHAR(10) NOT NULL CHECK (publish_mode IN ('OPEN','GATED')),
  mode_locked   BOOLEAN     NOT NULL DEFAULT FALSE,   -- 보험·의료: OPEN 전환 금지
  required_docs JSONB       NOT NULL DEFAULT '[]',     -- 업종별 자격 서류 목록
  sort_order    INT         NOT NULL DEFAULT 100,
  status        VARCHAR(10) NOT NULL DEFAULT 'HIDDEN' CHECK (status IN ('HIDDEN','ACTIVE','INACTIVE')),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE mal.consult_category_history (
  id BIGSERIAL PRIMARY KEY,
  code VARCHAR(10) NOT NULL REFERENCES mal.consult_category(code),
  action VARCHAR(20) NOT NULL,          -- CREATE/HIDE/ACTIVATE/DEACTIVATE/MODE_CHANGE/REORDER
  before_json JSONB, after_json JSONB,
  reason TEXT NOT NULL, actor_id BIGINT NOT NULL, approved_by BIGINT,
  acted_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE mal.consult_lead (
  id            BIGSERIAL PRIMARY KEY,
  axis          VARCHAR(10) NOT NULL DEFAULT 'consult' CHECK (axis = 'consult'),
  category_code VARCHAR(10) NOT NULL REFERENCES mal.consult_category(code),
  phone_verified_at TIMESTAMPTZ,                   -- INV-12
  assigned_partner_id BIGINT,                      -- INV-L1: 1리드 = 1업체
  status        VARCHAR(20) NOT NULL DEFAULT 'RECEIVED',
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);  -- 배정 업체 칸이 하나뿐이라 구조상 1리드 = 1업체

-- 2) 역할 이관
INSERT INTO core.role (code, system) VALUES ('MAL_PARTNER', 'MAL');
-- MAL_OWNER · LED_PARTNER 보유자에게 MAL_PARTNER 부여 + 축별 입점 승인 기록 생성 후 두 역할 삭제
-- MAL_BROKER 는 유지 (부동산 축 추가 자격)
-- OPS_LED 보유자에게 OPS_MAL + 상담 축 범위를 부여한 뒤 OPS_LED 삭제
```

### 6-3. 축별 규칙 분기 (Spring Boot 예시)

```java
public void onReceive(ConsultLead lead) {
    // 상담 축 전용 규칙: 기계·부동산 축 코드에서는 호출되지 않음
    if (lead.getPhoneVerifiedAt() == null) return;            // INV-12
    ConsultCategory c = categoryRepo.get(lead.getCategoryCode());
    if (c.getPublishMode() == GATED) reviewQueue.enqueue(lead); // 보험·의료 리드 건별 검수
    else allocator.assignExclusive(lead);                       // INV-L1 1리드 = 1업체
}

@Transactional
public void deactivate(String code, String reason, Long actorId) {
    if (leadRepo.countOpenByCategory(code) > 0)
        throw new Conflict("진행 중 리드가 있어 비활성할 수 없습니다");
    if (partnerRepo.countActiveByCategory(code) > 0)
        throw new Conflict("활성 인증업체가 있어 비활성할 수 없습니다");
    history.record(code, "DEACTIVATE", reason, actorId, null);
    categoryRepo.setStatus(code, INACTIVE);
}
```

## 8. 단계별 실행 절차와 필요 자원

6단계이며, 법무 재확인(2단계)은 화면·체계 작업과 함께 진행합니다. 보험·의료 공개만 법무 회신을 기다립니다.

1. **결정 확정 (대표)** — 기존 매물 등록 회원 이관 방식(재심사 / 일괄 승인), 일반 회원 소개하기 처리, 렌탈 포함, 탭 이름. 이유: 이관 대상과 버튼 동작이 여기서 정해집니다.
2. **법무 재확인 발송** — §7-1 12번의 세 질문. 이유: 보험·의료 회신의 전제였던 "리드관"이 사라집니다.
3. **시안 반영 (SGB\_Prototype\_v10\_3)** — 축 탭 3번, 상담 4화면, 「안심소개 파트너센터」 이름·진입점 정리, 매물 등록·중개사 인증 신청 이전, 소개하기 버튼 분기. 지난 축 재편 때 생긴 결함을 막기 위해 클래스 충돌 검사·이동 대상(data-go) 전수 대조를 돌립니다.
4. **체계 재편 (서버)** — 100\_lead 를 MAL 판으로 재작성, 역할 이관, LED 라우트 재등록, LED 체계 삭제. 이유: 순서를 바꾸면 이관 중 권한 없는 라우트가 생깁니다 — **새 역할·라우트 등록 → 데이터 이관 → 옛 LED 삭제** 순서를 지킵니다.
5. **검정** — 신규 검정, INV-SEP 회귀, LED 관련 기존 테스트 재작성, 390px · 다크/라이트.
6. **오픈** — 휴대폰 확인 연동 전에는 상담 탭을 "준비 중"으로 두고 신청 버튼을 막습니다. 보험·의료는 법무 재확인 후 공개합니다.

## 9. 발생할 수 있는 문제와 해결 방법

| # | 문제 | 왜 생기나 | 해결 |
| --- | --- | --- | --- |
| 1 | 보험·의료 법무 판단이 달라짐 | 회신 전제(리드관)가 사라짐 | 재확인 전까지 보험·의료만 "준비 중". 나머지 업종 먼저 진행 |
| 2 | 소비자가 "안심 = 플랫폼 보증"으로 오해 | 관 이름에 "안심" | 상담 탭에 "업체 자격은 확인하나 상담·계약 책임은 업체" 고지 (문구 법무 확인) |
| 3 | 리드 규칙이 매물 거래에 새거나 그 반대 | 한 체계 안에 두 흐름 | 축 값 필수 + INV-AX1·AX2 검정. 지난 재편 때 설정 키 덮어쓰기로 기존 화면이 죽은 전례 → 기존 회귀 필수 |
| 4 | 이관 중 권한 공백 | 옛 역할 삭제가 먼저 일어남 | 새 역할·라우트 등록 → 이관 → 옛 LED 삭제 순서 고정 |
| 5 | 업체가 파트너센터를 헷갈림 | 파트너센터가 두 곳 | 이름을 「제휴 파트너센터」 / 「안심소개 파트너센터」로 분명히, 안심소개 파트너센터는 MAL\_PARTNER 에게만 머리 메뉴 노출, 잘못 들어오면 다른 센터 안내 |
| 6 | 관리자가 실수로 업종 삭제 | 삭제 버튼 | 비활성만, 진행 중 리드·활성 업체 있으면 거부, 이력 기록 |
| 7 | 보험·의료가 자격 없이 노출 | 게시 방식 변경 실수 | 잠금 + LEGAL 승인 |
| 8 | 중고차 매물과 상담이 섞임 | 같은 관 두 축에 같은 업종 | 등록 화면 구분 안내, 소비자 신청은 상담 축에서만 생성 |
| 9 | 외부 연동 지연 | 휴대폰 확인이 알림톡·본인인증에 묶임 | 탭은 감추지 않고 "준비 중" 배지 |
| 10 | 기존 매물 등록 회원이 갑자기 게시를 못 함 | 전 축이 입점 승인 후 게시로 바뀜 | 오픈 전 이관 — 사업자 인증 통과 회원은 기계·설비 축 일괄 승인, 나머지는 재심사 안내와 유예 기간 |
| 11 | 일반 회원 참여 저하 | 상단 문구(매물을 소개하고 수익을…)는 일반 회원 대상인데 직접 게시 불가 | 소개코드 공유·소개받기로 수익을 얻는 경로를 문구와 버튼에 명시 |
| 12 | 부동산 업체 입점이 멈춤 | A-07 회신 대기, 중개사 인증 간주 모드 | 부동산 축은 신청만 받고 승인은 회신·국토부 대조 연결 후 |

## 10. 검정 체크리스트

### 소비자 화면 (안심소개)

- [ ] 안심소개 진입 시 1번 탭(기계·설비·시설)이 기본 선택된다
- [ ] 3번 탭 주소가 #/g/mal?ax=consult 이고 머리 메뉴 「안심소개」 강조가 유지된다
- [ ] 3번 탭에서 소개하기 3버튼·급매 띠·사고예방이 사라지고 「상담 신청하기」·「인증업체 등록」만 보인다
- [ ] 업종 목록이 카테고리 마스터의 공개 업종만, 정해진 순서로 보인다
- [ ] 인증업체가 0곳인 업종은 신청 버튼이 막힌다
- [ ] 1·2번 탭 기존 화면(성공현황·목록·매물 등록·중개사 확인)이 그대로 동작한다
- [ ] 390px 넘침 없음, 다크/라이트 대비 통과

### 업체 화면 (안심소개 파트너센터)

- [ ] 화면 제목·메뉴에 「안심소개 파트너센터」가 표시되고 제휴 파트너센터(/partners)와 메뉴가 섞이지 않는다
- [ ] MAL\_PARTNER 로그인 시에만 머리 메뉴에 「안심소개 파트너센터」가 보인다
- [ ] 상담 탭 「인증업체 등록」과 나의공간 「내 업체 관리」가 /partner 로 연결된다
- [ ] 입점 승인 전에는 서비스 등록·리드 목록에 들어갈 수 없다
- [ ] 리드 열람 시 소개캐시가 1회만 차감된다

* [ ] 일반 회원이 1·2번 탭 「소개하기」를 누르면 매물 등록이 아니라 입점·소개코드 안내가 뜬다
* [ ] 인증업체는 입점 승인받은 축에만 매물을 게시할 수 있다
* [ ] 옛 #/mal/register 주소가 파트너센터 매물 등록으로 넘어간다
* [ ] 부동산 매물은 중개사 인증과 노출료 결제 전에는 노출되지 않는다

- [ ] BASIC 회원은 본인인증 후 월 1건의 소개코드를 받고, 같은 사람의 다른 계정에는 지급되지 않는다
- [ ] 일괄 승인 대상에 시험 기간 통과 기록(재조회 전)이 섞이지 않는다

### 관리자

- [ ] 업종 추가 시 기본값이 숨김이다
- [ ] 진행 중 리드가 있는 업종은 비활성이 거부된다
- [ ] 보험·의료를 OPEN 으로 바꿀 수 없고, 게시 방식 변경은 LEGAL 승인 없이는 반영되지 않는다
- [ ] 모든 변경이 이력에 남는다

### 체계

- [ ] LED 체계·역할·라우트가 0건이다
- [ ] v\_sep\_\* 4개 뷰 0행, INV-AX1·AX2 통과
- [ ] 기계·부동산 축과 소개장터·소개창업에서 보험·의료 등록은 여전히 차단된다
- [ ] 휴대폰 확인 안 된 리드가 업체 리드 목록에 오르지 않는다
