소개뱅크 API 명세서

기존 문서에는 엔드포인트 이름만 38개 있었습니다. 이 문서는 그중 핵심 14개에 요청·응답·에러를 붙인 것입니다. 나머지는 이 형식을 따라 채우면 됩니다. 설계 규칙 6가지가 먼저 나오는데, 개별 엔드포인트보다 그쪽이 중요합니다 — 규칙이 흔들리면 38개가 전부 흔들립니다.

엔드포인트 14에러 코드 29 불변식 연결 INV-1~7요구사항 추적 FR-*

설계 규칙 6가지

엔드포인트를 추가할 때 이 규칙을 먼저 확인합니다. 개별 스펙과 충돌하면 이쪽이 이깁니다.

관 스코프 없는 조회는 없다업종·리스팅·통계 어디든 관이 파라미터로 들어갑니다. 기본값을 두면 반드시 잘못된 관의 데이터가 섞입니다.
제한업종은 필터가 아니라 부재다응답에서 빼는 것이 아니라 조회 대상이 아닙니다. 프론트가 숨기는 방식은 금지합니다.
불변식 위반은 409 + rule 필드어떤 규칙을 어겼는지 rule: "INV-3"로 내려주면 화면이 그대로 문구를 만들 수 있습니다.
존재 여부를 알려주지 않는다권한 없는 리소스는 403이 아니라 404입니다 — 403은 존재를 알려줍니다.
돈이 움직이면 멱등키네트워크 재시도가 중복 지급이 되지 않게 합니다. 키 없는 요청은 400.
스냅샷을 남긴다Deal 생성 시 요율·상한·부담 주체를 복사합니다. 관 설정 변경이 진행 중 거래를 흔들지 않습니다.

엔드포인트

돈과 자격이 걸린 경로를 우선 정의했습니다. 조회 계열은 형식만 맞추면 되지만, 이 14개는 규칙이 응답에 드러나야 합니다.

아직 확정할 수 없는 부분 에스크로 결제(POST /deals/{id}/escrow)와 본인확인 콜백은 업체가 정해져야 스펙이 나옵니다(결정 B-04 · B-07). 이 두 경로는 의도적으로 비워 두었습니다 — 임시로 써두면 나중에 지우지 않고 그대로 구현됩니다.
