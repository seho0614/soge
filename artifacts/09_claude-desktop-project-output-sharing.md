# Claude 데스크톱 프로젝트 결과물 공유 절차 (초보자용)

Oct 13, 2026 · @박세호

## 0. 한눈에 보기

**결론: 결과물은 GitHub 저장소 한 곳에 모으고, 거기서 AWS 터미널과 사람에게 각각 나눠 줍니다.** 이렇게 하면 공유한 뒤에도 진행 중인 소개뱅크 프로젝트를 데스크톱과 터미널 양쪽에서 끊김 없이 계속 쓸 수 있습니다.

**핵심 원칙 3가지**

1. **원본은 한 곳**: 최종본은 항상 GitHub 저장소(코드 + `docs/` 문서 + `CLAUDE.md`)에 둡니다. 데스크톱 채팅, AWS 서버, 공유 링크는 모두 이 원본의 "사본"입니다.
2. **공유는 두 갈래**: AWS의 Claude Code에는 **저장소로**, 팀원·외부 사람에게는 **링크나 파일로** 넘깁니다.
3. **한 번이 아니라 반복**: 프로젝트가 진행 중이므로 공유는 주 1회처럼 정해진 주기로 반복합니다. 반복할 때마다 데스크톱 프로젝트 자료도 최신으로 맞춥니다. (STEP 5)

**전체 순서**

1. STEP 1: 공유 전 최종본 확정하기
2. STEP 2: 경로 A — AWS 터미널로 넘기기
3. STEP 3: 경로 B — 팀원·외부에 공유하기
4. STEP 4: 최종 개발 결과 공유하기
5. STEP 5: 진행 중인 프로젝트를 계속 이어가기

**알아 둘 사실**: 데스크톱 채팅의 대화 기록은 터미널로 자동으로 넘어가지 않습니다. 그래서 결과물을 "파일"로 만들어 저장소에 넣는 과정이 꼭 필요합니다.

## 1. 결과물 종류별 공유 방법

먼저 내 결과물이 아래 표의 어느 종류인지 확인하세요. 종류마다 "저장소에 넣는 방법"과 "사람에게 주는 방법"이 다릅니다.

| 결과물 종류 | 데스크톱에서 만드는 곳 | AWS 터미널로 넘기는 방법 | 사람에게 주는 방법 |
| --- | --- | --- | --- |
| 기획서, 전략, 회의록 (문서) | 채팅 → 문서(Docs) | Markdown으로 내보내 `docs/`에 저장 | 문서 **Share** 또는 PDF·Word 내보내기 |
| 화면 시안, 포스터 (디자인) | 채팅 → 디자인 / 아티팩트 | 아티팩트 링크를 Claude Code에 전달, 또는 PNG·PDF로 `docs/design/`에 저장 | 아티팩트 **Share** 링크, PNG·PDF |
| 웹페이지, 대시보드 (아티팩트) | 채팅 또는 Code 탭 | 아티팩트 링크를 Claude Code에 전달 | 아티팩트 **Share** 링크 |
| 소스 코드 | Code 탭 (로컬 또는 SSH 세션) | `git push` → 서버에서 `git pull` | GitHub 저장소 초대, 릴리스 |
| 결정사항, 대화 흐름 | 채팅 | 요약해서 `CLAUDE.md`·`docs/decisions.md`에 기록 | 채팅 **Share** 링크(스냅샷) |
| 표, 데이터 | 채팅 → 시트 / 파일 | CSV로 저장해 `docs/data/`에 저장 | 파일 첨부, 시트 공유 |

**기억할 점**: AWS의 Claude Code가 확실하게 읽을 수 있는 것은 **저장소 안의 파일**과 **아티팩트 링크**입니다. 데스크톱 채팅 안에만 있는 내용은 읽지 못합니다.

## STEP 1. 공유 전 최종본 확정하기

공유하기 전에 "어느 것이 최종본인지"를 정하지 않으면, 나중에 여러 버전이 섞여 프로젝트를 이어가기 어려워집니다. 10분이면 끝납니다.

**1-1. 최종본에 이름과 날짜 붙이기**

파일과 아티팩트 제목을 아래 규칙으로 통일합니다.

```
[프로젝트]_[결과물이름]_v[번호]_[날짜]
예) 소개뱅크_런칭전략_v3_20261013
예) 소개뱅크_회원가입화면_v2_20261013
```

- 수정할 때마다 번호를 올립니다 (v1 → v2 → v3).
- "최종", "진짜최종" 같은 이름은 쓰지 않습니다.

**1-2. 데스크톱에서 최종 검수 요청하기**

결과물이 있는 채팅에서 아래 문장을 보냅니다.

```
이 결과물을 외부에 공유하기 전에 점검해 줘.
1) 사실과 다르거나 확정되지 않은 내용
2) 개인정보, 비밀번호, 내부 금액 등 공유하면 안 되는 정보
3) 앞에서 정한 결정과 다른 부분
4) 받는 사람이 이해하기 어려운 용어
문제가 있는 줄을 표로 정리해 줘.
```

**1-3. 공유 전 확인 목록**

- [ ] 파일·제목에 버전 번호와 날짜가 있다
- [ ] 개인정보(전화번호, 주민번호, 계좌), 비밀번호, API 키가 없다
- [ ] 확정되지 않은 내용은 "미정"으로 표시했다
- [ ] 받는 사람이 누구인지 정했다 (AWS 터미널 / 팀원 / 외부)
- [ ] 받는 사람이 수정까지 해야 하는지, 보기만 하면 되는지 정했다

## STEP 2. 경로 A — AWS 터미널(Claude Code)로 넘기기

데스크톱에서 만든 결과물을 GitHub 저장소에 넣으면, AWS 서버의 Claude Code가 그대로 이어받아 개발합니다. 결과물 종류에 맞는 방법 하나를 고르세요.

**2-1. 문서 결과물 (기획서, 전략 등)**

1. 데스크톱에서 문서를 엽니다.
2. 문서 이름을 누르고 **Export → Markdown**을 고릅니다. 파일이 내 PC에 저장됩니다.
3. 내 PC에서 서버의 `docs/` 폴더로 보냅니다. (연결 가이드 STEP 2-4에서 만든 `sogae` 별명 사용)

```bash
scp ./소개뱅크_런칭전략_v3_20261013.md sogae:~/sogaebank/docs/
```

4. 서버에서 저장소에 기록합니다.

```bash
cd ~/sogaebank
git add docs/
git commit -m "docs: 런칭전략 v3 추가"
git push
```

**2-2. 아티팩트 결과물 (화면 시안, 대시보드 등)**

아티팩트는 링크만 넘기면 됩니다. 같은 Claude 계정으로 로그인한 Claude Code는 아티팩트 링크를 읽을 수 있습니다.

1. 아티팩트 화면 위쪽에서 링크를 복사합니다. (`https://claude.ai/code/artifact/...` 형태)
2. AWS 서버의 Claude에게 이렇게 요청합니다.

```
이 아티팩트를 읽고 소개뱅크 화면으로 구현해 줘.
https://claude.ai/code/artifact/xxxx
구현 전에 계획부터 보여 줘.
```

3. 터미널에서 `/artifacts`를 입력하면 내가 만든 아티팩트와 공유받은 아티팩트 목록이 나옵니다. 고른 뒤 Enter를 누르면 현재 대화에 붙습니다.
4. 나중에 다시 참고할 수 있게 링크를 `docs/links.md`에 한 줄로 적어 두세요.

**2-3. 코드 결과물 (데스크톱 Code 탭에서 만든 코드)**

- **로컬 세션에서 만든 코드**: Code 탭에서 Claude에게 "변경 내용을 커밋하고 push해 줘"라고 요청합니다. 서버에서는 `cd ~/sogaebank && git pull`로 받습니다.
- **SSH 세션(서버에 직접 연결)에서 만든 코드**: 이미 서버에 있으므로 따로 옮길 필요가 없습니다. 커밋만 하세요.

**2-4. 결정사항 (채팅에서 정한 내용)**

1. 데스크톱 채팅에서 요청합니다: "오늘 이 대화에서 확정한 결정만 날짜와 이유를 붙여 목록으로 정리해 줘."
2. 결과를 서버의 `docs/decisions.md` 맨 아래에 붙여 넣습니다. (`nano docs/decisions.md`)
3. 꼭 지켜야 하는 규칙이면 `CLAUDE.md`의 "확정된 결정" 칸에도 한 줄 추가합니다.

**2-5. 마지막: 인수인계 노트 남기기**

여러 결과물을 한꺼번에 넘겼다면 `docs/handoff.md`에 무엇을 넘겼고 다음에 무엇을 할지 적습니다. 서버의 Claude에게 "docs/handoff.md 읽고 다음 작업 시작해 줘"라고 하면 바로 이어집니다. 형식은 이 문서의 템플릿 섹션에 있습니다.
