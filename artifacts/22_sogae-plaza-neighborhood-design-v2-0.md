# 소개뱅크 소개광장 우리동네 설계서 v2.0 (기획2 반영)

Sep 29, 2026 · @박세호

## 0. 개요와 최종 결론

09.29 소개광장 기획2의 우리동네(동네픽·동네소개·동네참여)를 소개뱅크에 적용하기 위한 설계서입니다. v1.0 설계서의 우리동네 부분을 대체하고, "이거 어때?"는 v1.0을 그대로 유지합니다.

1. **적용 순서**: 공통 기반 → 동네픽 1차(운영자 선정 + AI 문장 보조) + 동네소개 → 동네픽 2차(AI 매일 자동생성) → 동네참여(동네행사 → 체험해요 → 같이해요) → GPS "내 주변" 기능.
2. **가장 큰 설계 변경**: Google 지도 약관상 장소 이름·주소·사진·평점은 저장할 수 없고 place\_id만 영구 저장할 수 있습니다. 그래서 장소 정보는 화면에 보일 때마다 Google에서 불러오고, 소개뱅크 DB에는 **place\_id + 소개뱅크 자체 데이터(추천 이유·태그·회원 반응·소개)** 만 쌓습니다. 이 자체 데이터가 소개뱅크의 자산입니다.
3. **AI 매일 자동생성은 2차로 미룹니다.** 초기에는 AI가 고를 장소 데이터가 없어서, 억지로 생성하면 품질이 낮거나 없는 정보를 지어낼 위험이 큽니다. 동네소개로 장소 데이터가 쌓인 뒤 켭니다.
4. **위치정보 신고 없이 시작 가능**: 지역은 회원이 선택하고, 거리는 휴대폰 안에서 계산해 서버로 보내지 않으면 비신고 대상 조건에 맞습니다. GPS를 서버로 보내는 기능은 신고 수리 후 추가합니다(위치정보지원센터 확인 권장).

문서 성격: 권고안입니다. 숫자는 추정 초기값이며, 요금·약관·법률 항목은 적용 전 최신 확인이 필요합니다.

## 1. 기획2 검토 의견과 보완

기획 방향(말하면 AI가 정리, 지도 중심, 소개로 연결)은 그대로 살리고, 그대로 만들면 문제가 되는 6가지를 보완합니다.

| # | 기획2 내용 | 문제 | 보완안 |
| --- | --- | --- | --- |
| 1 | Google 지도에서 장소 정보를 보여주고 데이터화 | 약관상 place\_id만 영구 저장 가능, 좌표는 30일까지만 캐시, 이름·주소·사진·평점은 저장 불가. 장소명을 세션 밖에서 저장하면 스크래핑으로 간주 | 장소 정보는 표시할 때마다 조회. DB에는 place\_id와 소개뱅크 자체 데이터만 저장(§3) |
| 2 | AI PICK 한줄을 장소 데이터 분석으로 생성 | Google 리뷰·사진을 원료로 문장을 만들어 저장하면 약관 위반 소지 | AI 입력은 소개뱅크 자체 데이터(회원 소개이유·반응·운영자 태그) + 날씨·요일·시간만 사용 |
| 3 | 매일 자동생성, 승인 60분 후 자동 승인 | 사람 확인 없이 AI 글이 게시됨 → 폐업 가게·잘못된 정보 노출, 광고성 문제 | 1차는 100% 수동 승인. 2차에서 품질 조건을 모두 통과한 픽만 자동 승인(§4-5) |
| 4 | 초기 주요지역 서울·경기·각 시도 동시 활성화 | 지역이 넓으면 지역마다 글·소개가 흩어져 빈 화면이 됨 | 성남 분당·판교 1곳으로 시작 → 확장 기준 충족 시 지역 추가(§2-2) |
| 5 | 동네소개 "내 주변 질문", 카드 거리 표시 | GPS를 서버로 보내면 위치기반서비스사업 신고 대상 | 1\~3단계는 "선택한 지역" 기준. 거리는 휴대폰에서만 계산. 서버 GPS 기능은 신고 후(§3-3) |
| 6 | 체험해요(업체·소개뱅크 모집 체험·평가단) | 대가를 받은 후기에 표시가 없으면 표시광고법 위반 소지 | 체험해요 참여자의 후기에 "체험단 제공" 자동 표시 |

참고: 국내 동네 가게의 Google 장소 데이터 충실도(등록 여부·영업 상태)는 카카오·네이버와 차이가 있을 수 있습니다. 개발 전 판교 가게 20곳으로 검색 테스트를 권고합니다(체크리스트).

## 2. 적용 순서와 근거

순서는 "앞 단계가 다음 단계에 필요한 데이터를 만들어 주는가"로 정했습니다. 동네소개가 쌓는 장소 데이터가 AI 동네픽의 원료이고, 동네참여는 안전 위험이 커서 뒤에 둡니다.

### 2-1. 단계표

| 단계 | 적용 내용 | 기간(추정) | 선행 조건 | 이 순서인 이유 |
| --- | --- | --- | --- | --- |
| 1. 공통 기반 | 지역 체계, 장소 마스터(place\_id), Google 지도·장소검색 연결, AI 검색 입구, 관리자 승인 큐 | 3주 | Google Cloud 결제 계정, API 키 | 모든 메뉴가 공통으로 씀 |
| 2. 동네픽 1차 + 동네소개 | 운영자가 장소 선정 → AI가 한줄·태그 초안 → 수동 승인 게시. 동네소개 질문·소개·집계 | 5\~6주 | 1단계 | 동네픽은 유입, 동네소개는 장소 데이터 축적. 둘이 서로 연결됨 |
| 3. 동네픽 2차 | AI 매일 자동생성(지역·요일·날씨·주제), 조건부 자동 승인, 회원 반응 반영 | 3\~4주 | 지역당 자체 데이터 있는 장소 100곳 이상 | 원료 데이터가 있어야 AI 품질 확보 |
| 4. 동네참여-동네행사 | 공공데이터 행사정보 자동 수집·노출기간 자동 게시 | 2주 | 1단계 | 운영 부담 낮고 사고 위험 낮음 |
| 5. 동네참여-체험해요 | 업체 체험·평가단 모집, 승인형 참여 | 3주 | 4단계, 체험단 표시 정책 | 수익 연결(업체 모집) |
| 6. 동네참여-같이해요 | 주민 모임, 한 줄 등록, 자유·승인 참여 | 3주 | 안전 정책 확정 | 오프라인 만남 위험이 가장 큼 |
| 7. GPS 내 주변 | 서버 기반 현재 위치 추천·질문 | 2주 | 위치기반서비스사업 신고 수리 | 법적 선행 조건 |

### 2-2. 지역 확장 기준 (초기값 제안)

1. 1차 권역: 성남시 분당구(판교 포함)
2. 다음 권역 추가 조건: 현재 권역에서 월 활동 소개자 50명 이상, 질문 24시간 내 소개 달림 비율 70% 이상, 자체 데이터 있는 장소 300곳 이상
3. 확장 후보 순서: 서울 강남·서초·송파 → 경기 수원·용인 → 각 시도 대표 도시

## 3. 공통 기반

네 가지 기반(AI 검색 입구, 장소 마스터, 지역, 승인 큐)을 먼저 만들어 세 메뉴가 함께 씁니다.

### 3-1. AI 검색 입구 (타 관과 동일)

타 관의 AI 검색 컴포넌트를 재사용하고 범위만 `scope=CMU`로 지정합니다.

1. 입력: "판교에서 부모님 모시고 갈 고깃집 소개해줘"
2. AI가 의도와 조건을 분리: 지역=판교, 분야=고깃집, 상황=부모님 동반
3. 검색 순서: 동네픽 카드 → 동네소개 집계(소개 많은 장소) → 동네참여
4. 결과 3건 미만이면 "동네 사람에게 물어보기"를 먼저 표시(질문 문장 자동 작성)
5. 다른 관 의도면 해당 관으로 연결(예: "태양광 설치 업체" → 안심소개 태양광 분야)

### 3-2. 장소 마스터 — 약관을 지키는 저장 원칙

| 구분 | 데이터 | 저장 여부 |
| --- | --- | --- |
| Google 식별자 | place\_id | 영구 저장 가능 |
| Google 좌표 | 위도·경도 | 30일까지 캐시 후 삭제 → 갱신 |
| Google 장소 정보 | 이름·주소·전화·사진·평점·리뷰·영업시간 | 저장 불가 → 표시할 때 조회 |
| 소개뱅크 자체 | 소개이유, 이용 여부, 저장·가봤어요·소개할게요, 운영자 태그, AI PICK 문장, 동네 질문 연결 | 자유롭게 저장 (핵심 자산) |

표시 규칙: 장소 정보는 Google 지도 위에 표시하고, 지도 없이 카드로만 보여줄 때는 Google Maps 로고와 출처 표시를 붙입니다. 리뷰·사진을 쓰면 작성자 표시도 필요합니다.

### 3-3. 지역 체계와 위치 처리

1. 지역 구조: 시도 > 시군구 > 행정동. 회원은 "내 동네"를 목록에서 선택(최대 2곳)
2. 목록 선택은 위치정보 수집이 아니므로 신고 전에도 운영 가능
3. 카드 거리 표시: 휴대폰 브라우저가 현재 위치와 장소 좌표로 직접 계산하고 서버로 보내지 않음. 위치정보지원센터 안내상 단말기에서만 활용하고 사업자 시스템으로 전송하지 않으면 신고 제외 대상(적용 전 센터 확인 권장)
4. 서버가 현재 위치를 받는 기능(내 주변 실시간 추천 등)은 7단계, 신고 수리 후

### 3-4. 관리자 승인 큐

세 메뉴의 검수 대상을 한 화면에 모읍니다: 동네픽 초안, AI가 분류한 스팸·광고 의심, 중복 질문, 신고, 참여글 검토 필요. 관리자는 AI가 "예외"로 분류한 항목만 보고, 정상 항목은 AI 분류를 그대로 따릅니다(기획2의 예외 중심 검수).

## 4. 동네픽 설계

동네픽은 "왜 지금 이 장소인가"를 보여주는 지역 큐레이션입니다. 1차는 운영자가 장소를 고르고 AI가 문장을 돕고, 2차에서 AI가 매일 자동으로 만듭니다.

### 4-1. 사용자 흐름

1. 우리동네 → 동네픽 → 지역 선택(최초 1회, 이후 기억)
2. 오늘의 동네픽 3\~5개 → 지도 + 카드 목록
3. 장소 선택 → 저장 / 가봤어요 / 소개할게요
4. 더 궁금하면 "동네 사람에게 물어보기" → AI가 질문 문장 작성 → 동네소개에 게시 → 달린 소개는 해당 장소 데이터로 합산

### 4-2. 주제와 요일 배치

| 주제 | 역할 | 기본 배치 |
| --- | --- | --- |
| 오늘 뭐먹지 | 점심·저녁·카페 | 매일 |
| 요즘 여기 | 신규·화제 장소 | 화·목 |
| 생활픽 | 미용·운동·자동차·청소·수리 | 월·수 |
| 아이랑 | 육아·가족·체험 | 수·토 |
| 댕냥픽 | 반려동물 | 화·일 |
| 주말픽 | 나들이·행사·주말 활동 | 금·토·일 |

하루 3\~5개 = 오늘 뭐먹지 1\~2개 + 요일 주제 2\~3개. 비 오는 날은 실내 태그 장소를 우선합니다.

### 4-3. 장소 카드

대표사진 → 장소명·거리·가격대 → AI PICK 한줄 → 핵심태그 3개 → 회원반응 → 저장 / 가봤어요 / 소개할게요

| 요소 | 출처 | 비고 |
| --- | --- | --- |
| 대표사진 | 소개뱅크 등록 사진 우선, 없으면 Google 사진(출처 표시) | Google 사진은 호출 비용이 따로 발생 |
| 장소명·주소 | Google(표시 시 조회) | 저장 불가 |
| 거리 | 휴대폰에서 계산 | 서버 전송 없음 |
| 가격대·태그 | 소개뱅크(운영자·회원) | 자체 데이터 |
| AI PICK 한줄 | AI(자체 데이터 + 상황 조건) | 30자 이내, 같은 장소도 주제별로 다르게 |
| 회원반응 | 소개뱅크 | 가봤어요 수, 소개 수 |

장기 규칙(기획2 반영): 한 장소의 회원 반응이 10건 이상 쌓이면 AI 태그보다 회원이 많이 고른 소개이유를 태그로 우선 표시합니다.

### 4-4. 소개할게요 — 수익 연결점

누르면 "누구에게 소개할까요?" 세 가지를 띄웁니다.

1. **친구에게 공유**: 소개뱅크 소개링크(회원 소개코드 포함)로 공유 → 이 링크로 방문·이용이 성사되면 기존 소개 수익 구조로 연결
2. **동네 사람에게 소개**: 동네소개의 소개 1건으로 등록(이용 여부·소개이유 선택)
3. **내 소개목록에 저장**: 마이페이지 소개목록

소개비가 걸리는 장소의 공유·소개에는 "소개비 받는 소개" 표시를 자동으로 붙입니다.

### 4-5. 생성과 승인 흐름

| 단계 | 1차 (2단계) | 2차 (3단계) |
| --- | --- | --- |
| 후보 선정 | 운영자가 Google 장소검색으로 선택 | AI가 자체 데이터 있는 장소 풀에서 선정 |
| 문장 생성 | AI가 한줄·태그 초안 | AI가 주제·요일·날씨 반영해 생성 |
| 미리보기·수정 | 관리자 | 관리자 |
| 승인 | 100% 수동 | 조건 충족 시 60분 후 자동 승인, 미충족 시 대기 |
| 게시 | 지도 마커·장소 카드 생성 | 동일 |

자동 승인 조건(모두 충족): 픽 안의 모든 장소가 Google 조회로 영업 중 확인, 모든 장소에 자체 데이터 3건 이상, 최근 30일 관리자 수정률 10% 미만, 금지어·과장 표현 검사 통과.

### 4-6. AI 후보 선정 점수 (2차)

```latex
\text{픽점수} = 0.35\,\text{주제적합} + 0.30\,\text{회원반응} + 0.20\,\text{상황적합} + 0.15\,\text{신선도}
```

| 요소 | 계산 |
| --- | --- |
| 주제적합 | 장소 태그와 주제 태그 일치 비율 |
| 회원반응 | 가봤어요·저장·소개의 베이즈 평균(0\~1 환산) |
| 상황적합 | 날씨(비→실내), 시간(점심·저녁), 요일(주말) 일치 여부 |
| 신선도 | 같은 장소 14일 내 재노출 금지, 최근 노출일수록 감점 |

날씨는 기상청 단기예보(공공데이터포털)를 하루 1회 받아 씁니다. 매일 새벽 배치로 생성 → 오전 관리자 알림 → 승인 → 게시.

## 5. 동네소개 설계

동네소개는 "사용자는 말만 하고, 분류와 정리는 AI가 하는" 질문 → 소개 구조입니다. 소개 1건마다 place\_id·이용 여부·소개이유가 쌓여 소개뱅크 고유의 장소 데이터가 됩니다.

### 5-1. 사용자 흐름

1. 한 줄 질문: "판교에서 타이어 교체 친절하고 잘하는 곳 있을까요?"
2. AI 자동 처리: 분류(자동차 > 타이어), 태그(판교·친절), 문장 정리, **중복 질문 탐색** → 비슷한 질문이 있으면 "이 질문에 나도 궁금해요 누르기"를 먼저 제안
3. 동네에 질문 게시 → 알림 대상 회원에게 알림(v1.0 알고리즘 ② 재사용)
4. 다른 회원: 나도 궁금해요 / 소개할게요
5. 소개할게요 → Google 장소검색으로 장소 선택 → 이용했어요 / 소개만 할게요 → 소개이유 선택 → 이곳 소개하기
6. 장소별 자동 집계 → AI 결과요약 → 지도에서 보기

### 5-2. 소개이유 선택지 — 업종별 AI 생성, 미리 승인

요청마다 AI를 부르지 않고, 업종별 선택지를 AI가 한 번 만들고 관리자가 승인해 저장합니다(비용 절감, 집계 일관성).

| 업종 | 선택지 예 |
| --- | --- |
| 자동차 정비 | 설명을 잘해요 / 가격이 합리적 / 과잉정비 없어요 / 빨라요 / 친절해요 / 기타 |
| 병원 | 설명이 자세해요 / 대기가 짧아요 / 과잉진료 없어요 / 친절해요 / 기타 |
| 음식점 | 맛있어요 / 가성비 / 주차 편해요 / 분위기 / 친절해요 / 기타 |

### 5-3. 소개카드와 집계

장소명 → 소개한 회원 수 → 직접 이용 회원 수 → 주요 소개이유 3개 → 지도보기 → 나도 소개할게요

정렬: 직접 이용 소개 1.0, 소개만 0.5, 소개비 걸린 소개 0.5로 가중 합산해 순위를 매깁니다. 같은 회원이 같은 장소를 30일 내 여러 번 소개하면 1건으로 셉니다.

### 5-4. AI 결과요약

소개 3건 이상일 때만 생성합니다. 형식: "8명이 소개했고 그중 5명이 직접 이용했어요. 가장 많이 꼽은 이유는 '설명을 잘해요'입니다." 숫자는 서버 집계값을 그대로 넣고, AI는 문장만 다듬습니다(숫자를 AI가 만들지 않게).

### 5-5. 노출 위치 의견 (기획2 5번 질문 답)

| 목록 | 선정 규칙 | 노출 위치 | 단계 |
| --- | --- | --- | --- |
| 📍 우리 동네 질문 | 회원이 선택한 동네의 최신 질문 | 동네소개 메인 1번째 (기본 탭) | 2단계 |
| 🔥 지금 많이 궁금해요 | 최근 7일 나도 궁금해요 증가량 순(48시간 반감) | 동네소개 메인 2번째 + 소개광장 홈 위젯 3개 | 2단계 |
| 🙋 아직 소개가 필요해요 | 등록 24시간 경과, 소개 1건 이하 | 동네소개 메인 3번째 + 해당 분야 회원 알림 | 2단계 |
| ❤️ 내 관심사 | 최근 30일 조회·저장·소개 분야 기준 | 동네소개 메인 4번째 (로그인 + 행동 10건 이상일 때만) | 3단계 |

추가 노출:

1. 동네픽 장소 카드 아래: 그 장소가 소개된 질문 링크
2. 마이페이지: 내가 한 질문 / 내가 한 소개 / 내 소개목록
3. 기획2의 "내 주변 질문"은 GPS 없이 운영하는 동안 "우리 동네 질문"으로 이름을 바꿔 씁니다.

### 5-6. AI 관리 자동화

| AI 판정 | 처리 |
| --- | --- |
| 정상 | 즉시 게시 |
| 중복 질문 | 기존 질문으로 안내, 작성자가 원하면 게시 |
| 광고·스팸 의심 | 비공개 후 승인 큐 |
| 개인정보 포함(전화번호 등) | 자동 가림 후 게시 |
| 소개 부족(24시간 0건) | 알림 2차 발송, 🙋 목록 노출 |

## 6. 동네참여 설계

"보고 → 바로 참여"하는 지역 참여 서비스입니다. 세 유형을 위험이 낮은 순서(동네행사 → 체험해요 → 같이해요)로 엽니다.

### 6-1. 참여 유형

| 유형 | 연결 | 등록 주체 | 참여 방식 | 단계 |
| --- | --- | --- | --- | --- |
| 동네행사 | 지역-사람 | 공공데이터 자동 수집 + 운영자 | 정보 확인·관심있어요(외부 신청 링크) | 4단계 |
| 체험해요 | 업체-사람 | 지역 업체·소개뱅크 | 승인형(업체가 선정) | 5단계 |
| 같이해요 | 사람-사람 | 회원 | 자유참여 또는 승인형 | 6단계 |

동네행사 원천: 한국관광공사 TourAPI 행사정보 등 공공데이터를 하루 1회 수집하고, 행사 기간을 노출기간으로 자동 설정합니다.

### 6-2. 참여 흐름과 상태

1. 동네참여 → 내 지역 참여목록 → 참여카드 → 참여하기 → 간편 신청
2. 자유참여: 신청 → 즉시 확정. 승인형: 신청 → 주최자 승인 → 확정
3. 정원 초과 시 대기 → 취소 발생 시 대기 1순위 자동 확정
4. 알림: 확정 즉시, 전날 저녁, 시작 2시간 전
5. 종료 시각이 지나면 자동 종료 → 참여완료 처리

| 글 상태 | 전환 조건 |
| --- | --- |
| 검토필요 | AI가 부적절·광고·중복 의심으로 분류 |
| 모집중 | 게시 완료 |
| 모집완료 | 확정 인원 = 정원 |
| 종료 | 종료 시각 경과(자동) 또는 주최자 종료 |
| 신고 | 신고 접수 → 승인 큐 |

### 6-3. 한 줄 등록 — AI 추출

입력: "이번 토요일 오전에 탄천에서 강아지 산책 같이 하실 분 5명 정도"

```json
{
  "join_type": "TOGETHER",
  "title": "토요일 오전 탄천 강아지 산책 같이해요",
  "region": "분당구",
  "place_query": "탄천",
  "start_at": "2026-10-03T10:00",
  "end_at": null,
  "capacity": 5,
  "tags": ["댕냥", "산책", "초보가능"],
  "need_confirm": ["시작 시각", "모이는 장소"]
}
```

"오전"처럼 모호한 값은 AI가 채우되 `need_confirm`에 넣어 사용자 확인 화면에서 강조합니다. 날짜는 서버가 오늘 날짜 기준으로 다시 계산해 검증합니다(AI의 날짜 오류 방지).

### 6-4. 참여카드

대표이미지 → 제목 → 지역·거리 → 날짜·시간 → 현재/모집 인원 → 참가조건 → 한줄설명 → 참여하기 (보조: 관심있어요 / 공유 / 저장)

### 6-5. 안전·표시 정책

| 대상 | 정책 |
| --- | --- |
| 같이해요 | 성인 인증 회원만 개설·참여, 모임 장소는 공개 장소만(Google 장소 선택 필수), 개인 연락처 게시 금지(자동 가림), 신고 1회 시 즉시 비공개 검토 |
| 체험해요 | 참여자 후기에 "체험단 제공" 자동 표시, 업체 등록 시 사업자 확인 |
| 동네행사 | 출처·원문 링크 표시, 행사 변경 가능성 안내 |

## 7. 화면 ID와 데이터 구조

### 7-1. 화면 ID

### 7-2. 테이블 (v1.0의 PLACE 대상 대체)

```sql
-- 장소 마스터: Google 콘텐츠는 place_id와 30일 좌표 캐시만
CREATE TABLE cm_place (
  place_id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  google_place_id  VARCHAR(300) NOT NULL UNIQUE,   -- 영구 저장 허용
  region_id        BIGINT NOT NULL,                -- 소개뱅크 지역
  category         VARCHAR(50),
  own_tags         JSON,                           -- 운영자·회원 태그 (자체)
  price_level      TINYINT,                        -- 자체 입력
  lat_cache        DECIMAL(9,6),                   -- 30일 캐시
  lng_cache        DECIMAL(9,6),
  geo_cached_at    DATETIME,                       -- 30일 경과 시 삭제·갱신
  own_photo_url    VARCHAR(500),                   -- 소개뱅크 등록 사진
  created_by       BIGINT,
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 동네픽
CREATE TABLE cm_pick (
  pick_id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  region_id        BIGINT NOT NULL,
  theme            VARCHAR(20) NOT NULL,           -- EAT, NEW, LIFE, KIDS, PET, WEEKEND
  pick_date        DATE NOT NULL,
  title            VARCHAR(100),
  context_json     JSON,                           -- 날씨·요일·시간대
  status           VARCHAR(15) NOT NULL,           -- DRAFT, PREVIEW, APPROVED, AUTO_APPROVED, PUBLISHED, REJECTED, HOLD
  approve_deadline DATETIME,                       -- 자동 승인 기준 시각
  approved_by      BIGINT,
  gen_source       VARCHAR(10)                     -- STAFF, AI
);

CREATE TABLE cm_pick_card (
  pick_id BIGINT, place_id BIGINT, sort_no INT,
  ai_line VARCHAR(60), tags JSON,
  PRIMARY KEY (pick_id, place_id)
);

-- 장소 반응 (저장·가봤어요·소개할게요)
CREATE TABLE cm_place_reaction (
  place_id BIGINT, member_id BIGINT,
  reaction VARCHAR(10),                            -- SAVE, VISITED, RECOMMEND
  pick_id  BIGINT,                                 -- 어느 픽에서 반응했는지
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (place_id, member_id, reaction)
);

-- 동네소개의 소개 1건
CREATE TABLE cm_intro (
  intro_id     BIGINT PRIMARY KEY AUTO_INCREMENT,
  post_id      BIGINT NOT NULL,                    -- cm_post (ASK)
  place_id     BIGINT NOT NULL,
  member_id    BIGINT NOT NULL,
  used_yn      TINYINT(1) NOT NULL,                -- 이용했어요 1 / 소개만 0
  reasons      JSON,                               -- 선택한 소개이유 코드
  has_interest TINYINT(1) DEFAULT 0,               -- 소개비 걸림
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 장소별 소개 집계 (배치)
CREATE TABLE cm_place_intro_stat (
  place_id BIGINT PRIMARY KEY,
  intro_cnt INT, used_cnt INT, weighted_score DECIMAL(8,2),
  top_reasons JSON, calc_at DATETIME
);

-- 업종별 소개이유 선택지
CREATE TABLE cm_reason_template (
  category VARCHAR(50) PRIMARY KEY,
  reasons JSON, approved TINYINT(1) DEFAULT 0
);

-- 동네참여
CREATE TABLE cm_join (
  post_id        BIGINT PRIMARY KEY,               -- cm_post (JOIN)
  join_type      VARCHAR(12) NOT NULL,             -- TOGETHER, EXPERIENCE, EVENT
  source         VARCHAR(12) NOT NULL,             -- MEMBER, BIZ, PUBLIC_DATA
  place_id       BIGINT,
  start_at       DATETIME NOT NULL,
  end_at         DATETIME,
  capacity       INT,
  confirmed_cnt  INT DEFAULT 0,
  need_approval  TINYINT(1) DEFAULT 0,
  state          VARCHAR(12) NOT NULL,             -- REVIEW, OPEN, FULL, CLOSED, REPORTED
  expose_from    DATETIME, expose_to DATETIME
);

CREATE TABLE cm_join_member (
  post_id BIGINT, member_id BIGINT,
  status  VARCHAR(10) NOT NULL,                    -- APPLIED, CONFIRMED, WAITING, CANCELED, DONE
  applied_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (post_id, member_id)
);
```

`cm_post.post_type`에 `JOIN`을 추가하고, 기존 `MEET`는 사용하지 않습니다. 좌표 캐시는 매일 배치로 `geo_cached_at`이 30일 지난 행의 좌표를 비웁니다.

2025년 3월부터 월 $200 크레딧이 없어지고 항목별 무료 한도로 바뀌었습니다([Google 공식 요금 분류](https://developers.google.com/maps/billing-and-pricing/pricing-categories)). 장소 이름·평점·사진 등 요청하는 필드에 따라 Essentials/Pro/Enterprise 등급이 정해지므로, 필드별 등급은 공식 문서로 확인해야 합니다.

### 8-2. 월 비용 예시 (1차 권역, 월 이용자 3,000명 가정, 추정)

| 항목 | 계산 | 절감 전 | 절감 후 |
| --- | --- | --- | --- |
| 지도 로드 | 3,000명 × 월 8회 = 24,000 → 유료 14,000 | 약 $98 | 약 $98 |
| 장소 상세 | 3,000명 × 8회 × 카드 5개 = 120,000건 | Essentials 약 $550 / Pro 약 $1,955 | 카드 클릭 시에만 조회(10% 가정) 12,000건 → Pro 약 $119 |
| 장소 검색(소개하기) | 소개 건수에 비례 | 소액 | 소액 |
| AI 호출 | 동네픽 월 약 120회 + 질문 분류·요약 | 모델별 요금 확인 필요 | 동일 |
| 날씨·행사 공공데이터 | 이용 신청 | 무료(신청 필요) | 무료 |
| 알림톡 | 발송 건수 × 건당 요금 | 계약 요금 확인 필요 | 회원당 하루 3건 상한 |

### 8-3. 비용 절감 설계

1. 카드 목록에는 자체 데이터(AI PICK·태그·반응·자체 사진)만 표시하고, Google 장소 상세는 카드를 눌렀을 때만 조회
2. 요청 필드 최소화(field mask): 목록용·상세용 필드 세트를 나눠 등급이 올라가지 않게
3. 지도 마커는 30일 좌표 캐시로 표시(좌표 조회 호출 없음)
4. 공공데이터(지방행정 인허가 등)와 매칭되는 장소는 그 상호를 자체 표시명으로 사용 → 목록 단계 Google 조회 제거. 매칭 방식은 개발 전 검토 필요
5. Google Cloud 콘솔에서 항목별 일일 한도와 예산 알림 설정

### 8-4. 개발 자원

| 단계 | 기간(추정) | 인력 |
| --- | --- | --- |
| 1\~3단계(기반·동네픽·동네소개) | 약 11\~13주 | 개발 1\~2명, 콘텐츠 1명 |
| 4\~6단계(동네참여) | 약 8주 | 개발 1명 |

## 9. 문제와 해결, 체크리스트, 다음 할 일

가장 큰 위험 세 가지는 Google 약관 위반, AI 자동 게시 오류, 초기 빈 화면이며 모두 앞 절의 설계로 대응합니다.

| # | 문제 | 해결 |
| --- | --- | --- |
| 1 | 장소명·주소를 DB에 저장해 약관 위반 | place\_id만 저장, 좌표 30일 캐시 배치 삭제, 코드 리뷰 체크 항목에 추가 |
| 2 | AI가 폐업 가게·틀린 정보를 픽에 넣음 | 게시 전 Google 영업 상태 조회, 1차 수동 승인, 조건부 자동 승인 |
| 3 | 지역을 넓게 열어 빈 화면 | 1권역 시작, 확장 기준 충족 시 추가 |
| 4 | Google 요금 급증 | 목록은 자체 데이터, 상세는 클릭 시만, 일일 한도·예산 알림 |
| 5 | 국내 가게가 Google에 없거나 정보가 부실 | 사전 검색 테스트, 없는 장소는 "직접 등록 요청"으로 운영자 확인 후 처리 방식 검토 |
| 6 | 업체 셀프 소개·바이럴 | 반복 소개 1건 처리, 소개비 표시, v1.0 어뷰징 규칙 적용 |
| 7 | 같이해요 오프라인 사고 | 성인 인증, 공개 장소, 연락처 가림, 6단계로 늦춤 |
| 8 | AI가 날짜·인원 잘못 추출 | need\_confirm 강조, 서버 날짜 재검증 |
