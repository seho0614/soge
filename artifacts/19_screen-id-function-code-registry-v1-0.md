# 소개뱅크 화면 ID 기능 코드 예약표 v1.0

Oct 1, 2026 · @박세호

> **이 판은 대체되었습니다 (2026-10-01).** 레지스트리 대조판 `화면 ID 기능 코드 예약표 v1.1`이 정본입니다. 이 판의 §3-3 매핑 중 SRC(구현 화면으로 정정)·WAL(재부여 철회)은 v1.1 §4를 따르고, 초대 화면 `SB-HOM-INV-010 → SB-HOM-INT-010`이 추가되었습니다.

## 0. 개요와 결론

화면 ID 규칙 `SB-<영역3>-<기능3>-<일련3>`의 영역 코드와 기능 코드를 한 표로 정리한 예약표입니다. `화면ID 단일화 v2.0` §6의 예약 줄(30개)을 대체하고, 새 화면을 만들 때는 이 표에서 코드를 먼저 확인합니다(규칙 R5).

1. **기능 코드 97개**: 기존 예약 30개 중 28개 사용, 2개(BIZ·TRS) 미사용. 나머지 **67개는 쓰이고 있지만 예약표에 없던 코드**라 사후 등록합니다.
2. **영역 코드 16개 사용 중**: 이 중 ADS·AFC·AFF·LED 4개는 통합설계서 v10 §5-1 영역 목록에 없습니다.
3. **뜻이 겹치는 코드 6건**이 있습니다. 구현된 화면 ID는 바꾸지 않고(R4), 앞으로 만들 화면부터 정리합니다(§3).

## 4. 운영 절차, 확인 필요, 다음 할 일

이번처럼 구현이 예약표보다 앞서는 일을 막으려면, 코드 예약을 화면 설계의 첫 단계로 고정해야 합니다.

### 4-1. 새 화면 ID 부여 절차

1. 영역 결정: 어느 체계·사용자 공간인가 → §1 표에서 선택. 표에 없으면 영역 신설 승인부터
2. 기능 결정: §2 표에서 같은 뜻의 코드가 있으면 그대로 사용. 없을 때만 신규 3자리 코드 제안
3. 신규 코드 점검: §2 표에 같은 글자가 없는가, 영역 코드와 같은 글자가 아닌가, 뜻이 기존 코드와 겹치지 않는가
4. 예약표 등록(이 문서 갱신, 판번호 올림) → 그다음 화면 레지스트리 등록 → 구현
5. 일련번호: 같은 영역·기능 안에서 010부터 10 단위, 하위 단계는 011·012, 모바일은 M10, 모달은 -M1 접미(R3)
