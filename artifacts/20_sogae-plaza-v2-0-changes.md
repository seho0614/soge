# 소개광장 v2.0 → 통합설계서 v10 · 화면ID 예약표 반영 변경분 v1.0

Oct 1, 2026 · @박세호

## 0. 개요, 결론, 정정 사항

소개광장 우리동네 설계서 v2.0을 `통합설계서 v10`과 `화면ID 단일화 v2.0` 예약표에 넣기 위한 변경분입니다. 각 절은 대상 문서에 그대로 붙여 넣을 수 있게 작성했습니다.

1. **화면**: 구현본의 `SB-HOM-CMU-*` 체계를 정본으로 삼아 기존 4화면은 재정의, 신규 9화면을 추가합니다. 기능 코드 `CMU`를 예약표에 사후 등록합니다.
2. **데이터**: 소개광장은 CORE 체계(`www.`)에 속하고, 신규 테이블은 접두 `cmu_` 12개(+GPS 단계 2개)입니다. 기존 커뮤니티 테이블에는 컬럼을 추가하지 않고 1:1 부속 테이블로 붙입니다(v10 §6 원칙).
3. **불변식 3건, 법무 6건, 위험 4건, 결정 6건**을 추가합니다.

### 0-1. 정정 — 설계서 v1.0·v2.0의 화면 ID

| 구분 | 내용 |
| --- | --- |
| 잘못된 점 | 설계서 v1.0·v2.0은 `SB-CMU-*`처럼 CMU를 **영역 코드**로 제안했습니다. 규칙 `SB-<영역3>-<기능3>-<일련3>`의 영역 목록(HOM MNY MAL BIZ MYP PTC ADM AI + HLT 등)에 CMU가 없고, 구현본(73화면 구현 보고, 2026-10-02)은 이미 CMU를 **기능 코드**로 `SB-HOM-CMU-010~030` · `SB-ADM-CMU-010`에 쓰고 있습니다 |
| 적용 규칙 | R1 — 구현(kit)이 쓰는 ID가 1순위 정본 |
| 조치 | 설계서 v1.0·v2.0의 `SB-CMU-*` 제안 전부 철회 → 이 문서 §1의 `SB-HOM-CMU-*`로 대체. 새 영역 코드 신설은 불필요 |
| 데이터 접두 | 설계서의 `cm_` 접두를 기능 코드와 맞춰 `cmu_`로 변경 |

## 2. 통합설계서 v10 변경분 — 화면·데이터·불변식

## 4. 반영 절차와 확인 필요 사항

문서 반영은 예약표 → 통합설계서 → 설계서 v2.0 정정 순서로 합니다. 예약표가 먼저여야 규칙 R5(기능 코드를 먼저 잡고 화면을 만든다)를 지킵니다.

### 4-1. 반영 순서

1. `화면ID 단일화` 예약표에 §1-1 기능 코드 줄 반영, §7 마스터 표에 §1-2·§1-3 행 추가 → 판번호 v2.1
2. 화면 레지스트리(엑셀)에 신규 9화면 등록, 기존 4화면 이름 변경
3. `통합설계서 v10`에 §2·§3 블록을 해당 절에 붙여 넣기 → 판번호 v10.1(또는 v11)
4. 설계서 v2.0 §7-1 화면 ID 표를 이 문서 §1로 교체, §7-2 접두를 `cmu_`로 변경
