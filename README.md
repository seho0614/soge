## 4-1. 진짜 기반 이미지 확인 (v10.15)

킷을 만든 작업 환경은 Docker Hub 에 닿지 않아 기반 이미지(node:22-slim · postgres:16)를 같은 역할의 대체 이미지로 검정했습니다.
**인터넷이 되는 PC 에서 한 번** 아래를 돌려 진짜 이미지로 확인해 주십시오. 15 ~ 30분쯤 걸립니다(처음 받을 때).

```powershell
.\dev.ps1 realcheck           # 개발 데이터는 그대로 둡니다 (권장)
.\dev.ps1 realcheck fresh     # DB 볼륨을 지우고 새 설치로 확인 — 「yes」를 쳐야 진행합니다
```

1. 순서 — Docker 가 켜져 있는지 → 두 이미지를 Docker Hub 에서 받기 → 공식 이미지인지(표지 · 버전) → 전부 다시 빌드 → 기동 → 마이그레이션 수 · 컨테이너 안 버전 → 통합 검정 → 주소 6곳 · 메인 투표 3건.
2. 끝에 「진짜 이미지 확인 — 전체 통과」가 나오면 됩니다. 결과는 이 폴더의 `realcheck_날짜_시각.txt` 에도 남습니다 — **그 파일을 보내 주시면** 확인합니다.
3. 「실패」가 있으면 그 줄의 오른쪽 설명을 보십시오. 받기에서 멈추면 인터넷 · 사내 프록시 · Docker Hub 로그인 한도 문제입니다.
4. **실행할 때** — 킷 폴더에서 앞에 `.\` 를 붙입니다(`.\dev.ps1 realcheck`). 「디지털 서명되지 않았습니다」로 막히면 그 창에서 한 번만
   `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` (창을 닫으면 원래대로). 내려받은 zip 을 푼 폴더에서는 이 방법이 필요합니다. macOS · Linux 는 `./dev.sh realcheck`.
5. **v10.17 — 빨간 글씨 · 깨진 한글이 나오지 않습니다.** 전에는 PowerShell ISE 같은 창에서 docker 의 진행 줄이 빨간 오류(NativeCommandError)로 보이고
   검정 결과의 한글이 깨졌습니다(결과는 통과인데도). docker 를 PowerShell 을 거치지 않고 직접 띄워 UTF-8 로 읽도록 고쳐, 창의 종류 · 코드 페이지와 무관하게 같은 화면이 나오게 했습니다. 결과 파일에 검정 요약 4줄도 들어갑니다.
   ★ 작업 환경에서는 PowerShell 7(코드 페이지 CP949)로만 확인했습니다 — **Windows PowerShell 5.1 · ISE 에서는 PC 에서 한 번 돌려 확정**합니다(`sgb/docs/61_…` 8장).
6. 개발 데이터를 둔 채 **며칠 뒤 다시 돌려도** 통과합니다(전: 설치 24시간 뒤부터 광고 검정 AD-03 이 실패 — v10.17 에서 고침).
7. 「통합 검정 — 실패 있음」이 나오면 그 위에 **`FAIL …` 줄(어느 항목인지)** 이 보입니다(v10.17). `.\dev.ps1 check` 와 `realcheck` 를 **두 창에서 동시에 돌리지 마십시오** — 같은 검정 DB 를 써서 서로 깨뜨립니다.
