# 010. 회계 옮기기 준비 — 공용 부품 · 알림 보낼 표 · 옮기는 도구 (e3.1 · 2026-11-25)

> 대표 승인(11/25): E3 계획 · 알림은 「보낼 알림 표 + 1분마다」 · 코드는 「그대로 복사 + 규칙으로 고침」. 설계서 6절 E3.

## 1. 공용 부품 — 소개뱅크와 같은 모양(옮겨 온 코드를 고치지 않으려고)
| 파일 | 내용 |
|---|---|
| `api/src/core/errors.ts` | 소개뱅크와 같은 클래스 AppError · PolicyViolation(422) · StateConflict(409) · Forbidden(403) · NotFound(404) + ERP 짧은 함수(Unauthorized · Conflict · Policy · Unavailable) |
| `api/src/core/request-context.ts` | 소개뱅크 것 그대로 복사(트랜잭션 연결 · 행위자 · IP) |
| `api/src/core/request-context.middleware.ts` | 요청마다 문맥을 엶 · 로그인 확인 뒤 가드가 행위자를 채움 |
| `api/src/core/auth.ts` | Role · isSuper · hasRole · Principal(`req.principal`) 더함 · 행위자 채움 |
| `api/src/core/audit.interceptor.ts` | `@Audit(action, targetType, { idOnly · pick })` 그대로 · 기록은 ERP `erp_audit` |
| `api/src/db/database.service.ts` | `query` · `transaction`(중첩 합류) · `healthy` · ENC_KEY(소개뱅크와 같은 키) |
| `api/src/common/` | 소개뱅크 common.dto · strict-boolean · http-json 복사 |

## 2. 운영 알림 보낼 표 (E007)
- ERP 안에 소개뱅크와 **같은 이름 · 같은 칸**의 `ops_alerts` — 옮겨 온 코드의 `INSERT INTO ops_alerts` · `UPDATE … resolved_at`(82곳)을 고치지 않음 · 전표와 같은 트랜잭션.
- 정기 작업 `erp_alert_flush`(1분 · **정기 작업 주인과 상관없이** — `ALWAYS_JOBS`): 새 줄 → 소개뱅크 `/internal/erp/alerts` RAISE(detail.erpAlertId) · 풀린 줄 → 같은 종류에 안 풀린 것이 없으면 RESOLVE · 실패하면 5번까지 다시.
- 소개뱅크 화면(운영 알림 · 텔레그램 · 게시판) · 확인은 그대로 소개뱅크에서.
- 확인 필요: 소개뱅크가 받는 알림 종류는 `ACCT|HR|HRA|HRX|OFC|QLT|LGL|ITS|PRR|SAL|ERP|TRD_` 로 시작해야 함 — 옮긴 코드에 다른 종류가 있으면 e3.2 ~ 에서 목록으로 보고 소개뱅크 쪽 허용을 넓힘.

## 3. 옮기는 도구 `tools/port-from-core.py`
| 규칙 | 내용 |
|---|---|
| R1 | SQL 의 소개뱅크 표 읽기 `FROM · JOIN <표>` → `svc.<표>` (ERP 표 · ops_alerts 는 그대로) |
| R2 | `FROM site_settings` → `erp_site_settings`(ERP 설정 먼저 · 없으면 소개뱅크 — `prisma/svc-views-erp.sql`) |
| W | 소개뱅크 표 쓰기는 바꾸지 않고 목록(`write`) — 내부 API 로 |
| I | ERP 에 없는 import 는 목록(`missing-import`) — 그 판에서 옮기거나 대체 |
- 바꾼 줄은 모두 `docs/e3-port-<목록>.tsv` · `--check` 로 다시 돌려도 같은지.
