# 소개뱅크 — 개발 착수 절차서

**작성일** 2026-09-06
**대상** 킷을 받아 **처음 개발 환경을 만드는 사람**. 이후 기능 추가는 `27_개발절차서`, 배포는 `25_배포운영절차서`, 오픈은 `31_오픈절차서`.
**검증** Windows 11 · Node 22.15 · PostgreSQL 16.14 에서 이 순서 그대로 실행해 확인했습니다. 각 단계 끝의 **확인** 줄과 화면 출력이 다르면 다음 단계로 가지 마십시오.

---

# 0. 전체 흐름

```
1 준비물 확인  →  2 압축 해제 · 설치  →  3 환경 변수  →  4 데이터베이스
→ 5 마이그레이션  →  6 전체 검증  →  7 실행(3개)  →  8 눌러보기  →  9 관리자 계정
→ 10 첫 커밋 · 브랜치 규칙  →  11 매일 반복하는 것
```

소요 시간: 처음 **약 20분** (npm install 포함). 두 번째부터는 5분.

# 1. 준비물 확인

| 항목 | 확인 명령 | 기대 |
|---|---|---|
| Node.js 22 | `node -v` | `v22.x` |
| npm 10+ | `npm -v` | `10.x` 이상 |
| Git | `git --version` | `2.x` |
| PostgreSQL 16 **셋 중 하나** | 아래 표 | |

PostgreSQL 은 세 가지 중 **하나만** 있으면 됩니다. psql 은 필수가 아닙니다.

| 방법 | 언제 | 확인 |
|---|---|---|
| **① Docker** | 권장. 팀 전체가 같은 버전 | `docker compose version` |
| ② 설치된 PostgreSQL 16 | 이미 있을 때 | `psql --version` → `16.x` |
| ③ 임베디드 | Docker 도 PG 도 설치할 수 없는 PC | 준비물 없음 (4단계에서 내려받음) |

> **PostgreSQL 15 이하는 안 됩니다.** 마이그레이션 일부 문법이 16 전용입니다.
> Windows 에서는 **Git Bash** 를 쓰십시오. `npm run verify` 등 셸 스크립트가 bash 입니다. cmd · PowerShell 에서는 `npm run dev` · `db:migrate` · `smoke` · `typecheck` 같은 Node 명령만 됩니다.


`OK` 가 나와야 합니다. 여기서 실패하면 Node 버전을 먼저 의심하십시오.

# 3. 환경 변수

```bash
cp .env.example .env
```

`.env` 는 **API 서버와 모든 `scripts/*.js` 가 자동으로 읽습니다.** 이미 셸에 export 된 값이 있으면 그쪽이 우선입니다.

| 변수 | 지금 할 일 |
|---|---|
| `DATABASE_URL` | **4단계에서 고른 방법에 맞게** 고칩니다 (아래 표) |
| `JWT_SECRET` | 개발은 기본값 그대로. **운영은 32자 이상 · 절대 커밋 금지** |
| 나머지 | 그대로 둡니다. 연동 키가 없으면 스텁으로 돌고 응답에 `stub: true` 가 실립니다 |

**`.env` 는 `.gitignore` 에 있습니다.** 커밋되지 않는지 `git status` 로 한 번 확인하십시오.

# 4. 데이터베이스

## ① Docker (권장)

```bash
docker compose up -d
docker compose ps                # healthy 가 될 때까지 10초쯤
```

`.env` 의 `DATABASE_URL`: `postgresql://sgb:sgb@localhost:5432/sgb` (기본값 그대로)

## ② 설치된 PostgreSQL 16

```bash
createdb sgb
```

`.env` 의 `DATABASE_URL`: `postgresql://<사용자>:<암호>@localhost:5432/sgb`

> 확장 3종(`pgcrypto` · `citext` · `pg_trgm`) 을 마이그레이션이 만듭니다. **슈퍼유저 또는 CREATE EXTENSION 권한**이 필요합니다. 회사 DB 라면 DBA 에게 미리 요청하십시오.

## ③ 임베디드 (Docker 도 PG 도 없을 때)

```bash
npm i -D --no-save embedded-postgres@16.14.0-beta.17   # 최초 1회 · 약 100MB · package.json 에 남지 않습니다
npm run db:embedded                                    # 터미널 하나를 차지합니다. 개발 중 계속 켜 두십시오
```

`.env` 의 `DATABASE_URL`: `postgresql://postgres:postgres@localhost:54329/sgb`
데이터는 `.dev-db/` 에 남습니다 (gitignore 됨).

**확인** — 셋 중 무엇이든 이 명령이 `1` 을 찍어야 합니다.

```bash
node -e "require('./scripts/load-env');new (require('pg').Client)({connectionString:process.env.DATABASE_URL}).connect().then(c=>c.query('select 1 as ok')).then(r=>{console.log(r.rows[0].ok);process.exit(0)}).catch(e=>{console.error(e.message);process.exit(1)})"
```

# 5. 마이그레이션

```bash
npm run db:migrate
```

**확인**

```
ok 000_extensions               ...
ok 310_content_registry         ...
---
적용 32 · 기존 0 · 변경감지 0
```

한 번 더 실행하면 `적용 0 · 기존 32 · 변경감지 0` 이어야 합니다. **재실행이 안전한 것이 이 러너의 계약**입니다.

| 출력 | 의미 | 조치 |
|---|---|---|
| `변경감지 1` 이상 | 이미 적용된 SQL 파일이 수정됨 | 파일을 되돌리십시오. 바꿔야 하면 **새 번호로 추가** |
| `!! 3xx_... ERROR` 후 중단 | 그 파일에서 실패 | 원인을 고치고 다시 실행하면 **거기서 이어집니다** |
| `permission denied to create extension` | 방법 ② 권한 부족 | DBA 에게 확장 3종 생성 요청 |

`npm run db:migrate:sh` 는 같은 일을 psql 로 합니다 (CI 와 동일). **둘은 같은 이력 테이블 · 같은 체크섬**을 쓰므로 섞어 써도 됩니다.

> **여기서 통과하지 않은 채 개발을 시작하지 마십시오.** 기존 결함 위에 새 코드를 얹으면 원인이 섞입니다.

# 7. 실행

터미널 3개 (임베디드 DB 면 4개).

```bash
npm run start:dev             # API :3000 — src/ 가 바뀌면 자동 재시작
(cd site && npm run dev)      # 사용자 웹 :5174
(cd web  && npm run dev)      # 운영 BO  :5173
```

**확인**

```bash
curl -s http://localhost:3000/api/v1/health
# {"status":"ok","db":true,"time":"..."}
```

`db: false` 면 API 는 떴지만 DB 에 못 붙은 것입니다. `.env` 의 `DATABASE_URL` 과 4단계 확인 명령으로 돌아가십시오.

| 주소 | 무엇 |
|---|---|
| http://localhost:5174 | 사용자 웹. API 는 `/api` rewrite 로 3000 에 붙습니다 |
| http://localhost:5173 | 운영 BO. API 는 Vite proxy 로 3000 에 붙습니다 |
| http://localhost:3000/api/v1/health | 헬스체크 (인증 없음) |

포트를 바꾸려면 `.env` 의 `PORT` 와 `site/next.config.js` · `web/vite.config.ts` 의 대상 주소를 **함께** 바꾸십시오.

# 8. 눌러보기 — 5분 동선

브라우저에서 http://localhost:5174 :

1. **회원가입** — 아무 이메일 · 비밀번호 10자 이상. 가입 즉시 로그인 상태가 됩니다.
2. **본인인증** (`/verify`) — 스텁이라 즉시 통과하며 화면에 **"실제 확인이 이루어지지 않았습니다"** 가 보여야 합니다. 안 보이면 프런트 결함입니다.
3. **사업자 신청** (`/my/business`) — 신청은 되지만 검수 대기입니다. 승인은 운영 BO 에서 합니다 (9단계 뒤).
4. **탐색** — 관 3개(소개머니 · 소개몰 · 소개창업) 목록이 비어 있는 것이 정상입니다. 시험 데이터를 넣으려면:

```bash
npm run db:seed                # psql 필요. 없으면 db:verify 가 같은 픽스처를 넣습니다
```

curl 로 같은 것을 확인하려면:

```bash
B=http://localhost:3000/api/v1
curl -s -X POST $B/auth/signup -H 'Content-Type: application/json' \
  -d '{"email":"dev@example.com","password":"password1234","name":"개발자"}'
# {"accessToken":"...","refreshToken":"...","principal":{...}}
curl -s $B/me/summary -H "Authorization: Bearer <accessToken>"
# {"principal":{...},"unreadNotifications":0,"publishedListings":0,"openDeals":0,"blockedBy":"IDENTITY_REQUIRED"}
```

**access 토큰은 15분**입니다. 사용자 웹은 미들웨어가 refresh 쿠키로 조용히 재발급하므로 끊기지 않습니다. curl 로 시험할 때는 `POST /auth/refresh` 에 `{"refreshToken": ...}` 을 보내십시오. refresh 토큰을 `Authorization` 헤더에 넣으면 403 입니다 — 의도된 동작입니다.

# 9. 관리자 계정

가입은 `MEMBER` 만 줍니다. 운영 BO 에 들어가려면 역할을 직접 부여합니다.

```sql
INSERT INTO account_roles(account_id, role)
SELECT id, 'SUPER' FROM accounts WHERE email = 'dev@example.com';
```

psql 이 없으면:

```bash
node -e "require('./scripts/load-env');new (require('pg').Client)({connectionString:process.env.DATABASE_URL}).connect().then(c=>c.query(\"INSERT INTO account_roles(account_id,role) SELECT id,'SUPER' FROM accounts WHERE email='dev@example.com' ON CONFLICT DO NOTHING\")).then(r=>{console.log('rows',r.rowCount);process.exit(0)})"
```

**다음 요청부터 바로 적용됩니다.** 토큰을 다시 받을 필요가 없습니다 — principal 을 매 요청 DB 에서 조립하기 때문입니다.

**확인** — http://localhost:5173 에 같은 계정으로 로그인 → 대시보드 → **검수 큐**에서 8단계의 사업자 신청이 보여야 합니다. 승인하면 사용자 웹의 `blockedBy` 가 `BUSINESS_REQUIRED` 에서 `SUBSCRIPTION_REQUIRED` 로 바뀝니다.

# 11. 매일 반복하는 것

```
아침     git pull → npm run db:migrate (새 마이그레이션이 있으면 적용) → npm run start:dev
개발     27_개발절차서 의 9단계
커밋 전  npm run docs → npm run verify (또는 smoke + typecheck) → 커밋
```

### 자주 막히는 곳

| 증상 | 원인 | 조치 |
|---|---|---|
| `필수 환경변수 누락: DATABASE_URL` | `.env` 없음 또는 다른 폴더에서 실행 | `sgb/` 에서 실행, `cp .env.example .env` |
| `npm run smoke` 가 `AggregateError` | DB 에 못 붙음 (부팅 시 코드 라벨을 읽습니다) | 4단계 확인 명령 |
| `verify` 가 `psql: command not found` | 방법 ③ 또는 cmd | 6단계의 psql 없는 경로 |
| `레지스트리에 없는 API` | 새 엔드포인트를 `spec/screens.json` 에 안 붙임 | 27_개발절차서 ① |
| `codes.ts 드리프트` | 코드 라벨 마이그레이션 후 재생성 안 함 | `node scripts/gen-codes.js > src/generated/codes.ts` |
| 사용자 웹이 15분 뒤 로그아웃 | `site/src/middleware.ts` 가 빠짐 (검토 반영판 이전 킷) | 이 킷으로 교체 |
| 포트 3000 이미 사용 중 | 이전 API 프로세스가 남음 | Windows: `Get-NetTCPConnection -LocalPort 3000` 로 PID 확인 후 종료 |
| `변경감지 1` | 적용된 SQL 을 수정 | 되돌리고 새 번호로 |
