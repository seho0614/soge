## 2. API

| 누가 | 주소 | 하는 일 · 오류 |
|---|---|---|
| 당사자 | `POST /deals/{id}/contract/esign` | 요청. 409 NOT_AGREED · ALREADY_SIGNED · ESIGN_NOT_CONFIGURED · 422 ESIGN_CONTACT_MISSING · 502 ESIGN_FAILED. 대기 중이면 그 요청을 돌려줌 |
| 당사자 | `GET /deals/{id}/contract/esign` | 상태 · 지문 · 서명 시각 · 내 서명 주소(나에게만 · 대기 중 · 아직 안 했을 때) |
| 당사자 | `POST /deals/{id}/contract/esign/cancel` | 요청 취소(업체에도) · 409 ESIGN_NOT_PENDING |
| 당사자 | `POST /deals/{id}/contract/esign/mock-sign` | MOCK 만 · `{action: SIGN \| REJECT}` · 403 MOCK_ONLY |
| 업체 | `POST /webhooks/esign` | 머리글 `x-esign-timestamp`(초) · `x-esign-signature` = HMAC-SHA256(웹훅 비밀값, "시각.본문") hex 또는 base64 · 401 ESIGN_BAD_SIGNATURE(틀림 · 5분 넘게 어긋남) · 같은 eventId 한 번 · HTTP 는 업체에 다시 조회(실패 502 — 업체가 다시 보냄) · STUB 이면 받기만 |
| ADMIN · SUPER | `GET /admin/esign/status` · `GET /admin/esign/documents?days=` | 준비 상태 · 30일 · 목록(연락처 · 서명 주소 없음) |

## 3. 업체 공통 모양(HTTP · 계약 뒤 확인)

| 할 일 | 요청 | 기본값(.env 로 바꿈) |
|---|---|---|
| 만들기 | `POST {ESIGN_URL}/documents` · `{externalId, title, content, documentHash, expiresAt, callbackUrl, signers:[{externalId: BUYER\|SELLER, name, phone, email}]}` | 응답 `id`(ESIGN_RESULT_ID_PATH) · `signers[].signUrl`(https 만) |
| 조회 | `GET {ESIGN_URL}/documents/{id}` | `status`(ESIGN_RESULT_STATE_PATH) · `signers[].signedAt` · `documentHash` |
| 취소 | `POST {ESIGN_URL}/documents/{id}/cancel` | — |
| 상태 이름 | COMPLETED · SIGNED · DONE → SIGNED / DECLINED · REJECTED → REJECTED / EXPIRED / CANCELED · VOIDED → CANCELLED / PENDING · IN_PROGRESS · SENT → PENDING | `ESIGN_STATE_MAP`(JSON) 으로 더함 · 모르는 이름은 아무것도 바꾸지 않음 |
| 인증 | `Authorization: Bearer {ESIGN_API_KEY}` | ESIGN_AUTH_HEADER · ESIGN_AUTH_PREFIX |

## 6. 남은 것 · 주의

- 거절 · 만료 · 취소는 **알림을 새로 보내지 않음**(이력에만) — 알림 종류를 더하려면 알림 문구 · 정책 표가 함께 바뀜(다음 후보).
- 서명본 PDF 는 저장하지 않음(대표 결정 ③) — 파일 저장 위치 결정 뒤 다시 봄.
- `site.base_url` 이 비면 업체에 넘기는 웹훅 주소가 상대 경로가 됨 — 4절 5단계에서 확인.
- 거래 화면(`/deal/{id}/contract`)의 옛 「서명」 단추는 켜면 409 ESIGN_REQUIRED 글을 보여 줌 — 체결은 「내 계약」 화면에서.
