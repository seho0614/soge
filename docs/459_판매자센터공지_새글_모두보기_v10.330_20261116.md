# 459. 판매자센터 소개몰 공지 — 「새 글」 · 지난 공지 모두 보기 (v10.330 · 2026-11-16)

> 대표 「다음 개발 추천」 → 「2 + 3 묶어서」 · 「승인 + 통과하면 병합」(11/16). 마이그레이션 없음(260 그대로).

## 1. 왜

- 판매자센터 › 「소개몰 공지」 상자는 **최근 5건만** 보였고 「새 글」 표시가 없었습니다.
- 수수료율 변경 공지는 입점 약관 제17조 4항(30일 전 공지)의 증거입니다. 6번째보다 오래되면 판매자가 다시 찾을 길이 없었습니다.
- 소개광장 · 파트너센터 공지(v10.324 · 328)와 같은 찾기 · 쪽 넘기기를 판매자 공지에도 둡니다. **「모두 읽음」은 두지 않습니다** — 요율 공지는 판매자가 직접 펼친 기록이 증거여야 합니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| API `GET /me/health/seller/center` | `notices` 줄마다 `unread`(최근 30일 · 아직 안 펼침 — 다른 공지 화면과 같은 기준) · 전체 수 `noticeTotal` |
| 새 API `GET /me/health/seller/notices?q=&page=` | 소개몰(HLT) 공지만 · 이 판매자 등급 · 게시 중 · 끝나지 않은 것 · 고정 먼저 · 찾기(제목 · 본문 · 100자) · 30개씩 · 판매자가 아니면 403 `NOT_SELLER` |
| 사용자 웹 **소개몰 › 판매자센터 › 「소개몰 공지」 상자** | 안 읽은 공지 제목 앞 **「새 글」**(펼치면 바로 지움) · 공지가 5건보다 많으면 **「지난 공지 모두 보기 →」** |
| 새 화면 **판매자센터 › 소개몰 공지**(`/health/seller/center/notices` · SB-HLT-SEL-030) | 찾기 칸 · 30개씩 「지난 공지 더 보기 →」 · 「← 최근 공지」 · 빈 안내 · 펼치면 **판매자 읽음 기록**(`POST /me/health/seller/notices/{id}/read` · 요율 공지 「읽음 n / 대상 m」에 그대로 셈) · 첨부 |
| 공통 부품 `NoticeDetails` | `readPath` 칸 — 읽음 기록 주소를 바꿀 수 있음(비우면 지금처럼 `POST /me/notices/{id}/read`) |

- 일반 공지(관 지정 없음)는 지금처럼 판매자센터에 넣지 않습니다(소개광장 › 공지에서 봄).
- 소개광장 「모두 읽음」(D222)으로 생긴 읽음 줄도 「읽음」으로 봅니다(다른 공지 화면과 같음). 요율 변경 공지는 「모두 읽음」 대상이 아니라 직접 펼쳐야만 읽음이 됩니다.

## 3. 시험 (test_v1330)

1. ① 코드 — API · 화면 · `readPath` · screens.json · 문서 459 · 판 v10.330
2. ② API — 소개몰 공지 35건 + 일반 공지 1건: 판매자센터 5건 · `noticeTotal` · `unread` · 1쪽 30 + 2쪽 5 · 찾기 1 · 일반 공지 빠짐 · 판매자 아님 403
3. ③ 판매자 화면 — 「새 글」 → 「지난 공지 모두 보기」 → 2쪽 → 펼침 → 읽음 기록(bulk 아님) · 「새 글」 지움
4. ④ 소개광장 › 공지 「모두 읽음」 — 누른 뒤 새로 고치지 않아도 「새 글」 0(v10.328 에서 고친 것을 화면으로 확인)

## 4. 운영 적용

- 마이그레이션 · 설정 없음. 운영은 소개몰 입점(`mall.tenant`)이 꺼져 있어 판매자가 없으면 화면에 바뀌는 것이 없습니다.
- 적용 뒤 확인: 판매자 계정이 있으면 소개몰 › 판매자센터 › 「소개몰 공지」 상자에 「새 글」 · (6건 이상이면) 「지난 공지 모두 보기 →」.
