# 516. 내 로그인 기기 (v10.380 · 2026-11-18)

> 대표 11/18 「모두개발」 → ⑧ ① 설정 예약 변경 · ② 탈퇴 유예 끝 전날 알림 · ③ 점검 예정 회원 알림 · ④ 내 로그인 기기 목록 → 계획 「승인 + 통과하면 병합」(여덟 번째 묶음 · 운영은 v10.331 → v10.376 한 번에 다음 묶음). 이 문서는 ④. 마이그레이션 **D241**.

## 1. 왜

- 지금은 「모든 기기 로그아웃」(v10.181)만 있어, 잃어버린 휴대폰 하나만 끊으려 해도 모든 기기가 풀립니다. 어느 기기가 로그인돼 있는지도 볼 수 없습니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 마이그레이션 **D241** | 표 `login_sessions`(로그인 한 번 = 한 줄 · 판 번호 · IP 앞 두 마디 · 브라우저 종류 · 처음 · 마지막으로 씀 · 끊음) · 파기 `fn_purge_auth_records` 가 보관 날수 · 파기된 계정 줄도 지움 |
| 로그인 증표 | access · refresh 에 **`sid`**. 다시 받기 · 2단계 확인 뒤에는 같은 줄을 이어 씀 · 비밀번호를 바꾸면 새 줄. 요청마다 그 줄이 끊겼으면 비로그인(마지막으로 쓴 때는 5분마다 고침) · 끊긴 refresh 로는 다시 받지 못함. **v10.380 전에 받은 증표(sid 없음)는 만료될 때까지 그대로 · 목록에 없음** |
| 새 API | `GET /me/sessions`(로그인한 누구나 · 이 판 증표 · 끊지 않음 · 14일 안에 씀 · 지금 이 기기 표시) · `POST /me/sessions/{id}/revoke`(내 줄만 · 404 · 감사 `SESSION_REVOKE` · 지금 이 기기면 `current: true`) |
| 사용자 웹 **나의공간 › 계정 › 보안 · 로그인 기록 › 「로그인한 기기」** | 기기 · IP · 처음 로그인 · 마지막으로 씀 · 「로그아웃」(지금 이 기기면 로그인 화면으로) · 옛 방식 로그인 안내 |
| 운영 화면 **권한 계층 › 내 비밀번호 탭 › 「내 로그인 기기」 상자** | 같은 목록 · 다른 기기 「로그아웃」(지금 이 기기는 여기서 끊지 않음) |

## 3. 시험 (test_v1380)

1. ① 코드 — D241 · 증표 sid · 미들웨어 · API · 화면 · 문서 516 · 판 v10.380
2. ② API — 두 번 로그인 → 목록 2 · 지금 이 기기 · refresh 뒤 같은 줄 · 다른 기기 끊기 → 그 증표 비로그인 · 그 refresh 막힘 · 이 기기 그대로 · 남의 줄 404 · 감사
3. ③ 화면 — 사용자 웹 보안 화면 「로그인한 기기」 표 · 운영 화면 내 비밀번호 탭 상자

## 4. 운영 적용

- D241 과 함께. 적용 직후에는 모두 옛 증표라 목록이 비어 있고, 다시 로그인한 기기부터 보입니다.
