## 1. 결론

1. **오픈 날 켜는 22단계를 운영 화면 API 로 순서대로 켰을 때 모두 통과**했습니다(지키는 규칙을 그대로 거침). 소개비 스위치는 기대대로 본인인증 · 계좌인증 LIVE 전에 **막혔습니다**.
2. 간주 모드 4개를 끄고 · 알림톡 · 전자계약 · 안심번호 · AI 를 모두 켠 상태에서 흐름 시험과 화면 돌기를 돌렸습니다 — **고장 1건(카드 등록) 발견 · 이번 판에서 고침**. 나머지는 시험 환경 특성이었습니다.
3. 업체 응답이 있어야 갈 수 있는 값(LIVE · NICE · HTTP)을 DB 에 넣으면 **오픈 차단은 1건 — 파트너 이용약관 미게시**만 남습니다(이미 아는 항목 · terms-publishing 미정 2).
4. 오픈 날 **켜는 순서가 중요한 곳이 3군데** 있습니다(4절 순서표에 반영) — 세금계산서 간주 끄기 · 본인인증 NICE · 메일 보내는 주소.

## 2. A단계 — 오픈 날처럼 켜기 (운영 화면 API)

| 단계 | 한 일 | 결과 |
|---|---|---|
| 1 | 회사 수금 계좌 3칸(시험용 아닌 값) | 통과 · **간주(계좌) 는 DB 가 스스로 끔**(트리거) |
| 2 | 연동 BROKER · ETAX · PASS · BANK → 시험(TESTING) → 간주 끄기 etax → broker → payment | 통과 |
| 3 | 방식 — 전자계약 · 안심번호 · 알림톡 MOCK(운영은 HTTP) · 알림톡 템플릿 승인 → 알림톡 준비 켜기 | 통과 (템플릿 승인 전에는 준비 켜기가 막힘 — 맞음) |
| 4 | 메일 발송 인증 켜기 | 통과 |
| 5 | AI 월 상한 → AI 전체 → 검수 보조 · 상담 · 내 정보 조회 · 신청서 초안 | 통과 — 단, **처리방침 1.1 게시 전인데도 켜짐**(발견 1) |

본인인증은 흐름 시험이 시험 단추(STUB)로 회원을 만들기 때문에 STUB 로 두었습니다. 가짜 표준창(MOCK)으로 켜면 흐름 시험이 회원을 못 만들어(1차 리허설) — 표준창 자체는 test_v1141 이 따로 봅니다.
