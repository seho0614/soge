## 3. 전체 구조

```
                   ┌───────────── 사용자 웹(Next) ─────────────┐
[등록 · 수정 화면]  주소 검색(Daum · 그대로) → 저장 단추
                          │ POST /listings · PATCH /listings/:id  (address 그대로 · 좌표 없음)
                          ▼
                   ┌───────────── API(Nest) ─────────────┐
                   listing.service 저장(트랜잭션) ── 성공 응답(좌표를 기다리지 않음)
                          │ 저장 뒤 비동기
                          ▼
                   geo.service.geocodeListing(id)
                     ├─ 주소 해시가 같으면 건너뜀
                     ├─ 카카오 로컬 「주소 검색」 REST (3초 · 1회 재시도 없음)
                     ├─ listing_geo   ← 정확 좌표 (본인 · 운영만)
                     └─ geo_region    ← 「시도 시군구」 중심 (없을 때만 1회)
                          │ 실패 → listing_geo.status = FAILED · 사유 · 다음 배치에서 다시
                          ▼
[매물 상세]        GET /listings/:id → geo { precision: EXACT | REGION, lat, lng, radiusM }
                          ▼
                   KakaoMap 부품 — 보일 때만 SDK(autoload=false) · EXACT 핀 / REGION 원
[운영 검수]        GET /admin/listings/:id/geo → 정확 핀 · 「다시 변환」 단추
```

원칙

1. **등록은 지도 때문에 실패하지 않습니다.** 좌표 변환은 저장 뒤 따로 돌고, 실패하면 좌표만 비웁니다.
2. 정확 좌표는 `listing_geo` 한 곳에만 있고, 공개 보기(`v_*`) · 공개 API 에 나가지 않습니다(검정으로 막음).
3. 카카오 SDK 는 지도가 화면에 보일 때만 받습니다(공유 기능과 같은 불러오기 방식).

### 7-2. 카카오 로컬 호출

```ts
// src/common/geo/kakao-local.provider.ts (예시 — 개발 때 확정)
const BASE = process.env.KAKAO_LOCAL_BASE ?? 'https://dapi.kakao.com';
const TIMEOUT = Number(process.env.KAKAO_LOCAL_TIMEOUT_MS ?? 3000);

export type GeoResult =
  | { ok: true; lat: number; lng: number }
  | { ok: false; kind: 'NOT_FOUND' | 'KEY_MISSING' | 'QUOTA' | 'AUTH' | 'TIMEOUT' | 'UPSTREAM'; detail?: string };

export async function searchAddress(query: string): Promise<GeoResult> {
  const key = process.env.KAKAO_REST_KEY;
  if (!key) return { ok: false, kind: 'KEY_MISSING' };
  const url = `${BASE}/v2/local/search/address.json?analyze_type=exact&size=1&query=${encodeURIComponent(query)}`;
  const ac = new AbortController(); const t = setTimeout(() => ac.abort(), TIMEOUT);
  try {
    const r = await fetch(url, { headers: { Authorization: `KakaoAK ${key}` }, signal: ac.signal });
    if (r.status === 401 || r.status === 403) return { ok: false, kind: 'AUTH' };
    if (r.status === 429) return { ok: false, kind: 'QUOTA' };
    if (!r.ok) return { ok: false, kind: 'UPSTREAM', detail: String(r.status) };
    const j = await r.json() as { documents?: { x: string; y: string }[] };
    const d = j.documents?.[0];
    if (!d) return { ok: false, kind: 'NOT_FOUND' };
    return { ok: true, lat: Number(d.y), lng: Number(d.x) };   // 카카오는 x = 경도 · y = 위도
  } catch { return { ok: false, kind: 'TIMEOUT' }; }
  finally { clearTimeout(t); }
}
```

| 규칙 | 내용 |
|---|---|
| 찾는 글자 | 도로명 주소(`road`) → 없으면 지번(`jibun`). **상세주소(`detail`)는 카카오에 보내지 않음** |
| 구 중심 | `"{sido} {sigungu}"` 로 같은 호출 · `geo_region` 에 없을 때만 |
| 쿼터 초과 | `QUOTA` → 상태 FAILED · 사유 · 다음 배치에서 다시. 오류 코드 -10 도 QUOTA 로 봄(확인 필요) |
| 재시도 | 요청 안에서는 하지 않음 · 배치가 최대 3회(그 뒤는 운영 「다시 변환」) |
| 기록 | 주소 원문을 로그에 남기지 않음(해시만) |

### 7-3. 저장 흐름

| 단계 | 할 일 |
|---|---|
| 1 | 매물 저장 트랜잭션(지금 그대로) → 커밋 |
| 2 | 커밋 뒤 `geo.service.geocodeListing(id)` 를 기다리지 않고 부름(`void`) |
| 3 | 주소 해시(`sha256(road\|jibun)`)가 `listing_geo.address_hash` 와 같으면 끝 |
| 4 | `listing_geo` 에 PENDING 쓰기 → 호출 → OK(좌표) / FAILED · NOT_FOUND(사유) |
| 5 | `geo_region` 에 그 시 · 구가 없으면 한 번 더 호출해 넣음 |
| 6 | 서버가 꺼져 PENDING 으로 남은 줄 → 배치가 10분 뒤 다시 |

## 8. DB 설계 (D099)

```sql
-- D099_listing_geo — 카카오맵 1차 (docs/96)

-- ① 정확 좌표: 본인 · 운영만. 공개 보기(v_*)에 넣지 않음(③ 검사)
CREATE TABLE IF NOT EXISTS public.listing_geo (
  listing_id   uuid PRIMARY KEY REFERENCES public.listings(id) ON DELETE CASCADE,
  status       text NOT NULL DEFAULT 'PENDING',
  lat          numeric(9,6),
  lng          numeric(9,6),
  source       text NOT NULL DEFAULT 'KAKAO_LOCAL',
  address_hash text NOT NULL,
  fail_kind    text,
  tries        int  NOT NULL DEFAULT 0,
  geocoded_at  timestamptz,
  updated_at   timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_listing_geo_status CHECK (status IN ('PENDING','OK','FAILED','NOT_FOUND')),
  CONSTRAINT ck_listing_geo_ok     CHECK (status <> 'OK' OR (lat IS NOT NULL AND lng IS NOT NULL)),
  CONSTRAINT ck_listing_geo_kr     CHECK (lat IS NULL OR (lat BETWEEN 33 AND 39 AND lng BETWEEN 124 AND 132))
);
CREATE INDEX IF NOT EXISTS idx_listing_geo_todo ON public.listing_geo (updated_at) WHERE status IN ('PENDING','FAILED');
COMMENT ON TABLE public.listing_geo IS 'docs/96 — 매물 정확 좌표. 본인 · 운영 API 만 읽음. 공개 보기 · 공개 API 금지(v_geo_exact_leak).';

-- ② 공개 좌표: 실제 등록된 시 · 구만 생김(목록을 지어내지 않음 — D050 원칙)
CREATE TABLE IF NOT EXISTS public.geo_region (
  sido       text NOT NULL,
  sigungu    text NOT NULL,
  lat        numeric(9,6) NOT NULL,
  lng        numeric(9,6) NOT NULL,
  source     text NOT NULL DEFAULT 'KAKAO_LOCAL',
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (sido, sigungu)
);

-- ③ 유출 검사: 공개 보기(v_*)가 listing_geo 를 쓰면 줄이 나옴 → 통합 검정 실패
CREATE OR REPLACE VIEW public.v_geo_exact_leak AS
  SELECT DISTINCT v.view_name AS view_name
    FROM information_schema.view_table_usage v
   WHERE v.view_schema = 'public' AND v.table_name = 'listing_geo' AND v.view_name LIKE 'v\_%';

-- ④ 외부 연동 표
-- requires_ip = false: 카카오 로컬은 발신 IP 등록 없이 키로 부름(K9 허용 IP 는 선택)
INSERT INTO public.integrations (code, name, purpose, provider, requires_ip, secret_key_name)
VALUES ('MAP', '지도 · 주소 좌표(카카오 로컬)', '매물 소재지 주소 → 좌표(지도 표시)', 'Kakao', false, 'KAKAO_REST_KEY')
ON CONFLICT (code) DO NOTHING;

-- ⑤ 감사 동작 이름 LISTING_GEO_RETRY — 감사 동작 목록이 CHECK 로 묶여 있으면 그 목록에 더함(개발 때 확인)
```

| 확인 | 내용 |
|---|---|
| 자료 지움 | 없음 — 새 표 2개 · 보기 1개 · 줄 1개(되돌리기 쉬움) |
| 되돌리기 | `DROP TABLE listing_geo, geo_region; DROP VIEW v_geo_exact_leak; DELETE FROM integrations WHERE code='MAP'` — 이전 판 코드는 이 표를 모름 |

| 6 | 운영에서만 실패 | 서버 발신(3.37.95.217 → dapi.kakao.com:443) · K9 허용 IP |
