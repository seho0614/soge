# 727. DB 복원 반자동 리허설 (v10.585 · 2026-11-21 · 14차 운영 ①)

> 대표 11/21 「모두 개발진행」. 기존 「DB 복원 시험 기록」(D238 · v10.368 · `restore_drills` · 업무 안내 RESTORE_DRILL)을 **넓혔습니다** — 새 표 없음.

## 1. 결론

- 사람이 콘솔에서 하던 월 1회 복원 시험을 **스크립트 한 개**(`deploy/aws/restore-drill.sh`)로 반자동화했습니다. 행 수 세기 · 견주기 · 걸린 분 · 결과 JSON 은 스크립트가, 「스냅샷 복원」 단추와 지우기는 aws 명령이 있으면 스크립트가 · 없으면 사람이 합니다.
- 결과 JSON 은 운영 화면 **관 관리 › 업무 안내 › 「스크립트 결과 붙여 넣기」**(SUPER)로 기존 복원 시험 기록에 들어갑니다(`source = 'SCRIPT'` · 표마다 행 수 `detail`).
- **행 수 맞음은 서버가 다시 셉니다**(스크립트 값을 믿지 않음 · 설정 `ops2.drill_tol_pct` 5). 적으면 운영 알림 `RESTORE_DRILL_DUE` 가 풀립니다(사람이 적을 때와 같음).
- 개발 서버에서는 `tools/restore-drill-rehearse.sh`(infra)로 **덤프 → 복원 → 견주기**를 버리는 DB 에서 미리 해 봅니다. 운영 · RDS · AWS 에 닿지 않습니다.

## 2. 흐름

| 단계 | 하는 것 | 누가 |
|---|---|---|
| ① 운영 행 수 | `accounts · listings · deals · hlt_orders · terms · site_settings · ops_alerts · audit.audit_logs · schema_migrations` 행 수(읽기만 · `default_transaction_read_only=on`) | 스크립트 |
| ② 복원 | aws 방식: 가장 최근 자동 스냅샷(또는 준 이름) → `sgb-drill-날짜`(같은 서브넷 · 보안 그룹 · 퍼블릭 끔 · `db.t4g.micro`) · `aws rds wait` / 콘솔 방식: 사람이 「스냅샷 복원」 → Enter → 주소 넣기 | 스크립트 · 사람 |
| ③ 새 DB 행 수 | 운영 `.env` DATABASE_URL 에서 **호스트만** 바꿔 붙음(스냅샷은 같은 계정 · 비밀번호) · 주소가 퍼지기까지 20초씩 6번 | 스크립트 |
| ④ 견줌 | 표마다 복원 ≤ 운영 · 차이 ≤ max(100, 운영 × 5퍼센트) → 맞음 · 결과 JSON(화면 끝 · `~/sgb-data/logs/restore_drill_*.json`) | 스크립트 |
| ⑤ 붙여 넣기 | 업무 안내 › 「스크립트 결과 붙여 넣기」 | SUPER |
| ⑥ 지우기 | aws 방식: yes 받고 `delete-db-instance --skip-final-snapshot` / 콘솔: 사람이 · 안 지우면 끝날 때 경고 | 스크립트 · 사람 |

### 안전장치
1. 복원 DB 주소가 운영 DB 주소(.env 호스트 · aws describe 의 엔드포인트)와 같으면 **멈춤**(종료 2).
2. 지우는 것은 이름이 `sgb-drill-` 로 시작하는 인스턴스만.
3. 화면 · 파일에는 행 수만(회원 · 내용 · 접속 주소 값 없음).
4. 기본 실행(인자 없음)은 읽기만 — 순서 · 방식만 보여 줌.

## 3. 바뀐 것

| 곳 | 내용 |
|---|---|
| DB | `restore_drills.source`(MANUAL · SCRIPT · 처음 MANUAL) · `restore_drills.detail`(jsonb · 8000바이트 · 객체) · 검사 `ck_restore_drills_source` · `ck_restore_drills_detail` · 쌓기만 트리거 그대로 |
| 설정 | `ops2.drill_tol_pct` 5(0 ~ 50 · ADMIN 범위) |
| 업무 안내 | RESTORE_DRILL 새 판(스크립트 순서 6줄) — 이미 스크립트 판이 있으면 더하지 않음 |
| API | `GET /api/v1/admin/ops2/restore-drills/script`(SUPER) · `POST /api/v1/admin/ops2/restore-drills/result`(SUPER · 감사 `RESTORE_DRILL_ADD` pick) |
| 화면 | 업무 안내 › 복원 시험 기록 아래 상자 `Ops2DrillPaste`(SB-ADM-OPS-030 · SUPER 만 그림) |
| 도구 | core `deploy/aws/restore-drill.sh` · infra `tools/restore-drill-rehearse.sh` |
| 권한(D258) | `perm_route_map` 두 줄 → 업무 `ops-guide`(VIEW · EDIT) |

### POST 오류
| 응답 | 코드 | 까닭 |
|---|---|---|
| 400 | VALIDATION_ERROR | 표 이름 형식 · 행 수 정수 아님 · 표 0 또는 30 넘음 |
| 409 | OPS2_DRILL_DUP | 같은 날 · 같은 스냅샷 스크립트 결과가 이미 있음 |
| 422 | OPS2_DRILL_MODE | 리허설(`--compare`) 결과 |
| 422 | OPS2_DRILL_TABLES | 같은 표 두 번 |
| 422 | RESTORE_DRILL_DATE · RESTORE_DRILL_SNAPSHOT | 기존 사람 적기와 같은 규칙 |

## 4. 운영에서 쓰는 법(대표 · 사람)

```bash
bash ~/sgb/deploy/aws/restore-drill.sh            # 읽기만 — 방식 · 순서
bash ~/sgb/deploy/aws/restore-drill.sh --run      # 복원 시험(콘솔 방식이면 물음에 답)
# aws 방식으로 하려면(선택): .env 에 RDS_INSTANCE_ID=운영인스턴스이름 · 서버에 aws 명령 · rds:Describe* · RestoreDBInstanceFromDBSnapshot · DeleteDBInstance 권한
```
- 운영 서버에는 지금 aws 명령이 없어(메모) **콘솔 방식**으로 돕니다. aws 방식은 권한 정책을 대표가 정한 뒤.
- 예상 비용: `db.t4g.micro` 30분 정도 · 한 달 한 번(서울 기준 시간당 요금은 **확인 필요**) — 지우지 않으면 계속 나감.

## 5. 리허설(개발 서버)

```bash
bash tools/restore-drill-rehearse.sh ~/kits/out/SGB_DevDocker_Integrated_*_v10_585.zip -o /tmp/rdreh.txt
```
- 버리는 postgres:16(127.0.0.1 임의 포트) · 킷 마이그레이션 + 시드 → `pg_dump -Fc` → 새 DB `drill` 에 `pg_restore`(오류 0 이어야) → 킷 `restore-drill.sh --compare` 맞음 → 일부러 `accounts` · `audit.audit_logs` 를 지운 DB 가 「다름」인지(시드 행이 100 이하면 한도 안이라 건너뜀).
- realcheck 에 넣지 않았습니다(약 1분 · 도커 이미지 `sgb-dev-checks` 필요) — 넣을지는 대표 결정.

## 7. 확인할 것

1. 스냅샷 복원 뒤 보안 그룹이 운영 서버에서 5432 로 들어오게 되어 있는지(콘솔 방식은 사람이 운영과 같은 보안 그룹을 고름).
2. 스냅샷 시각과 시험 시각 사이가 길면(하루 넘게) 차이가 5퍼센트를 넘을 수 있음 — 설정을 올리거나 그날 스냅샷으로.
3. 복원 DB 에 붙는 계정 · 비밀번호는 **스냅샷 때 값** — 그 뒤 비밀번호를 바꿨다면 붙지 못함(③ 실패 · 「새 DB 에 붙지 못함」).
