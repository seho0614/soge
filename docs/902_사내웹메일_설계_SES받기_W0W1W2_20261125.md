# 902. 사내 웹메일 설계 — AWS SES 받기 · W0 임시 받기 · W1 공용 메일함 · W2 ERP 웹메일 (2026-11-25 · 설계)

> 대표 결정(11/25): 「사내 웹메일 구축」 → **B. AWS 로 직접 구축**(메일 서비스 가입 A 대신) → 순서 W0 · W1 · W2 **모두 진행**.
> 기준: decisions/mail-ses #3(EC2 에 메일 서버를 두지 않음 — SES 는 서버가 아닌 AWS 서비스라 어긋나지 않음) · docs/892(SES 보내기 임시 · `mail.sogaebank.com`) · docs/334(SES → SNS 웹훅 · 서명 검사) · design/ERP분리_설계서(E4G).
> **코드 · 마이그레이션 없음(설계).** 개발은 W1 = 묶음 7 · W2 = ERP E4G.

## 0. 결론

- 11/25 공개 DNS 조회 결과 **sogaebank.com 에 MX(메일 받는 서버) · SPF 가 없습니다**(가비아 권한 네임서버도 빈 답). 처리방침 · 위치기반 약관의 문의처 **privacy@sogaebank.com 으로 오는 메일이 되돌아갑니다**. 결정 mail-ses #8 「기존 메일함 유지」는 사실과 달라 고칩니다.
- 그래서 세 단계로 나눕니다.

| 단계 | 언제 | 하는 일 | 누가 |
|---|---|---|---|
| **W0 임시 받기** | 지금 · 코드 없음 | SES 받기 규칙 → S3 원본 보관 + SNS 로 대표 개인 메일에 도착 알림 · 가비아 MX · SPF | 대표(콘솔 · 가비아) · Claude 단계별 블록 |
| W1 공용 메일함 | 묶음 7(소개뱅크 · 2 ~ 3판) | 운영 화면 「공용 메일함」 — privacy@ · help@ · admin@ · dmarc@ 읽기 · 답장 · 담당 · 처리 완료 · W0 동안 S3 에 쌓인 메일도 가져옴 | Claude |
| W2 사내 웹메일 | ERP E4G(5 ~ 8판) | 직원마다 메일함 · 폴더 · 검색 · 첨부 · 스팸함 · 서명 · 메일 → 결재 · 거래처 첨부 · AI 요약 | Claude |

- SES 받기는 서울 리전에서 지원됩니다 — 받는 주소 `inbound-smtp.ap-northeast-2.amazonaws.com`(AWS General Reference 「Amazon SES endpoints and quotas」). 한 통 크기 한도 · 받기 규칙 개수 한도는 W0 블록 때 같은 문서에서 확인해 적습니다(확인 필요).

## 1. 구조

```
보내는 사람 ─▶ MX 10 inbound-smtp.ap-northeast-2.amazonaws.com
                │ SES 받기 규칙 세트(활성 1개) — 스팸 · 바이러스 검사 · SPF · DKIM · DMARC 판정이 머리에 붙음
                └─▶ S3 작업 하나  s3://〔메일 버킷〕/inbound/〔메시지 ID〕  (암호화 · 공개 막음 · 버전 · 원본 · 40MB 까지)
                      └─ 작업에 건 SNS 주제 sgb-mail-inbound ─▶ (W0) 대표 개인 메일 구독(보낸 사람 · 제목 · 위치)
                                                           ─▶ (W1 · W2) POST /api/v1/webhooks/ses/inbound  (서명 검사 · 주제 고정)
                                                                 │ 서버가 S3 에서 원본을 가져와(서명 v4 · 읽기 전용 열쇠) 풀기(MIME) → DB
                                                     ▼
                                                 웹메일 화면 ── 보내기 = SES(루트 도메인 DKIM) ─▶ 받는 사람
```

## 2. W0 — 임시 받기 (대표 · 콘솔 · 단계별 블록)

| 블록 | 할 일 | 확인 |
|---|---|---|
| 1 | S3 버킷 `sgb-mail-inbound-sogaebank`(서울 · 공개 막음 · 버전 · SSE-S3) + 버킷 정책(SES 만 PutObject · `AWS:SourceAccount` · `receipt-rule-set/*`) | 정책 저장됨 |
| 2 | SES › 확인된 자격 증명 › 도메인 `sogaebank.com`(루트) · Easy DKIM → 가비아에 CNAME 3줄 | 상태 「확인됨」 |
| 3 | SNS 주제 `sgb-mail-inbound` · 구독 = 대표 개인 메일(이메일 프로토콜) → 메일의 확인 링크 | 구독 「확인됨」 |
| 4 | SES › 이메일 수신 › 규칙 세트 만들기 · **활성으로 설정** · 규칙: 받는 사람 `privacy@ · help@ · admin@ · dmarc@sogaebank.com` · 스팸 · 바이러스 검사 켬 · 작업 **S3 하나**(버킷 · 접두어 `inbound/` · SNS 주제 연결) — SNS 작업은 넣지 않음 | 규칙 「사용」 |
| 5 | 가비아 DNS: `@ MX 10 inbound-smtp.ap-northeast-2.amazonaws.com` · `@ TXT "v=spf1 include:amazonses.com ~all"` · `_dmarc TXT p=none` | `dig MX sogaebank.com` 값 |
| 6 | 운영 서버 S3 읽기 권한(IAM 정책 · 사용자 열쇠 → 운영 .env) | 열쇠 보관 |
| 7 | 개인 메일에서 privacy@sogaebank.com 으로 시험(글만 · 첨부 1MB) → S3 에 객체 · 알림 메일 | 둘 다 |

- 받는 주소를 규칙에 적힌 4개로 한정합니다(도메인 전체로 받으면 스팸이 많아짐). 직원 주소는 W2 때 더합니다.
- **11/25 고침: 받기 규칙에 SNS 작업을 넣지 않습니다** — SNS 작업은 150KB 넘는 메일을 반송합니다(AWS 「Publish to Amazon SNS topic action」 · 한도 조정 불가). S3 작업에 SNS 주제를 걸어 알림만 받고, 원본은 서버가 S3 에서 가져옵니다.
- 블록 6(새로): 운영 서버 S3 읽기 권한 — 정책 `sgb-mail-inbound-read`(`inbound/*` GetObject 만) · 지금은 개발 · 운영이 같은 EC2 라 **IAM 사용자 열쇠를 운영 .env**(`MAIL_S3_ACCESS_KEY_ID` · `MAIL_S3_SECRET_ACCESS_KEY`) · 서버를 나눈 뒤(docs/903) 운영 EC2 역할로.
- 사람이 따라 할 자세한 절차서: `~/outputs/W0_메일받기_임시구축_절차서_20261125.md`(PDF 같은 이름).
- `mail.sogaebank.com`(docs/892 서비스 보내기 · 반송 MX)과 루트 도메인 MX 는 서로 다른 이름이라 겹치지 않습니다.

## 3. W1 — 운영 화면 「공용 메일함」 (묶음 7)

| 항목 | 설계 |
|---|---|
| 위치 | 운영 화면 › 고객센터 › **공용 메일함**(1:1 문의 옆) |
| 받기 | `POST /api/v1/webhooks/ses/inbound` — v10.209 SNS 서명 검사(`ses-feedback.ts` 공통 부분) 재사용 · 주제 `mail.inbound_topic_arn` 하나만 · 같은 알림 번호 한 번만 · 스위치 `mail.inbound`(처음 off) |
| 풀기 | S3 원본(읽기 권한 · 운영 서버 IAM — 운영에 aws 자격이 없으면 웹훅 본문 안 원본(작은 메일) + 「S3 에서 가져오기」 단추(SUPER))(확인 필요) · MIME 풀기는 검증된 라이브러리 1개(새 패키지 — 그 판에서 이름 · 판 고정 · 승인) |
| 표 | `mail_boxes`(공용 주소 · 담당 역할) · `mail_messages`(받은 · 보낸 · 머리 · 판정 · 상태 NEW/ASSIGNED/DONE · 스레드) · `mail_attachments`(S3 열쇠 · 이름 · 크기 · 형식) · `mail_access_log`(열람 기록 — 개인정보 문의라 누가 열었는지 남김) |
| 화면 안전 | 본문 HTML 은 **허용 목록 방식으로 걸러서**(스크립트 · 이벤트 · iframe 제거) 격리된 틀에 표시 · 바깥 그림은 처음엔 막고 「그림 보기」 · 첨부는 바이러스 판정이 FAIL 이면 내려받기 막음 · SPF · DKIM · DMARC 실패면 「보낸 사람 확인 안 됨」 띠 |
| 답장 | SES 로 보냄(보내는 주소 = 그 공용 주소 · 루트 도메인 DKIM) · 원문 인용 · 보낸 기록 · 반송 · 수신 거부는 v10.209 길 그대로 |
| 권한 | privacy@ = 개인정보 담당 역할 · help@ = 고객센터 · admin@ · dmarc@ = SUPER — perm 업무별 권한으로 |
| 알림 | 새 메일 → 운영 알림(담당 역할) · 하루 요약 줄 · 3영업일 안 답한 privacy@ 메일은 경고(개인정보 권리 요청 기한과 연결) |
| 보관 | DB 5년 · S3 원본 같은 기간(수명 주기 규칙 · 운영 화면 설정 · 법무 확인 필요) |
| 시험 | 스스로 만든 SNS 인증서 · 가짜 S3 · 일부러 넣은 스크립트 · 그림 · 바이러스 판정 FAIL · 큰 첨부 |

## 4. W2 — ERP 사내 웹메일 (E4G)

| 항목 | 설계 |
|---|---|
| 메일함 | 직원마다 `이름@sogaebank.com`(조직도에서 만듦 · 받기 규칙에 주소 더함 — 규칙 고치기는 AWS API · ERP 서버 IAM 최소 권한) · 공용 메일함은 W1 표를 ERP 로 옮겨 함께 |
| 기능 | 받은 · 보낸 · 임시 · 스팸 · 휴지통 · 내 폴더 · 대화 묶음 · 검색(제목 · 보낸 이 · 본문 · 기간) · 첨부 미리보기 · 서명 · 부재 자동 응답 · 읽음 표시 |
| 연결 | 메일 → 결재 첨부(E4G) · 거래처 카드 활동(E5 세일즈) · 업무 만들기 · AI 요약 · 답장 초안(직원용 AI 채팅 · 권한 안) |
| 보내기 | SES · 직원 주소마다 보낸 한도 · 큰 첨부는 S3 링크 · 외부로 가는 개인정보 경고(주민등록번호 · 계좌 꼴 글자) |
| 없음 | 휴대폰 앱 · IMAP/POP(바깥 메일 프로그램 연결) — 필요하면 나중에 따로 |

## 5. 비용 (추정 · 확인 필요)

- SES 받기 · 보내기는 건수 · 크기 요금, S3 는 저장 · 요청 요금 — 직원 6 ~ 20명 규모면 월 수 달러 수준으로 추정. **AWS SES · S3 요금 페이지에서 확인 필요**(이 서버에서는 요금표를 조회하지 않음).

## 6. 위험과 대비

| 위험 | 대비 |
|---|---|
| 스팸 · 피싱 | SES 판정 · 받는 주소 한정 · 「보낸 사람 확인 안 됨」 띠 · 링크 주소 그대로 보이기 |
| 본문 속 악성 코드(XSS) | 허용 목록 걸러내기 · 격리 틀 · 그림 막기 — 시험에 일부러 넣은 스크립트 |
| 개인정보 문의 놓침 | 담당 역할 알림 · 3영업일 경고 · 열람 기록 |
| 메일 잃음 | S3 버전 · 원본 보관 · DB 는 S3 에서 다시 만들 수 있음 |
| 운영 반영이 늦음(모두 개발 뒤) | W0 가 그동안 받아 S3 에 보관 · 대표 알림 |
