- 11/25 묶음 2 ~ 5 첫 전체 점검에서 실패 21개 중 16개가 **시험 하나의 실패 로그인**에서 번졌습니다. test_v1774 · 1775 · 1782 가 시드에 없는 `super@x.com` 으로 로그인 → `fn_login_fail` 이 같은 IP 를 잠금 → 뒤 순서 시험이 모두 UNAUTHENTICATED. 전체 점검 2시간 반을 한 번 더 돌렸습니다.
- 이번 판부터 세 곳에서 미리 잡습니다.
  1. **미리 검사 ⑤ 시험 로그인 계정 대조** — main 과 달라진 · 새 시험의 `login('…')` · `.agree('…')` 계정이 시드(core `scripts/local-setup.sh` · `seed-*` · `fixture.sql`)에 있는지 봅니다. 시험이 스스로 만드는 계정(로그인 줄 밖에서 같은 주소가 나옴)은 괜찮음. 모르는 계정이 있으면 rc=1 과 줄 번호.
  2. **미리 검사 ⑥ 새 시험 점검판 먼저** — main 에 없는 새 시험 목록을 보이고, 점검판에서 그 시험만 돌리는 `qa/new_tests_on_board.sh` 를 안내합니다(미리 검사 자체는 점검판 주소를 쓰지 않는 규칙 그대로 · test_v1628). 보조 일꾼(fork)이 쓴 시험은 전체 점검 전에 한 번 돌려 봅니다.

- 확인: 11/25 첫 점검 기록(full_20261124_v10.783)에 돌리면 「실패 21개 중 9개 UNAUTHENTICATED · 가장 먼저 test_v1774」 — 실제 원인과 같음. 두 번째 점검(모두 통과)에는 알림 없음. 지금 시험 687개 전부 대조하면 모르는 계정 0.
