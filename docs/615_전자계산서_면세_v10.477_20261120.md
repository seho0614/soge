# 615. 전자계산서(면세) 발행 (v10.477 · 2026-11-20)

## 1. 결론
면세 재화 · 용역은 세금계산서가 아니라 **계산서**(부가세 0)를 발행합니다(일반 원칙 · 세무사 확인). 확정한 **거래명세서**(㉓)의 **면세 품목**(품목 과세 구분 EXEMPT) 공급가 합으로 **전자계산서**를 따로 요청 · 발행합니다. 구조는 ㉒ 세금계산서 그대로 — 표 `acct_tax_invoices` 에 종류 **EXEMPT**, 발행은 **전자세금계산서 어댑터(EtaxService)** 그대로(`assume.etax` on 이면 **간주 발행** · 승인번호 없음 · 번호 「간주-SGB-E-…」). **외부 연동 줄을 더하지 않습니다(15종 그대로)**. **처음 꺼짐** `acct.exempt_invoice`. 위치: **회계 › 세무 › 전자계산서(면세)** · SB-ADM-FIN2-030 · API `/admin/acct/exempt-invoices`.

| 스위치 `acct.exempt_invoice` | 거래명세서 세금계산서 | 전자계산서 |
|---|---|---|
| off(처음) | 전과 같음(면세 품목도 한 장 — 이 상태가 세법상 맞지 않을 수 있음을 화면에 안내) | 요청 · 발행 422 EXEMPT_OFF |
| on | **과세 · 영세 품목만**(공급가 · 부가세) · 면세만 있는 문서는 422 ACCT_DOC_EXEMPT_ONLY | 면세 품목 공급가 합 · 부가세 0 |

## 2. 흐름
1. 거래명세서 확정 → 「계산서 요청」(이 화면) → `acct_tax_invoices` kind EXEMPT · 금액 · 공급받는 자를 그때 값으로 고정(D244 가드 그대로).
2. 「발행」 → `EtaxService.send('exempt', …)` — 간주면 간주 발행, 업체 연동(off + ETAX_URL)이면 전송(중립 형식 `taxType: 'EXEMPT'` · 업체를 정하면 etax.http.ts 한 파일을 그 업체의 계산서 형식으로).
3. 발행되면 트리거가 거래명세서 `exempt_invoice_no` 에 번호를 적음 → 그 거래명세서는 취소 못 함(수정 전자계산서 먼저).
4. 보내기 전 요청은 「취소」(사유) → 같은 문서로 다시 요청.
5. **매출처별 계산서 합계**(그 달 발행 · 공급받는 자별 매수 · 공급가) — 계산서합계표 제출 자료(세무사 확인).

## 3. DB 막음
- `kind <> 'EXEMPT' OR vat = 0`(CHECK) · 요청 넣을 때 확정한 거래명세서(마지막 판) · 공급가 = 면세 품목 공급가 합(트리거 `ACCT_EXEMPT_INVOICE`) · 문서의 전자계산서 연결은 취소한 요청일 때만 바뀜 · 발행 번호는 한 번만.
- 전송 기록 `etax_send_log` 종류에 EXEMPT.
- `/admin/etax/exempt/{id}/send`(운영 관리자 길)로 와도 스위치가 꺼져 있으면 422.

## 4. 주의 · 확인
1. 공급받는 자가 사업자번호 없는 개인이면 발행이 막힘(ETAX_PERSON_BUYER — 영수증으로 갈음 · ㉒ 와 같음).
2. 소개몰 직판 면세 상품의 개인 소비자 판매는 계산서 대상이 아님(영수증 · 카드) — 이 화면은 거래명세서(기업 거래)만.
3. 켜기 전 세무사 확인 · 업체(ASP) 계약 때 계산서 발행 가능 여부 확인 — `assume.etax` 를 끄는 순서는 ㉒ 그대로.
