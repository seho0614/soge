2. 텔레그램을 끄려면 운영 화면 › 사이트 설정 `ops.telegram_chat` 값을 비우거나 연동 키에서 토큰을 지웁니다.
3. 개발 서버 `~/kits/release` 에 다른 판 킷(v10.197 ~ v10.199)이 남아 있어도 **v10.200 킷만** 올립니다.

## 5. 되돌리기

| 상황 | 할 일 |
|---|---|
| 화면이 이상함 | `bash ~/sgb/deploy/aws/rollback.sh` → `yes` — 코드만 v10.199 로 돌아갑니다. DB(D178 칸 · 설정 줄 · 함수 · 제약)는 남습니다 — v10.199 는 새 칸 · 함수 · 설정을 쓰지 않고, 바뀐 `fn_integ_secret_set` 은 다른 키에는 전과 같게 동작합니다. 4-2 로 만든 투표도 남습니다(투표 관리에서 감출 수 있음) |
| 되돌린 뒤 다시 v10.200 으로 | `bash ~/sgb/deploy/aws/rollback.sh` 를 한 번 더 → `yes`(v10.200 판 폴더가 남아 있음) |
| DB 까지 | 보통 필요 없습니다. 하려면 RDS → `sgb-before-v10-200-YYYYMMDD` 복원 → `.env` 접속 주소 교체 → `pm2 restart sgb sgb-site sgb-jobs` 순서로 합니다. 스냅샷 뒤에 생긴 자료는 사라집니다 |

## 6. 하지 말 것

- 법무 확인 전 처리방침 게시 · `publish-terms.sh`
- 결제대행사 연결 전 「주문 받기 켜기」
- 운영에서 `verify` · `attack` · `db:seed` · `open-prep.sh apply`
- 목록을 보기 전 `cleanup.sh --apply`
- 운영 `.env` 에 텔레그램 토큰 넣기(운영 화면 연동 키로 넣음 · 암호화 보관)
- 봇 토큰을 메신저 · 메일 · 문서에 붙여 두기(받는 즉시 연동 키 칸에 넣고 지움)

## 7. 확인하지 못한 것

| 무엇 | 까닭 |
|---|---|
| 운영 판 · 디스크 · 판 보관 폴더 | sgbdev 는 운영 서버를 볼 수 없음 — 3-0 으로 확인 |
| 운영 서버에서 api.telegram.org 로 나가는 길 | 운영 보안 그룹 · 방화벽을 볼 수 없음 — 4-3 의 시험 메시지로 확인 |

| 실제 텔레그램 서버로 보내기 | 개발 서버 시험은 가짜 텔레그램 서버로 함 — 4-3 의 시험 메시지가 첫 실제 확인 |
