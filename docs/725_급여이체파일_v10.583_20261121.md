# 725. 급여 이체 파일 (v10.583 · 2026-11-21)

> 대표 11/21 「16개 모두 동시에」 — 13차 인사 · 회계 ③. 회계 › 인사 › 급여 뒤 새 탭 「급여 이체 파일」(키 `hra-payfile`).

## 1. 결론

- 확정(FIXED) · 지급(PAID)한 급여의 **실지급액**으로 은행 대량 이체용 **CSV(UTF-8 BOM)** 를 만듭니다.
- 직원 급여 **계좌**는 직원 대장에 넣지 않고 따로(`hra_pay_banks`) **암호문**(pgp_sym_encrypt · fn_enc_key — 대량 이체 v10.454 와 같은 방식)으로만 저장 · 화면 · API 는 **끝 4자리(「****1234」)** 만.
- 계좌 원문은 **스위치 `hra.payfile_export`(처음 off)** 가 켜져 있고 **내려받기 승인(ExportGate · 대상 `HRA_PAY_FILE`)** 을 받은 뒤 한 번 내려받는 파일에만 들어갑니다.
- 은행 양식 칸 짝짓기(칸 순서 · 칸 이름 · 머리줄 · 날짜 모양)는 SUPER — 전표 CSV 양식(v10.389 `formats.ts`)과 같은 방식.

## 2. 흐름

1. 지급 담당 · SUPER 가 직원마다 은행 코드(숫자 3) · 계좌(숫자 6 ~ 20) · 예금주 · **사유**를 넣음 → 바뀐 기록(끝 4자리만) + 운영 알림 `HRA_PAY_BANK_CHANGED`(INFO · 계좌 가로채기를 일찍 알아채려고).
2. 급여 탭에서 확정 → 이 탭에서 달 고르기 → 계좌 없는 직원 · 합계 확인.
3. 「이체 파일 내려받기(승인)」 → 사유 적어 요청 → 다른 SUPER 승인(SUPER 한 명이면 스스로) → 24시간 안 한 번.
4. 파일 기록(`hra_payfile_logs` — 달 · 양식 · 줄 수 · 합계 · SHA-256 · 승인 번호 · 누가) · 감사 `HRA_PAYFILE_EXPORT` 는 고른 칸만(파일 · 계좌 없음).
5. 은행 인터넷뱅킹 대량 이체에 올림 → 은행 화면 합계 · 줄 수와 맞춤 → 내려받은 파일은 지움 → 급여 탭 「지급」.

## 3. 양식 칸

| field | 뜻 |
|---|---|
| bank | 은행 코드(숫자 3) — 꼭 |
| acct | 계좌번호(원문 · 숫자만) — 꼭 |
| amount | 실지급액 — 꼭 |
| holder | 예금주(없으면 직원 이름) |
| name · emp | 직원 이름 · 직원 번호 |
| memo | 받는 분 통장 표시(「11월급여」) |
| send_memo | 보내는 분 통장 표시(직원 이름) |
| pay_day · ym | 지급일(양식 날짜 모양) · 급여 달 |
| blank | 빈 칸 |

- 처음 양식 「기본(은행 코드 · 계좌 · 금액 · 예금주 · 적요)」 — **쓰는 은행의 실제 대량 이체 양식에 맞춰 SUPER 가 고쳐야 합니다**(은행마다 칸 · 인코딩이 다름 · 확인 필요).
- 인코딩은 UTF-8(BOM) 하나 — EUC-KR 만 받는 은행이면 엑셀로 열어 다른 이름으로 저장(대표 확인).

## 4. API

| 방법 | 주소 | 역할 | 감사 |
|---|---|---|---|
| GET | `/admin/hra/payfile?ym=` | SUPER · PAYOUT | — |
| PUT | `/admin/hra/pay-banks/{직원}` | SUPER · PAYOUT | `HRA_PAY_BANK_SET`(번호 · 끝 4자리) |
| GET | `/admin/hra/bank-formats` | SUPER · PAYOUT | — |
| POST · PUT | `/admin/hra/bank-formats` · `/{id}` | SUPER | `HRA_BANK_FORMAT_SAVE` |
| GET | `/admin/hra/payfile/export?ym=&formatId=&ticket=` | SUPER · PAYOUT | `HRA_PAYFILE_EXPORT`(고른 칸) |

- 주소가 `/admin/hra` 라 세무사 · ADMIN 은 못 봄(급여 탭과 같은 범위).
- 오류: `HRA_PAY_BANK` · `HRA_PAY_ACCT` · `HRA_PAY_HOLDER` · `HRA_BANK_FORMAT` · `HRA_BANK_FORMAT_NAME` · `HRA_PAYFILE_OFF` · `HRA_PAYFILE_STATE` · `HRA_PAY_BANK_MISSING` · `HRA_PAYFILE_EMPTY` · `EXPORT_NEED_APPROVAL`.

## 5. DB (13차 SQL `hra_583_payfile.sql`)

- `hra_pay_banks`(직원 하나 · `bank` · `acct_enc` · `acct_tail` · `holder` · 지우기 막음) · `hra_pay_bank_changes`(쌓기만) · `hra_bank_formats`(기본 하나 · 고유 이름) · `hra_payfile_logs`(쌓기만).
- **INV-11 감시 낱말(account_no · bank_code …) 칸 없음** → `v_inv11_violations` 예외 줄 없음(규칙 19).
- 내려받기 승인 대상 `HRA_PAY_FILE` — DB CHECK 는 D284 와 같은 방식으로 한 낱말 더함 · 서버 `EXPORT_TARGETS` 는 옛 시험이 배열 끝 글자를 보므로 배열 줄은 그대로 두고 아래에서 붙임.
- 권한 시드 `hra-payfile` — R_PAYOUT 넷 · 주소 6.

## 7. 대량 이체(v10.454)로 바로 넘기지 않은 까닭

- 급여는 「지급」 때 `PAYROLL_PAID` 전표(미지급금 / 보통예금)가 생기고, 대량 이체 LIVE 성공 줄도 `TRANSFER_PAID` 전표(미지급금 / 보통예금)를 만듭니다 — 같은 돈이 장부에 두 번 들어갑니다.
- 금융결제원 연동이 켜진 뒤 「급여 → 대량 이체 묶음 만들기」를 하려면 둘 중 하나의 전표를 빼는 규칙이 먼저 필요합니다(대표 · 세무사 결정 · 다음 판 후보).
