# 569. 홈택스 매입 세금계산서 가져오기 (v10.432 · 2026-11-20)

> 대표 11/19 「모두개발」 → ㉒ 외부 회계 연동. **이카운트 ERP 연동은 보류(대표 11/19)** — 이 판은 매입 세금계산서 가져오기 하나입니다.
> 마이그레이션 D255 · 시험 test_v1432 · 화면 SB-ADM-ACC-350.

## 1. 결론

- 홈택스를 직접 읽지 않습니다(공동인증서 · 스크래핑 — 보안 · 약관 문제). **연동 업체(바로빌 · 팝빌 등) API** 하나를 어댑터로 둡니다.
- 업체 계약 전에는 **간주(ASSUME)** — 업체에 묻지 않고 시험 줄(「(간주)」 공급자)을 만듭니다. 간주 줄은 매입으로 넘기지 않습니다.
- 가져온 줄은 사람이 계정 · 낸 방법을 골라 「매입으로」 → ⑫ 매입 관리(매입 세금계산서)에 들어가고, 전표는 기존 자동 전표(PURCHASE)가 만듭니다.

## 2. 위치

| 화면 | 위치 |
|---|---|
| 가져온 줄 · 가져오기 · 매입으로 · 넘기지 않음 | 회계 › (매입 · 경비) › **세금계산서 받기** |
| 켜기 · 방식 · 업체 | 정책 › 전체 설정 `acct.taxinbox` · `acct.taxinbox_mode` · `acct.taxinbox_provider`(SUPER) |
| 업체 API 키 | 외부 연동 › 연동 키 「매입 세금계산서 가져오기 · 연동 업체 API 키」(SUPER · 암호화) |

## 3. 설정 · 키

| 이름 | 처음 값 | 뜻 |
|---|---|---|
| acct.taxinbox | off | 가져오기 켜기 — 켜면 매일 08:10 지난 7일(정기 작업 acct_taxinbox) |
| acct.taxinbox_mode | ASSUME | ASSUME 간주 · LIVE 연동 업체 |
| acct.taxinbox_provider | GENERIC | GENERIC · POPBILL · BAROBILL — 응답 칸 이름 기본값만 다름(**업체 문서로 확인 필요**) |
| TAXINBOX_API_KEY | — | 외부 연동 › 연동 키(운영 화면이 먼저 · 없으면 .env) |
| TAXINBOX_API_BASE · TAXINBOX_CORP_NUM | — | .env — 업체 주소 · 우리 사업자번호 |
| TAXINBOX_MAP | — | .env JSON — 응답 칸 경로를 업체 모양에 맞춤(목록 · 승인번호 · 작성일 · 공급자 번호 · 이름 · 품목 · 공급가 · 세액 · 종류) |

- LIVE 인데 주소 · 키 · 사업자번호 중 하나라도 없으면 **422 TAXINBOX_NOT_READY** — 조용히 간주로 돌아가지 않습니다.
- 요청 모양(GET `{base}/purchase-invoices?from=YYYYMMDD&to=YYYYMMDD` · `Authorization: Bearer` · `X-Corp-Num`)은 일반 모양입니다. **실제 업체 API 형식은 계약 뒤 확인 필요** — `taxinbox.ts` 의 `HttpTaxInbox` 한 곳만 고치면 됩니다.

## 4. 규칙

1. 승인번호(24자리) 하나에 한 줄 — 다시 가져와도 한 번(이미 있음으로 셈).
2. 가져온 줄의 내용은 고치거나 지울 수 없음(DB 가 막음 TAXINBOX_LOCKED). 상태는 새로 → 매입으로 넘김 · 넘기지 않음(사유)만.
3. 매입으로 넘길 때 같은 공급자 · 날짜 · 합계의 매입이 이미 있으면 409 TAXINBOX_DUP — 다른 건이면 「같은 매입이 있어도 넘기기」.
4. 면세 계산서(세액 0)는 불공제로 넘어감. 기업업무추진비 계정은 ⑫ 규칙대로 불공제.
5. 품의 번호를 붙일 수 있음(v10.417 · 한도는 DB 가 지킴).
6. 가져오기 기록은 쌓기만(acct_tax_inbox_fetches · 키 · 개인정보 없음).
7. 외부 연동 표 TAXINBOX 는 오픈 차단이 아니고, 간주는 `assume.*` 가 아닌 `acct.taxinbox_mode` 라 오픈 체크리스트 「간주 모드 켜짐」 줄 수가 바뀌지 않습니다.
