## 2-1. DB 띄우기 ★ 45초 기다리셔야 합니다

```bash
node scripts/dev-db.js &

```

**바로 다음 명령을 치면 실패합니다.** DB가 뜨는 데 45초가 걸립니다.

확인:

```bash
node -e "const{Client}=require('pg');new Client('postgresql://postgres:postgres@localhost:54329/postgres').connect().then(()=>console.log('DB ok')).catch(()=>console.log('아직'))"
```

### ★ `psql`은 없습니다

킷에도 `npm ci` 후에도 **`psql`은 들어 있지 않습니다.** 딸려 오는 것은 셋뿐입니다.

```
initdb · pg_ctl · postgres
```

그래서 이 절차서는 SQL을 쓸 때 `psql` 대신 **위처럼 `node -e`**를 씁니다.
`psql`을 쓰고 싶으시면 따로 설치하셔야 합니다 (`apt install postgresql-client` 등).

### DB가 안 뜨면

| 증상 | 원인 | 해결 |
|---|---|---|
| `ECONNREFUSED 54329` | 서버 안 뜸 | 아래 참조 |
| `directory ".dev-db" exists but is not empty` | **클러스터는 있는데 서버만 꺼짐** | `pg_ctl`로 직접 기동 |

두 번째 경우:

```bash
node_modules/@embedded-postgres/linux-x64/native/bin/pg_ctl \
  -D .dev-db -o "-p 54329" -l /tmp/pg.log start
```

## 7. 감시 뷰 77개

「0이어야 정상」인 뷰입니다.

```bash
node -e "
const {Client}=require('pg');
(async()=>{const c=new Client(process.env.DATABASE_URL);await c.connect();
const w=(await c.query(\"SELECT viewname n FROM pg_views WHERE schemaname='public' AND obj_description(('public.'||quote_ident(viewname))::regclass) LIKE '%0이어야%'\")).rows;
let hit=0;
for(const v of w){const [r]=(await c.query('SELECT count(*)::int n FROM '+v.n)).rows;
  if(r.n>0){console.log('  이상 '+v.n+' — '+r.n+'건');hit++}}
console.log('감시 '+w.length+' · 이상 '+hit);
await c.end();})();"
```

전부 조회해서 **0건이어야 합니다.** 지금은 3건이 나오는데 **전부 정상 사유**입니다.

| 뷰 | 사유 | 언제 사라지나 |
|---|---|---|
| `v_bank_assumed` | 계좌인증 계약 전 | 계약 후 |
| `v_company_account` | 회사 계좌 미입력 | 계약 후 |
| `v_phase2_blockers` | 소개몰·소개창업에 물건 없음 | 공급자 확보 후 |
| `v_restricted_unlinked` | **시험 데이터 `NEWR`** | ★ 아래 참조 |

### ★ `v_restricted_unlinked` 는 실제 문제입니다

기준 데이터(`B900_reference_data`)에 **시험용 데이터가 굳어 있습니다.**

| 표 | 값 | 영향 |
|---|---|---|
| `restricted_industries` | `NEWR` 신규제한 | 연결 업종 0개 → 트리거가 못 잡음 |
| `categories` | `TESTRSTR` 시험제한업종 | **APPROVED 상태 — 사용자에게 보입니다** |
| `banned_words` | 시험차단어·시험주의어 | 실사용에 무해 |
| `site_settings` | **`company.bank_name` = 시험용가상은행** | ★ 계좌번호 `999999-99-999999` |

**계좌 설정이 가장 위험합니다.** 계약 후 실제 계좌로 바꾸지 않으면 입금 안내에 가짜 번호가 나갑니다. 다만 `v_company_account` 감시 뷰가 이것을 이미 잡고 있습니다.

원인은 `build-baseline.js`가 **당시 DB를 그대로 떠서** 시험 흔적까지 기준 데이터로 굳힌 것입니다.

정리하시려면 새 마이그레이션으로 지우십시오. 기존 파일은 고치지 마십시오.

```sql
DELETE FROM categories            WHERE code = 'TESTRSTR';
DELETE FROM restricted_industries WHERE code = 'NEWR';
DELETE FROM banned_words          WHERE word LIKE '시험%';
-- site_settings 의 계좌 3건은 계약 후 실제 값으로 UPDATE
```

**이 넷 말고 다른 것이 나오면 문제입니다.**
