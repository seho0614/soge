# 271. CI(A안) — 풀 리퀘스트 자동 점검 · 킷 자동 생성 · 운영 반영은 사람 (2026-11-02)

> 대표 「CI/CD」 → A · B · C 설명 → **「일단 A 안으로」** · **「통과해야 병합」**(11/2). 결정 기록 deploy-cicd #17.
> 설정 파일: sgb-infra `ci/sgb-ci.cfn.yml`(AWS 자원) · `ci/pr-check.sh`(점검) · `ci/kit-build.sh`(킷). **운영 서버 · 운영 RDS 에는 아무것도 하지 않습니다.**

## 1. 무엇이 바뀌나

| 지금 | A안 뒤 |
|---|---|
| Claude 가 개발 서버에서 realcheck · 시험 → 풀 리퀘스트 → 대표 「승인」 → 병합 | 같음 **+ 풀 리퀘스트를 올리면 AWS 가 한 번 더 점검**(형 검사 · 빈 DB 마이그레이션 2번 · 불변식 · 시험 안전 · 오류 코드 · 권한 · SQL) → 결과 댓글 · **통과 표시가 없으면 병합 단추가 잠김** |
| 병합 뒤 Claude 가 `make-kit.sh` 로 킷 → 집 PC 로 내려받기 → 운영 서버로 올리기 | **main 이 바뀌면 AWS 가 킷을 S3 에**(zip · tar.gz · SHA256SUMS · 덮어쓰지 않음). 운영 서버에 aws 명령 도구 · 읽기 권한이 생기면 운영에서 바로 받기(그 전에는 지금처럼) |
| 운영 반영: 사람이 precheck → 스냅샷 → apply → postcheck | **그대로**(대표 승인 뒤 사람) |

개발 서버 realcheck · 기능 점검 · 회귀 시험(화면 확인 포함)은 **그대로 돕니다** — AWS 점검은 그보다 가벼운 「두 번째 눈」입니다.

## 2. 만들어지는 것 (CloudFormation 스택 하나)

| 자원 | 이름 | 하는 일 |
|---|---|---|
| S3 버킷 | (정하는 이름) | `kits/<판>/<시각>_<core 커밋>/` 에 킷 · 공개 막음 · 암호화 · 판 기록(지난 판 30일) · **스택을 지워도 버킷은 남음** |
| CodeBuild | `sgb-pr-check` | 풀 리퀘스트 점검(중간 크기 기계 · 40분 제한 · 동시에 2개) |
| CodeBuild | `sgb-kit-build` | 킷 만들기(작은 기계 · 20분 제한 · 하나씩) |
| IAM 역할 | `sgb-ci-pr-check` | 저장소 2개 읽기 · 풀 리퀘스트 댓글 · 승인 표시 — **S3 쓰기 없음**(풀 리퀘스트 코드를 돌리므로) |
| IAM 역할 | `sgb-ci-kit-build` | 저장소 3개 main 읽기 · S3 `kits/` 쓰기 |
| IAM 역할 | `sgb-ci-events` | 아래 규칙이 CodeBuild 를 시작 |
| EventBridge 규칙 | `sgb-ci-pr` | sgb-core · sgb-infra 에서 main 으로 가는 풀 리퀘스트가 열리거나 고쳐지면 점검 |
| EventBridge 규칙 | `sgb-ci-main` | 세 저장소 main 이 바뀌면 킷 |

비용(예상 · **AWS 요금 페이지에서 확인 필요**): 점검 한 번 10 ~ 15분 · 한 달 30번이면 약 400분 → 월 몇천 원 이하 · S3 는 판마다 약 60MB.

## 3. 순서 (대표 · AWS 콘솔 · 서울 리전)

> ⚠ 한 단계씩. 끝날 때마다 결과를 Claude 에게 알려 주십시오.

### 3-1. 설정 파일 받기 (집 PC PowerShell)

```powershell
scp sgb-dev:~/sogaebank/sgb-infra/ci/sgb-ci.cfn.yml C:\sgb\
```

### 3-2. 스택 만들기

```
AWS 콘솔 → CloudFormation → 스택 생성 → 새 리소스 사용(표준)
 → 「템플릿 파일 업로드」 C:\sgb\sgb-ci.cfn.yml → 다음
 → 스택 이름 sgb-ci · KitBucketName = (정한 버킷 이름) · BuildImage 는 그대로 → 다음 → 다음
 → 맨 아래 「IAM 리소스를 생성할 수 있음을 승인합니다」 체크 → 제출 → 상태 CREATE_COMPLETE 까지(3 ~ 5분)
 → 「출력」 탭의 PrCheckRoleArn 값을 복사해 Claude 에게
```

- [ ] CREATE_COMPLETE · [ ] 출력 PrCheckRoleArn 받음

### 3-3. 「통과해야 병합」 승인 규칙 (CloudShell · 콘솔 오른쪽 위 `>_` 아이콘)

Claude 가 계정 번호를 넣은 명령을 따로 드립니다(아래는 모양). **승인 규칙은 연결한 뒤에 새로 연 풀 리퀘스트부터** 걸립니다.

```bash
aws codecommit create-approval-rule-template --region ap-northeast-2 \
  --approval-rule-template-name sgb-ci-must-pass \
  --approval-rule-template-description "AWS 자동 점검(sgb-pr-check)이 통과 표시해야 main 병합 — docs/271" \
  --approval-rule-template-content '{"Version":"2018-11-08","DestinationReferences":["refs/heads/main"],"Statements":[{"Type":"Approvers","NumberOfApprovalsNeeded":1,"ApprovalPoolMembers":["arn:aws:sts::<계정번호>:assumed-role/sgb-ci-pr-check/*"]}]}'
aws codecommit batch-associate-approval-rule-template-with-repositories --region ap-northeast-2 \
  --approval-rule-template-name sgb-ci-must-pass --repository-names sgb-core sgb-infra
```

- [ ] 「associatedRepositoryNames」에 sgb-core · sgb-infra

### 3-4. 시험 (Claude)

1. Claude 가 문서 한 줄짜리 시험 풀 리퀘스트를 sgb-infra 에 올림 → 10분 안에 댓글 「자동 점검 통과」 · 승인 1/1
2. 일부러 문법이 틀린 시험 파일 풀 리퀘스트 → 「자동 점검 실패」 · 병합 시도가 막히는지 확인 → 닫고 갈래 지움
3. 다음 판(실제 sgb-core 풀 리퀘스트)에서 sgb-core 점검 확인 · 병합 뒤 S3 `kits/` 에 킷이 생기는지

## 4. 그 뒤 일하는 방식

| 단계 | 누가 | 바뀐 점 |
|---|---|---|
| 개발 · realcheck · 회귀 | Claude(개발 서버) | 없음 |
| 풀 리퀘스트 | Claude | 올린 뒤 **AWS 점검 통과 댓글을 기다림**(10 ~ 15분) |
| 병합 | 대표 「승인」 → Claude | 통과 표시가 없으면 병합이 거절됨 |
| 킷 | AWS | S3 `kits/<판>/…` · 절차서에 그 경로 · sha256 을 적음 |
| 운영 반영 | 대표(ubuntu) | 없음 — 킷 받는 곳만 S3 로 바뀔 수 있음(운영 서버 준비 뒤) |

sgb-docs · sgb-adx 풀 리퀘스트는 점검하지 않습니다(문서 · 광고는 지금처럼). sgb-adx 는 main 이 바뀌면 킷만 새로 만듭니다.

## 5. 문제가 생기면

| 상황 | 할 일 |
|---|---|
| 점검이 안 시작됨 | CodeBuild → `sgb-pr-check` → 빌드 기록 비었는지 · EventBridge 규칙 `sgb-ci-pr` 사용 상태 |
| 점검이 계속 실패(코드 문제 아님) | Claude 가 로그를 보고 고침 · **급하면** 승인 규칙을 그 풀 리퀘스트에서만 「재정의」(override · 콘솔 풀 리퀘스트 화면 · 대표만) — 기록이 남음 |
| Node 22 가 이미지에 없다고 나옴 | 스택 「업데이트」 → BuildImage 를 새 판(`aws/codebuild/standard:8.0` 등 · AWS 문서 확인)으로 |
| 전부 걷어내기 | 승인 규칙 연결 해제(`batch-disassociate-…`) → 템플릿 삭제 → CloudFormation 스택 `sgb-ci` 삭제(버킷은 남음 · 필요 없으면 비우고 따로 삭제) |

## 6. 하지 않는 것

- 운영 서버 자동 배포(CodeDeploy) — 운영 전환 때 서버 재설계와 함께 다시 봄(deploy-cicd #17)
- 비밀 값 · `.env` 를 CodeBuild 에 넣기 — 점검은 버리는 컨테이너 DB 만 씀
- 승인 규칙을 대표 승인 대신으로 쓰기 — **대표 「승인」은 그대로 필요**

## 7. 확인하지 못한 것

|---|---|
| CodeBuild 이미지의 Node 22 지원 · 요금 | 바뀔 수 있음 — 스택 만들 때 · 첫 점검에서 확인 |
| 실제 동작 | AWS 자원이 아직 없음 — 3-4 시험으로 |
