# 472. 운영 화면 「업무 안내」 (v10.339 · 2026-11-17)

> 대표 11/17 「업무별 워크 플로우 작성」 → 흐름표(운영진 12 · 개발 · 운영 적용 4 · 회원 · 파트너 7 — 비공개 웹 페이지) → 「다음개발」 ④ 업무 흐름표를 운영 화면에(docs/469 머리말의 네 가지 중 넷째) · 「승인 + 통과하면 병합」. 마이그레이션 **D229**(266 → 267 · 스냅샷 필요).

## 1. 왜

- 흐름표는 운영 화면 밖(웹 페이지)에 있어, 운영자가 일하다 바로 볼 수 없었습니다. 단계마다 「어느 메뉴 › 탭」인지 다시 찾아야 했습니다.
- 운영 규칙이 바뀌면 흐름표도 바뀌어야 하는데, 고칠 사람 · 고친 기록이 없었습니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 마이그레이션 **D229** | 표 `ops_guides`(업무 코드 · 판 · 이름 · 누가 · 단계 jsonb `[{t, go}]` · 알아 둘 것 · 순서) — **고치기 · 지우기 막음**(트리거 `trg_ops_guides_guard` — 고치면 새 판) · 보기 `v_ops_guide_current`(업무마다 가장 높은 판) · **처음 업무 12가지**(1:1 문의 답변 · 자주 묻는 질문 관리 · 회원 권한 주기 · 검수 · 업종 승인 · 파트너 입점 · 자격 심사 · 거래 분쟁 · 정산 · 지급 · 소개몰 판매자 · 주문 · 운영 알림 확인 · 약관 게시 · 리드관 켜기 · 끄기). 지우는 문장 없음 |
| 새 API `GET /admin/ops-guides` | 운영 역할 모두(REVIEWER · ADMIN · PAYOUT · SUPER · PARTNER_MAL · PARTNER_AFF) · 고친 사람 가린 메일 · `canEdit`(SUPER) |
| 새 API `POST /admin/ops-guides/{code}` | **SUPER** · 새 판(옛 판 남음) · 감사 `OPS_GUIDE_SAVE` · 422 `OPS_GUIDE_CODE` · `TITLE` · `WHO` · `STEP` · `TAB`(「이 화면」은 운영 화면 탭 이름 모양만) · `NOTE` |
| 운영 화면 **관 관리 › 「업무 안내」**(SB-ADM-SIT-110 · 「자주 묻는 질문」 다음) | 업무마다 접는 상자 — 이름 · 누가 · 판 · 단계(번호 = 순서) · 단계마다 **「이 화면」**(그 탭으로 이동 · 권한 없는 화면은 흐림) · 알아 둘 것 · SUPER 는 「고치기」 → 한 줄 = 한 단계(끝에 ` | 탭이름`) → 「새 판으로 저장」. 운영 역할 모두 볼 수 있음 |

- 흐름표 웹 페이지의 「개발 · 운영 적용」 · 「회원 · 파트너」 갈래는 운영 화면에 넣지 않았습니다(운영진 업무만).
- 「이 화면」 탭 이름이 바뀌면(메뉴 고침) 단추가 그 탭을 못 찾습니다 — 메뉴를 고칠 때 업무 안내도 새 판으로 고칩니다.
