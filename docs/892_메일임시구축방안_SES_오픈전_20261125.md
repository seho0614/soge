# 892. 메일 임시 구축 방안 — Amazon SES · sogaebank.com (오픈 전 · 오픈 때 정식 재구축) (2026-11-25)

> 대표 11/25 「추천하는 방법대로 구축하는 방안 · SES 를 이용 · 오픈 때 정식으로 다시 구축」 · 샌드박스는 **「B. 지금 해제 신청」**(11/25 대표 — 회원 메일을 지금부터 보냄).
> **세부 클릭 순서는 docs/167 v1.4(메일 구축 절차서)가 기준**이고, 이 문서는 그것을 **「지금 임시로」와 「오픈 때 정식으로」 두 번으로 나눈 계획**입니다.
> 요금 · 심사 기간 · 한도 · 콘솔 메뉴 이름은 바뀔 수 있습니다. **적용하는 날 AWS 문서로 다시 확인하십시오.**

## 1. 결론

| 항목 | 내용 |
|---|---|
| 방식 | 보내기 = **Amazon SES 서울(ap-northeast-2) · SMTP 465** · 받기 = **지금 쓰는 `@sogaebank.com` 메일함 그대로**(자체 메일 서버는 만들지 않음) |
| 보내는 주소 | **`no-reply@mail.sogaebank.com`** · 보내는 이름 「소개뱅크」 |
| 답장 · 문의 주소 | `help@sogaebank.com`(고객) · `privacy@sogaebank.com`(개인정보) · `dmarc@sogaebank.com`(보고서) · `admin@sogaebank.com` — 모두 지금 메일함 |
| 코드 개발 | **없음** — 메일 발송기(v10.43) · 알림 메일(v10.85) · 운영 화면 「메일」(v10.140) · 반송 처리(v10.209 · 꺼진 채)가 이미 운영에 있음 |
| 지금(임시) | 도메인 인증 · DNS · SMTP 자격 증명 **임시용** · **샌드박스 해제 신청(결정 1 = B)** · 승인 뒤 회원 인증번호 · 알림 메일 켬 · 반송 웹훅도 지금 켬 |
| 오픈 때(정식) | 임시 자격 증명 폐기 → 정식 자격 증명 · DMARC 올리기 · 새 서버로 옮기면 465 · 연동 키 · 웹훅 주소 확인(4절) |
| 다시 하지 않는 것 | **도메인 인증 · DKIM · DNS 레코드는 같은 AWS 계정이면 그대로 씀**(오픈 때 다시 넣지 않음) |
| 걸리는 시간 | 임시 약 1 ~ 2시간 + DNS 반영 대기(수 분 ~ 수 시간) · 정식 약 1시간 + 샌드박스 해제 심사(보통 1일 안팎 · **확인 필요**) |
| 비용 | 보낸 양만큼(1천 통 단위 과금 · **요금 적용일 확인 필요**) · 하루 2천 통이면 한 달 6만 통 규모 |

## 3. 지금 — 임시 구축 (오픈 전)

| 단계 | 할 일 | 하는 사람 | docs/167 v1.4 | 확인 칸 |
|---|---|---|---|---|
| 0 | 가비아 DNS 지금 화면 통째로 캡처 · 지금 메일 레코드(MX · `@` SPF) 확인 | 대표 · 담당 | 3단계 0번 | ☐ |
| 1 | SES 서울에서 도메인 `mail.sogaebank.com` 인증 만들기 — MAIL FROM `bounce.mail.sogaebank.com` · Easy DKIM RSA 2048 · 나온 DNS 표 저장 | 〃(AWS 콘솔) | 1단계 1 ~ 3 | ☐ |
| 2 | 시험 받을 주소 2 ~ 3개 「이메일 주소」로 인증(받은 메일의 링크 누름 · 해제 승인 전 시험용) | 〃 | 1단계 4 | ☐ |
| 3 | 계정 수준 억제 목록(반송 · 불만) 켜기 · CloudWatch 경보 2개(반송률 0.05 · 신고율 0.001) | 〃 | 2단계 | ☐ |
| 4 | 가비아 DNS 4줄 넣기(아래 표) — `@` 의 MX · SPF 는 **넣지도 바꾸지도 않음** | 〃(가비아) | 3단계 | ☐ |
| 5 | SES 「확인됨」 · DKIM 성공 · MAIL FROM 성공 | 〃 | 4단계 | ☐ |
| 6 | SMTP 자격 증명 만들기 — IAM 사용자 이름 **`ses-smtp-interim`**(임시라는 표시 · 오픈 때 지움) → 운영 화면 › 외부 연동 › 연동 키 › 메일 줄에 붙여 넣기 | 대표(SUPER) | 5단계(v10.140 부터) | ☐ |
| 7 | 운영 화면 › 외부 연동 › 메일 › 「연결 확인」 → 「연결됨 — email-smtp.ap-northeast-2.amazonaws.com:465」 | 〃 | 5단계 3 | ☐ |
| 8 | 사이트 설정 `notify.mail_from = no-reply@mail.sogaebank.com` | 〃 | 7단계 1 | ☐ |
| 9 | 메일 › 「시험 메일 보내기」(2단계 주소로) → 받은편지함 · 원본 `spf=pass` · `dkim=pass` · `dmarc=pass` | 〃 | 7단계 2 | ☐ |
| 10 | **샌드박스 해제 신청**(트랜잭션 · https://sogaebank.com · 하루 300 ~ 2,000통 · 사용 설명은 docs/167 6단계 예시 — 반송 웹훅을 켠다는 줄 더함) → 승인 메일(한도 · 초당 발송 수) | 대표 · 담당 | 6단계 | ☐ |
| 11 | **반송 · 수신 거부 웹훅 켜기** — SNS 주제 · 구독(`https://sogaebank.com/api/v1/webhooks/ses`) → 사이트 설정 `notify.ses_topic_arn` → `notify.ses_feedback = on` | 〃 · SUPER | docs/334 3절 | ☐ |
| 12 | **승인 뒤에만** `notify.email_verified = on` → 상담 신청 · 비밀번호 찾기 · 알림 메일 열림 → 메일 › 발송 기록 「보냄」 · 승인 전에 켜면 회원 메일이 거절(FAILED)로 쌓임 | 대표(SUPER) | 7단계 3 | ☐ |
| 13 | 켠 뒤 1주 — 반송률 5% 미만 · 신고율 0.1% 미만 · 발송 기록 실패 까닭 · `dmarc@` 보고서 | 운영자 | 8단계 | ☐ |

**가비아 DNS 에 넣을 줄**(호스트 칸에는 `sogaebank.com` 을 빼고 적음 · 값은 **SES 화면 표가 우선**):

| # | 타입 | 호스트 | 값 | 오픈 때 |
|---|---|---|---|---|
| 1 ~ 3 | CNAME | `xxxx._domainkey.mail`(SES 표 그대로 3줄) | `xxxx.dkim.amazonses.com` | 그대로(같은 계정이면) |
| 4 | MX | `bounce.mail` | `10 feedback-smtp.ap-northeast-2.amazonses.com` | 그대로 |
| 5 | TXT | `bounce.mail` | `v=spf1 include:amazonses.com ~all` | 그대로 |
| 6 | TXT | `_dmarc.mail` | `v=DMARC1; p=none; rua=mailto:dmarc@sogaebank.com` | 보고서가 깨끗하면 `p=quarantine` 으로(4절 ④) |

- 「4줄」은 종류 기준(DKIM 3줄은 한 묶음)입니다. 실제로 넣는 줄은 6줄입니다.
- ⚠ 호스트에 `….sogaebank.com` 을 통째로 넣으면 `…sogaebank.com.sogaebank.com` 이 됩니다.
- ⚠ `@` 의 TXT · MX 는 건드리지 않습니다 — 지금 회사 메일이 끊기지 않게(결정 mail-ses #8).

**임시 기간에 나가는 메일**: 해제 승인 전 = 시험 메일 · 인증한 주소로 가는 운영 알림뿐 / 승인 · 12단계 뒤 = 회원 인증번호 · 비밀번호 찾기 · 회원 알림 · 운영 알림 모두. ⚠ 켜면 대기 중인 알림 메일도 보내기 시작합니다 — 3일 넘은 알림 · 쓰지 않는 계정 · 회원이 끈 알림은 보내지 않고 닫습니다(docs/139).

## 6. 위험과 대비

| 위험 | 대비 |
|---|---|
| DNS 를 잘못 넣어 회사 메일이 끊김 | `@` 는 건드리지 않음 · 0단계 캡처로 되돌림 · 넣은 뒤 `Resolve-DnsName -Type MX sogaebank.com` 이 0단계와 같은지 |
| SMTP 비밀번호 유출 | 화면에 한 번만 보임 · 메신저 · 메일 · 채팅(Claude 포함)에 붙이지 않음 · 운영 화면 연동 키에만(암호화 · 끝 4자리) · 오픈 때 임시 것 삭제 |
| 샌드박스 심사가 늦어지거나 거절됨 | 그동안 회원 인증은 휴대폰(알림톡) 길로(v10.43 · 둘 중 하나로 확인) · 거절이면 까닭을 고쳐 다시 신청 · `notify.email_verified` 는 승인 전 켜지 않음 |
| 스팸함으로 감 | 시험 메일 원본에서 spf · dkim · dmarc 모두 pass 확인 · 하나라도 fail 이면 3단계 DNS 다시 |
| 반송 · 신고율이 올라 SES 검토 · 정지 | 회원 메일을 지금부터 보내므로 억제 목록 · 경보 · 웹훅 모두 지금 켬 · 오래된 · 오타 주소 반송이 원인이면 답장 기한 안에 까닭 · 조치 회신 · 급하면 `notify.email_verified = off` |

## 7. 현장 체크리스트

**임시(지금)**
- ☐ 가비아 DNS 캡처 · 지금 MX 기록
- ☐ SES 도메인 `mail.sogaebank.com` 확인됨 · DKIM 성공 · MAIL FROM 성공
- ☐ 시험 주소 인증 2 ~ 3개
- ☐ 억제 목록 반송 · 불만 · 경보 2개
- ☐ 연동 키 메일 줄(`ses-smtp-interim`) · 연결 확인 「연결됨」
- ☐ `notify.mail_from = no-reply@mail.sogaebank.com`
- ☐ 시험 메일 받은편지함 · spf · dkim · dmarc pass
- ☐ 샌드박스 해제 승인
- ☐ SNS 주제 · 구독 확인됨 · `notify.ses_feedback` on
- ☐ (승인 뒤) `notify.email_verified` on · 발송 기록 「보냄」
- ☐ 1주 평판 지표
- ☐ 회사 메일(`@sogaebank.com`) 주고받기 이상 없음

**정식(오픈)**
- ☐ 정식 자격 증명 · 임시 IAM 사용자 삭제
- ☐ `_dmarc.mail` p=quarantine
- ☐ (새 서버) 465 OK · 연동 키 · 설정 · SNS 구독 확인됨
- ☐ (새 계정) 도메인 인증 · 샌드박스 해제 다시
- ☐ 한도가 오픈 발송량보다 큼
- ☐ 오픈 뒤 1주 평판 지표
