# 006. 소개뱅크 → ERP 표 구조 뽑기 (e2.1 · 2026-11-25)

> 대표 승인(11/25 「전체개발 진행」 · E2 계획) · 설계서 design/ERP분리_설계서 4-2 · 6절 E2.

## 무엇
- `tools/gen-erp-schema.py` — 소개뱅크 마이그레이션을 모두 넣은 **버리는 DB**(`SRC_DB`)에서 ERP 표만 골라 ERP 마이그레이션을 만듦. 손으로 고치지 않음 · 다시 돌리면 같은 결과(`--check`).
- 고르는 표: 접두어 acct · hr · hra · hrx · ofc · qlt · lgl · its · prr · sal + corp_docs · corp_doc_versions(회사 문서).

| 만드는 파일 | 내용 |
|---|---|
| `prisma/migrations/E004_core_tables` | 표 · 순번 · 기본값 · 색인 · 제약 · 트리거 · 함수(ERP 표를 쓰는 것 + 그것이 부르는 것) · 조회(ERP 표만 쓰는 것) |
| `prisma/migrations/E005_core_seed` | 소개뱅크 마이그레이션이 넣은 처음 자료(계정과목 · 양식 등 · 회원 자료 아님) |
| `docs/e2-fk-dropped.tsv` | 지운 외래 키 — 소개뱅크 표(accounts · 상품 · 판매자 · 광고주 · files)를 가리키던 것 · 번호 칸만 남김 |
| `docs/e2-svc-refs.tsv` | 함수 · 조회 안에서 소개뱅크 표를 읽는 곳 → e2.3 에서 `svc.` 로 |

## 지키는 것
1. `SRC_DB` 가 데이터베이스 sgb · 5432(확인판) · RDS 주소면 멈춤 — 읽기만.
2. ERP 표끼리 외래 키는 그대로 · 소개뱅크 표를 가리키는 외래 키만 지움.
3. 소개뱅크 표를 읽는 조회는 e2.3(svc) 전까지 주석으로 보류.
4. **E2 병합 뒤 소개뱅크(sgb-core)의 회계 · 인사 표는 고치지 않음**(대표 11/25) — 그 뒤 변경은 sgb-erp 에만.

## 확인 필요
- E005 는 `session_replication_role = replica` 로 트리거를 건너뜀 — RDS 에서는 마스터 사용자(rds_superuser)로 돌려야 함(E8 에서 확인).
