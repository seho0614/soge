# 273. 보안 머리글 · API 전체 요청 한도 · 올린 파일 하루 백업 (v10.176 · 2026-11-02)

> 대표 「다음 개발」 → 「모두」(11/2). 배경: 사용자 웹 전체 공개(11/1 · domain-dns #11) 뒤 점검해 보니 ① 보안 머리글이 한 곳에도 없었고(Nginx 예시 · Next · API)
> ② API 요청 한도는 가입 · 로그인 · 검색 기록에만 있었으며 ③ RDS 스냅샷에는 DB 만 들어가 **올린 파일(사진 · 영상)은 백업이 없었음**.
> 마이그레이션 **1개(D165)** · 203. 앞 판: v10.175(docs/270). 운영은 v10.173 · 묶음 절차서 docs/272(v10.173 → v10.175).

## 1. 무엇을 하나

| # | 부분 | 내용 |
|---|---|---|
| 1 | **보안 머리글** | 사용자 웹 화면: HTTPS 만 쓰기(HSTS 1년) · **남의 사이트 안에 끼워 보이기 금지**(같은 사이트 안은 허용 — `X-Frame-Options SAMEORIGIN` + `frame-ancestors 'self'`) · 파일 종류 추측 금지(`nosniff`) · 다른 사이트로 넘길 때 주소는 도메인만(`Referrer-Policy`) · 카메라 · 마이크 끔 · 위치는 우리 사이트만(동네 인증 · 맛집 지도) · `X-Powered-By` 숨김. API: 같은 것 + 끼워 보이기 전부 금지(`DENY` · JSON 만 내보냄) |
| 2 | **API 전체 요청 한도** | IP 하나가 **1분에 600번**(설정 `abuse.api_per_ip_min` · 0 = 끔 · 바꾸면 1분 안에 반영)을 넘게 API 를 부르면 **429 `API_RATE_LIMIT` 「요청이 너무 많습니다. 잠시 뒤 다시 시도해 주십시오.」** + `Retry-After`(다음 1분 창까지 초) · 영어 사전 있음. **세지 않음**: 내부 IP(같은 서버 · 사설망) · 로그인한 운영자(ADMIN · SUPER · REVIEWER · PAYOUT). IP 는 HMAC 값(날짜를 섞음)으로 API 프로세스 메모리에서만 셈 — DB 에 남기지 않음. 운영 화면 「공개 직후 지켜보기」에 **「한도 걸림(1시간)」** 칸 |
| 3 | **올린 파일 하루 백업** | `deploy/aws/uploads-backup.sh` — `~/sgb-data/uploads` → `~/sgb-data/backup/uploads/uploads_YYYYMMDD.tar.gz`(한국 날짜) · **7개만 남김**(그보다 오래된 `uploads_*.tar.gz` 만 지움) · 같은 날 다시 돌리면 건너뜀 · 묶은 뒤 파일 수 대조 · 디스크 여유가 (올린 파일 + 1GB)보다 적으면 **만들지 않고** 운영 알림 `UPLOADS_BACKUP_SKIPPED`(WARN · 하루 한 번) · `check` 는 읽기만 |

### 왜 600 인가 (제안 때 300 에서 바꿈)
사용자 웹 화면(서버 렌더링)이 API 를 부를 때도 **접속자 IP 를 넘기므로** 화면 한 장이 API 여러 번으로 셉니다. 빠르게 둘러보는 손님 · 검색 로봇이 걸리지 않게 넉넉히 600 으로 시작하고,
「한도 걸림」 칸 · 운영 알림을 보며 운영 화면 설정에서 줄이거나 늘립니다.

### 넣지 않은 것
- **스크립트 출처 제한(전체 CSP)** — 카카오 지도 · 결제창 · 분석 스크립트 등 출처가 많아 하나만 빠져도 화면이 깨짐. 끼워 보이기 막기(`frame-ancestors`)만 넣음. 나중에 「보고만 하기(Report-Only)」로 먼저 모은 뒤 판단 권함.
- **HSTS `includeSubDomains` · `preload`** — 하위 주소 중 HTTPS 가 아닌 곳이 생기면 못 열림 · preload 는 되돌리기 어려움.

## 3. 시험 (test_v1176)

1. 코드 — D165 · 미들웨어 순서 · 빠지는 것 · 머리글 · 사전 · 지켜보기 칸 · 스크립트 문법 · 실행 권한 · 판
2. API — 머리글 · **같은 공인 IP 로 1분에 600 넘게 → 429 + Retry-After** · 같은 IP 라도 운영자 증표면 통과 · 다른 IP · 내부 통과 · 「한도 걸림」 늘어남
3. 사용자 웹 — 화면 머리글 6가지 · `X-Powered-By` 없음 · `/api` 는 API 머리글 하나(겹치지 않음)
4. 스크립트 — 만듦(파일 수 그대로) · 같은 날 건너뜀 · 7개만 남김(다른 파일 그대로) · 디스크 부족 → 2 + 운영 알림 한 번만

## 4. 운영에서 (적용 뒤)

1. **머리글 확인**(집 PC):
   ```
   curl -sI https://sogaebank.com/ | findstr /i "strict-transport x-frame content-security permissions-policy x-powered"
   ```
   `Strict-Transport-Security` · `X-Frame-Options: SAMEORIGIN` · `Content-Security-Policy: frame-ancestors 'self'` · `Permissions-Policy` 가 보이고 `X-Powered-By` 는 없어야 함
2. **올린 파일 백업 등록**(ubuntu · 한 번):
   ```bash
   bash ~/sgb/deploy/aws/uploads-backup.sh check     # 읽기만 — 파일 수 · 크기 · 디스크 여유
   bash ~/sgb/deploy/aws/uploads-backup.sh           # 첫 묶음 만들기
   crontab -e                                        # 아래 한 줄 더함(서버 시간대 UTC 기준 = 한국 04:30)
   30 19 * * * bash /home/ubuntu/sgb/deploy/aws/uploads-backup.sh >/dev/null 2>&1
   ```
   `~/sgb` 바로가기를 쓰므로 판이 바뀌어도 그대로. 기록은 `~/sgb-data/logs/uploads-backup_YYYYMMDD.txt`
3. (선택) 운영 화면(admin) 파일에도 머리글 — 운영 Nginx `/etc/nginx/sites-enabled/sgb` 운영 화면 server 칸에 `nginx-sgb.conf.example` 의 `add_header` 4줄(+ `/assets/` 안에 다시) → `sudo nginx -t` → `sudo systemctl reload nginx`. 운영 화면은 허용 IP 에서만 열려 급하지 않음 — **이번 적용에는 넣지 않음**
4. 한도 조정 — 운영 화면 › 사이트 설정 `abuse.api_per_ip_min`(0 = 끔)
