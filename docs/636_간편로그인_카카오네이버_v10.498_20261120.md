# 636. 카카오 · 네이버 간편 로그인 (v10.498 · 2026-11-20)

## 1. 결론
사용자 웹 로그인 화면에 **「카카오로 로그인」 · 「네이버로 로그인」**(켜진 업체만)을 더했습니다. 방식은 **OAuth 2.0 authorization code + state + PKCE(S256)** 이고, state · PKCE 값은 **서버(API)만** 알며 이 브라우저와 묶습니다(httpOnly 쿠키의 묶음 값 지문). 처음 온 업체 회원은 **새로 가입**하거나, 업체가 **확인한 이메일과 같은 계정이 있을 때만 그 계정 비밀번호를 넣어 연결**합니다 — **저절로 합치지 않습니다.** 본인인증(NICE)은 **지금과 같이 그대로** 필요하고, **운영 역할 계정은 간편 로그인을 쓸 수 없습니다.** 모두 **처음 꺼짐**(`social.kakao` · `social.naver` off · 방식 `social.mode` = ASSUME 간주). 키는 기존 **외부 연동 › 연동 키** 화면(외부 연동 17번째 **SOCIAL**).

| 설정 | 처음 | 뜻 |
|---|---|---|
| `social.kakao` · `social.naver` | off | 로그인 화면 단추 · 시작 허용(SUPER) |
| `social.mode` | ASSUME | ASSUME = 업체를 부르지 않는 간주(점검판 시험) · **운영 서버(NODE_ENV=production)에서는 간주 로그인 막힘** / LIVE = 업체 |
| `social.privacy_ok` | off | 처리방침에 간편 로그인 항목 게시 · 법무 확인을 마쳤다는 표시 — **LIVE 로 켜기 전 필수**(422 SOCIAL_PRIVACY_FIRST) |

| 키(연동 키 · SOCIAL) | 필요 | 뜻 |
|---|---|---|
| `KAKAO_LOGIN_CLIENT_ID` | 선택 | 카카오 로그인 client_id — **비우면 카카오맵(MAP)의 `KAKAO_REST_KEY` 를 다시 씀**(3절) |
| `KAKAO_LOGIN_SECRET` | 선택 | 카카오 앱에서 Client Secret 을 켰을 때만 |
| `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` | 둘 다 | 네이버 개발자센터 애플리케이션 |
| `SOCIAL_TIMEOUT_MS`(.env) | 선택 | 업체 호출 제한 시간(처음 5000) |

## 2. 흐름
```
로그인 화면 ─ 카카오 단추 ─▶ GET /login/social/kakao?next=…        (사용자 웹 서버)
   ① 묶음 값(무작위 32바이트) → 쿠키 sgb_sb(httpOnly · /login/social · 10분)
   ② POST /auth/social/kakao/start {redirectUri, binding} → API: state · PKCE verifier 생성 · soc_states(지문 · 10분 · 한 번) → 업체 주소
   ③ 302 → kauth.kakao.com (간주면 바로 ④ 로)
업체 로그인 · 동의 ─▶ GET /login/social/kakao/callback?code&state
   ④ POST /auth/social/kakao/callback {code, state, binding(쿠키), redirectUri}
      · state 지문 · 묶음 지문 · redirectUri · 10분 · 한 번 모두 맞아야(아니면 409 SOCIAL_STATE_INVALID)
      · LIVE: code + code_verifier → 접근 증표 → 회원 정보(번호 · 이메일 · 별명) → 증표는 버림
   ⑤ 연결된 회원 → LOGIN(증표 쿠키 · next) / 연결 시작이었으면 LINKED / 처음이면 PENDING(이어서 표 · 쿠키 sgb_st · 15분)
이어서 화면 /login/social/continue(SB-HOM-UPT-020)
   · 같은 이메일 계정(업체가 확인한 이메일 · 활동 중 · 운영 역할 아님 · 비밀번호 있음) → 「기존 계정에 연결」 = 그 계정 비밀번호 확인(이메일 로그인과 같은 잠금 · 표마다 5번)
   · 「새로 가입」 = 이름 · (업체가 이메일을 안 주면) 이메일 · 필수 약관 · 추천 코드 → 비밀번호 없는 계정 + 연결
내 정보 › 로그인 기록 › 「간편 로그인」(SB-MYP-UPT-010) — 연결하기(로그인한 본인 계정) · 끊기 · 첫 비밀번호 만들기
```

## 3. 카카오 키 — 지도(MAP) 앱 키를 다시 쓸 수 있는가(판단)
1. 카카오 로그인의 `client_id` 는 **그 카카오 앱의 REST API 키**입니다. 지도 · 주소 좌표(MAP)도 같은 종류의 키를 씁니다. 그러므로 **지도와 같은 카카오 디벨로퍼스 앱에서 「카카오 로그인」을 켜면 그 REST API 키를 그대로 client_id 로 쓸 수 있습니다.**
2. 그래서 코드는 **`KAKAO_LOGIN_CLIENT_ID` → (비면) MAP 의 `KAKAO_REST_KEY`(운영 화면 값 → .env)** 순서로 읽습니다. 운영 화면 › 간편 로그인에 「카카오맵 REST 키를 다시 씀」으로 표시됩니다.
3. **추천: 같은 앱을 씀**(키 하나 · 관리 한 곳). 다만 앱 하나에 로그인 동의 항목 · Redirect URI · 비즈 앱 전환(이메일 받기에 필요할 수 있음)이 함께 묶이므로, 지도 키를 다른 업무와 나눠 쓰고 싶으면 **새 앱을 만들고 `KAKAO_LOGIN_CLIENT_ID` 만 넣으면** 됩니다.
4. **확인 필요**: 카카오 이메일(kakao_account.email)은 동의 항목 설정 · 비즈 앱 여부에 따라 받을 수 없을 수 있음 — 그때는 이어서 화면이 이메일을 직접 받음. **카카오의 PKCE 지원 · 동의 항목 조건은 2026-11 공개 문서 기준이며 운영 켜기 전 카카오 디벨로퍼스 문서로 다시 확인합니다.**

## 4. 지키는 것(보안 · 정책)
| # | 규칙 | 어디서 |
|---|---|---|
| 1 | state(무작위 32바이트) · PKCE verifier(48바이트)는 서버만 · DB 는 state **지문**만 · 10분 · 한 번(맞든 틀리든 쓰면 끝) | soc_states · callback |
| 2 | 다른 브라우저에서 돌아오면 거절(묶음 쿠키 지문 대조) — 로그인 위조(CSRF) 막음 | callback |

## 6. 업체 콘솔 준비(대표 · 사람)
1. **카카오 디벨로퍼스**: (지도 앱 또는 새 앱) › 카카오 로그인 활성화 › Redirect URI `https://sogaebank.com/login/social/kakao/callback` › 동의 항목(닉네임 · 카카오계정 이메일 — 선택 동의) › (선택) 보안 › Client Secret 켜기 → `KAKAO_LOGIN_SECRET`.
2. **네이버 개발자센터**: 애플리케이션 등록 › 네이버 로그인 › 제공 정보(이메일 · 별명) › 서비스 URL `https://sogaebank.com` · Callback URL `https://sogaebank.com/login/social/naver/callback` → `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET`. 검수(서비스 적용) 전에는 등록한 테스트 아이디만 로그인됨.
3. 운영 화면 › 외부 연동 › 연동 키(SUPER)에 키 넣기 → 운영 화면 › 회원 › 간편 로그인에서 「키 있음」 확인.
4. 사용자 웹 `.env` 의 `SITE_ORIGIN` 이 `https://sogaebank.com` 인지(돌아올 주소 앞부분 · 업체에 등록한 주소와 같아야 함).

## 7. 확인하지 못한 것(운영 켜기 전)
1. 업체 주소 · 칸 이름(kauth/kapi · nid/openapi · `kakao_account.is_email_verified` · `response.email`) — 2026-11 공개 문서 기준 기억값 · **업체 문서로 다시 확인**.
2. 네이버는 PKCE 를 문서에 적지 않음 — 보내도 무시되는 것으로 봄(state + client_secret 로 막음) · 확인 필요.
3. 네이버 이메일은 `@naver.com` 일 때만 「확인된 이메일」로 봄(연락처 이메일은 확인 여부를 알 수 없어서) — 정책 확인 필요.
4. 업체 쪽 「연결 끊기(unlink)」 API 는 부르지 않음(회원 번호 원문을 보관하지 않으므로) — 끊기 안내에 「업체 쪽 연결된 서비스에서도 지울 수 있음」을 적음. 카카오 「연결 끊기 알림(웹훅)」 연동은 다음 후보.
5. 업체 로그인 단추 모양 · 색은 업체 안내서 값을 토큰으로(`--sgb-kakao-*` · `--sgb-naver-*`) — 최신 안내서 확인.

## 8. 오류가 날 때 확인 순서
1. 로그인 화면에 단추가 없음 → `social.kakao/naver` on · 운영 서버면 방식 LIVE · `GET /auth/social/providers`.
2. 돌아온 뒤 「요청이 오래되었거나 다른 브라우저」 → 10분 넘김 · 쿠키 막힘(사생활 보호) · SITE_ORIGIN 과 접속 주소가 다름(쿠키 · redirectUri 불일치).
3. 502 SOCIAL_TOKEN_FAIL → 업체 콘솔의 Redirect URI · client_id · Client Secret(켰는데 키 없음).
4. SOCIAL_PROFILE_FAIL → 동의 항목 · 업체 장애. 운영 화면 › 간편 로그인 「7일 실패 코드」.
