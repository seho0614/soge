### 4-2. RDS 스냅샷 (DB 를 되돌릴 유일한 길)

```
AWS 콘솔 → RDS → 데이터베이스 → sgb-db → 작업 → 스냅샷 생성
이름: sgb-before-v10-50-YYYYMMDD   → 「사용 가능」이 될 때까지 기다림
```

**넘어가기 전 확인 (빠뜨리면 DB 를 되돌릴 길이 없습니다)**

- [ ] RDS → 스냅샷 목록에 `sgb-before-v10-50-YYYYMMDD` 가 있음
- [ ] 상태가 **「사용 가능」**
- [ ] 만든 시각이 4-1 precheck 뒤
- [ ] (지난번 남은 일) `sgb-before-v10-45-20261016` 또는 `sgb-after-v10-45-20261016` 이 있는지도 함께 봄 — 없어도 이번 적용은 진행 가능

앞의 세 칸이 모두 맞을 때만 4-3 의 apply 에서 `yes` 를 칩니다. 아니면 `yes` 가 아닌 아무 값이나 쳐서 멈춥니다(DB 를 건드리지 않음).

### 4-3. 적용

```bash
bash ~/SGB_DevDocker_Integrated_20261002_v10_50/sgb/deploy/aws/apply.sh
#  「스냅샷을 만들었습니까?」 → 소문자 yes
#  기대: 「적용 5 · 기존 136 · 변경감지 0」 → 「마이그레이션 적용 수 = 파일 수 — 141 / 141」
```

apply 는 `.env` · Nginx · 인증서 · 비밀번호 창을 건드리지 않습니다. API 가 90초 안에 뜨지 않으면 전 판(v10.45)으로 스스로 돌아갑니다(DB 는 141 그대로 — 7절).
적용 뒤에도 **로그인은 풀리지 않습니다**(D102 증표 판 번호가 0 에서 시작).

## 8. 되돌리기

| 상황 | 할 일 |
|---|---|
| 화면이 이상함 | `bash ~/sgb/deploy/aws/rollback.sh` — 코드만 v10.45 로. DB 는 141 그대로 둡니다. D099 ~ D103 은 표 · 함수 · 설정을 **더하기만** 해서 v10.45 코드가 쓰지 않습니다. 탈퇴 가드 트리거는 v10.45 에 탈퇴 경로가 없어 걸리지 않습니다(리허설은 하지 않음 — 확인 필요) |
| DB 까지 되돌려야 함 | RDS → 스냅샷 `sgb-before-v10-50-YYYYMMDD` → 복원(새 인스턴스) → `.env` 접속 주소 교체 → `pm2 restart sgb sgb-site sgb-jobs` |
