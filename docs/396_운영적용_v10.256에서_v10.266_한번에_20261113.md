### 4-2. 알아 둘 것

1. **「켜기 전 점검」의 「위험 1」은 정상**입니다 — 운영 본인인증이 시험용(STUB)이라 지금 보상을 켜면 가짜 계정으로 보상을 받을 수 있다는 뜻입니다. **보상은 NICE 연동 뒤 켜기를 권합니다**(점검은 막지 않음).
2. 운영은 보상 규칙이 꺼져 있어 본인인증을 마친 분은 「보상 없음」, 인증 전이면 「본인인증 기다림」으로 나옵니다. 나중에 켜도 이미 인증한 분에게 소급해 주지 않습니다.
3. **보상 시뮬레이션의 원천징수는 어림**입니다(서버 출금과 같은 식 · 한 사람 한 달 몫을 한 번 출금한다고 봄). 실제 세율 · 신고는 세무 확인이 필요합니다.
4. **신청 진행표**의 날짜는 적은 그대로 보여 줍니다(업체에 확인하지 않음). 「신청서 값」은 운영 설정(`footer.*` · `site.base_url` · `infra.egress_ip`)에서 읽습니다 — 틀린 값이 보이면 운영 설정에서 고칩니다.
5. 알림 길 도우미의 「시험 성공」은 **마지막 시험** 기준입니다. 처리방침 1.1 초안(docs/393)은 **문서만**입니다 — 이번 적용으로 약관은 바뀌지 않습니다.
6. 개발 서버 `~/kits/release` 에 다른 판 킷(v10.256 · 258 · 260 등)이 있어도 **v10.266 킷만** 올립니다.

## 5. 되돌리기

| 상황 | 할 일 |
|---|---|
| 화면이 이상함 | `bash ~/sgb/deploy/aws/rollback.sh` → `yes` — 코드만 **v10.256** 으로 돌아갑니다. DB 는 243 그대로 남지만 칸 4개를 더한 것뿐이라 v10.256 코드가 그대로 돕니다(새 칸은 쓰지 않음). 2절의 새 상자 · 표시가 모두 사라지고 「최근 7일 경고 이상」은 옛 셈으로 돌아갑니다 |
| 되돌린 뒤 다시 v10.266 으로 | `bash ~/sgb/deploy/aws/rollback.sh` 를 한 번 더 → `yes`(v10.266 판 폴더가 남아 있음) |
| DB 까지 | 보통 필요 없습니다. 하려면 RDS → `sgb-before-v10-266-YYYYMMDD` 복원 → `.env` 접속 주소 교체 → `pm2 restart sgb sgb-site sgb-jobs` 순서로 합니다. 스냅샷 뒤에 생긴 자료(가입 · 신청 등)는 사라집니다 |
