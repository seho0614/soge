**작성일** 2026-09-03
**전제** 반응형 단일 코드베이스 (C-04 확정) · 73화면 · API 99
**상태** 구현 완료 — 사용자 웹 60파일 · 운영 BO 24파일

---

## 1. 앱 2개

| 앱 | 스택 | 이유 |
|---|---|---|
| **사용자 웹** | Next.js 15 App Router · **SSR** | 매물 노출이 SEO에 걸려 있습니다. CSR이면 리스팅이 검색에 안 잡힙니다 |
| **운영 BO** | Vite + React **SPA** | SEO 무의미. 검수가 병목이라 착수 속도 우선 |

배포도 나눕니다 — `web-api` / `admin-bo` 태스크와 짝을 맞춥니다.

### 왜 하나로 합치지 않는가

BO는 로그인 필수이고 검색 노출이 필요 없습니다. SSR을 얹으면 빌드 시간만 늘고 얻는 게 없습니다. **검수 화면을 빨리 만들어야 하는데** Next.js 라우팅 규칙에 맞추느라 늦어지면 임계 경로가 밀립니다.

## 2. 반응형 — 화면이 하나입니다

C-04 확정으로 `-M10`·`-M30` 화면 ID가 폐기되고 통합 ID로 흡수됐습니다.

| | 반응형 | `m.` 분리 |
|---|---|---|
| 화면 수 | **71** | 90+ |
| PC 문의 단절 | **구조적으로 재발 불가** | 화면 수만큼 반복 |
| SEO | 단일 URL | 정규화 태그 관리 |

**상세 화면이 하나이므로 PC에만 문의 버튼이 없는 상태가 생길 자리가 없습니다.**

### 뷰포트 분기

CSS로만 합니다. 컴포넌트를 나누지 않습니다.

```
< 768px   모바일 — 하단 고정바 노출 · 사이드바 숨김
≥ 768px   태블릿 — 2열 그리드
≥ 1200px  데스크톱 — 3열 · 사이드 필터 상시
```

### ★ 상세 화면 CTA 배치 — 남은 유일한 귀속 구멍

```
[문의하기]   주 동선 · 시각적 우위 · 귀속 안 (INV-2)
[전화하기]   보조 · 하단 · 낮은 대비 · 귀속 밖
```

모바일 하단 고정바가 같은 컴포넌트의 CSS 분기라 **배치가 한 줄로 뒤집힙니다.** 전화가 위로 올라가면 통화가 귀속 밖으로 샙니다.

050 안심번호(B-19)가 붙기 전까지 **이 배치가 유일한 방어**입니다.

## 3. 디자인 방향

### 3-1. 이 제품이 무엇인가

사업자가 다른 사업자에게 거래를 소개하고 소개비를 받는 **B2B 플랫폼**입니다. 금액이 수백만~수억이고, 사용자는 하루에도 여러 건을 훑는 실무자입니다.

소비자 마켓플레이스가 아닙니다. **설레게 만들 필요가 없고, 빠르게 판단하게 만들어야 합니다.**

### 3-2. 판단의 축 세 가지

화면 설계는 이 셋을 얼마나 빨리 읽히게 하느냐입니다.

```
얼마인가    소개비 금액 · 부담 주체
믿을 만한가  사업자 인증 · 성사 실적 · 등록 경과
내 건인가    업종 · 지역 · 등급 매칭
```

### 3-3. 색 5개

| 축 | 값 | 근거 |
|---|---|---|
| 기본 | `#101418` 잉크 / `#FFFFFF` / `#F2F4F6` 면 | 장시간 목록 스캔. 색을 아껴야 금액이 보입니다 |
| 강조 | `#1B4D8F` 감청 | 금융·계약 문서의 관행색 |
| **금액** | `#0F6B4A` 짙은 초록 | **소개비 전용.** 다른 어디에도 쓰지 않습니다 |
| 경고 | `#B3261E` | 반려 · 차단 · 분쟁 |
| **광고** | `#8A6A00` 황토 | **우선노출 라벨 전용** (B-20) |

**관이 셋이라 관별 색을 쓰고 싶어지는데, 그러면 금액과 경쟁합니다.** 관 구분은 색이 아니라 **라벨과 위치**로 하십시오.

### 3-4. 타이포

| 역할 | 값 |
|---|---|
| 본문·UI | Pretendard — 국문 숫자 가독이 좋고 사업자명 한자·영문 혼용에 강함 |
| **금액** | 동일 패밀리 + **`tabular-nums` 필수** |

목록에서 자릿수가 흔들리면 비교가 안 됩니다. 디스플레이용 별도 서체는 두지 않습니다 — **큰 글씨가 필요한 곳은 금액뿐**이고 금액은 장식이 아닙니다.

## 4. 핵심 컴포넌트

### 4-1. 목록 카드

73화면 중 관 랜딩·목록·검색·마이페이지가 모두 이걸 씁니다.

```
┌────────────────────────────────────────────┐
│ [업종]  제목이 여기 두 줄까지                │
│                                            │
│ 소개비 3,000,000원   부담: 매수인            │
│ ─────────────────────────────────────────  │
│ ㈜상호 · 사업자 인증 · 성사 12건   3일 전    │
└────────────────────────────────────────────┘
```

| 규칙 | 이유 |
|---|---|
| **금액이 시각적 정점** | 제목보다 크거나 최소 동등 |
| 신뢰 지표 한 줄 압축 | `owner.verified` · `owner.confirmedDeals` |
| **등급 표시 안 함** | 필터·정렬에만. "브론즈 매물"로 보이면 낙인 |
| 그림자 없음 | 목록이 길어지면 시각적 소음. 구분선으로 충분 |

### 4-2. 광고 카드 — 별도 영역

API가 `promoted` 와 `organic` 을 **분리해 내려줍니다.**

```tsx
<AdSection notice={data.adNotice}>
  {data.promoted.map(x => <Card {...x} adLabel={x.adLabel} />)}
</AdSection>
<List>{data.organic.map(x => <Card {...x} />)}</List>
```

**하나의 배열로 합쳐 렌더하지 마십시오.** 라벨을 빠뜨리면 노출순위 표시 의무 위반이 화면 단에서 발생합니다(전상법 · INV-11).

### 4-3. 상태 배지 — 서버 라벨을 씁니다

```tsx
// ✗ 하드코딩
{status === 'PUBLISHED' ? '노출 중' : ...}

// ✓ 서버가 내려준 것
<Badge tone={codes[domain][status].tone}>{item.statusLabel}</Badge>
```

부팅 시 `GET /codes` 로 라벨 번들을 한 번 받고 로컬에서 씁니다. **"노출 중"을 "게시 중"으로 바꾸는 데 배포가 필요 없습니다.**

### 4-4. 목적지 없는 링크

푸터 약관 5종은 법무 대기라 문서가 없습니다. **숨기지 않습니다.**

```tsx
{link.available
  ? <a href={...}>{link.label}</a>
  : <span className="tbd" title={link.tip}>{link.label}</span>}
```

`.tbd` 는 점선 밑줄 + `cursor: help`. **없다는 사실이 보여야 합니다.**

### 4-5. 스텁 표시

외부 연동이 스텁이면 응답에 `stub: true` 가 옵니다.

```tsx
{result.stub && <Notice>연동 준비 중 — 실제 확인이 이루어지지 않았습니다</Notice>}
```

구 모델에서 **"클릭 즉시 통과"가 실동작처럼 보인 것**이 시연 리스크로 지목됐습니다.

## 5. 상태 관리

| 대상 | 방법 |
|---|---|
| 서버 데이터 | **TanStack Query** — 캐시·재검증·낙관적 갱신 |
| 코드 라벨 | 부팅 시 1회 로드 → Context |
| 인증 | Context (accessToken 메모리 · refresh 쿠키) |
| 폼 | React Hook Form + zod (서버 DTO 와 같은 규칙) |

**전역 스토어를 두지 않습니다.** 서버 데이터가 대부분이고 TanStack Query 가 캐시를 갖습니다. Redux 를 얹으면 같은 데이터가 두 곳에 생깁니다.

### 낙관적 잠금

수정 폼은 `version` 을 hidden 필드로 실어 보냅니다.

```
409 VERSION_CONFLICT → "다른 곳에서 먼저 수정되었습니다" + 다시 불러오기 버튼
```

## 6. 오류 처리

서버가 `{ code, message, field }` 를 내려줍니다.

| 상태 | 처리 |
|---|---|
| 400 | `field` 에 인라인 표시 |
| 403 | 게이트별 유도 화면으로 (아래) |
| **409** | **재시도 버튼 없이** "다시 불러오기" |
| **422** | `message` 를 그대로 표시. 사용자에게 보여도 되는 문장입니다 |

### 403 게이트 유도

| code | 이동 |
|---|---|
| `IDENTITY_REQUIRED` | `SB-HOM-AUT-030` 본인인증 |
| `BUSINESS_REQUIRED` | `SB-MYP-BIZ-020` 사업자 전환 안내 |
| `SUBSCRIPTION_REQUIRED` | `SB-MYP-SUB-020` 업그레이드 |

**한도 초과(`VIEW_QUOTA_EXCEEDED`)는 구독 전환의 가장 강한 순간입니다.** 토스트로 끝내면 매출 기회를 버립니다.

## 7. 타입 · API 연동

```bash
npx openapi-typescript docs/06_openapi.json -o src/api/schema.ts
```

**DTO를 손으로 옮겨 적지 않습니다.** `x-status: NOT_IMPLEMENTED` 인 API 는 스키마가 없으므로 그 화면은 아직 착수 대상이 아닙니다 — **문서가 착수 가능 여부를 알려줍니다.**

```
현재 112 / 112 정의됨 — 전 화면 착수 가능
```

## 8. 파일 규칙

```
app/
  (user)/               사용자 웹
    money/[id]/page.tsx
  components/
    SB-HOM-MCH-010.tsx  ← 화면 ID 를 파일명에
```

**화면 컴포넌트 파일명에 화면 ID를 넣습니다.** 73화면을 소수 인원이 추적하는 유일한 방법입니다. 화면정의서에서 ID로 검색하면 바로 파일을 찾습니다.

## 9. 착수 순서

임계 경로가 검수(T3)이므로 프런트도 거기부터입니다.

| 순서 | 작업 | 주차 |
|---|---|---|
| 1 | 디자인 토큰 · 목록 카드 · 폼 · 배지 · 오류 표시 | W3~W4 |
| 2 | **`ADM-REV-010/020/030` 검수** | **W4~W6** |
| 3 | `AUT-010/020/030` 인증 3종 | W4~W6 |
| 4 | `HOM-REG-010/020` 등록 · 수정 | W6~W8 |
| 5 | 관 랜딩 3 + 목록/상세 | W6~W9 |
| 6 | `MCH-010` 문의 + **CTA 배치 확정** | W7~W9 |
| 7 | `DEL-010/020/030` 계약·신고·성사 | W10~W12 |
| 8 | `MYP-STL-*` 정산 · `SUB-*` 구독 | W12~W14 |
| 9 | ADM 나머지 · 퀵메뉴 · 고객센터 | W12~W15 |

**2번이 1번 다음인 이유** — 검수 화면이 없으면 등록해도 노출이 안 되고, 그 뒤 화면을 실데이터로 볼 수 없습니다.
