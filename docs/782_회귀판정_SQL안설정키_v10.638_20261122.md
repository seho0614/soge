# 782. 회귀 판정 — SQL 글 안 설정 키 · 값 확인 잠금 · 모든 요청에 걸리는 키는 혼자 — v10.638 (2026-11-22)

## 1. 결론

- 11/22 v10.627 ~ 637 전체 점검에서 test_v1104 가 실패했습니다(영어 요청이 원문으로 옴). 원인은 동시 단계에서 같이 돈 **test_v1119** 입니다.
  - test_v1119 는 `psql("UPDATE site_settings SET value='on' WHERE key='i18n.enabled'")` 처럼 **설정 키를 SQL 글 안에** 씁니다. 회귀 판정(reg_classify)은 키를 「따로 떨어진 글자」에서만 찾아, 잠금이 `set:footer · set:legal` 뿐이었고 **`set:i18n` 이 없었습니다**. 그래서 같은 설정을 켰다 끄는 test_v1104 와 동시에 돌았습니다.
  - test_v1093 은 `i18n.enabled = off` 를 **확인만** 해서 PAR(아무와 동시)이었습니다 — 다른 시험이 켜 둔 사이에 돌면 깨집니다.
  - 그날은 「늘 혼자」 손 목록에 5개(1093 · 1104 · 1105 · 1119 · 1296)를 넣어 막았습니다.
- 이번 판부터 규칙이 이것을 스스로 가립니다.
  1. **SQL 글 안 키** — psql 에 넘기는 글이 `site_settings` · `setting_schedules` 를 다루면 그 안의 `'키.이름'`(`key = '…'` · `key IN ('…', '…')` · f-string 고정 부분)을 키로 셉니다.
  2. **SETREAD** — psql 의 `SELECT … FROM site_settings` 로 값을 확인하는 시험도 같은 잠금(`set:앞마디`)을 받습니다. 키를 못 찾은 읽기는 그대로 PAR.
  3. **SETGLOBAL** — 바꾸면 다른 시험의 로그인 · 권한 · 접속이 달라지는 키(`perm.mode` · `perm.enforce` · `admin.mfa_required` · `admin.ip_verify` · `auth.login.*` · `sec2.member_mfa` · `signup.open` · `site.maintenance_from/until` · `security.geo_*` 등)를 바꾸는 시험은 잠금이 아니라 **혼자(SOLO)** 돕니다.
  4. 손 목록은 원래 3줄(1570 · 1420 · 1421)로 되돌렸습니다 — i18n 5개는 모두 `set:i18n` 잠금이라 서로 동시에 돌지 않습니다.
  5. **묶음 실행 `POST /admin/…/run`** (전표 `acct/journal/run` · 은행 `bank-feed/run` · 재주문 · 퇴직금 · BI 등)을 부르는 시험은 잠금 `job` 을 받습니다 — 아래 3절 실패의 원인.
