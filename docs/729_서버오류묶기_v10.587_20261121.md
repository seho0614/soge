# 729. 서버 오류 묶기 (v10.587 · 2026-11-21 · 14차 운영 ③)

> 대표 11/21 「모두 개발진행」. 기존 「서버 오류 30일 기록」(D204 · v10.250 · `ops_server_error_days`)을 **재사용** — 서버 코드(launch-watch · scheduler)는 고치지 않고 DB 트리거로 붙였습니다.

## 1. 결론

- 같은 오류를 **지문**으로 묶어 한 줄로 봅니다 — 지문 = 방법 · 주소(번호 · uuid 지운 모양) · 오류 종류 · 응답 번호 · DB 오류 번호(가린 설명 앞 `[42702]`).
- 묶음마다 **처음 · 마지막 · 모든 횟수 · 난 날 수 · 최근 7일** · 상태(열림 · 확인함 · 알리지 않음 · 고침). 30일 기록이 지워져도 묶음은 남습니다.
- **처음 보는 오류**가 나면 운영 알림 `SERVER_ERROR_NEW`, 「고침」으로 둔 오류가 **다시 나면** `SERVER_ERROR_REOPEN`(둘 다 WARN · 한 시간 10건까지).
- 스위치 `ops2.error_new_alert` 는 **처음 on** — 알리기만 하는 것이고(개인정보 · 돈 · 외부 호출 없음) 꺼 두면 새 오류를 모르기 때문입니다. 끄면 묶기만 합니다.

## 2. 동작

```
API 5xx → (메모리) recordServerError → 10분 launch_watch flushServerErrors
      → INSERT … ON CONFLICT DO UPDATE ops_server_error_days(n 더함)
      → 트리거 trg_ops2_error_group_touch(AFTER INSERT OR UPDATE OF n)
           · 더해진 수(새 줄 n · 고친 줄 NEW.n − OLD.n)를 ops2_error_groups 에
           · 새 지문 → 줄 만들고 SERVER_ERROR_NEW / FIXED 였으면 OPEN 으로 · reopened_n + 1 · SERVER_ERROR_REOPEN
           · MUTED 는 다시 나도 알림 없음 · 한 시간 10건 넘으면 alert_skipped = true
```
- **트리거는 실패해도 오류를 내지 않습니다**(WARNING 만) — 넣기가 실패하면 launch_watch 가 건수를 메모리로 되돌려 다음 10분에 **두 번 세기** 때문.
- 처음 적용 때 이미 있는 30일 기록으로 묶음을 채움(`backfilled = true` · 알림 없음 · 화면에 `*`).
- 같은 (날 · 방법 · 주소 · 종류 · 응답) 줄 안에서 DB 오류 번호가 바뀌면, 그 뒤 더해진 수는 새 번호의 묶음으로 갑니다(30일 기록이 번호를 키로 갖지 않아 생기는 근사 · 화면 설명에 적음).

## 3. 바뀐 것

| 곳 | 내용 |
|---|---|
| DB | 표 `ops2_error_groups`(지문 32자 · 칸 길이는 D204 와 같음) · 함수 `fn_ops2_error_fp` · `fn_ops2_error_group_touch` · 트리거 `trg_ops2_error_group_touch` · 설정 `ops2.error_new_alert`(on) · 기능 스위치 한눈에 한 줄 |
| API | `GET /api/v1/admin/ops2/error-groups?state=&days=`(ADMIN · SUPER · 1 · 7 · 30 · 90 · 365일) · `POST /api/v1/admin/ops2/error-groups/{fp}/state`(ADMIN · SUPER · 감사 `OPS2_ERROR_GROUP_STATE` pick) |
| 화면 | 위험감지 › 서버 오류 아래 「오류 묶음」 상자 `Ops2ErrorGroups`(SB-ADM-OPS-020) · 운영 알림 종류 이름 두 개 |
| 권한(D258) | `perm_route_map` 두 줄 → 업무 `server-errors`(VIEW · EDIT) |

### 상태 바꾸기 오류
| 응답 | 코드 | 까닭 |
|---|---|---|
| 400 | VALIDATION_ERROR | 상태가 OPEN · ACK · MUTED · FIXED 아님 |
| 404 | NOT_FOUND | 지문 형식 아님 · 없음 |
| 409 | OPS2_ERROR_SAME · OPS2_ERROR_CHANGED | 이미 그 상태 · 그 사이 바뀜 |
| 422 | OPS2_ERROR_NOTE | 「알리지 않음」에 까닭 2자 미만 |

## 4. 남기는 것 · 남기지 않는 것

- 남김: 지문 · 방법 · 주소 모양 · 종류 · 응답 · DB 오류 번호 · 가린 설명(D204 maskDetail 결과 그대로) · 요청 번호 · 시각 · 횟수 · 상태 · 메모.
- 남기지 않음: 요청 본문 · 증표 · 회원 · IP. 묶음 줄은 지우지 않음(종류 수가 적음 — 1년에 수백 줄 예상 · 늘면 다음 판에서 보관 기간).

## 5. 시험 — `qa/test_v1587.py`

- ① 코드 ② 30일 기록에 시험 줄(`/api/v1/t1587/…`)을 넣어 묶음 · 알림 · 더하기 · 목록(7일 5) · 고침 → 다시 나면 열림 · 409 · 422 · 404 · 400 · 스위치 off ③ 화면.
- 한 시간 알림이 이미 10건 이상이면 알림 확인은 건너뜀(묶음은 봄). 시험 줄 · 묶음 · 알림은 replica 로 지움.

## 6. 확인할 것

1. 하루 요약 · 주간 알림에 「새 오류 묶음 n」 한 줄 넣기는 다음 판 후보(scheduler 를 고쳐야 해서 이번엔 안 함).
2. 알림이 잦으면 묶음마다 「알리지 않음」을 먼저 — 스위치를 끄면 새 오류도 모릅니다.
