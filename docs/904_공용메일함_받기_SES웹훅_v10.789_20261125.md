# 904. 사내 웹메일 W1-1 — 공용 메일함 받기(SES 받기 → SNS → 웹훅) — v10.789 (2026-11-25)

## 1. 결론

- 설계 docs/902 W1 의 첫 판입니다. **privacy@ · help@ · admin@ · dmarc@sogaebank.com** 으로 온 메일을 소개뱅크 DB 에 받습니다.
- 받는 길: SES 받기 규칙 **S3 작업 하나**(원본 보관 + SNS 주제로 위치 알림) → **`POST /api/v1/webhooks/ses/inbound`**(로그인 없는 공개 주소 · AWS 서명 검사) → 서버가 **S3 에서 원본을 가져와** 풂.
  - ★ SES 받기 규칙에 SNS 작업을 넣으면 **150KB 넘는 메일이 반송**됩니다(AWS 「Publish to Amazon SNS topic action」 · 한도 조정 불가). 그래서 규칙은 S3 작업만 씁니다(한 통 40MB 까지).
  - S3 읽기: 운영 .env `MAIL_S3_ACCESS_KEY_ID` · `MAIL_S3_SECRET_ACCESS_KEY`(그 버킷 `inbound/` GetObject 만) 또는 운영 EC2 인스턴스 역할 — 서명 v4 를 새 패키지 없이(`s3-get.ts`).
  1. 스위치 **`mail.inbound`(처음 off · SUPER)** · 주제 **`mail.inbound_topic_arn`** 하나만 · v10.209 SNS 서명 검사 그대로.
  2. 같은 SES 메시지 번호 + 메일함은 한 줄. S3 에서 가져오지 못하면(설정 전 · 실패) 위치만 남기고, 운영 화면 「S3 에서 가져오기」(`POST /admin/mailbox/messages/{id}/fetch`)로 다시 가져옵니다. SNS 작업 알림(Base64)이 와도 처리합니다(작은 메일 · 시험).
  3. 원본 풀기(MIME)는 **새 패키지 없이**(`src/common/mail/mime-parse.ts`) — EUC-KR · RFC 2047 · multipart · base64 · quoted-printable · RFC 2231 파일 이름.
  4. 15MB 넘는 메일은 첨부를 DB 에 두지 않으려고 **S3 위치만**(화면에 「원본만(S3)」).
  5. 판정(스팸 · 바이러스 · SPF · DKIM · DMARC) 저장 · 스팸 또는 바이러스 FAIL 이면 상태 SPAM.
- 마이그레이션 **D330**(368번째) · 운영 화면은 v10.791.
