# 718. 회원 휴면 계정 (v10.576 · 2026-11-21)

> 대표 11/21 「16개 모두 동시에」 — 11차 회원 · 거래 ④. 스위치 `mtr.dormant` · `mtr.dormant_mail` **처음 off**. **법무 확인 필요 · 회사 선택.**

## 1. 결론

- 마지막 로그인(없으면 가입)부터 **365일**(설정) 동안 로그인하지 않은 회원을 **휴면**으로 바꿉니다. **30일 전**(설정)에 사이트 알림(켜면 메일도) 한 번.
- 휴면이 되면 **이름 · 전화번호를 따로 암호화해 보관**(`pii.mtr_dormant_vault`)하고 회원 표에는 「휴면 회원」 · 전화 비움 · 상태 `DORMANT` · 로그인 증표 무효.
- **로그인하면 바로 풀립니다**(이메일 로그인 · 간편 로그인 · 비밀번호 재설정 링크). 이름 · 전화는 DB 트리거가 되돌립니다. SUPER 도 본인 확인 뒤 풀 수 있습니다(사유 · 감사).

## 2. 법무 확인 필요 — 회사 선택으로 둔 까닭

- 예전 정보통신망법 · 개인정보 보호법은 1년 미이용 회원 정보를 파기하거나 분리 보관하게 했습니다(「개인정보 유효기간제」).
- **2023년 개정 개인정보 보호법(2023-09-15 시행)으로 이 의무 조항은 없어진 것으로 알고 있습니다 — 추가 확인이 필요합니다.** 그래서 이 기능은 법 의무가 아니라 **회사 선택**(보관 최소화 · 계정 도용 줄이기)으로 만들었습니다.
- 켜기 전에 할 일: ① 법무 확인 ② 약관 · 처리방침에 「휴면 기준 · 분리 보관 · 해제 방법」 게시 ③ 기존 회원 안내.

## 3. 재사용 · 새로 만든 것

| 기존 | 쓰는 곳 |
|---|---|
| 탈퇴 유예(v10.376 · D240) | 로그인 때 상태에 따라 다른 길 — 같은 자리(auth.service · social.ts)에 「휴면이면 풂」 한 줄 |
| 탈퇴 유예 전날 메일(v10.378) | 알림 메일 모양(반송 · 수신 거부 주소 뺌 · 메일 준비 안 되면 안 보냄) |
| 개인정보 암호화(`pgp_sym_encrypt` · `fn_enc_key`) · pii 스키마 | 금고 |
| 상태 바뀌면 로그인 풀기(`trg_revoke_on_status`) · `token_version` | 휴면 때 다른 기기 로그인 풀림 |
| 운영 화면 회원 상태 이름(`Members.tsx` DORMANT 「휴면」 — 이미 있음) | 그대로 |

- **회원 상태 CHECK 에 `DORMANT` 를 더했습니다**(`accounts_status_check`). `DORMANT` 로 바꾸는 것은 휴면 함수만(트리거가 막음).

## 4. 빼는 회원(후보 뷰 `v_mtr_dormant_pool`)

운영 역할(ADMIN · SUPER · REVIEWER · PAYOUT · ACCOUNTANT · PARTNER_*) · 진행 중 거래(성사 · 정산 · 취소 전) · 유료 구독 중 · 안심 · 제휴 파트너(신청 · 활동) · 탈퇴 · 파기 · 정지.

## 5. 흐름

1. 매일 04:40 `mtr_daily` — 기준일 - 알림일 지난 회원에게 알림(`MTR_DORMANT_NOTICE` · 메일은 `mtr.dormant_mail`) · `mtr_dormant` NOTICED.
2. 알림 뒤 알림 일수가 지나고 그 사이 로그인 없고 기준일이 지났으면 `fn_mtr_dormant_apply` → DORMANT.
3. 로그인(비밀번호 맞음) · 간편 로그인 · 재설정 링크 → `fn_mtr_dormant_wake` → ACTIVE · 이름 · 전화 되돌림 · 금고 지움 · `MTR_DORMANT_WAKE` 알림 · `mtr_dormant` RESTORED(풀린 길 기록).
4. 한 번에 많아야 500명(알림) · 500명(휴면) · 40초.

## 7. 고친 기존 파일(패치)

- `auth.service.ts` 로그인 · `social.ts` 간편 로그인 — 휴면이면 풂(그 뒤 검사는 그대로).
- `account-security.service.ts` — 재설정 요청은 휴면 계정에도 링크 · 재설정 때 링크가 맞으면 먼저 풂(기존 `fn_password_reset_consume` 은 쓰는 계정만 받아 고치지 않음).

## 8. 한계 · 주의

- 로그인 아이디(이메일)는 회원 표에 남습니다(로그인으로 풀어야 하므로). 배송지 · 사업자 정보 등 다른 표의 정보는 옮기지 않았습니다.
- 휴면 회원 매물은 회원 상태를 보는 화면에서 안 보일 수 있습니다(1년 미접속이라 대부분 이미 만료).
- 운영자가 회원 상태를 직접 바꿔도(정지 등) 트리거가 이름 · 전화를 먼저 되돌립니다(풀린 길 STATUS).
- 휴면 뒤 얼마 지나면 파기할지(예전 법의 「파기」 선택지)는 넣지 않았습니다 — 대표 결정.
