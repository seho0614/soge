# 671. 리뷰 작성 적립 (v10.533 · 2026-11-20)

## 1. 결론
소개몰 **직판 주문을 구매확정**한 회원이 리뷰를 쓰고 그 리뷰가 **보이게(VISIBLE) 되면** ㊲(D267) **적립금 장부에 바로 적립**합니다(주문 하나에 한 번). 사진이 붙은 리뷰는 가산하고, 리뷰를 **지우거나(본인) 가리면(운영 · 반품)** 그 리뷰로 준 묶음의 남은 금액을 **회수**합니다. 처음에는 꺼져 있습니다(`mall.review_points` off · 적립금 `mall.points` 도 켜져 있어야 함). 위치: 운영 **소개몰 › 리뷰 적립**(SB-ADM-SLX-020 · 탭 `slx-review-points`).

| 항목 | 규칙(처음 값 · 정책 › 전체 설정에서 고침) |
|---|---|
| 주는 때 | 리뷰가 VISIBLE 이 되는 순간 — 바로 보이는 리뷰는 쓸 때 · 금칙어로 확인 대기(PENDING)면 운영 「보이기」 때(DB 트리거) |
| 조건 | `mall.points` · `mall.review_points` on · **직판(DIRECT) 주문** · 구매확정 · 확정 뒤 `mall.review_points_days` 30일 안에 쓴 리뷰 · 글 `mall.review_points_min_len` 20자 이상 |
| 금액 | 글 `mall.review_points_text` 500원 + 사진 있으면 `mall.review_points_photo` 500원(가산) · 둘 다 0 ~ 5,000 |
| 한 주문 한 번 | `hlt_review_rewards.order_id` 고유 — 한 주문의 여러 상품 리뷰도 한 번 · **회수된 뒤 다시 써도 다시 주지 않음**(지웠다 쓰기 되풀이 막음) |
| 사진 | 리뷰 쓰기 `photoFileId`(선택) — 올리기를 마친 **본인** 회원 사진(기존 용도 REQUEST_IMAGE · jpg · png 10MB) · DB 트리거 `fn_hlt_review_photo_guard` · 공개 주소 `/health/reviews/{id}/photo`(보이는 리뷰만 · 쓴 사람 · 운영자는 늘) |
| 사진 가산 시점 | 적립하는 순간에 사진이 붙어 있어야 가산(나중에 붙인 사진은 다시 셈하지 않음) |
| 회수 | 지움(본인) · 가림(운영) · 반품(D036 트리거가 가림) · 운영 회수(사유) → 묶음 남은 금액 REVOKE · 이미 쓴 몫은 운영 알림 `MALL_REVIEW_POINT_SHORT` |
| 실패 | 적립 · 회수가 실패해도 **리뷰 쓰기 · 지우기는 막지 않음** — 운영 알림 `MALL_REVIEW_POINT_FAIL` |

## 2. 장부 · 전표 (㊲ 그대로)
- 묶음 근거에 `REVIEW` 하나만 더함(`ck_hlt_point_lot_source` — D267 의 이름 없는 CHECK 를 이름 있는 것으로 바꿔 넓힘 · `ux_hlt_point_lot_review` 주문마다 하나).
- 기록은 `EARN`(사유 「리뷰 작성 적립」 · detail.kind = REVIEW) · 회수는 `REVOKE` — 그래서 전표 **MALL_POINT_EARN(판매촉진비 / 적립금 충당부채) · MALL_POINT_LAPSE(반대)** 가 고치지 않아도 그대로 잡음(sources.ts · journal.ts 패치 없음).
- 적립금 사용 · 소멸 · 30일 전 알림 · 운영 지급 · 회수는 ㊲ 규칙 그대로(유효 기간 `mall.points_valid_days`).
- 회원 알림 `HLT_REVIEW_POINT`(적립 때 · 링크 /my/health/benefits).

## 3. 전체 구조
1. `hlt_reviews.photo_file_id`(새 칸) · 트리거 `trg_hlt_review_photo_guard`.
2. 표 `hlt_review_rewards`(주문 고유 · 리뷰 번호는 리뷰가 지워져도 남김 · 묶음 · 금액 · 사진 · 회수 기록 · 지우지 않음 · 주기 → 회수 한 방향) · 트리거 `trg_hlt_review_reward_guard`.
3. 함수 `fn_hlt_review_reward(review)` · `fn_hlt_review_reward_revoke(review, why, actor)` · 트리거 `trg_hlt_review_reward_ins` · `_upd`(상태가 바뀔 때) · `_del`.
4. 서버 `src/modules/slx/review-points.ts`(보기 · 운영 회수 · 사진) · 리뷰 쓰기 패치(사진 · 응답 `pointAmount` · 목록 `photoUrl`).
5. 운영 화면 `SlxReviewPoints` — 스위치 · 금액 · 최근 30일 적립 · 사진 · 회수 · 기록 100(가린 이름) · 회수 단추(사유).

## 6. 법무 · 확인할 것 · 주의 — **법무 확인 끝(11/20 · 11/21 대표)**
1. **법무 확인 끝(11/20 · 11/21 대표)**: 리뷰 대가 적립은 「대가성 리뷰」 표시 의무(표시광고법 · 추천 · 보증 심사지침 — 「적립금을 받고 쓴 리뷰」 표시) 대상인지 · 표시 문구 · 위치. 지금 상품 화면에는 표시가 없음 — 켜기 전에 정할 것.
2. 별점 · 좋은 리뷰에만 주는 조건은 두지 않음(글 길이 · 사진만) — 조작 리뷰 유도 방지.
3. 회원 화면(site/) 리뷰 쓰기 칸의 사진 올리기 · 「적립 n원」 안내는 「주문 받기」를 켤 때(서버는 준비).
4. 새 파일 용도(REVIEW_IMAGE)를 만들지 않고 기존 회원 사진 용도를 씀 — ㊾(b279 · 매물 동영상)이 같은 때 파일 용도 목록(ck_files_purpose)을 고칠 수 있어 겹치지 않게(NOTES 3절).
5. 처리방침: 새로 모으는 항목은 리뷰 사진(회원이 고른 사진 · 공개) — 「처리방침 고칠 곳」: 소개몰 리뷰 항목에 「사진(선택)」 · 보관 = 리뷰를 지울 때까지(파일은 기존 회원 파일 파기 규칙) · **법무 확인 끝(11/20 · 11/21 대표)**.
