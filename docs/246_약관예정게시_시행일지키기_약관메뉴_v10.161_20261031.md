# 246. 약관 예정 게시 — 시행일 지키기 · 운영 화면 「약관」 메뉴 (v10.161 · 2026-10-31)

> 대표 지시(10/31 「추천 후보 모두다」) — ① 약관 시행일 지키기(예정 게시) ② 운영 화면 「약관」 메뉴 따로 ③ docs 저장소 기록.
> 마이그레이션 **1개(D151)** · 189.

## 1. 왜

| 전(v10.160 까지) | 문제 |
|---|---|
| 시행일을 미래로 넣고 「게시」해도 앞 판이 **그 자리에서 보관**(DB 트리거 `fn_archive_prior_terms` · 서버 publish 둘 다) | 시행일 전인데 앞 판이 사라짐 — 「지금 적용되는 약관」이 없는 날이 생김 |
| `/terms/required` 가 게시된 판이면 바로 요구 → **게시 즉시 재동의 화면** | 이용약관 **제14조**(시행 7일 전 고지 · 불리한 변경 30일 전 · 시행일부터 적용)와 어긋남 — docs/242 §2 #3 법무 질문 |
| 바뀔 약관을 미리 알릴 화면이 없음 | 7일 전 고지를 할 곳이 없음 |

## 2. 바뀐 것

| # | 곳 | 내용 |
|---|---|---|
| 1 | DB **D151** `v_terms_current` | 약관마다 **지금 시행 중인 판** 하나 — 시행일이 지난 게시 판 중 가장 최근 · 없으면(처음 게시) 가장 이른 예정 판 |
| 2 | DB `v_terms_upcoming` | **시행 예정 판**(게시됐지만 시행 전 · 지금 판이 따로 있음) |
| 3 | DB `fn_terms_archive_due()` | 새 판이 시행된 약관의 앞 판을 보관 — 매시간 작업(`expire_badges` 에 붙임) · 게시 · 운영 화면 목록에서 부름 |
| 4 | DB `fn_archive_prior_terms()`(트리거) | 게시하는 순간 앞 **게시** 판을 보관하던 것을 3 으로(시행일이 지난 경우만). 같은 약관의 초안 · 법무 검토 판 보관은 그대로 |
| 5 | DB `v_term_not_agreed` · `fn_privacy_ai_ready()` | 지금 시행 중인 판을 봄 — **AI 켜기 조건도 시행일부터**(처음 게시하는 처리방침은 바로) |
| 6 | DB 설정 `terms.reconsent_before_effective`(기본 off) | **법무가 「게시 즉시 재동의」가 맞다고 하면 on** — 예전처럼 게시하는 즉시 재동의(1 이 가장 최근 게시 판을 고름) · 운영 화면 「약관」 의 스위치 · SUPER만(서버 403 TERMS_SETTING_SUPER) |
| 7 | 서버 `/terms/required` · `/terms/agree` · 가입 · 파트너 약관 · 맞춤형 광고 · 처리방침 판 표시 · 관 점검 수 | `status = 'PUBLISHED'` 대신 `v_terms_current`(예정 판과 앞 판이 함께 게시돼 있어도 한 줄) |
| 8 | 서버 게시 `PATCH /admin/terms/{code}/publish` | 응답 `scheduled` · `archived` · 시행 예정 판은 약관마다 하나(422 `TERM_SCHEDULED_EXISTS`) · 이미 게시된 판 다시 게시 막음(422 `TERM_PUBLISHED` — 시행일 덮어쓰기) · 새 판 시행일은 지금 판 시행일보다 뒤(422 `TERM_DATE_BEFORE_CURRENT` — 앞이면 그날 뒤 옛 판이 다시 지금 판이 됨) |
| 9 | 서버 **새** `PATCH /admin/terms/{code}/unschedule`(SUPER · 감사 `TERM_UNSCHEDULE`) | 시행 예정 판 게시 취소 — 시행일 전 · 그 판 동의 기록 0 일 때만(422 `TERM_NOT_SCHEDULED` · `TERM_HAS_CONSENT`) · 법무 검토로 · 본문 날짜 → 〔시행일〕 |
| 10 | 서버 **새** `GET /terms/upcoming`(공개) | 시행 예정 약관 — 바뀔 글 · 시행일 · 바뀐 점 · 지금 판 번호(전체 회원 대상만) |
| 11 | 운영 화면 「약관」 | 상태 칸 **「시행 예정」** · 줄마다 **「예정 취소」** · 게시 확인 창에 「앞 판은 시행일 전날까지 · 재동의는 시행일부터」 · **제14조 경고**(7일 안 ⚠ · 30일 안 불리한 변경 안내) |
| 12 | 운영 화면 메뉴 | **관 관리 › 약관**(`#/terms` · SUPER) — 법정 고지 맨 아래 구역과 같은 부품 · 같은 명세 SB-ADM-SIT-070 |
| 13 | 사용자 웹 | 시행 예정 약관이 있으면 ① 바닥줄 위 한 줄 「약관 변경 예정: …(시행일) 자세히」 ② 약관 화면(`/terms`) · 동의 화면(`/terms/agree`) 맨 위 「약관이 바뀝니다」 — 펼치면 바뀐 점 · 바뀔 글. 없으면 아무것도 안 그림 · 영어 사전 |

## 3. 흐름 (예: 이용약관 1.0 시행 중 → 1.1 을 12-15 시행으로 게시)

| 날 | 회원이 보는 것 | DB |
|---|---|---|
| 게시한 날 ~ 12-14 | 약관 전문 = 1.0 · 바닥줄 「약관 변경 예정: 이용약관(2026-12-15)」 · 재동의 **없음** | 1.0 게시(지금 판) · 1.1 게시(시행 예정) |
| 12-15 00:00 부터 | 약관 전문 = 1.1 · 로그인하면 **재동의 화면**(1.0 → 1.1 · 바뀐 점) | 1.1 이 지금 판 · 1.0 은 다음 매시간 작업(또는 운영 화면 목록)에서 보관 |
| 게시 뒤 취소하려면 | 시행일 전 · 1.1 동의 0건이면 「예정 취소」 | 1.1 → 법무 검토 · 시행일 없음 · 본문 날짜 → 〔시행일〕 |

## 4. 남은 판단 (법무)

- docs/242 §2 #3 — 지금 코드는 **제14조 문구대로(시행일부터 재동의)**. 법무가 「게시 즉시 재동의」가 맞다고 하면 운영 화면 › 관 관리 › 약관 › 「게시 즉시로 바꾸기(법무 판단 뒤)」(설정 `terms.reconsent_before_effective = on` · SUPER만 · 감사 SITE_SETTING_UPDATE) — 코드 바꾸지 않음.
- 처음 게시(오픈 전 · 앞 판 없음)는 지금처럼 게시 판이 바로 지금 판(가입 동의 · AI 켜기 조건).
