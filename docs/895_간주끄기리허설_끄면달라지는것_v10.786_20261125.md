# 895. 간주 끄기 리허설 — 「간주 모드 끄는 순서」 줄마다 「끄면 달라지는 것」 — v10.786 (2026-11-25)

## 1. 결론

- 대표 결정(11/25): 묶음 6 「간주 모드 끄기 리허설 화면」은 **기존 상자에 덧붙임**(새 화면 없음). 오픈 점검 허브 · 오픈 체크리스트 「간주 모드 끄는 순서」(v10.315 · docs/439)와 겹치는 「끌 수 있나」는 그대로 두고, 빠져 있던 **「끄면 무엇이 달라지나」**만 더했습니다.
- 위치: 운영 화면 › **오픈 체크리스트** › 「관리자 스위치」 바로 위 **「간주 모드 끄는 순서」** › 줄마다 맨 오른쪽 칸 **「끄면 달라지는 것 — 간주 기록 N건」**(누르면 펼침).
- 펼치면 네 가지가 나옵니다. 모두 **읽기만**이고 아무것도 끄지 않습니다.
  1. **연결 어댑터** — 끄면 부르게 되는 연동과 실제 구현 여부(REAL · STUB · NONE · `src/common/integration/registry.ts`) · 외부 연동 상태
  2. **바뀌는 동작** — 예: 결제가 시험 승인 대신 토스페이먼츠 실제 승인 · 소개몰 하위가맹점 자동 등록(시험 번호) 막힘
  3. **간주로 남은 기록** — 끈 뒤 다시 보거나 정리할 것의 건수
  4. **끈 뒤 할 일**과 **경고**(어댑터가 REAL 이 아님 · 외부 연동이 시험 중 · 연결됨이 아님 → 서버가 끄기를 막음)

| 간주 | 어댑터 | 세는 기록 |
|---|---|---|
| 수금 계좌 | — | 수금 계좌가 시험용 값 · 빈칸이면 1 |
| 중개사 | BROKER(REAL) | `v_broker_verified_assumed`(실제 대조 없이 승인 · 재대조 대상) |
| 세금계산서 | ETAX(REAL) | `etax_status` 칸이 있는 표 모두 — 간주 발행(승인번호 없음) |
| 결제 | PG(REAL) | 구독 청구 `is_stub` · 소개몰 결제 `stub` · 리드 캐시 충전 `stub` · 하위가맹점 `STUB-SUB-…` · 지급 요청 `stub` |

- 고침: 앞서 「BANK · BROKER 어댑터가 STUB」이라고 말씀드린 것은 틀렸습니다. 연동 표(registry.ts) 기준으로 **BANK(1원 계좌인증) · BROKER · ETAX · PG 는 REAL**, **STUB 는 PASS(본인인증) · ALIMTALK(알림톡) · SAFENUM(050) · ESIGN(전자계약)**입니다. 결제 줄의 경고는 「하위가맹점 · 지급대행 실제 연동은 결제대행사 계약 뒤」입니다.
