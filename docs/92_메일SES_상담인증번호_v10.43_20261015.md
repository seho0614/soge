## 6. SES 도메인 인증 (AWS 콘솔)

1. 콘솔 오른쪽 위 지역을 **아시아 태평양(서울) ap-northeast-2** 로 바꿉니다.
2. Amazon SES → 「자격 증명(Identities)」 → 「자격 증명 생성」
   - 유형: **도메인** · 이름: `mail.sogaebank.com`
   - 「사용자 지정 MAIL FROM 도메인 사용」 체크 → `bounce.mail.sogaebank.com`
   - DKIM: **Easy DKIM** · RSA 2048 비트
3. 만들면 DNS 레코드 표가 나옵니다(DKIM CNAME 3줄 · MAIL FROM 의 MX · TXT). **그 값을 그대로** 7절처럼 가비아에 넣습니다.
4. (샌드박스 동안 시험용) 「자격 증명 생성」 → 유형 **이메일 주소** → 시험받을 내 주소 → 받은 메일의 확인 링크를 누름

## 7. 가비아 DNS 레코드

가비아 → My가비아 → 도메인 → `sogaebank.com` → **DNS 정보 → DNS 설정**. 「호스트 이름」 칸에는 `sogaebank.com` 을 **빼고** 적습니다.

| # | 타입 | 호스트 | 값 | 용도 |
|---|---|---|---|---|
| 1 ~ 3 | CNAME | `xxxx._domainkey.mail` (SES 표 그대로 3줄) | `xxxx.dkim.amazonses.com` | DKIM 서명 |
| 4 | MX | `bounce.mail` | `10 feedback-smtp.ap-northeast-2.amazonses.com` | 반송 받기(MAIL FROM) |
| 5 | TXT | `bounce.mail` | `v=spf1 include:amazonses.com ~all` | SPF(MAIL FROM) |
| 6 | TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@sogaebank.com` | DMARC — 처음 2 ~ 4주는 `p=none` 으로 보고만 받고, 문제없으면 `quarantine` |
| 7 | MX | `@` | 회사 메일함 서비스가 알려 주는 값(Google Workspace 면 `1 smtp.google.com`) | **회사 메일 받기** — 메일함 서비스를 정한 뒤 |

- ⚠ 4 · 5 의 값은 **SES 표에 나온 값이 우선**입니다(위는 서울 지역의 흔한 값).
- ⚠ 가비아 「호스트 이름」에 `xxxx._domainkey.mail.sogaebank.com` 을 통째로 넣으면 `…sogaebank.com.sogaebank.com` 이 됩니다. 10/12 www · admin 을 잘못 넣은 것과 같은 실수이니 주의하십시오.
- `@` 의 SPF(`v=spf1 include:_spf.google.com ~all` 등)는 회사 메일함을 정한 뒤 그 서비스 안내대로 넣습니다. 서비스 메일은 `mail.` 하위 도메인이라 서로 섞이지 않습니다.
- 넣은 뒤 확인(PC PowerShell):
  ```powershell
  Resolve-DnsName -Type TXT _dmarc.sogaebank.com
  Resolve-DnsName -Type MX  bounce.mail.sogaebank.com
  ```

## 8. SMTP 자격 증명 · 운영 .env · 켜기

1. SES → 「SMTP 설정」 → 「SMTP 자격 증명 생성」 → IAM 사용자 이름(예: `ses-smtp-sogaebank`) → 만들기
   - **사용자 이름 · 비밀번호는 이 화면에서 한 번만 보입니다.** 내려받은 CSV 를 안전한 곳에 두고, 메신저 · 메일 · 채팅에 붙이지 마십시오.
   - 이것은 SMTP 전용 값입니다. IAM 액세스 키와 다릅니다.
2. 운영 서버(ubuntu)의 `~/sgb/.env` 에 넣습니다(sgbdev · Claude 는 이 파일을 보지 않습니다).
   ```
   SMTP_HOST=email-smtp.ap-northeast-2.amazonaws.com
   SMTP_PORT=465
   SMTP_USER=(CSV 의 사용자 이름)
   SMTP_PASS=(CSV 의 비밀번호)
   MAIL_FROM_NAME=소개뱅크
   ```
   → `pm2 restart sgb --update-env` (적용 절차서 순서대로)
3. 서버에서 SES 465 로 나갈 수 있는지(EC2 보안 그룹 아웃바운드가 기본값이면 열려 있음):
   ```bash
   timeout 5 bash -c '</dev/tcp/email-smtp.ap-northeast-2.amazonaws.com/465' && echo OK
   ```
   ※ EC2 의 25번 포트 제한은 465 와 관계없습니다.
4. 운영 화면 → 사이트 설정 → `notify.mail_from` = `no-reply@mail.sogaebank.com`
5. 시험: 상담 신청 화면에서 **SES 에 인증한 내 주소**로 신청 → `notify.email_verified` 가 아직 off 라 「준비 중」이 맞음 → 운영 화면에서 `notify.email_verified = on` → 다시 신청 → 메일이 **받은편지함**(스팸함 아님)에 오는지, 보낸 사람이 「소개뱅크 <no-reply@mail.sogaebank.com>」인지 확인
6. 받은 메일 「원본 보기」에서 `spf=pass` · `dkim=pass` · `dmarc=pass` 확인 → 하나라도 fail 이면 **바로 off** 하고 7절 레코드를 다시 봅니다.

### 잘 안 될 때 확인 순서

| 증상 | 확인 |
|---|---|
| 상담 신청이 계속 「준비 중」(`NOTIFY_NOT_READY`) | ① `.env` 에 SMTP_HOST · USER · PASS ② `notify.mail_from` 또는 MAIL_FROM ③ `notify.email_verified = on` ④ `pm2 restart … --update-env` 했는가 |
| `OTP_SEND_FAILED` | `pm2 logs sgb` 의 `[Mail] 보내지 못함 … AUTH`(자격 증명) · `REJECTED`(샌드박스 · 인증 안 된 주소 · 발신 도메인) · `TIMEOUT` · `NETWORK`(465 아웃바운드) |
| 메일이 스팸함으로 | 6단계 `spf · dkim · dmarc` 결과 · 가비아 호스트 이름 중복(`.sogaebank.com.sogaebank.com`) |
