# 383. 운영 적용 기록 · 하루 요약 「대표 할 일」 줄 · 「적기」 지난 기록 — v10.244 ~ v10.246 (2026-11-12)

> 대표 「다음개발」 → 후보 3가지 「모두」 → 계획 「승인 + 통과하면 병합」(11/12).
> **마이그레이션 D202 하나(239 → 240)** — 표 하나 더함 · 지우는 것 없음 · 스위치 · 설정 값을 바꾸지 않음 · **적용 스크립트(apply · precheck · postcheck · rollback) 바뀌지 않음** · 사용자 웹 바뀌지 않음.

## 1. 왜

운영 판은 운영 서버 파일(`~/sgb/VERSION`)로만 알 수 있어, 언제 어떤 판을 올렸는지 · 되돌렸는지가 운영 화면에 남지 않았습니다(인계 메모 · 절차서에만 사람이 적음). 또 v10.240 「대표 할 일」 카드는 첫 화면을 열어야만 보였고, v10.241 「적기」는 가장 최근 줄만 보여 앞 기록을 볼 수 없었습니다.

### 알아 둘 것

1. **첫 기록은 v10.244 이상 판이 운영에서 처음 뜰 때** 생깁니다(FIRST · 앞 판 없음). 그 전 적용 이력(v10.236 · v10.240 등)은 인계 메모에만 있습니다.
2. apply 가 **교체 전에 멈추면**(빌드 실패) 새 판 API 가 뜨지 않아 줄이 생기지 않습니다 — 지금 판 그대로라 맞는 기록입니다.
3. rollback 하면 옛 판 API 가 뜨는데, **옛 판(v10.243 이하)에는 이 기능이 없어** 되돌림 줄이 생기지 않습니다. 다시 v10.244 이상으로 올라올 때 「앞 판」은 마지막으로 적힌 판입니다(그 사이 되돌림은 빠짐). v10.244 이상끼리 되돌리면 BACK 줄이 생깁니다.
4. postcheck 결과 파일 시각은 **운영 서버 시각**(파일 이름)입니다 — 운영 서버가 UTC 면 한국 시각보다 9시간 이릅니다. 기록 줄 시각은 한국 시각입니다.
5. 결과 파일은 `cleanup.sh` 가 오래된 것부터 지울 수 있습니다 — 파일이 없으면 「결과 파일 없음」으로 나오고 다른 것은 그대로입니다.
