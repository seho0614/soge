# 582 근태(출퇴근) — v10.445 (D259 · 2026-11-20)

> 대표 11/20 「다음개발」 ㉖ 인사 2. 직원이 운영 화면에서 출근 · 퇴근을 누르고, 관리자가 달마다 확인합니다.

## 1. 결론
- 직원(회계 › 인사 › 급여의 직원 대장)을 **운영 계정에 연결**(SUPER)하면, 그 직원이 **사무 › 내 인사**에서 「출근」 · 「퇴근」을 누릅니다.
- 관리자(ADMIN · SUPER)는 **회계 › 인사 › 근태**에서 달 집계를 보고, 잘못 누른 시각을 **사유와 함께 고치고**, 달 끝에 **확인**합니다(확인 뒤 못 고침).

## 2. 정확한 위치
| 할 일 | 위치 |
|---|---|
| 직원 ↔ 계정 연결 | 운영 화면 **회계** › 하위 묶음 「인사」 › 탭 **「근태」** › 표 「계정 연결」 칸(SUPER) |
| 출근 · 퇴근 | 운영 화면 **사무** › 탭 **「내 인사」** › 상자 「오늘」 |
| 시각 고침 · 빠진 날 | 회계 › 「인사」 › 「근태」 › 날마다 표 「고침」 · 상자 「빠진 날 넣기」 |
| 달 확인 | 회계 › 「인사」 › 「근태」 › 「달 확인」 단추 |

## 3. 규칙
1. 하루 한 줄(직원 · 날짜). 출근 두 번 · 퇴근 두 번은 409.
2. 퇴근은 24시간 안 가장 최근 출근 줄에 붙음(밤샘 근무).
3. 「늦음」 = 설정 `hr.work_start`(처음 09:00 · 한국 시각) 뒤 출근.
4. 시각 고침 · 빠진 날 넣기는 **관리자 · 사유 2자 이상 · 본인 줄은 안 됨(HR_SELF)** · 앞뒤 시각이 고침 기록에 쌓임.
5. DB 가 막음: 지우기 · 직원 · 날짜 바꾸기 · 확인한 줄 고치기 · 고침 기록 없는 시각 바꾸기.
6. 세무사(ACCOUNTANT)는 근태를 보지 못함(/admin/hr 아래).

## 4. API
| 방법 | 주소 | 권한 |
|---|---|---|

## 5. DB
- `acct_employees.account_id`(한 계정 = 한 직원) · `acct_attendance`(하루 한 줄) · `acct_attendance_fixes`(쌓기만) · 설정 `hr.work_start`.
