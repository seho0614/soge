# 233. 오픈 날 사고 막는 서버 잠금 2개 — v10.153 (2026-10-30)

> 오픈 전체 리허설(docs/228 4절)의 **발견 5**(본인인증 NICE 를 키 확인 없이 켜면 모든 가입이 막힘)와 **발견 2**(세금계산서 간주를 업체 설정 없이 끄면 발행이 멈춤)는 지금까지 오픈 날 순서표(사람)에만 기댔습니다.
> 대표 「진행」(10/30) → v10.151 처리방침 확인(docs/231)과 같은 모양으로 **서버가 막고, 막을지는 최고 관리자가 운영 화면에서 정함**.
> 앞 판: v10.152(docs/232) · **마이그레이션 D146 하나(184)** · 설정 2개 · API 1개.
> 운영 적용은 v10.152(docs/232)를 먼저 하고, 이 판은 **그다음 운영 적용 때** 함께 올립니다(연동 업체가 정해지기 전에는 NICE · 세금계산서를 켤 일이 없음).

## 1. 결론

| 설정 | 처음 값 | 켜져 있을 때 서버가 거절하는 것 | 오류 |
|---|---|---|---|
| `identity.require_check` 「NICE 바꾸기 전 키 확인」 | **on** | 본인인증 방식(identity.provider)을 **NICE** 로 바꾸기 — 최근 7일 안 「NICE 키 확인」 성공(스텁 아님)이 없으면 | 422 `IDENTITY_CHECK_FIRST` |
| `etax.require_config` 「간주 끄기 전 설정 확인」 | **on** | 전자세금계산서 간주(assume.etax) **끄기** — 업체 주소 · 키(`ETAX_URL` · `ETAX_KEY`)가 없으면 | 422 `ETAX_CONFIG_FIRST` |

- 꺼져 있으면(off) 지금처럼: NICE 는 키 3개만, 세금계산서 간주 끄기는 연동 상태(TESTING · LIVE)만 봅니다.
- 바꾸기는 **최고 관리자(SUPER)** 만 — 운영(ADMIN)은 403 `INTEG_SETTING_SUPER`. 끌 때 확인 창 · 감사 기록(SITE_SETTING_UPDATE).
- **되돌리는 쪽은 언제나 됩니다** — 본인인증 STUB 로 되돌리기 · 세금계산서 간주 다시 켜기. 문제가 생기면 바로 되돌릴 수 있게(v10.65 스위치 원칙과 같음).
- 이미 NICE 이거나 간주가 꺼진 상태는 건드리지 않습니다(바꾸는 순간만 봄).

## 2. NICE 키 확인 (새 API)

| 항목 | 내용 |
|---|---|
| API | `POST /api/v1/admin/identity/nice-check` — SUPER · 감사 `INTEG_TEST_NICE` |
| 하는 일 | NICE **기관 토큰 · 암호화 토큰만** 받아 봄(docs/214 ① ②). 표준창을 띄우지 않아 **회원 · 요금과 상관없음** |
| 결과 | `integration_tests` 에 본인인증(PASS) · `NICE_TOKEN` 한 줄 — 성공 · 까닭(NOT_CONFIGURED · AUTH · TIMEOUT · NETWORK · UPSTREAM · HTTP_4XX · BAD_RESPONSE) · 키 값은 남기지 않음 |
| 근거 | 최근 7일 안 성공한(스텁 아닌) 줄 — 결제 · 계좌를 LIVE 로 올리는 규칙(docs/220)과 같은 기간 |
| 운영 화면 | 외부 연동 › 본인인증 — 「NICE 키 확인」 단추 · 마지막 확인 결과 · 「NICE 바꾸기 전 키 확인 — 켜짐 / 꺼짐」 줄. 잠금이 켜져 있고 7일 안 성공이 없으면 NICE 단추가 잠김 |
| 주의 | 키 확인 전에 보관하던 기관 토큰을 버리고 지금 키로 새로 받음(비밀값만 바꾼 경우도 확인됨). NICE 는 **발신 IP(3.37.95.217) 등록**이 있어야 연결됩니다 |
