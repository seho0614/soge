# 318. 하루 요약 텔레그램 · 운영자 낯선 로그인 알림 · 약관 법무 검토 묶음 — v10.201 (2026-11-06)

> 계기: 운영 v10.200 적용(docs/317) 뒤 대표 「다음 개발 모두」 → 후보 3가지 「모두」.
> - 운영 메일이 준비되지 않아(NO_SMTP) 하루 요약(`launch_digest`)이 매일 만들어져도 아무에게도 가지 않음
> - 11/6 「주문 받기」를 누가 켰는지 잡지 못함 · 운영자 2단계 인증은 꺼진 채 — 운영 계정의 낯선 곳 로그인을 알릴 장치가 없음
> - 오픈 차단 21건 중 10건(약관 6 · 바닥줄 4)이 약관 게시에 달림 — 초안 9개를 법무에 한 번에 보낼 방법이 없음
>
> **마이그레이션 1개(D179 · 216 → 217)** · 새 API 1개(SUPER).

## 1. 바뀐 것

| # | 무엇 | 내용 |
|---|---|---|
| 1 | 하루 요약 텔레그램 | 하루 요약 작업(매일 09:00)이 메일 다음에 **급한 알림과 같은 대화방**으로 한 통(하루 요약 글 + 「오픈 차단 N건」 줄). 메일과 따로 — 메일이 준비 안 돼도 감. 설정 `ops.telegram_digest`(on · 운영 알림 화면 「하루 요약 끄기 / 받기」 · SUPER). 꺼짐 · 준비 안 됨 · 실패는 다시 보내지 않고 하루 요약 알림 기록(`DAILY_DIGEST` detail `pushed` · `pushReason`)에만 |
| 2 | 운영자 낯선 로그인 | 운영 역할(SUPER · ADMIN · REVIEWER · PAYOUT · PARTNER_MAL · PARTNER_AFF) 계정의 성공 로그인이 **지난 30일 그 계정 로그인에 없던 IP 대역(앞 두 마디) 또는 브라우저 종류**이거나 30일 만의 첫 로그인이면 운영 알림 `STAFF_LOGIN_NEW`(경고). **급한 알림 대상** — 메일 · 텔레그램으로 10분 안(같은 종류 1시간에 1통). 제목에 이메일 앞 두 글자 · 역할 · IP 대역 · 브라우저 · 까닭. 회원 로그인 · 실패 로그인은 남기지 않음. 설정 `ops.staff_login_alert`(on). DB 트리거(`login_history`)라 로그인 길이 늘어도 빠지지 않음 · 알림을 못 남겨도 로그인은 그대로 |
| 3 | 약관 법무 검토 묶음 | 운영 화면 › 사이트 기본 정보 · 법정 고지 › 약관 「**법무 검토용 내려받기**」 → HTML 한 파일. 약관마다 가장 높은 번호의 게시 안 된 판(초안 · 법무 검토)을 **지금 시행 중인 게시판과 줄 단위로 비교**(초록 = 더한 줄 · 빨강 = 뺀 줄) · 남은 〔미확정〕 노란 표시 · 막힌 까닭 · 고친 까닭 · 확인 칸. 읽기만 · 바깥 글꼴 · 그림 · 스크립트 없음(브라우저로 열고 PDF 로 인쇄). **검토를 돕는 자료일 뿐 법적 적정성 판단은 법무** |

## 3. DB (D179)

1. 설정 `ops.staff_login_alert` · `ops.telegram_digest`(둘 다 on · ADMIN · `^(on|off)$`)
2. `fn_staff_login_watch()` + 트리거 `trg_staff_login_watch`(login_history AFTER INSERT) — 알림 시각은 `clock_timestamp()`(`ops_alerts` 의 (종류, 시각) 유일 제약에 한 거래 안 두 로그인이 겹치지 않게)
3. `fn_ops_alert_mail_pending()` · `fn_ops_alert_push_pending()` — 대상에 `STAFF_LOGIN_NEW` 더함(나머지 기준은 D177 · D178 그대로)
4. 지우는 문장 없음 · 재실행 안전 · **이미 있는 로그인 기록은 건드리지 않음** — 적용 뒤 운영 계정마다 지난 30일 기록과 다른 곳에서 처음 로그인할 때 한 번씩 알림이 날 수 있음(정상)
