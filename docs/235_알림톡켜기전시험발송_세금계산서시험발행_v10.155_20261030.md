## 1. 결론

| 잠금 | 처음 값 | 켜져 있을 때 서버가 거절하는 것 | 오류 |
|---|---|---|---|
| `alimtalk.require_test` 「알림톡 켜기 전 시험 발송 확인」(새 설정) | **on** | 알림톡 켜기(`notify.alimtalk_ready` = on) — 최근 7일 안 **지금 방식(MOCK · HTTP)으로 성공한 시험 발송**이 없으면 | 422 `ALIMTALK_TEST_FIRST` |
| `etax.require_config` 「간주 끄기 전 확인」(D146 · 뜻을 넓힘) | **on** | 세금계산서 간주(`assume.etax`) 끄기 — ETAX_URL · ETAX_KEY 가 없으면(그대로 `ETAX_CONFIG_FIRST`) · **최근 7일 안 「세금계산서 키 확인」 · 「시험 발행」 둘 다 성공이 없으면** | 422 `ETAX_TEST_FIRST` |

- 방식 · 키 · 승인 템플릿 검사(`ALIMTALK_NOT_READY`)는 그대로 먼저 봅니다.
- 알림톡 시험은 **지금 방식으로 보낸 것만** 근거입니다 — 점검판 MOCK 성공이 대행사(HTTP) 근거가 되지 않습니다. 방식을 바꾸면 다시 시험합니다.
- 잠금 바꾸기는 **최고 관리자(SUPER)** 만(`alimtalk.*` · `etax.require_config`) — 끌 때 확인 창 · 감사 기록.
- **되돌리는 쪽은 언제나 됩니다** — 알림톡 끄기 · 세금계산서 간주 다시 켜기. 이미 켜져 있거나 꺼진 값은 건드리지 않습니다.

## 2. 세금계산서 키 확인 · 시험 발행 (새 API)

| 항목 | 내용 |
|---|---|
| API | `POST /api/v1/admin/integ-tests/etax-test` — SUPER · 감사 `INTEG_TEST_ETAX` · 하루 `integ.etax_test_daily`(3)번(실제로 보낸 것만 셈) |
| ① 키 확인 | **운영 주소(ETAX_URL · ETAX_KEY)** 에 없는 문서 번호를 조회 — 404 = 키가 맞음 · 401/403 = 틀림. **발행 없음** |
| ② 시험 발행 | **업체 시험 주소(ETAX_TEST_URL)** 로 1건 — 공급자 = 공급받는 자 = 운영 법인(footer.company_name · footer.biz_reg_no) · 1,000원 + 부가세 100원 · 품목 「소개뱅크 연동 시험 발행(업체 시험 환경)」. 키는 `ETAX_TEST_KEY`, 없으면 `ETAX_KEY` |
| 성공 | 업체가 국세청 승인번호 24자리를 돌려줌(`SENT`). 접수만 하면(`PENDING`) 실패로 두고 다시 시험 |
| 안 보내는 경우 | 시험 주소 없음(`NOT_CONFIGURED`) · **시험 주소가 운영 주소와 같음(`SAME_URL` — 실제 세금계산서가 나가므로)** · 공급자 정보 없음(`SUPPLIER`) |
| 기록 | `integration_tests`(ETAX · `ETAX_KEY` / `ETAX_TEST_ISSUE`) 두 줄 — 키 값은 남기지 않음 |
| 운영 화면 | 외부 연동 › 결제 · 계좌 연결 확인 — 세금계산서 줄 4개(주소 · 키 / 시험 주소 / 키 확인 7일 / 시험 발행 7일) · 「세금계산서 키 확인 · 시험 발행」 단추 · 잠금 줄 |
| 업체 형식 | 요청 · 응답은 `etax.http.ts` 의 **중립 형식(자리표시)** 그대로 — 업체가 정해지면 그 파일만 업체 형식으로 바꾸면 시험 발행도 같이 맞춰집니다(시험 환경 모양이 다르면 그때 고침) |

## 5. 하지 말 것
- `ETAX_TEST_URL` 에 운영 주소를 넣지 마십시오 — 서버가 같은 주소는 막지만, 주소 모양만 다른 운영 주소는 구별하지 못합니다(실제 세금계산서가 나감).
- 운영에서 잠금을 끄고 켜거나 끄지 마십시오 — 끄는 것은 업체 장애로 시험이 안 되는데 꼭 바꿔야 하는 경우만(감사 기록에 남음).
- 시험을 오픈 전날보다 너무 일찍 하면 7일이 지나 다시 해야 합니다.
