# 88. 리팩토링 — 코드 구조만 · 동작 그대로 — v10.39 (2026-10-13 · 대표 지시 「리팩토링」 → 「코드 구조만」)

> 바탕 v10.38. 범위: **코드 구조만**입니다. 화면 글 · 시안 글 · 규칙은 바꾸지 않았습니다.
> 응답이 바탕 v10.38 과 같은지는 두 판의 API 를 같은 DB 에 나란히 띄워 대조했습니다(7절).

## 1. 결론

세 가지를 정리했습니다. **화면 · API 응답 · 막히는 규칙은 바탕 v10.38 과 같습니다.**

1. **「내 파트너 · 내 신청 줄 찾기」를 한 곳으로 모음** — `PartnerActorService` 새 파일 하나.
2. **쓰지 않는 사업자 게이트 코드를 뺌** — P2P(v10.37) 뒤 어디서도 나오지 않는 `BUSINESS_VERIFIED` · `BUSINESS_REQUIRED`.
3. **통과만 하던 DB 판매 게이트를 뺌** — 트리거 3개와 함수 2개(D097).

## 2. 왜

| 문제 | 영향 |
|---|---|
| 같은 조회 SQL이 서비스 7곳(파트너 · 파트너센터 · 리드 이용료 · 노출 · 제휴 · 축 입점 · 소개창업)에 12번 따로 적혀 있음 | v10.38 처럼 규칙이 바뀌면 여러 곳을 같이 고쳐야 하고, 한 곳을 빠뜨리면 화면마다 판정이 달라짐 |
| 사업자 게이트 코드 · 안내 표가 남아 있음(나오지 않는 오류 코드) | 「사업자만」 규칙이 아직 있는 것처럼 읽힘 · 새로 쓰면 P2P 를 어김 |
| 매물 저장마다 「통과만」 하는 트리거 3개 | 일은 없는데 「사업자만 판매」가 DB 에 있는 것처럼 보임 |

## 3. 바뀐 구조

### ① PartnerActorService (`sgb/src/modules/partner/partner-actor.service.ts`)

| 메서드 | 하는 일 | 쓰는 곳(전에는 각자 SQL) |
|---|---|---|
| `forMember(계정)` | 대표 또는 합류한 직원의 파트너 · 대표 것 먼저 | 파트너 홈 · 서비스 · 리드(partner.service) · 파트너센터(partner-center.service) · 리드 이용료(lead-cash.service) |
| `ownedId(계정, 활동 중만)` | 대표 본인의 파트너 번호 · 최근 승인 먼저 | 법률 · 세무 노출(directory.service) · 제휴 영업(affiliate.service — 활동 중만) |
| `actor(계정, 만들기)` | 신청이 붙는 줄 · 활동 자격 · 개인 여부(DB `fn_actor_business` · `fn_actor_ok`) | 입점 · 공인중개사(partner.service) · 축 입점(consult.service) · 인력대행 회신(biz-axis.service) |

각 자리는 **전에 내보내던 칸만 그대로** 돌려줍니다. 예: 파트너 홈 응답에는 직원 정산 권한 칸이 섞이지 않습니다.

### ② 뺀 코드 — 나오지 않던 것

| 곳 | 뺀 것 |
|---|---|
| API `core/auth.ts` | 게이트 종류 `BUSINESS_VERIFIED`와 그 판정(쓰는 API 0) |
| API 설명(OpenAPI) | 문의 · 요청 제안의 막힌 이유 목록, 내 요약 예시, 소개창업 올리기 403 설명에서 `BUSINESS_REQUIRED` |
| 사용자 웹 | 상세 · 문의 · 대화의 `BUSINESS_REQUIRED` 안내 표와 분기, 막힌 이유 타입, 제휴 신청 오류 분기 |
| 운영 화면 | 오류 안내 표의 `BUSINESS_REQUIRED` 줄 |
| 이름 | 파트너센터 화면 변수 `bizOk` → `actorOk`(본인인증 또는 사업자 인증) |

### ③ D097 (`sgb/prisma/migrations/D097_drop_passthrough_seller_gates/migration.sql`)

- `trg_listing_seller_gate`, `trg_listing_business_gate`, `trg_listing_business_gate_u`와 `fn_listing_seller_gate`, `fn_listing_requires_business`를 뺍니다.
- 인증이 필요한 등록의 게이트는 그대로입니다: 보험 · 의료 자격, 부동산(공인중개사 · 소유 확인), 제한업종, 안심소개 입점 승인.
- `item_types.requires_business` 칸은 자료라 그대로 둡니다(읽는 곳 없음 · 참고 값).
