## 1. 결론

| 번호 | 무엇 | 결과 |
|---|---|---|
| 1 | 재동의 흐름(운영 화면에서 새 판 게시 → 기존 회원) | **정상** — 게시하면 앞 판 보관 · 회원은 「옛 판에 동의함 · 새 판 미동의」 · 로그인하면 동의 화면 · 체크하고 동의하면 다음 화면 · 동의 기록은 옛 판 · 새 판 두 줄로 남음(sgb-infra `qa/test_v1159.py`) |
| 2 | **고침 — 새 판이 앞 판의 대상 · 알림을 잃던 것** | 「고치기」로 만든 새 판이 기본값(전체 회원 · 동의 항목)으로 만들어졌음 → **파트너 이용약관 새 판을 게시하면 모든 회원에게 동의를 받고, 위탁 안내 새 판은 동의 항목이 될 수 있었음**(v10.157 부터 · 운영에는 아직 없음). 이제 `audience` · `is_notice` 를 앞 판에서 이어받음 |
| 3 | **고침 — 「바뀐 점」 칸** | 재동의 화면의 「바뀐 점」이 「—」로 나왔음(「고치기」에 적는 칸이 없었음) → 운영 화면 「고치기」에 **바뀐 점(300자)** 칸 · 새 판인데 비우면 경고 · `PUT /admin/terms/{code}` 에 `changeNote` |
| 4 | **법무 판단 필요 — 시행일 전 재동의** | 시행일을 내일로 게시해도 **게시하는 순간** 앞 판이 보관되고 모든 회원에게 재동의를 받음. 이용약관 제14조는 「시행 7일 전 알림 · 불리하면 30일 전」 — 이 차이를 docs/242 2절 3번으로 법무에 넘김(바꾸려면 개발 · 대표 결정 뒤) |
| 5 | 점검 시간 | 회귀 시험 69개 중 사용자 웹을 재시작하는 시험 약 12번이 **재시작마다 운영 빌드(약 4.5분)** 를 다시 했음(회귀 약 65분 중 45분쯤). 점검판 사용자 웹은 **컨테이너를 새로 만들 때 한 번만 빌드**하고, 재시작 때는 데이터 캐시만 지우고 띄움(sgb-infra `docker-compose.site-prod.yml`) · 회귀 실행기를 저장소로(`qa/run_regression.sh` · `qa/mkpost1145.py`) |

- 시험을 나눠 **동시에** 돌리는 것은 하지 않았습니다 — 시험들이 점검판 DB · 설정 · 약관을 같이 바꾸고 되돌려서, 동시에 돌리면 서로 섞여 실패가 무작위로 납니다. 빌드를 한 번으로 줄이는 쪽이 같은 효과를 안전하게 냅니다.
- 운영 서버의 사용자 웹은 바뀌지 않습니다(점검판 compose 만).
