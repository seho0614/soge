# 542. 수동 전표 쓰기 · 결재 (v10.405 · 2026-11-20)

> ⑮ 두 번째(D248). 대표 11/19 「승인 + 통과하면 병합」 — 자동으로 안 잡히는 거래를 화면에서 전표로 · 쓴 사람과 다른 SUPER 가 승인해야 장부에.

## 1. 결론

- 운영 화면 **회계 › 수동 전표**(SUPER · PAYOUT)에서 임대료 · 대출 · 이자 · 보증금 · 잡이익처럼 **자동 전표로 안 잡히는 거래**를 씁니다 — 날짜 · 적요 · 거래처 · 증빙 · 줄(계정 · 차변 · 대변 · 줄 메모).
- 흐름: **요청(REQUESTED) → 쓴 사람이 아닌 SUPER 승인(APPROVED)** — 그때 `acct_entries`(source `MANUAL`)로 장부에 들어감 · **반려(사유)** · **취소**(쓴 사람 · SUPER · 요청 상태만).
- 검사(서버 · DB 두 겹): 줄 2 ~ 30 · 줄마다 차변 · 대변 중 하나만 1원 이상 정수 · 아는 계정 · **차변 합 = 대변 합**(DB 미룬 검사 D242 가 다시 확인) · **마감한 달 · 마감한 해**(⑭ `fn_acct_year_closed`)는 요청 · 승인 때 모두 막음.
- 자기 승인 막기 · SUPER 만 승인 · 내용 고치기 막기 · 지우기 막기는 DB 트리거 `fn_acct_manual_guard` 가 합니다(화면 · API 를 거치지 않아도).
- 화면은 차변 합 · 대변 합 · 차이를 바로 보여 주고, 맞지 않으면 「요청 올리기」가 꺼집니다.

## 3. 주의

1. 승인된 전표는 고치지 않습니다 — 틀리면 반대 수동 전표를 씁니다(쌓기만 원칙).
2. SUPER 가 한 사람뿐이면 그 사람이 쓴 수동 전표는 승인할 사람이 없습니다 — 지급 담당(PAYOUT)이 쓰고 SUPER 가 승인하는 흐름을 권합니다.
3. 계정 선택은 계정표(⑫ 규칙 화면에서 더한 U_ 계정 포함) 전체입니다. 어떤 계정을 쓸지는 세무사 확인.
