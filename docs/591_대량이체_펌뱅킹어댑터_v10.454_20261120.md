# 591. 대량 이체 — 금융결제원 오픈뱅킹 어댑터 (v10.454 · 2026-11-20)

## 1. 결론
거래처 대금 · 경비를 **묶음**으로 만들고, **만든 사람이 아닌 두 사람이 승인**한 뒤에만 보냅니다. 보내는 길은 **금융결제원 오픈뱅킹**입니다(대표 11/20 「금융결제원을 이용한다」). 보내기는 **처음 꺼짐**이고, 켜도 방식이 **간주(ASSUME)**면 금융결제원에 보내지 않습니다. 위치: **회계 › 자금 › 대량 이체** · SB-ADM-FIN-020 · API `/admin/fin/transfers`(세무사 읽기 범위 밖).

| 단계 | 누가 | 내용 |
|---|---|---|
| 1 묶음 만들기 | SUPER · PAYOUT | 이름 · 지급일(오늘이나 뒤) → DRAFT |
| 2 줄 넣기 · 빼기 | SUPER · PAYOUT | 받는 분 · 은행 코드 3자리 · 계좌번호(암호문으로만 저장 · 화면은 끝 4자리) · 금액 · 낸 계정(처음 AP 미지급금) · 통장 표시 — 묶음 200줄 · 합계 `acct.transfer_max`(처음 5천만 원) |
| 3 승인 | 만든 사람이 아닌 SUPER · PAYOUT 2명 | 한 사람 한 번 · 두 번째에 APPROVED(DB 가 다시 확인) · 승인 뒤 줄 · 묶음은 못 고침(취소하고 새로) |
| 4 보내기 | SUPER · PAYOUT | `acct.transfer` on 일 때만 · ① **수취조회**(돈 안 나감 · 받는 분 이름이 은행과 다르거나 계좌 오류면 그 줄 **HOLD = 보내지 않음**) ② 거래고유번호 저장 · 묶음 **CHECKING**(보냄 · 결과 확인 중) ③ 줄마다 **입금이체** |
| 5 결과 조회 | SUPER · PAYOUT | 응답이 없거나 처리 중인 줄(**PENDING**)은 **다시 보내지 않고** 금융결제원 결과조회로만 확정 · 모두 확정이면 SENT · PARTIAL · FAILED · 보내기가 꺼져도 됨 |
| 취소 | SUPER · PAYOUT | 보내기 전(DRAFT · APPROVED)만 · 사유 |

| 줄 결과 | 뜻 |
|---|---|
| OK | 입금 성공(LIVE) → 다음 전표 만들기 때 TRANSFER_PAID |
| FAIL | 금융결제원 · 은행이 거절 — 돈 안 나감 |
| HOLD | 수취조회에서 막음(이름 다름 · 계좌 오류) — **보내지 않음** |
| PENDING | 응답 없음 · 처리 중 — 돈이 나갔는지 모름 → 「결과 조회」 |
| ASSUMED | 간주(금융결제원에 안 보냄 · 전표 없음) |

| 설정(정책 › 전체 설정) | 처음 | 뜻 |
|---|---|---|
| `acct.transfer` | off | 보내기 켬(만들기 · 승인 · 결과 조회는 꺼져도 됨) |
| `acct.transfer_mode` | ASSUME | ASSUME = 금융결제원에 보내지 않고 간주 결과 · 전표 없음 / LIVE = 금융결제원 오픈뱅킹 |
| `acct.transfer_max` | 50000000 | 한 묶음 합계 상한(원) |

| 키 · .env | 어디 | 뜻 |
|---|---|---|
| `FIRMBANK_CLIENT_ID` · `FIRMBANK_CLIENT_SECRET` | 운영 화면 › 외부 연동 › 「연동 키」(SUPER · 암호화) | 금융결제원 오픈뱅킹 이용기관 앱 키 |
| `FIRMBANK_ORG_CODE` | .env | 이용기관코드(영문 · 숫자 10자) — 거래고유번호 앞 10자 |
| `FIRMBANK_CNTR_ACCOUNT` | .env | 약정 출금계좌(숫자만) |
| `FIRMBANK_ENV` | .env | `TEST`(처음 · 시험 서버) → 시험 끝나면 `PROD` |
| `FIRMBANK_API_BASE` · `FIRMBANK_TEST_BASE` | .env | 운영 · 시험 서버 주소(비우면 알려진 기본값) |
| `FIRMBANK_REQ_NAME` | .env | 요청 고객 이름(통장 표시용 · 처음 「한국바이오헬스케어」) |
| `FIRMBANK_MAP` | .env | 경로 · 칸 이름 · 성공 코드를 JSON 으로 바꿈(공식 가이드와 다를 때) |

- LIVE 인데 키 · 이용기관코드 · 약정계좌가 없으면 422 TRANSFER_NOT_READY(조용히 간주로 바꾸지 않음).
- 전표: **LIVE 로 성공(OK)한 줄만** TRANSFER_PAID(차변 낸 계정 / 대변 보통예금 · 거래처 = 받는 분) — 기간 분석 · 거래처 원장에서 갚을 돈이 줄어듦.

## 2. 금융결제원 오픈뱅킹 흐름(코드 `src/modules/acct/transfer.ts` KftcTransfer)
1. 토큰: `POST /oauth/2.0/token`(form · `grant_type=client_credentials` · `scope=oob`) — 만료 60초 전까지 메모리에 둠.
2. 수취조회: `POST /v2.0/inquiry/receive` — 줄마다 · 받는 분 이름(`account_holder_name`)을 줄의 받는 분과 비교(띄어쓰기 · (주) 무시).
3. 입금이체: `POST /v2.0/transfer/deposit/acnt_num` — 한 번에 한 줄 · 약정 출금계좌 · 이름 확인 옵션 켬.
4. 결과조회: `POST /v2.0/transfer/result` — 원거래 거래고유번호 · 날짜 · 금액으로.
- **거래고유번호(bank_tran_id) = 이용기관코드 10자 + `U` + 9자리** — DB 시퀀스(fn_acct_transfer_tran_id)로 만들고 줄에 저장(UNIQUE). 한 번 정한 번호는 바꾸지 않고 다시 쓰지 않습니다(DB 가 막음).
- 성공 판정(처음 값): `rsp_code = A0000` 이고 줄 `bank_rsp_code = 000` → OK · `rsp_code = A0007` 또는 `bank_rsp_code = 400` → PENDING · 응답 없음(시간 넘음 · 연결 끊김 · 서버 오류) → PENDING · 그 밖 → FAIL.

## 3. 대표 확인 필요(금융결제원)
1. **금융결제원 오픈뱅킹 이용기관 등록**(보안 점검 · 약정계좌 · 수수료)은 대표가 금융결제원에 확인 — **일반 법인이 「입금이체」 이용기관이 될 수 있는지 먼저 확인**(처음 도입 때 자료는 핀테크 · 전자금융업자 위주). **안 되면 거래 은행 펌뱅킹을 같은 어댑터 자리에** 넣습니다(transfer.ts 의 어댑터 한 곳 · FIRMBANK_MAP).
2. 위 경로 · 칸 이름 · 응답 코드는 「금융결제원 오픈뱅킹 v2.0 으로 알려진 값」입니다 — 2026-11-20 공식 개발자 가이드로 확인하지 못했습니다. 등록 뒤 받은 가이드로 대조하고, 다르면 `FIRMBANK_MAP` 만 고칩니다.
3. 발신 IP(3.37.95.217)를 금융결제원에 등록해야 할 수 있습니다.
4. 수수료 · 하루 한도 · 영업시간 밖 이체 가능 여부는 계약 문서로 확인.

## 4. 주의
1. 점검판 · 시험은 간주만 씁니다(실제 금융결제원 호출 없음). 처음 LIVE 는 `FIRMBANK_ENV=TEST`(시험 서버)로 1원 ~ 소액 묶음부터.
2. 수취조회가 안 되면(토큰 · 연결 실패) **아무 줄도 보내지 않고** 묶음은 APPROVED 그대로(TRANSFER_UPSTREAM) — 잠시 뒤 다시 보내면 됩니다.
3. 입금이체 응답이 끊기면 그 줄은 PENDING — **다시 「보내기」하지 말고 「결과 조회」**를 누르십시오(같은 거래고유번호로 묻기만 함 · 이중 이체 막기). 결과 조회도 계속 모르면 금융결제원 · 은행 화면에서 확인.
4. 받는 분 이름이 은행과 다르면 보내지 않습니다(HOLD) — 이름을 고쳐 새 묶음으로.
