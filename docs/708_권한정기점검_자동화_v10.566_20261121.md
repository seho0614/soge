# 708. 권한 정기 점검 자동화 — 분기 「거둘 후보」 (v10.566 · 2026-11-21)

> 대표 11/21 「모두 개발진행」. 직원 · 권한 › 새 탭 「거둘 후보」(키 `perm-review`). v10.180 「권한 점검」(분기 점검 완료 기록)은 그대로 두고, 그 옆에서 **무엇을 거둘지**를 자동으로 모읍니다. SQL `prr_1_v10566_perm_review.sql`(마이그레이션 번호는 메인이 정함).

## 1. 결론

- 분기마다 「거둘 후보」를 자동으로 만들고(정기 작업 `prr_daily` 매일 09:20 · 스위치 `prr.review_auto` 처음 on — 목록 · 알림만), **SUPER 가 골라 한 번에 거둡니다**(사유 필수). 자동으로 거두는 일은 없습니다.
- 후보 근거는 이미 있는 기록을 다시 씁니다 — 권한그룹 · 개별 권한(`perm_account_groups` · `perm_account_overrides`) · 역할(`account_roles` · 기한) · 로그인 기록(`accounts.last_login_at`) · 직원 대장(`acct_employees.left_on`) · 막힘 기록(`perm_shadow_log`) · 안 쓴 기간(기존 설정 `ops.role_idle_days` 90).
- 새로 쌓는 것은 **업무 사용 기록 하나**(`prr_task_use` — 계정 · 업무 · 마지막 쓴 날)뿐입니다. PermGuard 가 운영 역할 API 요청을 볼 때 하루 한 번 적습니다(주소 · 시각 · 내용 없음).

## 2. 후보 종류(같은 대상이 여럿에 걸리면 위 것 하나만)

| 종류 | 뜻 | 대상 |
|---|---|---|
| 퇴사자 권한 `LEFT_STAFF` | 퇴사일이 오늘 전인 직원의 연결 계정에 남은 것 | 역할 · 권한그룹 · 개별 권한 |
| 오래 로그인 안 함 `LOGIN_IDLE` | 운영 역할 계정이 90일 넘게 로그인 안 함(한 번도 없으면 역할 받은 날부터) · 활성 계정만 | 역할 · 권한그룹 |
| 안 쓴 권한그룹 `GROUP_IDLE` | 붙은 지 90일 넘었는데 그 그룹이 여는 업무(`fn_perm_group_expand`)를 90일 동안 한 번도 안 씀 · SUPER 계정 빼고 | 권한그룹 |
| 외부 계정 기한 없음 `EXTERNAL_NO_EXPIRY` | 직원 대장 연결 없는 외부 역할(세무사 · 파트너 담당)에 기한이 없음(v10.563 전에 준 것) | 역할 |
| 역할 없는데 권한 남음 `ROLE_GONE` | 운영 역할이 모두 없어졌는데(기한 지나 거둠 등) 권한그룹 · 개별 권한이 남음 — **기한 지난 외부 계정**이 여기 걸림 | 권한그룹 · 개별 |
| 기한 지난 권한 줄 `EXPIRED_LEFTOVER` | 기한이 지나 효력은 없지만 남아 있는 줄(정리) | 권한그룹 · 개별 |

- 「안 쓴 권한그룹」은 **업무 사용 기록을 모으기 시작한 날(`prr.use_since` = 마이그레이션 날)부터 90일이 지나야** 셉니다. 그 전에는 다른 다섯 종류만 나옵니다(화면에 「모은 지 n일」).
- 줄마다 「최근 막힘」 = 그 계정의 최근 90일 `perm_shadow_log` 수 — 쓰려다 막힌 사람을 모르고 거두지 않게 보여만 줍니다.

## 3. 흐름

1. 정기 작업 `prr_daily`(09:20)가 이번 분기 후보를 다시 만듦 — 새 후보만 더하고, 대상이 이미 없어진 열린 줄은 `GONE`. 다시 돌려도 같음. 열린 후보가 있으면 운영 알림 `PRR_REVIEW_OPEN`(INFO · 분기마다 한 번 · 0 이면 풂).
2. SUPER 가 「거둘 후보」에서 종류로 거르고 골라 **한 번에 거두기**(사유) — 줄마다 결과(마지막 SUPER · 자기 자신 · 이미 결정은 그 줄만 실패).
   - 역할 = `account_roles` 지움(권한 변경 기록 `role_changes` 에 「권한 정기 점검 — 사유」 · 처리자) · 권한그룹 · 개별 = 지움 + `perm_changes` 계정마다 한 줄(`PRR_REVOKE`)
   - 역할이 모두 없어진 계정은 `STAFF_LEFT_ROLE` 풀림(v10.563 `resolveLeftAlert` 재사용)
3. 그대로 둘 것은 **그대로 두기**(메모 필수) — 결정은 한 번(DB 트리거가 바꾸기 · 지우기를 막음).
4. 분기 점검 완료 기록은 기존 「권한 점검」 탭(`audit.role_reviews`)에서 — 이 화면 위에 그 분기 기록 여부와 링크.

## 4. API

| 방법 | 주소 | 역할 | 감사 | 오류 |
|---|---|---|---|---|
| GET | `/admin/staff/review?quarter=2026-Q4` | ADMIN · SUPER(메일 원문은 SUPER) | 없음 | 422 PRR_QUARTER |
| POST | `/admin/staff/review/build` | SUPER | PRR_REVIEW_BUILD(pick) | 422 PRR_QUARTER_RANGE(이번 분기만) |
| POST | `/admin/staff/review/revoke` `{ ids, reason }` | SUPER | PRR_REVIEW_REVOKE(pick) | 422 PRR_REASON · PRR_IDS · 줄마다 PRR_NOT_OPEN · SELF_GRANT · STAFF_LAST_SUPER |
| POST | `/admin/staff/review/keep` `{ ids, note }` | SUPER | PRR_REVIEW_KEEP(pick) | 409 PRR_NOT_OPEN · 422 PRR_NOTE |

- 주소는 `/admin/staff` 아래(`/admin/acct` 밖) — 세무사는 못 봅니다(계약 규칙 8).
- 업무 권한 시드: 업무 `perm-review`(그룹 acl) · R_ADMIN 4수준 · 주소 4줄(`perm_route_map` — GROUPS 판정에서 「연결 안 된 주소」가 생기지 않게).

## 6. 현장 체크리스트
1. 적용 날 「거둘 후보」를 열어 퇴사자 권한 · 외부 계정 기한 없음 줄부터 정리.
2. 90일 뒤(사용 기록이 쌓인 뒤) 「안 쓴 권한그룹」을 처음 봄 — 분기 결산처럼 드물게 쓰는 권한은 「그대로 두기」 + 메모.
3. 분기마다 이 화면을 정리한 뒤 「권한 점검」에서 점검 완료 기록을 남김.

## 7. 확인할 것 · 한계
- 업무 사용은 「그 업무 주소를 부른 적」입니다 — 화면만 열고 API 를 안 부른 탭, `perm_route_map` 에 없는 주소는 셈에 안 들어갑니다(그 경우 「안 쓴 권한그룹」으로 잘못 나올 수 있음 → 그대로 두기).
- 요청이 역할 검사를 통과한 뒤(PermGuard) 적으므로, perm.enforce = ON 에서 권한그룹이 막은 요청도 「씀」으로 적힙니다(거두기 판단에는 보수적).
- 권한 점검 주기 · 보관 기간은 최신 고시 확인이 필요합니다(docs/281 5절과 같음).
