# 745 성사 뒤 후기 요청 자동 — v10.603 (17차 ⑲ · 2026-11-21)

## 1. 결론
- 성사 확정(CONFIRMED · SETTLED) 뒤 `lsq.review_ask_days`(3)일 지나도 후기를 안 쓴 **구매자 · 판매자** 에게 회원 알림 `LSQ_REVIEW_ASK` 한 번, `lsq.review_ask_again`(7)일 뒤 한 번 더(0 이면 없음).
- 소개자는 후기를 쓰지 않는 기존 규칙 그대로(요청 안 감). 회원이 알림을 끄면 안 감(fn_notify). 스위치 `lsq.review_ask` 처음 **off**.

## 2. 재사용
| 기존 | 어떻게 |
|---|---|
| 후기 deal_reviews · POST /deals/{id}/reviews(D023) | 그대로 — 요청만 더함 · 링크 /deal/{id}/review |
| 회원 알림 fn_notify · 알림 종류 정책 | 새 종류 LSQ_REVIEW_ASK(끌 수 있음) · 글 LSQ_REVIEW_ASK_INAPP |
| 정기 작업 job_schedules | 새 lsq_daily(매일 10:20) |

## 3. DB
- `lsq_review_asks`(거래 × 당사자 PK · ask_count 1 ~ 2 · reviewed_at) · 트리거 `trg_lsq_review_ask_done`(deal_reviews AFTER INSERT → reviewed_at).

## 4. API · 화면
| 주소 | 역할 |
|---|---|
| GET /admin/lsq/review-asks | 최근 30일 요청 · 다시 · 요청 뒤 후기(전환율 · 평균 일수) · 성사 · 후기 수 · 날마다 |
| POST /admin/lsq/daily/run | SUPER · lsq_daily 지금 한 번 |
- 운영 `SB-ADM-LSQ-020` 검수 › 거래 후기 요청.

## 5. 켜는 순서
1. 알림 글 확인(「후기는 고칠 수 있지만 지워지지 않습니다」). 2. `lsq.review_ask` 켬. 3. 다음 날 운영 화면에서 요청 · 전환 확인.
- 켜면 **최근 30일 안 성사 거래 중 3일 지난 것** 이 첫날 한꺼번에(하루 500명 상한).
