# 715. 신고 → 이의 제기 (v10.573 · 2026-11-21)

> 대표 11/21 「16개 모두 동시에」 — 11차 회원 · 거래 ①. 앞머리 `mtr_` · 마이그레이션 번호는 합칠 때(메인) 정함. 스위치 `mtr.appeal` **처음 off**.

## 1. 결론

- 신고 때문에 내려간 **내 매물 · 소개광장 글 · 댓글**의 작성자가 나의공간에서 **이유를 보고 대상마다 한 번** 이의를 냅니다.
- 운영자가 다시 판단합니다(위험감지 › 이의 제기). **받아들이면** 글 · 댓글은 다시 보이고, 매물은 **검수 대기**로 돌아가며, 그 대상의 신고는 **기각**으로 닫히고 신고한 사람에게 결과가 갑니다. **받아들이지 않으면** 그대로 두고 사유를 작성자에게 알립니다.
- 처리 기한(처음 72시간)을 넘기면 운영 알림 `MTR_APPEAL_OVERDUE`(경고 · 하나만 · 다 처리되면 풀림).
- 새로 만든 것은 이의 표 하나와 화면 · API 뿐입니다. 신고 표 · 신고 트리거(`fn_report_guard` · `fn_report_escalate`)는 **고치지 않았습니다**.

## 2. 재사용한 기존 기능

| 기존 | 쓰는 곳 |
|---|---|
| 신고(`reports` · `report_reasons` · v10.27 · D110) | 내려간 근거 · 사유 이름 · 건수 · 운영 처리 내용 |
| 글 · 댓글 되살리기(v10.72 · v10.80 `community.service unhide`) | 받아들일 때 같은 방식(상태 PUBLISHED · 신고 수 0 · 처리 전 신고 기각 · 신고한 사람 `REPORT_RESOLVED` 알림) |
| 검수 큐(`review_items` · `fn_review_sla_due`) | 매물은 바로 게시하지 않고 검수 대기 — 게시 조건(중개사 · 자리 수 · 금지어 트리거)은 검수 승인 때 그대로 봄 |
| 신고 처리 기한(v10.367 `REPORT_OVERDUE`) · 신고 분류(v10.527 lsy) | 기한 알림을 같은 모양(열린 것 하나 · 풀림)으로 · 분류 화면 바로 뒤에 탭 |

## 3. 대상 · 규칙

| 대상 | 「신고로 내려감」 판단 | 받아들이면 |
|---|---|---|
| 매물(LISTING) | 상태 반려(REJECTED) · 정지(SUSPENDED) **그리고** 그 매물에 인정(UPHELD) · 검수 대기(QUEUED) 신고 | 상태 IN_REVIEW + 검수 큐 한 줄(이미 대기 중이면 안 넣음 · 사유 「이의 제기 받아들임」) |
| 글(POST) | 감춤(HIDDEN) **그리고** 그 글에 신고 | PUBLISHED · 감춘 시각 · 사유 비움 · 신고 수 0 |
| 댓글(COMMENT) | 감춤(HIDDEN) **그리고** 그 댓글에 신고 | PUBLISHED · 신고 수 0 |

- 대상마다 **한 번**(DB 고유 색인 `uq_mtr_appeal_target`) · 내려간 뒤 `mtr.appeal_days`(30)일 안 · 글 10 ~ 1000자(서버 · DB 같은 길이).
- 「내려간 때」 = 그 대상 신고의 마지막 처리 · 접수 시각.
- 작성자 화면에 **신고한 사람은 보이지 않습니다**(사유 이름 · 건수 · 운영 처리 내용 · 글 감춘 사유만).
- 결정은 한 번 — 결정한 줄의 상태 · 사유 · 결정자는 DB 트리거(`fn_mtr_appeal_guard`)가 막고, 이의 기록은 지울 수 없습니다.
- 받아들이면 그 대상의 열린 · **인정** 신고까지 기각으로 바꿉니다(처리 내용 「작성자의 이의 제기를 운영자가 받아들여 다시 올렸습니다 — 사유」). 그래서 v10.575 신뢰 점수 · 이상 거래 점수의 「인정된 신고」에서도 빠집니다.
- 요청(REQUEST) · 프로필(PROFILE) 신고는 이번에 넣지 않았습니다(내려가는 길이 없음).

## 6. DB · 설정 · 작업

- 표 `mtr_appeals`(대상 · 작성자 · 글 · 낼 때 상태 · 사유 요약 · 상태 · 기한 · 결정 · 되돌린 상태 · 기각한 신고 수) · 트리거 `trg_mtr_appeal_guard`.
- 설정 `mtr.appeal`(off) · `mtr.appeal_days`(30 · 1 ~ 90) · `mtr.appeal_sla_hours`(72 · 24 ~ 336) — 정규식 서버 = DB.
- 정기 작업 `mtr_hourly`(매시간) — 기한 넘긴 열린 이의가 있으면 `MTR_APPEAL_OVERDUE`.
- 알림: 작성자 `MTR_APPEAL_DECIDED`(→ `/my/appeals`) · 신고한 사람 `REPORT_RESOLVED`(기존과 같음).
- 권한 시드: 업무 `mtr-appeals`(위험감지 묶음) · `R_ADMIN` 네 수준 · 주소 지도.
