## 1. 결론

| 항목 | 내용 |
|---|---|
| 방식(`identity.provider`) | **STUB**(처음 · 지금처럼 바로 통과 · 「실제 확인이 이루어지지 않았습니다」) · **MOCK**(점검판 가짜 표준창 · 운영 서버에서는 못 고름 · 고르면 STUB 으로 읽음) · **NICE**(키 3개가 있어야 고름) — 바꾸기는 **SUPER** |
| 흐름 | `/verify` 「휴대폰 본인확인」 → `POST /verifications/identity/start`(요청 번호 1회용 · 10분 · 1시간 10번) → NICE 표준창(POST 폼 · 같은 창) → `/verify/return` → `POST /verifications/identity/complete` → 끝 · `?next=` 로 돌아감 |
| 저장 | CI 는 **서버 열쇠 HMAC 해시만**(`ci_hash` 64자) · 이름 · 생년월일 · DI 원문 저장 안 함 · 이름은 회원 이름과 같은지(`name_match`)만 · 표준창 세션 열쇠는 암호화 저장 → 끝나면 비움 |
| 같은 사람 다른 계정 | `identity.ci_duplicate = warn`(통과 · 운영 화면에 수) · `block` 이면 409 `CI_DUPLICATE` |
| 나이 | `identity.min_age = 14` — 미만이면 422 `UNDER_AGE` |
| 고친 잠재 오류 | 전에는 `PASS_API_KEY` 를 넣으면 `stub=false` · **CI 가 빈 채로** 저장돼 소개코드 무료분이 0 이 됐음 → STUB 은 늘 `stub-ci` · MOCK · NICE 는 표준창으로만 |
| 운영 화면 | 외부 연동 › **「본인인증」**(방식 단추 · 키 3줄 · 최근 30일 성공 · 실패 까닭 · 시험용 통과 · 다른 계정 수) · 「연동 키」에 NICE 3줄 |

## 2. 오류 처리 (대표 「오류처리」)

| 경우 | 응답 | 기록(fail_code) |
|---|---|---|
| STUB 인데 표준창 시작 | 409 `USE_STUB` | — |
| MOCK · NICE 인데 옛 단추 | 409 `USE_STANDARD_WINDOW` | — |
| 1시간 10번 넘게 시작 | 422 `TOO_MANY_REQUESTS` | — |
| NICE 연결 실패 · 시간 초과 · 키 없음 · 사이트 주소(https) 없음 | 409 `IDENTITY_UNAVAILABLE` | `UNAVAILABLE` |
| 10분 지남 | 422 `IDENTITY_EXPIRED` | `EXPIRED` |
| 같은 요청 다시 | 409 `IDENTITY_USED` | 그대로 |
| 남의 요청 · 없는 요청 | 404 | — |
| 무결성 값 틀림 · 복호화 실패 · 요청 번호 다름 | 422 `IDENTITY_INTEGRITY` | `INTEGRITY` · `REQ_MISMATCH` |
| 표준창에서 취소 · 실패 | 422 `IDENTITY_FAILED` | `NICE_<결과 코드>` |
| CI 없음 | 422 `IDENTITY_FAILED` | `NO_CI` |
| 만 14세 미만 | 422 `UNDER_AGE` | `UNDER_AGE` |
| 다른 계정에서 인증한 사람(block) | 409 `CI_DUPLICATE` | `CI_DUPLICATE` |
| 운영 서버에서 MOCK 고름 · 키 없이 NICE | 422 `MOCK_NOT_ALLOWED` · `IDENTITY_KEYS_MISSING` | — |
| ADMIN 이 방식 바꿈 | 403 `INTEG_SETTING_SUPER` | — |

실패 기록은 **트랜잭션 밖에서 먼저** 저장하고 세션 열쇠를 비운 뒤 오류를 돌려줌. 바깥 오류 문장은 회원에게 보이지 않고 로그에만.
