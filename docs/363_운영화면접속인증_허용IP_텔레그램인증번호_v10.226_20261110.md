# 363. 운영 화면 접속 인증 — 허용 IP 밖이면 그날 텔레그램 인증번호 — v10.226 (2026-11-10)

> 계기: 대표 「운영페이지 아이피제한 없이 접속 권한을 따라 접속 관리 · 아이피 다르면 접속인증 후 접속가능(매일 · 핸드폰번호) · 오픈 전에는 접속인증 없이 가능」(11/10)
> → 물음 답: 기준 「허용 IP 목록 + 그 밖은 인증」 · 기간 「그날 자정까지」 · Nginx IP 제한은 「문자 연동 준비 뒤」 · 보내는 길 「텔레그램 먼저 · 문자는 나중」 → 계획 「승인」.
> **마이그레이션 1개 D195(232 → 233)** · 새 API 9개 · 설정 1개(`admin.ip_verify` off) · 운영 Nginx 는 바꾸지 않음.

## 1. 동작

| 상태 | 운영 역할만 요구하는 API(운영 화면) |
|---|---|
| `admin.ip_verify` = **off**(처음 · 오픈 전) | 지금과 같음 — 로그인 · 역할(· 2단계 인증 설정)만 |
| on · 허용 IP(`staff_ip_allow`) | 인증 없이 |
| on · 허용 IP 밖 · 그 운영자가 그 IP 로 **오늘(한국 날짜)** 인증함 | 통과 — 한국 시간 자정까지 |
| on · 허용 IP 밖 · 오늘 인증 안 함 | **403 `IP_VERIFY_REQUIRED`** → 운영 화면이 「접속 인증」 화면만 보임 |

- 회원 기능(회원 역할이 섞인 API)은 보지 않음(2단계 인증과 같은 범위). 로그인 · `/auth/ip-verify*` 는 인증 전에도 됨.
- 운영 역할: REVIEWER · ADMIN · PAYOUT · SUPER · PARTNER_MAL · PARTNER_AFF.
- 2단계 인증이 켜져 있으면 2단계 → 접속 인증 순서.

## 2. 인증번호

| 항목 | 값 |
|---|---|
| 보내는 길 | 텔레그램 — 운영자 개인 대화 번호(`staff_access.telegram_chat`)가 있으면 그 사람에게만 · 없으면 운영 대화방(`ops.telegram_chat` — 대화방 사람 모두 봄 · 글에 가린 이메일) |
| 번호 | 6자리 · **5분** · 저장은 sha256(계정 · IP · 번호)만 — 원래 번호는 DB · 감사 기록에 없음 |
| 상한 | 1분에 한 번(429 `IP_VERIFY_WAIT`) · 하루 10번(429 `IP_VERIFY_DAY_LIMIT`) · 5번 틀리면 그 번호 끝 · 15분 동안 새 번호도 막음(423 `IP_VERIFY_LOCKED`) |
| 기록 | 감사 `STAFF_IP_CODE_SENT` · `STAFF_IP_VERIFIED` · `STAFF_IP_LOCKED`(가린 IP) · 통과 기록 `staff_ip_passes`(고칠 수 없음) |
| 문자(휴대폰) | 대행사 연동 뒤 — `channel` 에 `SMS` 자리만 둠(알림톡 · 문자 틀 docs/215 에 템플릿 더하기) |

## 3. 켜기 · 받을 곳

- 켜기 · 끄기는 **SUPER 만**(403 `IP_VERIFY_SETTING_SUPER`) · 바뀌면 운영 알림 「중요 설정 바뀜」.
- 켜기 전 검사: 텔레그램 봇 토큰(422 `IP_VERIFY_NO_TELEGRAM`) · 모든 운영자의 받을 곳 — 운영 대화방이 있거나 모두 개인 대화 번호가 있어야(422 `IP_VERIFY_NO_RECEIVER` · 이메일 목록). 켜는 순간 받을 곳이 없어 잠기는 일을 막음.
- 받을 곳 바꾸기: 본인(`PUT /me/staff/telegram` — **접속 인증을 마친 뒤에만** · 비밀번호만 아는 사람이 번호를 빼돌리지 못하게) · SUPER(운영자마다 · 시험 글).
- 개인 대화 번호 알아내기: 그 운영자가 봇에게 아무 말이나 보냄 → SUPER 가 「외부 연동 › 텔레그램 대화방 찾기」(v10.200)에서 번호 확인.

## 5. 운영 Nginx IP 제한 (지금은 그대로 — 문자 연동 뒤)

- 지금: `/etc/nginx/sites-enabled/sgb` 운영 화면 블록 `allow 121.168.92.13; deny all;`(3곳 · /api/ · / · /assets/).
- **이 제한은 `admin.sogaebank.com` 만 막음** — 사용자 웹 주소(`sogaebank.com/api/…`)를 거치면 운영 API 에 닿는 길이 있음(로그인 · 역할로만 막힘). `admin.ip_verify` 를 켜면 그 길도 이 인증이 막음.
- 풀 때(대표 결정 뒤 · 사람이 · 순서):
  1. 운영 화면 「접속 인증」에서 허용 IP(집) · 모든 운영자 받을 곳 확인 → 스위치 **켜기** → 다른 곳(휴대폰 핫스팟 등)에서 인증 화면 · 번호 · 통과 확인
  2. ubuntu: `sudo cp /etc/nginx/sites-enabled/sgb ~/sgb-nginx-before-ipopen.conf` → 운영 화면 블록의 `allow …; deny all;` 줄 지움 → `sudo nginx -t` → `sudo systemctl reload nginx`
  3. 되돌리기: `sudo cp ~/sgb-nginx-before-ipopen.conf /etc/nginx/sites-enabled/sgb && sudo nginx -t && sudo systemctl reload nginx`
  - postcheck [8] 「운영 화면은 허용 IP 만」 줄은 그때 고침(지금은 그대로 통과해야 정상).
