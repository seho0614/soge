# 757. 권한그룹 전환 준비 — 역할 이름으로 막는 곳 조사 (v10.615 · 2026-11-21)

> 대표 11/21 승인. 판정 방식 perm.mode(docs/706 · ROLE → COMPARE → GROUPS)를 GROUPS 로 바꾸기 전에, 가드(@Roles) 밖에서 **역할 이름(ADMIN · SUPER · PAYOUT · REVIEWER · PARTNER_* · ACCOUNTANT)으로 직접 허용 · 막는 곳**을 src · prisma(함수 · 트리거) · web · site 전체에서 찾아 표로 정리하고, 권한그룹과 함께 보게 고칠 곳은 고쳤습니다.
> 새 파일 `src/modules/admin/pgx-perm.ts` · `src/modules/admin/pgx-open.ts` · SQL `sql/pgx_role_checks.sql` · 패치 `patches/1_pgx_server.md`(27) · `patches/2_pgx_web.md`(5).

## 1. 결론

- 조사한 줄: src 318줄(자동 생성 `src/generated/codes.ts` 67줄 빼고) · prisma 함수 · 트리거 34곳 · web 107줄 · site 4줄.
- **고친 곳 20곳**(서버 13 · 화면 3 · DB 4) — 모두 **perm.mode = GROUPS 일 때만** 다르게 움직입니다. ROLE · COMPARE 에서는 지금과 똑같습니다(로그인 화면 1곳만 모든 모드 — 6절).
- **그대로 둔 곳** — 아래 3절 표의 까닭 다섯 가지(SUPER 전용 · 법정 분리 · 운영자 판별 · @Roles 상수 · 업무 단위 없음). 이것들은 GROUPS 에서 **넓어지지 않습니다**(좁게 보이거나 역할로 남을 뿐).
- **남은 문제 0** — `pgx-open.ts` 의 `PGX_OPEN` 이 빈 배열. 이 목록이 비어 있지 않으면 `PUT /admin/perm/mode` 가 GROUPS 를 422 `PERM_MODE_NOT_READY` 로 막고, 「판정 방식」 상자 `groupsReady` 도 거짓(`roleChecksOpen` 수)이 되게 **서버 조건에 더했습니다**(4절).

## 4. GROUPS 로 바꾸는 서버 조건에 「남은 문제 0」 더함

- `src/modules/admin/pgx-open.ts` `PGX_OPEN`(지금 `[]`) — 이 표에서 「고칠 것 · 아직」이 생기면 번호를 넣음.
- `PUT /admin/perm/mode` GROUPS: 연결 안 된 /admin 주소 0 · 최근 24시간 다름 0 **그리고 PGX_OPEN 0** 이어야 함 — 아니면 422 `PERM_MODE_NOT_READY`(details `roleChecksOpen` · `items`). `GET /admin/perm/mode` 에 `roleChecksOpen` · `groupsReady` 도 이 조건.
- 새 코드 규칙(합칠 때 안내): 서비스 안에서 역할 이름으로 허용 · 막는 줄을 새로 쓰면 `pgxCan` 으로 쓰거나, 못 맞추면 `PGX_OPEN` 에 번호 · docs/757 표에 줄. 시험 test_v1615 ① 이 새 역할 검사 줄 수를 세어 바뀌면 알림(5절).
