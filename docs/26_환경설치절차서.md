# 1. 요구 사항

## 1-1. 런타임

| 항목 | 버전 | 확인 |
|---|---|---|
| **Node.js** | **22 LTS** | `node -v` |
| **PostgreSQL** | **16** | `psql --version` |
| npm | 10+ | `npm -v` |
| Git | 2.x | `git --version` |

> **PostgreSQL 16 이 필요합니다.** 15 이하에서는 일부 문법이 동작하지 않습니다.
> Node 는 20 에서도 돌지만 22 로 맞추십시오 — CI 가 22 입니다.

## 1-2. DB 확장 3종

마이그레이션이 자동으로 만듭니다. **슈퍼유저 권한이 필요합니다.**

| 확장 | 쓰는 곳 |
|---|---|
| `pgcrypto` | UUID 생성 · 암호화 |
| `citext` | 이메일 대소문자 무시 비교 |
| `pg_trgm` | 통합 검색 (한국어 유사도) |

권한이 없으면 DBA에게 미리 요청하십시오.

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
CREATE EXTENSION IF NOT EXISTS citext;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

## 1-3. 디스크 · 메모리

| 대상 | 필요 |
|---|---|
| 저장소 | 500MB (node_modules 3개 포함) |
| 메모리 | 2GB (Next.js 빌드 시 피크) |

# 2. 로컬 개발 환경

## 2-1. 설치 (5분)

```bash
tar xzf sgb-app-kit.tar.gz && cd sgb

# 앱 3개 — 각각 별도 node_modules 입니다
npm install                  # API        182 packages
(cd site && npm install)     # 사용자 웹   35 packages
(cd web  && npm install)     # 운영 BO     30 packages
```

## 2-2. 데이터베이스

세 가지 중 하나를 고르십시오. **psql 은 이제 필수가 아닙니다** — `npm run db:migrate` 는 Node 로 돕니다.

| 방법 | 준비물 | 명령 |
|---|---|---|
| 설치된 PostgreSQL 16 | psql | `createdb sgb` |
| Docker | Docker | `docker compose up -d` → `postgresql://sgb:sgb@localhost:5432/sgb` |
| 임베디드 (Docker 도 PG 도 없을 때) | 없음 | `npm i -D embedded-postgres@16.14.0-beta.17` → `npm run db:embedded` → `postgresql://postgres:postgres@localhost:54329/sgb` |

```bash
cp .env.example .env           # DATABASE_URL · JWT_SECRET 을 여기에. 스크립트가 자동으로 읽습니다
npm run db:migrate             # 마이그레이션 32개 (Node · psql 불필요)
npm run db:migrate:sh          # 같은 일을 psql 로 (CI 와 동일)
npm run db:seed                # 시험 데이터 (psql 필요)
```

**`db:migrate` 는 재실행해도 안전합니다.**

```
1회차  적용 32 · 기존 0 · 변경감지 0
2회차  적용 0  · 기존 32 · 변경감지 0
```

`변경감지` 가 0 이 아니면 **적용된 마이그레이션 파일이 수정된 것**입니다. 되돌리거나 새 번호로 추가하십시오.

## 2-3. 환경 변수

```bash
export DATABASE_URL="postgresql://사용자:암호@localhost:5432/sgb"
export JWT_SECRET="$(openssl rand -base64 32)"
```

| 변수 | 필수 | 기본값 | 비고 |
|---|:-:|---|---|
| `DATABASE_URL` | ● | — | 없으면 부팅 실패 |
| `JWT_SECRET` | ● | — | **운영은 32자 이상** — 짧으면 부팅 거부 |
| `PORT` | | 3000 | |
| `DB_POOL_MAX` | | 10 | 태스크×풀 ≤ RDS 한도 |
| `NTS_SERVICE_KEY` | | — | 없으면 스텁 |
| `PASS_API_KEY` | | — | 없으면 스텁 |

**외부 연동 키는 없어도 됩니다.** 어댑터가 스텁으로 동작하고 응답에 `stub: true` 를 실어 화면이 표시합니다.

## 2-4. 검증

```bash
npm run verify
```

기대 출력:

```
통과 127 / 실패 0          ← DB 불변식
API 리스트: 114 오퍼레이션 · 정의 114
통과 22 / 실패 0           ← 문서 정합성
라우트 115건               ← 부팅 스모크
백엔드 타입 오류 0
프런트 타입 오류 0
전체 검증 통과
```

**여기서 실패하면 그 상태로 개발을 시작하지 마십시오.**

## 2-5. 실행

터미널 3개가 필요합니다.

```bash
npm run dev                  # API      :3000
(cd site && npm run dev)     # 사용자 웹 :5174
(cd web  && npm run dev)     # 운영 BO  :5173
```

`localhost:5174` 를 열면 가입 → 인증 → 탐색 → 문의까지 눌러볼 수 있습니다.

## 2-6. 관리자 계정 만들기

가입 후 역할을 부여합니다. **가입 시에는 `MEMBER` 만 받습니다.**

```sql
INSERT INTO account_roles(account_id, role)
SELECT id, 'SUPER' FROM accounts WHERE email = '내이메일@example.com';
```

역할은 다음 요청부터 적용됩니다 — principal 을 매 요청 DB에서 재조립하기 때문입니다.

## 2-7. 자주 겪는 문제

| 증상 | 원인 · 해결 |
|---|---|
| `password authentication failed` | `DATABASE_URL` 의 사용자·암호 확인 |
| `permission denied to create extension` | 슈퍼유저로 확장 3종을 미리 생성 |
| `JWT_SECRET too short` | 운영 모드에서 32자 미만. `openssl rand -base64 32` |
| 라우트가 적게 등록됨 | 컨트롤러가 `app.module.ts` 에 없습니다 |
| `DUPLICATE ROUTES` | 두 컨트롤러가 같은 경로를 정의했습니다 |
| 문서 드리프트 | `npm run docs` 후 커밋 |

# 3. AWS 운영 환경

## 3-1. 계정 구조

| 환경 | AWS 계정 | 이유 |
|---|---|---|
| dev · stg | **비운영 계정** | VPC 분리 |
| prod | **운영 계정** | SCP 로 위험 작업 차단 |

**Organizations + SCP** 로 운영 계정의 리전 이탈·CloudTrail 중지를 막습니다.

## 3-2. 구축 순서

**N-03 이 임계 경로입니다.** 외부 연동 6종이 여기에 걸려 있습니다.

| ID | 작업 | 주차 | 비고 |
|---|---|---|---|
| N-01 | 계정 3개 · Organizations · IAM Identity Center · Terraform 골격 | W1 | 계정 발급에 며칠 |
| N-02 | VPC · RDS · ECS · ECR · ALB (dev) | W1~W2 | ACM 인증서 |
| **N-03** | **NAT EIP 고정 → 발신 IP 등록 신청** | **W2** | ★ **심사 2~4주** |
| N-04 | CI/CD · 마이그레이션 러너 | W2~W3 | |
| N-05 | Secrets Manager · CloudWatch · Sentry · 백업 | W3~W4 | |
| N-06 | stg 구축 (운영과 동일 구성) | W4~W5 | 검수 BO 검증용 |
| N-07 | prod 구축 · Multi-AZ · WAF | W12~W14 | 오픈 5주 전 |
| N-08 | 부하테스트 · 취약점 진단 | W15~W16 | 조치 시간 2주 |
| N-09 | 데이터 마이그레이션 리허설 | W15~W17 | 잔액 정합성 필수 |
| N-10 | DR 리허설 | W17 | **해 본 적 없는 절차는 절차가 아닙니다** |
| N-11 | 오픈 · 롤백 대기 | W19 | |

## 3-3. 리소스 사양

**리전 `ap-northeast-2` 고정** — 개인정보 국외이전 판단을 아예 발생시키지 않는 것이 가장 싼 법무 대응입니다.

### ECS Fargate

| 태스크 | 사양 | 수 | 스케일 |
|---|---|---:|---|
| `web-api` | 0.5 vCPU / 1GB | 2 | CPU 70% |
| `admin-bo` | 0.25 / 0.5GB | 1 | 고정 |
| `worker` | 0.25 / 0.5GB | 1 | 고정 |

### RDS PostgreSQL 16

| 항목 | dev/stg | prod |
|---|---|---|
| 인스턴스 | db.t4g.small | **db.t4g.medium** |
| 가용성 | Single-AZ | **Multi-AZ** |
| 백업 | 7일 | **35일 + PITR** |
| 암호화 | KMS | KMS |

**오픈 D-14 에 Multi-AZ 로 전환**합니다. 그 전까지 월 $130 을 아낍니다.

> **커넥션 풀 계산** — 태스크 4 × 풀 10 = 40 ≤ `db.t4g.medium` 한도.
> 스케일 아웃 시 다시 계산하십시오. **커넥션 고갈은 CPU가 한가한데 응답이 멈추는 형태**라 원인 찾기가 어렵습니다.

### 그 외

| 리소스 | 설정 |
|---|---|
| ElastiCache Redis | 세션 · 정책 캐시(TTL 60초) · **오픈 전 Multi-AZ 전환** |
| S3 `sgb-uploads` | presigned URL 만 |
| S3 `sgb-contracts` | **Object Lock** |
| S3 `sgb-audit` | **Object Lock (Compliance, 5년)** |
| SQS | `q-notify` · `q-review` · `q-settlement` · `q-archive` (DLQ 有) |
| NAT Gateway | **EIP 고정** — 외부 연동 화이트리스트용 |

## 3-4. 시크릿

**전부 Secrets Manager 에 둡니다. 코드·환경파일·저장소에 두지 않습니다.**

```
DATABASE_URL
JWT_SECRET              운영은 32자 이상
NTS_SERVICE_KEY
TOSS_SECRET_KEY         결제(토스페이먼츠) — 서버가 읽는 이름. 전에는 PG 키로 적혀 있었습니다(v10.26 · G-174)
PASS_API_KEY
BANK_VERIFY_KEY
ALIMTALK_KEY
```

ECS 태스크 정의에서 주입합니다. **부팅 시 필수 키를 검증하고 없으면 프로세스가 뜨지 않습니다** — ECS 헬스체크가 롤아웃을 막습니다.

> **DB 에 키를 넣지 마십시오.** 백업·복제본에 전부 퍼집니다. 관리자 화면에서는 Secrets Manager 키 **이름**과 등록 여부만 관리합니다.

## 3-5. 배치 스케줄 (EventBridge)

`POST /api/v1/admin/jobs` 를 호출합니다.

| 주기 | job |
|---|---|
| 매시간 | `sla_alert` · `expire_badges` |
| 매일 03:00 | `attribution_archive` · `pii_purge` |
| 매일 09:00 | `deal_auto_confirm` |
| 매일 10:00 | `promo_expiry` |
| 수요일 10:00 | `settlement_batch` |
| 매월 1일 | `k_alert` |

**앱 내 cron 을 쓰지 않습니다.** ECS 태스크가 2개면 두 번 실행됩니다.

# 4. CI 설정

`.github/workflows/db-invariants.yml` 가 이미 있습니다. 하는 일:

```
1. PostgreSQL 16 서비스 기동
2. 마이그레이션 적용
3. 재실행 안전성 확인 (멱등)
4. DB 불변식 127건
5. 문서 재생성 → git diff --exit-code   ← 드리프트 차단
6. 문서 정합성 22건
```

**5번이 중요합니다.** 문서를 손으로 고치거나 재생성을 잊으면 CI가 막습니다.
