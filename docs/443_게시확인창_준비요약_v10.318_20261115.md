# 443. 게시 확인 창에 게시 준비 요약 — v10.318 (2026-11-15)

> 대표 결정(11/15): 「다음개발」 → A · B · C 모두 · 「승인, 병합」.
> **마이그레이션 없음.** 「게시」를 누르면 확인 창에 「게시 준비」 결과가 함께 나오고, 「아직」이 있으면 한 번 더 입력해야 게시됩니다. 서버는 막지 않고 기록만 남깁니다.

## 1. 바뀐 것 (정확한 위치)

| 곳 | 내용 |
|---|---|
| 운영 화면 **관 관리** › 탭 **「약관」** › 초안 줄 **「게시」** → 확인 창 | 끝에 「게시 준비 — 아직 n · 알아 둘 것 n · 됨 n」 · 「아직」 항목마다 「✗ 항목: 내용」 |
| 확인 뒤 입력 창 | 「아직」이 있으면 **「게시」라고 입력**해야 게시 — 다른 글 · 취소면 「게시하지 않았습니다 — 게시 준비 「아직」 n건」 |
| 게시 뒤 결과 줄 | 「아직」인 채 게시했으면 「게시 준비 「아직」 … 인 채로 게시함(감사 기록에 남음)」 |

## 2. API

| API | 바뀐 것 |
|---|---|
| `PATCH /admin/terms/{code}/publish` | 응답에 `readyCheck`(ready · todo 항목 이름 · info 수) — 게시하는 때의 게시 준비 결과 · 감사 기록 TERM_PUBLISH `after_data` 에도 남음. **막지 않음** — 지금 규칙(빈칸 거절 TERM_HOLES · 시행일 · 30일)은 그대로 |

서버에서 막지 않는 까닭: 위탁 표 · 법무 회신처럼 「아직」인 채 게시해야 할 때가 있고, `scripts/publish-terms.sh` · 옛 시험의 게시 길이 같은 API 를 씁니다. 막는 것은 화면의 입력까지, 서버는 기록.
