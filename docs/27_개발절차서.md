## ① 화면 레지스트리

**API 를 먼저 만들면 검증이 막습니다.** 화면 없는 엔드포인트를 허용하지 않기 때문입니다.

```json
{
  "id": "SB-MYP-XXX-010",
  "name": "화면 이름",
  "group": "MYP",
  "url": "/my/xxx",
  "p": "P1",
  "roles": ["BIZ_OWNER"],
  "gates": ["BUSINESS_VERIFIED"],
  "apis": ["GET /me/xxx", "POST /me/xxx"],
  "nav": "SB-MYP-MAIN-010",
  "new": true
}
```

`apis` 의 경로는 `/api/v1` 을 뺀 형태로 씁니다. **컨트롤러 경로와 정확히 일치해야** 병합이 됩니다.

## ② 마이그레이션

```bash
mkdir -p prisma/migrations/320_기능이름
$EDITOR prisma/migrations/320_기능이름/migration.sql
npm run db:migrate
```

### 규칙 5가지

| 규칙 | 이유 |
|---|---|
| **적용된 파일을 수정하지 않습니다** | 체크섬이 거부합니다. 새 번호를 추가하십시오 |
| **컬럼명을 추정하지 않습니다** | `docs/11_DB설계서.md` 를 먼저 보십시오 |
| **규칙은 DB 에 둡니다** | 앱에만 두면 SQL 로 직접 하면 통과합니다 |
| 코드 추가 시 라벨도 | CHECK 만 추가하면 화면에 영문이 나갑니다 |
| DB 변경은 2단계 | 컬럼 추가 → 코드 배포 → (1주 후) 구 컬럼 제거 |

> **컬럼명 추정으로 네 번 틀렸습니다.**
> `executed_by`(없음) · `EXECUTED`(→`DONE`) · `verified_at`(→`completed_at`) · `READ`(→`VIEW`).
> 전부 실행해 보고 나서야 발견됐습니다.

### 규칙을 DB에 두는 법

```sql
-- 검사 함수
CREATE OR REPLACE FUNCTION fn_assert_xxx() RETURNS trigger AS $$
BEGIN
  IF <위반 조건> THEN
    RAISE EXCEPTION 'XXX_VIOLATION: 사용자에게 보여도 되는 문장입니다.';
  END IF;
  RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER trg_xxx BEFORE INSERT OR UPDATE ON 테이블
  FOR EACH ROW EXECUTE FUNCTION fn_assert_xxx();
```

**예외 문구가 그대로 사용자에게 나갑니다.** `DbErrorFilter` 가 422로 옮기고 프런트가 그대로 띄웁니다.

## ③ DTO

요청·응답을 별도 클래스로 둡니다. **엔티티를 그대로 내보내지 않습니다** — 컬럼 추가가 곧 API 변경이 됩니다.

```ts
export class CreateXxxDto {
  @ApiProperty({
    minLength: 5,
    description: '30자 미만이면 자동검수를 통과하지 못하고 사람이 봅니다',
  })
  @IsString() @MinLength(5) title!: string;
}
```

**설명에 "왜 그런지"를 씁니다.** "제목"이 아니라 위처럼 쓰면 프런트가 UX를 설계하는 근거가 됩니다.

| 항목 | 규칙 |
|---|---|
| 요청 | `class-validator` + `@ApiProperty` 를 같은 필드에 |
| 응답 | 별도 클래스 |
| 열거형 | `@ApiProperty({ enum: [...] })` |
| 금액 | `number` (정수). `Float` 금지 |
| 상태 | `status` + `statusLabel` 함께 |

## ④ 서비스

**상태 전이만 합니다. 규칙을 재검사하지 않습니다.**

```ts
async submit(input: CreateXxxDto) {
  return this.db.transaction(async () => {
    const [row] = await this.db.query(
      `INSERT INTO xxx (...) VALUES (...) RETURNING id, status`, [...]);
    // 금칙어·제한업종·한도 검사가 여기 없습니다. 트리거가 합니다.
    await this.reviews.enqueue({ targetId: row.id });   // 같은 트랜잭션
    return row;
  });
}
```

| 규칙 | 이유 |
|---|---|
| **`tx` 인자를 만들지 않습니다** | `AsyncLocalStorage` 가 전달합니다. 한 곳만 빠뜨려도 트랜잭션 밖에서 돕니다 |
| 리포지토리는 트랜잭션을 열지 않습니다 | 서비스가 엽니다. 그래야 다른 모듈도 같은 트랜잭션에 들어옵니다 |
| append-only 테이블에 update/delete 금지 | DB가 막지만 컴파일 타임이 낫습니다 |
| 0행 UPDATE 는 409 | 권한 없음과 이미 처리됨을 구분하지 않습니다 |

### 오류 던지기

```ts
import { PolicyViolation, StateConflict, Forbidden, NotFound } from '../../core/errors';

throw new StateConflict('ALREADY_DECIDED', '이미 처리된 건입니다.');       // 409
throw new PolicyViolation('QUOTA_EXCEEDED', '이번 달 한도를 모두 썼습니다.'); // 422
```

| 클래스 | 상태 | 언제 |
|---|---|---|
| `NotFound` | 404 | 대상이 없음 |
| `Forbidden` | 403 | 권한·게이트 |
| **`StateConflict`** | **409** | **재시도해도 같음** |
| **`PolicyViolation`** | **422** | **다른 값으로 재시도 가능** |

**409와 422를 섞지 마십시오.** 프런트가 재시도 버튼을 띄울지 판단해야 합니다.

## ⑤ 컨트롤러

```ts
@Post()
@ApiBearerAuth()
@Roles('BIZ_OWNER', 'BIZ_STAFF')
@RequireGate('IDENTITY_VERIFIED')
@Audit('XXX_CREATE', 'XXX')
@ApiOperation({
  summary: '한 줄 요약',
  description: '**왜 이런 제약이 있는지**를 씁니다. 프런트가 읽습니다.',
})
@ApiOkResponse({ type: XxxResultDto })
@ApiResponse({ status: 422, description: 'QUOTA_EXCEEDED · RESTRICTED_CATEGORY', type: ErrorDto })
create(@Body() dto: CreateXxxDto) {
  return this.service.submit(dto);
}
```

### 데코레이터 세트

| 데코레이터 | 빠뜨리면 |
|---|---|
| `@Roles` | **권한이 뚫립니다** |
| `@RequireGate` | 게이트 안내가 불친절해집니다 (DB는 여전히 막음) |
| `@Audit` | 감사 기록이 없습니다 |
| `@PiiAccess` | 개인정보 조회 이력이 안 남습니다 |
| `@ApiOperation` · `@ApiResponse` | 프런트가 스키마를 못 받습니다 |

**`@PiiAccess` 는 개인정보를 반환하는 조회에만** 붙입니다.

```ts
@Get('accounts')
@PiiAccess('ACCOUNT', '회원 관리')
```

### 라우트 순서 주의

**고정 경로를 동적 경로보다 먼저 정의하십시오.**

```ts
@Patch('integrations/egress-ip')   // ← 먼저
@Patch('integrations/:code')       // ← 나중
```

반대면 `egress-ip` 가 `:code` 에 먹혀 "없는 연동입니다"가 나옵니다. **실제로 겪었습니다.**

# 4. 프런트 개발

## 4-1. 타입은 생성합니다

```bash
cd site && npx openapi-typescript ../docs/06_openapi.json -o src/lib/schema.ts
```

**DTO 를 손으로 옮겨 적지 마십시오.**

## 4-2. 하지 말아야 할 것

| 유혹 | 대신 |
|---|---|
| 상태 라벨 하드코딩 | `statusLabel` 을 씁니다 |
| 역할·게이트 재계산 | `canInquire` 같은 서버 판정을 씁니다 |
| 광고와 일반 목록 합치기 | `promoted` / `organic` 분리 유지 |
| 목적지 없는 링크 숨기기 | `available: false` 를 점선으로 표시 |
| 스텁을 실동작처럼 | `stub: true` 를 화면에 표시 |
| 문구 하드코딩 | `GET /ui-messages` |
| `localStorage` 에 토큰 | HttpOnly 쿠키 (SSR 이 읽어야 함) |

## 4-3. 오류 처리

```tsx
if (err.status === 409) { /* 재시도 버튼 없이 "다시 불러오기" */ }
if (err.status === 422) { /* message 를 그대로 표시 */ }
if (err.status === 403) { /* code 에 따라 유도 화면으로 */ }
```

| code | 이동 |
|---|---|
| `IDENTITY_REQUIRED` | `/verify` |
| `BUSINESS_REQUIRED` | `/my/business` |
| `SUBSCRIPTION_REQUIRED` | `/my/subscription/upgrade` |

**한도 초과는 구독 전환의 가장 강한 순간입니다.** 토스트로 끝내면 매출 기회를 버립니다.

## 4-4. 화면 파일명

```
site/src/app/my/xxx/page.tsx           사용자 웹 — 경로가 곧 화면
web/src/app/admin/Xxx.tsx              운영 BO
```

**주석 첫 줄에 화면 ID를 씁니다.** 71화면을 소수 인원이 추적하는 방법입니다.

```tsx
/** SB-MYP-XXX-010 화면 이름 */
```

# 5. 테스트

## 5-1. 목 DB 를 쓰지 않습니다

이 시스템의 규칙 대부분이 트리거와 CHECK 에 있습니다. **목으로 테스트하면 아무것도 검증되지 않습니다.**

## 5-2. 검증 4층

| 층 | 명령 | 대상 |
|---|---|---|
| DB 불변식 | `npm run db:verify` | 실 PostgreSQL · 127건 |
| 문서 정합성 | `node scripts/verify-docs.js` | 22건 |
| 부팅 | `npm run smoke` | 라우트 115 · 중복 |
| 전체 | `npm run verify` | 위 전부 + 타입 + 빌드 |

## 5-3. 동시성 시험

트랜잭션이 걸린 코드를 고쳤다면 겹쳐 실행해 보십시오.

```
옛 구현(단일 커넥션 공유): A 유실 — B의 ROLLBACK에 휘말림
현재:                      A는 커밋 · B만 롤백
```

# 6. 코드 리뷰 체크리스트

```
□ 화면 레지스트리에 등록했는가
□ 규칙을 DB 에 뒀는가 (앱에만 두면 SQL 로 우회됩니다)
□ 컬럼명을 DB설계서에서 확인했는가
□ app.module 과 dump-swagger 에 배선했는가
□ 데코레이터 세트를 다 붙였는가
□ 고정 경로를 동적 경로보다 먼저 뒀는가
□ 409 와 422 를 구분했는가
□ 문구를 소스에 하드코딩하지 않았는가
□ append-only 테이블에 update/delete 를 만들지 않았는가
□ 불변식 시험을 추가했는가 (막는 것 + 통과하는 것)
□ npm run docs 후 커밋했는가
□ npm run verify 가 통과하는가
```

# 7. 자주 겪는 문제

| 증상 | 원인 |
|---|---|
| 라우트가 안 생김 | `app.module.ts` 배선 누락 |
| `DUPLICATE ROUTES` | 두 컨트롤러가 같은 경로 정의 |
| 고정 경로가 404 | 동적 경로가 먼저 등록됨 |
| 문서 드리프트 | `npm run docs` 후 커밋 안 함 |
| `codes.ts 드리프트` | `node scripts/gen-codes.js > src/generated/codes.ts` |
| `레지스트리에 없는 API` | `spec/screens.json` 에 화면 연결 |
| 화면에 영문 코드 | `code_labels` 에 라벨 누락 |
| 422 인데 프런트가 못 읽음 | `@ApiResponse(422)` 누락 |
| 트랜잭션이 안 걸림 | `this.db.transaction()` 밖에서 쿼리 |
| 시험이 다음 실행 방해 | `fixture.sql` 에 정리 구문 누락 |
