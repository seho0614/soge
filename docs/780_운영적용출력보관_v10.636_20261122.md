## 1. 결론

- 운영 적용 때 대표가 붙여 넣는 precheck · apply · postcheck 출력에는 **오픈 차단 · 약관 게시 수 · postcheck 통과 / 실패 / 확인** 같은 실제 숫자가 있지만, 대화에만 남고 킷 · 저장소에는 없었습니다. 그래서 다음 절차서 초안의 precheck [5] 는 「`오픈 차단 …`」처럼 빈 모양, postcheck 기대는 〔채울 것〕이었습니다.
- 이번 판부터
  1. 붙여 넣은 출력을 `tools/ops-result-save.py <올린 판> <파일>` 로 **`~/kits/ops/results/<판>_apply.txt`** 에 남깁니다(결과 줄 「적용 전 점검 —」 · 「적용 후 확인 —」이 있어야 · 비밀 값처럼 보이는 줄이 있으면 저장 안 함 · 덮어쓰지 않음).
  2. 절차서 초안 도구(`ops-doc-draft.py --results`, 기본 그 폴더)가 지금 운영 판의 파일을 읽어 **precheck [5] 에 실제 오픈 차단 · 약관 줄**, **postcheck 기대에 실제 통과 · 실패 · 확인**을 적습니다(`--postcheck-base` 를 따로 주면 그것이 먼저).
- v10.617 적용 출력(11/22 02:01 ~ 02:16 UTC · 275줄)을 저장했습니다 → v10.617 → v10.626 초안에서 [5] `오픈 차단 11건 [ASSUME:4 INTEGRATION:5 READY:2]` · `약관: 게시 11(…) · 초안 2`, postcheck 기대 **통과 54 · 실패 0 · 확인 5** 가 채워짐을 확인했습니다.
- 마이그레이션이 `open_blockers` · `terms` 표에 쓰면(INSERT · UPDATE · DELETE · ALTER) [5] 에 ⚠ 「숫자가 바뀔 수 있음」을 붙입니다.
