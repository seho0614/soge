# 739. 가입 퍼널 분석 (v10.597 · 2026-11-21 · 16차 회원 · 성장 ⑬)

## 1. 결론
가입 화면부터 첫 거래까지 **어디서 많이 멈추는지**를 **숫자로만** 봅니다(누가 멈췄는지는 알 수 없음). 대부분은 **이미 있는 기록을 읽기만** 하고, 새로 쌓는 것은 **가입 화면 1 ~ 5단계에 닿은 하루 수**뿐입니다(스위치 `grw.signup_steps` 처음 **off**). 위치: **회원 › 회원 성장 › 가입 퍼널** · SB-ADM-GRW-020.

## 2. 재사용한 기능 (넓힘)
| 기능 | 쓰는 곳 |
|---|---|
| 화면 사용 통계(v10.508 · D274 `site_usage_daily`) | `/signup` · `/signup/done` 화면 본 수(`site.usage_stats` on 일 때만 쌓임 · 꺼져 있으면 「꺼져 있음」) |
| 유입 기록(D010 `attribution_events` · source INTRO · AD) | 유입 경로 「소개코드 링크」 · 「광고」 — 가입 뒤 하루 안까지 이어진 기록 |
| 추천 관계(D189 `introducer_referrals`) | 유입 경로 「추천 코드」(먼저 봄) |
| 회원 · 활동 표(accounts · favorites · conversations · listings · requests · deals) | 가입 → 본인인증 → 첫 활동(관심 · 문의 · 매물 · 요청) → 첫 거래(취소 아닌 거래) |
| 운영 · 직원 역할 목록(`STAFF_ROLES` · admin/staff.ts) | 운영 · 직원 계정 셈에서 뺌 |

## 3. 새로 쌓는 것
| 항목 | 내용 |
|---|---|
| 보내는 곳 | 가입 화면(SignupWizard) — 단계가 바뀔 때 `grwStep(step)` → `POST /site/grw/signup-step { s: 1 ~ 5 }` |
| 보내는 것 | 단계 번호 하나 — 계정 · 이메일 · 입력 글 · 방문자 번호 · 쿠키 없음 |
| 보내지 않음 | 스위치 off(`GET /site/grw/switches` 로 탭마다 한 번 확인) · DNT · GPC · 로봇 · 같은 탭 같은 단계 두 번째 |
| 저장 | `grw_signup_steps_daily`(day · step · n) — 칸이 이것뿐 |
| 보관 | `site.usage_keep_days`(400일) 지난 줄 정기 작업 `grw_daily`(08:00)가 지움 |
| 제한 | IP 지문 1분 60번(메모리에서만 · 저장 안 함) |

## 4. 화면 (SB-ADM-GRW-020)
가입 화면 본 수 → 가입 단계 1 ~ 5(앞 단계 대비 이탈 %) → 가입 → 본인인증 → 첫 활동 → 첫 거래 · 유입 경로 넷(추천 코드 · 소개코드 링크 · 광고 · 직접)별 수와 비율 · 날마다 가입 · 기간 7 · 30 · 90일.

## 5. 처리방침 (법무 확인)
- 단계 수는 개인을 알아볼 수 없는 하루 합계라 **동의 대상은 아님으로 봄**(v10.508 판단과 같음). 그래도 **처리방침 1.2 게시 뒤** 「자동 수집 장치」 조의 화면 사용 합계 문장에 「가입 화면 단계별 합계」를 덧붙인 뒤 켬을 권함 — **법무 확인**.
