# 653. 매물 끌어올리기 (v10.515 · 2026-11-20)

## 1. 결론(대표 결정 11/20)
「**끌어올리기는 상황에 따라 전환 가능 · 관리자가 지정.**」
- 방식 `lsx.bump_mode` = **OFF(처음) · FREE · PAID** — 운영 화면에서 SUPER 가 언제든 바꿈(바뀐 기록 · 사유는 「전체 설정」 기록 그대로).
- **FREE**: 회원마다 기간당 무료 횟수(`lsx.bump_free_count` 3 / `lsx.bump_period_days` 30일) · 같은 매물 최소 간격(`lsx.bump_min_hours` 24시간).
- **PAID**: 1회 금액(`lsx.bump_price` · 공급가 · 처음 0 = 정하지 않음 → PAID 로 못 바꿈) + 부가세(D243 별도 시작일 뒤 `fn_vat10`) · 기존 결제 어댑터(키 없으면 시험 결제 · 간주) · **결제 승인 뒤에만** 끌어올림 · 최소 간격은 무료와 같음.
- 회원 등급 · 파트너별로 다르게 하지 않음 — **한 가지 규칙**(다음 후보: 등급별 무료 횟수 · 파트너 묶음 금액).
- **노출 가산은 방식과 상관없이 같은 상한 · 감쇠** — 유료라고 더 올리지 않음(노출 공정성).
- 운영자 직접 끌어올리기는 **바로잡기용으로만**(대표 결정 11/20) — **SUPER 만** · 사유 종류 **「오류 바로잡기」(FIX_ERROR) · 「회원 요청 대신」(MEMBER_REQUEST)** 둘 + 글 사유 · 그 밖 사유는 서버(DTO `@IsIn` · 서비스 422 `LSX_ADMIN_BUMP_REASON`) · DB(CHECK · 트리거 `trg_lsx_admin_bump_guard` 가 SUPER 아님을 막음 `LSX_ADMIN_BUMP_SUPER`) 둘 다 막음 · 감사 `LSX_ADMIN_BUMP` · 「끌어올림」 표시 그대로 · 같은 상한 · 감쇠.

## 2. 노출 엔진에 주는 영향(INV-11 · 전자상거래법)
| 항목 | 내용 |
|---|---|
| 바뀌는 곳 | 기본 목록(`ListingRepository.organic`)의 **최신순(RECENT) 정렬 키 하나** — `coalesce(greatest(게시 시각, 끌어올린 시각), epoch)` · 효과 중인 줄은 `lsx_bump_live` |
| 상한 | 끌어올린 시각 = 그 순간(앞날 없음 · DB `LSX_BUMP_FUTURE`) — 그 시각의 새 글과 같은 자리에서 시작해 **더 위로 가지 않음** · 효과 시간 `lsx.bump_effect_hours`(처음 72 · 1 ~ 168 · DB 상한 168시간 `LSX_BUMP_CAP`) |
| 감쇠 | 새 글이 올라올수록 내려감 · 효과 시간이 지나면 `lsx_hourly` 가 지워 **원래 자리**(게시 시각) |
| 그대로 | 소개비 · 인기 · 관련도 · 마감 · 금액 정렬 · 우선노출(광고) 영역 · 건수 · 상세 · 구독 가중치 없음(INV-11 · 기본 정렬에 대가 가중치 없음) · `ExposureEngine`(쓰이지 않는 옛 엔진) 그대로 |
| 표시 | 효과 중이면 카드에 「**끌어올림**」, 유료면 「**유료 끌어올림**」(`bumpLabel` · 사용자 웹 GwList · GwCard · ListingCard) — 대가에 따른 순위 표시(전자상거래법) · **법무 확인** → **2026-11-21 대표 법무 확인 끝** |
| 커서 | 키셋 커서가 같은 식을 쓰므로 쪽 넘김이 어긋나지 않음 · 효과가 끝나는 순간 그 매물 자리만 바뀜 |
| 색인 | 정렬 식이 바뀌어 `idx_listings_browse(published_at)` 순서를 그대로 타지 못함 — 지금 규모(수천 건)는 문제없음 · 커지면 `lsx_bump_live` 와 합친 정렬 칸 검토 |

## 3. 유료 흐름
1. `GET /me/lsx/listings/{id}/bump-quote` — 방식 · 남은 무료 횟수 · 금액(공급가 · 부가세 · 합계) · 다음 가능 시각.
2. `POST /me/lsx/listings/{id}/bump`(결제 없이) → 422 `LSX_BUMP_PAYMENT_REQUIRED`(금액 · 주문 번호 · 상품 이름) — 결제 **전에** 상태 · 간격을 먼저 봄(결제 뒤 막히면 돈만 나감).
3. 결제창(토스 · 키 없으면 시험 결제 `stub_…`) → 성공 주소 `/my/listing-tools/bump-pay` → 같은 API 에 `paymentKey · orderId · amount` → `confirmOrRecover`(이미 승인된 결제는 조회로 인정) → 승인 뒤에만 `lsx_bump_payments` + 끌어올림(같은 트랜잭션).
4. 결제 키 한 번만(끌어올리기 · 소개코드 · 구독 청구서와도 대조 · 409 `PAYMENT_KEY_USED`) · 금액 다르면 422 `LSX_AMOUNT_MISMATCH`.
5. 환불: **끌어올린 뒤 회원 환불 없음**(문구 법무 확인 · **2026-11-21 대표 법무 확인 끝**) · 결제 오류 · 중복 결제는 운영 환불(SUPER · 사유 · 결제사 취소 · 시험 결제는 표시만 · 그 효과도 끝냄).
6. 전표(초안 · 세무사 확인): `LSX_BUMP_PAID` 차변 PG 받을 돈 / 대변 끌어올리기 매출(`REV_BUMP` · 404 용역매출) · 부가세예수금 · `LSX_BUMP_REFUND` 반대 · 시험 결제는 `acct.include_stub` 따름.
