# 694. 월간 뉴스레터 (v10.556 · 2026-11-21)

## 1. 결론
달마다 **소식 메일 한 호**를 운영 화면에서 만듭니다. 서버가 공지 · 인기 매물 · 이벤트 후보를 골라 두고, 운영자가 고르기 · 틀 고치기 · 미리보기 · 나에게 시험을 한 뒤 **최고 관리자(SUPER)가 보냅니다**. 위치: 운영 **회원 › 월간 뉴스레터**(SB-ADM-OPZ-010 · 탭 `opz-newsletter` · 문자 · 메일 캠페인 바로 뒤).

**새 발송 길은 없습니다.** 보내기 · 시험은 ㊳ 문자 · 메일 캠페인(D268 · docs/621)에 **EMAIL · 대상 ALL 캠페인 한 줄**로 넘깁니다. 그래서 정보통신망법 제50조 관련 규칙을 캠페인 서버가 그대로 지킵니다.

| 지키는 것 | 누가 |
|---|---|
| 마케팅 수신 동의가 지금 유효한 회원만 · 2년 넘은 동의 뺌 · 반송 · 수신 거부 주소 뺌 | 캠페인 서버(받는 사람 고정 때 · 보낼 때 다시) |
| 21:00 ~ 08:00 은 야간 광고 동의자만 · 나머지는 08:00 뒤 | 캠페인 서버 · DB 트리거 |
| 제목 앞 **(광고)** · 끝에 보낸 곳 · 연락처 · 무료 **수신 거부 링크** | 캠페인 renderCampaign(운영자가 지우지 못함) |
| 처음 꺼짐 | `opz.nl_enabled` off **그리고** `campaign.enabled` off · `campaign.send_mode` ASSUME(보내지 않고 기록만) |

## 2. 전체 구조
1. 표 `opz_nl_issues` — 달(YYYY-MM)마다 한 호(취소한 호 빼고 · 부분 고유 색인) · 호 이름 · 메일 제목(90자 · 보낼 때 앞에 (광고)) · 첫 인사(500자) · 틀(10 ~ 1,200자 · 주소 직접 쓰기 금지 DB CHECK) · 고른 공지 · 매물 · 이벤트 id(묶음마다 10개) · 채운 본문(2,000자 = 캠페인 글 한도) · 상태(초안 → 보냄 · 초안 → 취소 · 보냄 → 취소) · 넘긴 캠페인 번호.
2. 트리거 `trg_opz_nl_guard` — 보냈거나 취소한 호는 글을 못 고침 · 상태 되돌림 막음 · 지우기 막음.
3. 서버 `src/modules/opz/newsletter.ts` — 후보 · 틀 채우기 · 캠페인 맞추기(syncCampaign) · 시험 · 보내기 · 취소. 설정 `opz-settings.ts`.
4. **틀 채우기**는 ㊿ 메일 문구 템플릿(D280 · b280)의 `renderMailTemplate` 재사용 — 자리값 `{month}` `{intro}` `{notices}` `{listings}` `{events}` `{base}` · 한 번만 바꿈. 주소는 서버가 만든 것만 들어감(공지 `/community?board=NOTICE#n-<id>` · 매물 `/<관>/<id>` · 이벤트 `/money/event`).
5. 후보: 공지 = 게시 중 · 끝나지 않음 · **손님에게도 보이는 등급**(fn_notice_grades(NULL) · 관리자 등급 뺌) · 최근 62일 / 매물 = 게시 중 · 켜진 관 · 최근 `opz.nl_listing_days`(30)일 · 좋아요 · 조회 순 / 이벤트 = 게시 중 · 안 끝남. 각 20개 · 처음 `opz.nl_items`(5)개씩 골라 둠.

## 3. API (ADMIN · SUPER · `/api/v1/admin/opz`)
| 방법 | 주소 | 누가 | 오류 |
|---|---|---|---|
| GET | /newsletters | ADMIN · SUPER | |
| GET | /newsletters/{id} | ADMIN · SUPER | 404 |
| POST | /newsletters | ADMIN · SUPER | 409 OPZ_NL_EXISTS · 422 OPZ_NL_YM · OPZ_NL_TITLE |
| PUT | /newsletters/{id} | ADMIN · SUPER | 409 OPZ_NL_STATE · 422 OPZ_NL_FRAME · OPZ_NL_PICK · OPZ_NL_SUBJECT · OPZ_NL_INTRO |
| POST | /newsletters/{id}/test | ADMIN · SUPER | 422 OPZ_NL_LONG · MKT_TEST_* |

| POST | /newsletters/{id}/cancel | 초안 ADMIN · 보낸 호 SUPER | 409 OPZ_NL_STATE · OPZ_NL_DONE |
| PUT | /newsletter-settings | **SUPER** | 422 OPZ_REASON · OPZ_RANGE · OPZ_NOTHING |

설정 3: `opz.nl_enabled` off · `opz.nl_items` 5(1 ~ 10) · `opz.nl_listing_days` 30(7 ~ 90). 정기 작업 `opz_daily`(09:10)이 켜짐인데 이달 호가 없으면(10일부터) 운영 알림 `OPZ_NL_REMIND`(INFO · 달마다 한 번).

## 4. 켜는 순서(대표)
1. 회원 › 문자 · 메일 캠페인에서 보낸 곳 이름 · **연락처**(campaign.contact) 채움 → 메일 준비됨 확인.
2. 이 화면에서 이달 초안 → 고르기 · 틀 → 「나에게 시험」(간주면 기록만 · 미리보기 확인).
3. 법무 확인(5절) 뒤 SUPER 가 `opz.nl_enabled` on · 캠페인 `campaign.enabled` on · 방식 LIVE.
4. 「보내기」(확인 글자 · 예약 가능) → 캠페인 정기 작업(5분)이 보냄 · 결과는 이 화면 목록 · 캠페인 화면.

## 5. 법무 · 처리방침 — **법무 확인 끝(11/21 대표)**
1. 새로 모으는 개인정보 없음 · 받는 사람은 기존 마케팅 수신 동의자 — 처리방침 고칠 곳 없음.
2. 뉴스레터(공지가 섞인 소식 메일)는 **광고로 다룸**(제목 (광고) · 마케팅 동의자만 · 수신 거부) · 한 달 한 호 — 표기 · 수신 거부 처리는 ㊳ 캠페인(docs/621)과 같음.
3. 매물 제목을 메일에 실음 — 매물 주인 이름 · 연락처는 싣지 않음(제목 · 관 이름 · 주소만).
