# 632. 협력사(공급사) 평가 (v10.494 · 2026-11-20)

## 1. 결론
⑯ 거래처 대장의 **매입처(SUPPLIER · BOTH)** 를 **분기마다** 평가합니다. **납기 점수는 ㉑ 국내 발주 · 입고 자료로 자동**으로 셈하고, 품질은 ③ 품질 클레임 수로 제안(고칠 수 있음), 가격 · 대응은 사람이 매깁니다. 가중 합으로 등급(A ~ D)을 내고, **확정하면 고치지 않습니다**(DB 도 막음). 위치: **소개몰 › 협력사 평가** · SB-ADM-QLT-010 · API `/admin/qlt/suppliers` · `/admin/qlt/pos/{id}/due`.

## 2. 납기 — 어떻게 자동으로 셈하나
| 항목 | 규칙 |
|---|---|
| 대상 발주 | 그 분기에 **입고한**(acct_pos.state = RECEIVED · received_on 이 분기 안) 그 거래처 발주 |
| 납기일 | `qlt_po_due.due_on` — ㉑ 발주 표(acct_pos)에 칸이 없어 표를 고치지 않고 따로 둠. **발주 상태(ORDERED)일 때만** 넣고 고침(입고 · 취소 뒤에는 그대로 · DB 트리거) |
| 납기일이 없으면 | 발주일 + `qlt.po_lead_days`(처음 7일 · 1 ~ 90) |
| 제때 | 입고일 ≤ 납기일 |
| 납기 점수 | 제때 ÷ 입고 발주 × 100(반올림) · 그 분기 입고가 없으면 직접 넣음(넣지 않으면 100) |
| 늦은 날(평균) | 늦은 발주만의 (입고일 − 납기일) 평균 |

## 3. 점수 · 등급
| 칸 | 처음 값 · 셈 |
|---|---|
| 품질 | 100 − 10 × 그 분기 클레임 수(반려 뺌 · 0 아래 없음) — **제안**이고 저장 때 바꿀 수 있음 |
| 가격 · 대응 | 사람이 0 ~ 100 |
| 가중치 | `qlt.eval_weights` = 납기,품질,가격,대응 = **30,40,15,15**(합 100이 아니면 처음 값으로 셈) |
| 합계 | (납기 × 30 + 품질 × 40 + 가격 × 15 + 대응 × 15) ÷ 100 · 소수 한 자리 |
| 등급 | `qlt.eval_grades` = **90,80,70** 이상 A · B · C · 나머지 D |

- 숫자는 회사 일반 기준(법정 값 아님) — 설정은 SUPER 가 바꿈. 저장할 때의 가중치 글자(weights)를 평가 줄에 같이 남겨, 나중에 가중치를 바꿔도 옛 평가는 그대로 읽힙니다.
- 같은 거래처 · 같은 분기는 한 줄(UNIQUE) — 다시 저장하면 덮어쓰고, **확정(FINAL)** 하면 저장 · 확정 모두 409 · DB 도 막음 · 지우지 않음.

| 표 | 내용 |
|---|---|

| `qlt_sup_evals` | 거래처 · 분기 · 입고 발주 수 · 제때 · 늦은 날 · 클레임 수 · 점수 4 · 가중치 · 합계 · 등급 · 메모 · 초안/확정 |

| API | 권한 | 설명 |

## 5. 권한 · 세무사
- 탭 `qlt-supeval`(소개몰 묶음 · SUPER · ADMIN · PAYOUT). ㉕ 권한 시드: 업무 `qlt-supeval` · 묶음 R_ADMIN · R_PAYOUT 네 단계 · 주소 5.
- 세무사(ACCOUNTANT)는 보지 않음 — 탭 앞머리가 `acct-` 가 아니고 API 가 `/admin/acct/` 밖(`/admin/qlt/`).
