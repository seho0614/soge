# 625. 계약 검토 요청 (v10.487 · D269 · 2026-11-20)

## 1. 결론
계약을 맺기 전 **계약서 파일을 올려 검토를 요청**하고, 요청한 사람이 아닌 운영자가 **검토 의견**(위험 낮음 · 보통 · 높음 · 외부 변호사 의견 옮김)을 남기면, **SUPER(요청한 사람 아님)가 승인 · 반려**합니다.
승인한 계약을 맺으면 ⑯ 계약 대장(회계 › 매입 · 경비 › 계약)에 넣고 여기서 **연결**합니다. 위치: **사무 › 「계약 검토」** · SB-ADM-LGL-020.

## 2. 흐름
| 단계 | 누가 | 상태 |
|---|---|---|
| 요청 — 계약 이름 · 종류(새 계약 · 갱신 · 변경 · 해지) · 상대 · 금액 · 검토 희망일 · 보아 줄 곳 · 계약서(LGL_DOC 1 ~ 5개) | 운영 관리자 | REQUESTED |
| 검토 의견(여러 번 · 쌓기만 · 수정본 파일 3개) | 요청한 사람이 아닌 운영 관리자 · SUPER | 첫 의견이면 REVIEWED |
| 승인 · 반려(사유 2자 이상) | SUPER · 요청한 사람 아님 · 의견이 있어야 함 | APPROVED · REJECTED |
| 취소(결정 전) | 요청한 사람 · SUPER | CANCELED |
| 계약 대장 연결(한 번 · 바꾸지 않음) | 운영 관리자 | 상태 그대로 |

- 갱신 · 변경 · 해지 요청은 계약 대장의 기존 계약을 꼭 고릅니다(422 `LGL_REVIEW_LINK`).
- DB 가 막음: 요청 내용 고치기 · 지우기 · 상태 거꾸로 · 의견 전 승인 · 요청한 사람의 의견 · 요청한 사람의 승인 · 반려(`ck_lgl_rv_self`) · 연결 바꾸기.

## 3. 알림
검토 희망일이 지났는데 결정 · 취소가 안 됐으면 운영 알림 `LGL_REVIEW_LATE`(경고 · 요청마다 한 번 · 결정 · 취소하면 풀림 · 정기 작업 `lgl_due`).

## 4. 판단 — 결재선(approval.ts)에 넣지 않은 까닭
- 결재선(품의 · 경비 청구 · 수동 전표)은 돈이 나가는 문서용이고, 새 종류를 더하려면 `DOC_KINDS` · `fn_acct_doc_info` 를 고쳐야 해서 다른 묶음(㉜ 출장)과 겹칩니다.
- 계약 검토는 「의견 → SUPER 결정」 두 단계로 충분해 따로 상태를 둡니다. 계약으로 돈이 나가면 기존처럼 계약 대장 · 고정비 · 매입 · 결재선을 탑니다.

## 6. 확인할 것
- 계약서 · 수정본 파일은 법무 전용 용도 LGL_DOC(대표 11/20) — 운영 관리자 · SUPER · 올린 사람만 엶 · 지급 담당 · 세무사 · 검수 담당은 못 엶(404).
- 외부 변호사에게 보내는 일은 이 화면 밖(메일) — 받은 의견을 「외부 변호사 의견」으로 옮겨 적습니다.
