# 619. 소개몰 정기 배송 (v10.481 · 2026-11-20)

## 1. 결론
회원이 **직판 상품 옵션 · 수량 · 배송지 · 주기**를 정하면, 결제일마다 서버가 주문을 만들고 **정기 결제**합니다. 결제는 기존 결제 어댑터(`payment.provider` · `chargeWithBillingKey` · 구독과 같은 카드 등록 키 `billing_keys`)를 쓰고, 처음에는 **간주(ASSUME)** — 결제대행사를 부르지 않고 시험 결제로 승인합니다. `mall.subscribe`(처음 off) 와 「주문 받기」(`mall.order_open`)가 **모두 켜져 있을 때만** 돕니다. 위치: **소개몰 › 정기 배송** · SB-ADM-MBS-030 · 운영 API `/admin/health/subscriptions` · 회원 `/me/health/subscriptions`.

| 항목 | 규칙 |
|---|---|
| 신청 | 직판 · 판매 중 · 켠 옵션 · 수량 1 ~ 10 · 본인 배송지 · 주기 14 · 28 · 30 · 60 · 90일 · 첫 결제일 내일 ~ 60일(비우면 내일) · 본인인증 회원 |
| 겹침 | 회원 · 옵션마다 해지 안 된 정기 배송 하나(DB 고유 색인 · 409 HLT_SUB_DUP) |
| 건너뛰기 | 다음 결제일 한 번(다시 누르면 풀기) → 그날 회차 SKIPPED · 다음 결제일 = 결제일 + 주기 |
| 멈춤 · 다시 | 멈추면 결제일이 지나도 안 돎 · 다시 하면 지난 결제일은 몰아서 하지 않고 내일부터 |
| 해지 | 끝(고치지 못함 · DB) · 이미 결제된 주문은 그대로 |
| 값 | 결제일의 **지금 판매가** × 수량 · 배송비(직판 0) |
| 실패 | 재고 · 판매 중지 · 결제 거절 → 주문 취소(재고 되돌림) · 회차 FAILED · 다음 날 다시 · `mall.subscribe_retry` 3번 이어서 실패하면 **멈춤** + 운영 알림 `MALL_SUBSCRIBE_FAIL` |
| 결과 모름 | 결제대행사 응답이 없을 때(D022 uncertain) — 실패로 적지 않고 회차를 「주문함」으로 남김(다음 날 새 주문을 만들지 않음) · 운영 알림 `MALL_SUBSCRIBE_UNCERTAIN`(CRITICAL) · 결제대행사에서 확인 |

## 2. 정기 작업 `mall_subscribe` (매일 07:10)
1. 스위치 확인(`mall.subscribe` · `mall.order_open`) — 하나라도 꺼져 있으면 아무것도 안 함.
2. 결제일이 오늘 이하인 진행 중 정기 배송(오늘 회차 · 처리 중 회차가 없는 것) 200개까지.
3. 건너뛰기면 SKIPPED → 다음 결제일.
4. 아니면 한 트랜잭션: 주문(`subscription_id` · 배송 요청 「정기 배송」) · 품목 · 결제 준비(CARD · READY) · 회차 ORDERED.
5. 청구 — `mall.subscribe_mode` = ASSUME(간주 · `stub = true` · 결제 키 `assume_sub_주문번호`) · LIVE(카드 등록 키로 `chargeWithBillingKey` · 같은 회차는 한 번만 청구되게 idempotencyKey `hltsub-회차`).
6. 승인 → 결제 PAID(주문 결제 완료는 기존 트리거) · 회차 PAID · 다음 결제일 · 실패 수 0.

운영 「지금 돌리기」(POST `/admin/health/subscriptions/run`)는 같은 일을 지금 함 — 날짜마다 한 번이라 두 번 눌러도 같음.

## 3. 외부 연동 · 켜는 순서
- 새 외부 연동 줄은 없음(토스 결제 어댑터 재사용 · `TOSS_SECRET_KEY` 가 없으면 기존 스텁) → verify-invariants 연동 수 그대로.
- 켜는 순서: ① 결제대행사 계약 · 정기 결제(빌링) 승인 ② 회원 카드 등록 화면(구독 결제 수단과 같음) ③ `mall.order_open` on ④ `mall.subscribe` on(ASSUME 로 하루 지켜봄) ⑤ `mall.subscribe_mode` = LIVE.
- LIVE 에서는 카드 등록 키가 없는 회원은 신청을 받지 않음(422 HLT_SUB_NO_CARD).
