### 4-2. 알아 둘 것

1. 접속 인증은 **꺼진 채**입니다. 켜기 전 대표 할 일(docs/363 9절): ① 「접속 인증」 탭 「지금 주소 넣기」로 집 IP 를 허용 목록에 ② 텔레그램 봇 토큰 · 운영 대화방(또는 운영자별 개인 대화) ③ 켜기(SUPER) → 휴대폰 핫스팟으로 인증 확인 ④ Nginx 허용 IP 풀기는 그다음(문자 연동 뒤).
2. 받을 곳이 없는 운영자가 있으면 켜기가 **422 로 막힙니다**(그 사람 이메일이 나옴) — 켜는 순간 잠기는 사람이 없게 한 안전장치입니다.
3. 문자 길(SMS · SMS_THEN_TELEGRAM)은 알림톡 업체 · `STAFF_IP_OTP` 템플릿 승인 뒤에만 고를 수 있습니다. 그 전에는 텔레그램 길만 씁니다.
4. 켠 뒤 ③ 핫스팟 확인을 하면 **「접속 인증 처음 보는 대역」 운영 알림이 하나 생기는 것이 정상**입니다(핫스팟은 처음 보는 대역). 운영 화면 「운영 알림」에서 「확인」하면 됩니다.
5. 급한 알림 메일 · 텔레그램 대기 목록은 **CRITICAL 먼저 · 최근 순 50건**입니다(v10.230 · D198). 남은 것은 메시지 끝 「보내지 못한 알림 n건 더」로 알리고 24시간 안에는 다음 차례에 이어서 보냅니다. 지금 운영은 메일 설정 전(NO_SMTP)이라 알림이 쌓이기만 하므로, 텔레그램을 켜기 전에 「운영 알림」 › 「한꺼번에 확인」(v10.232 · 풀린 것 · 24시간 넘은 INFO · WARN — CRITICAL 은 빼고 몇 건인지 먼저 보임)으로 정리하십시오. CRITICAL 은 하나씩 보고 확인합니다.
6. 「입점 열기 준비」는 스위치를 바꾸지 않습니다. 업종 정정신고(통신판매중개)를 마치면 그 줄의 「적기」(SUPER)로 신고 날짜 · 접수번호를 적습니다 — 둘 다 있으면 「준비됨」이 되고 판매 열기 판단에 들어갑니다(적은 값을 그대로 믿음 · 감사 기록 HLT_BIZ_REPORT). 일반 설정 화면에서 같은 값을 바꾸는 것도 SUPER 만입니다.
7. 개발 서버 `~/kits/release` 에 다른 판 킷(v10.225 · v10.227 · v10.229)이 있어도 **v10.232 킷만** 올립니다.

## 5. 되돌리기

| 상황 | 할 일 |
|---|---|
| 화면이 이상함 | `bash ~/sgb/deploy/aws/rollback.sh` → `yes` — 코드만 v10.224 로 돌아갑니다. DB 는 237 그대로 남지만 더한 것만 있어(표 · 칸 · 설정 · 템플릿 줄 · 트리거 · 함수) v10.224 코드가 그대로 돕니다. 소개몰 안내 띠 · 「접속 인증」 탭 · 「입점 열기 준비」는 사라집니다 |
| 되돌린 뒤 다시 v10.232 로 | `bash ~/sgb/deploy/aws/rollback.sh` 를 한 번 더 → `yes`(v10.232 판 폴더가 남아 있음) |
| 접속 인증을 켰는데 아무도 못 들어감 | 집 IP(Nginx 허용)에서는 허용 목록 IP 라면 그대로 들어갑니다. 그래도 막히면 운영 DB 에서 `admin.ip_verify` 를 off 로 — 명령은 Claude 에게 받아서 칩니다(30초 안에 반영) |
| DB 까지 | 보통 필요 없습니다. 하려면 RDS → `sgb-before-v10-232-YYYYMMDD` 복원 → `.env` 접속 주소 교체 → `pm2 restart sgb sgb-site sgb-jobs` 순서로 합니다. 스냅샷 뒤에 생긴 자료(가입 · 신청 등)는 사라집니다 |

## 6. 하지 말 것

- 적용 확인 중 「접속 인증」 스위치 켜기(4-2 ① ~ ② 를 마치기 전)
