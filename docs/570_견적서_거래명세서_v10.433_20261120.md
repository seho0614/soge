# 570. 견적서 · 주문서 · 거래명세서 · 발주서 인쇄 (v10.433 · 2026-11-20)

대표 11/19 「이카운트 연동은 보류 → 그냥 내부 시스템으로」 · 내부 ERP 완성 4가지 중 1.

## 1. 결론
거래처(⑯ 거래처 대장)에 **견적서 → 주문서 → 거래명세서**를 이어 만들고 인쇄합니다. 거래명세서를 **확정**하면 매출 전표와 세금계산서 요청으로 이어집니다.
위치: **회계 › 견적 · 명세서**(장부 묶음) · 화면 SB-ADM-ACC-380.

| 항목 | 내용 |
|---|---|
| 표 | acct_sales_docs(문서) · acct_sales_doc_lines(품목 줄) · acct_doc_counters(번호) |
| 번호 | Q(견적) · O(주문) · S(거래명세서) - YYMM - 0001(종류 · 달마다 1부터) |
| 셈 | 공급가 = 수량 × 단가(원 미만 버림) · 부가세 = 과세 줄 공급가 × 10%(원 미만 버림) · 면세 · 영세 0 |
| 고치기 | 내용은 DB 가 막음(ACCT_DOC_FIXED) — 「고치기」 = 새 판(rev+1 · 옛 판 superseded_by · 초안 · 보냄일 때만) |
| 상태 | 초안 → 보냄 → 확정 · 취소(사유) — 앞으로만 |
| 이어 만들기 | 견적 → 주문 · 거래명세서 / 주문 → 거래명세서(품목 그대로 · 앞 문서는 확정) |
| 매출 전표 | 거래명세서 확정 → 다음 전표 작업에서 SALES_DOC(차변 외상매출금 / 대변 매출 계정 · 부가세예수금) · 확정 뒤 취소 → SALES_DOC_CANCEL(반대) |
| 매출 계정 | 문서마다 고름(처음 REV_SALES 「매출(견적 · 거래명세서)」 · 404 용역매출) |
| 세금계산서 | 확정한 거래명세서 → acct_tax_invoices(kind SALES_DOC) 요청 → 전자세금계산서 /admin/etax/sales-doc/{id}/send · 발행되면 문서에 번호 · 발행한 명세서는 취소 막음 |
| 인쇄 | 브라우저 인쇄(새 창 · 종이 · PDF) · 공급자 = 설정 footer.*(회사 이름 · 사업자번호 · 대표 · 주소 · 전화) |
| 발주서 | ㉑ 국내 구매 발주(acct_pos · acct_po_lines) 인쇄 모양 GET /admin/acct/sales-docs/po/{id}/print |
| 권한 | 만들기 · 고치기 · 이어 만들기 SUPER · PAYOUT · ADMIN / 상태 · 세금계산서 SUPER · PAYOUT |

## 2. 주의
1. 매출 전표는 「확정」 때 생깁니다(발생주의 · 인도 기준). 견적 · 주문은 장부에 들어가지 않습니다.
2. 개인 거래처(사업자번호 없음) 세금계산서는 요청 줄만 생기고 주민번호 발행은 회계 프로그램에서.
3. 소개몰 직판 결제(MALL_SALE)와 겹치지 않게 — 소개몰 주문에는 거래명세서를 확정하지 마십시오(같은 매출이 두 번).

## 3. 시험 (test_v1433)
