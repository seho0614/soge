# 602. 출장 신청 → 여비 정산 → 경비 청구 (v10.464 · 2026-11-20)

## 1. 결론
출장 신청은 **⑯ 품의 하나를 같이 올려** 지금 결재선 · 결재함 · SUPER 결재를 그대로 탑니다. 다녀온 뒤 본인이 정산하면 **⑫ 경비 청구 하나**가 품의에 연결되어 올라가고, 승인 · 지급 · 전표는 경비 청구 그대로입니다. 한 출장에 살아 있는 청구는 **하나만**(DB 가 막음). 위치: **사무 › 출장** · SB-ADM-OFC-030.

| 단계 | 하는 일 | 표 |
|---|---|---|
| 신청 | 가는 곳 · 지역(서울 · 광역시 · 그 밖) · 목적 · 가는 날 · 오는 날 · 교통비 예상 → 예상 여비 셈 → 품의(계정 EXP_TRAVEL 여비교통비 · 쓸 날 = 가는 날) | ofc_trips + acct_requisitions |
| 결재 | 사무 › 결재함(중간 단계) · 회계 › 품의(마지막 SUPER) — 바뀐 것 없음 | acct_approval_steps |
| 정산 | 본인 · 오는 날이 지난 뒤 · 품의 승인 → 일비 · 식비 · 숙박 · 교통 → 경비 청구(간이 · 부가세 0 · requisition_id = 출장 품의) | ofc_trip_settlements + acct_expense_claims |
| 승인 · 지급 | 회계 › 경비 청구 — SUPER 승인(본인 불가) · 지급 담당 지급 · 전표 EXPENSE_APPROVED · EXPENSE_PAID | (기존) |

## 2. 여비 셈 — 일반 원칙 값(확인 필요 · SUPER 가 고침)
| 항목 | 처음 값 | 셈 |
|---|---|---|
| 일비 ofc.trip_per_diem | 25,000원/일 | × 날수(오는 날 − 가는 날 + 1) |
| 식비 ofc.trip_meal | 25,000원/일 | × 날수 |
| 숙박 상한 ofc.trip_lodging_caps | 서울 100,000 · 광역시 80,000 · 그 밖 70,000(1박) | 예상 = 상한 × (날수 − 1) · 정산 = min(실제 숙박비, 상한 × 실제 박수) |
| 교통비 | — | 예상 = 적은 금액 · 정산 = 실제 금액 |

- 근거: 공무원 여비 규정(국내 여비)을 참고한 일반 원칙 값입니다(docs/555 「일반 원칙 값 적용」과 같은 방식 · **최신 금액 · 비과세 범위 확인 필요**). 일비 · 식비가 실비변상 비과세로 인정되려면 회사 여비 규정이 있어야 합니다 — 세무사 확인.
- 정산은 **신청 때 기준**(basis)으로 셉니다 — 기준을 바꿔도 이미 신청한 출장은 그대로.
- 정산 금액이 품의 금액 × (1 + acct.req_tolerance_pct%)를 넘으면 422 OFC_TRIP_OVER(기존 품의 가드 REQ_OVER 와 같은 선) — 다시 신청하거나 차액은 따로 품의.
- 경비 청구는 **간이(SIMPLE · 부가세 0 · 매입세액 공제 안 함)**로 올립니다. 숙박 · 교통 세금계산서 · 카드 영수증으로 공제받으려면 그 건만 회계 › 경비 청구에서 따로 올리고 정산 금액에서 빼십시오(문서 4절).

## 3. 두 번 청구 막기
1. 서비스: 같은 출장에 살아 있는(REQUESTED · APPROVED · PAID) 청구가 있으면 409 OFC_TRIP_DOUBLE.
2. DB: ofc_trip_settlements.claim_id 고유 · 트리거 fn_ofc_trip_settle_guard(살아 있는 청구가 있으면 OFC_TRIP_DOUBLE · 출장 간 사람 · 출장 품의의 청구만) · ofc_trips.claim_id 고유 · 정산 줄 없는 청구는 붙이지 못함.
3. 품의 쪽: fn_acct_req_link_guard 가 품의에 붙은 청구 합(반려 · 취소 뺌)을 허용 비율로 막음 — 정산 밖에서 같은 품의로 경비를 또 올려도 넘으면 막힘.
4. 청구가 반려 · 취소되면 다시 정산할 수 있습니다(새 청구 · 정산 줄이 하나 더 쌓임 · 출장은 새 청구를 가리킴).

## 4. API
| 방법 | 주소 | 설명 |
|---|---|---|
| GET | /admin/office/trips?view=mine\|all | 본인(SUPER · 지급 담당은 all) · 품의 상태 · 청구 상태 · 정산 가능 여부와 까닭 · 기준 |
| GET | /admin/office/trips/{id} | 신청 때 기준 · 정산 기록 |
| POST | /admin/office/trips | 신청 + 품의(같은 거래) · 422 OFC_TRIP_DEST · REGION · PURPOSE · DATE · AMOUNT |
| POST | /admin/office/trips/{id}/cancel | 정산 전 · 본인 · SUPER · 품의도 취소 |
| POST | /admin/office/trips/{id}/settle | 본인 · 409 OFC_TRIP_STATE · DOUBLE · 422 OFC_TRIP_EARLY · NIGHTS · AMOUNT · OVER |
| PUT | /admin/office/trip-standards | SUPER · 일비 · 식비 · 숙박 상한 셋 · 사유(설정 바뀜 기록은 site_settings 트리거) |

## 5. 주의
1. 30일보다 오래된 출장은 신청하지 않습니다 — 경비 청구로 바로 올리십시오.
2. 증빙 파일(ACCT_EVIDENCE · 3개)은 경비 청구와 같은 규칙(본인이 올린 것 · 올리기 끝난 것).
3. 세무사는 이 화면을 못 봅니다(경비 청구 · 품의는 기존 회계 화면에서 읽음).
