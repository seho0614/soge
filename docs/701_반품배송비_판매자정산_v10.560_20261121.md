# 701. 반품 배송비 판매자 정산 — 9차 (v10.560 · D290 · 2026-11-21)

## 1. 결론
입점 판매자(일반 입점 TENANT · 브랜드 직영관 BRAND) 주문에서 **회원 사정 반품**(단순 변심 · 잘못 주문)으로 환불할 때 뺀 **왕복 배송비를 그 판매자에게 정산**합니다. **수수료는 매기지 않습니다**(대표 11/21 결정 「수수료 없음」).

- 지금까지: 환불 = 결제 금액 − 왕복 배송비(`hlt_returns.ship_deduction`)인데, 뺀 배송비가 정산에 들어가지 않아 **회사에 남았습니다**.
- 이제: 주 정산 마감(`fn_hlt_settle_close`)이 반품 한 건마다 정산 항목 **RETURN_SHIP**(+뺀 배송비 · 수수료 0 · 수수료 부가세 0)을 한 번 붙이고, 정산서 지급액에 더합니다.
- **직판(DIRECT)은 그대로** — 회사가 판매자이므로 뺀 배송비는 회사 몫입니다.
- 근거: 판매 약관 제3조 · 입점 약관 제17조 4항(회원 사정 반품 배송비는 구매자 부담 · 금액은 판매자가 정함) · 제19조 2항(「판매자에게 귀속되는 배송비」는 정산에 더함). 약관 문구는 바꾸지 않아도 맞습니다.

## 3. 금액 예 (입점 판매자 · 수수료 12% · 왕복 반품비 6,000원 · 부가세 별도 시작 전)
| 경우 | 전(v10.558) | 후(v10.560) |
|---|---|---|
| **정산 전 반품** — 30,000원 주문을 배송 뒤 단순 변심 반품 · 환불 24,000원 | 판매자 0원 · 회사에 6,000원 남음 | 판매자 **+6,000원**(RETURN_SHIP · 수수료 0) · 회사 0원 |
| **정산 뒤 반품** — 50,000원 주문이 정산(판매자 44,000 = 50,000 − 수수료 6,000)된 뒤 단순 변심 반품 · 환불 44,000원 | 다음 회차 REFUND −44,000 → 판매자 순 0원 · 회사에 6,000원 남음 | 다음 회차 REFUND −44,000 + RETURN_SHIP +6,000 → 판매자 순 **+6,000원** · 회사 0원(수수료 6,000 은 약관 제20조대로 회사가 돌려줌) |
| **하자 반품**(파손 · 오배송 · 표시와 다름) | 전액 환불 · 차감 0 | 같음(RETURN_SHIP 없음) |
| **직판 반품** | 환불 = 결제 − 6,000 · 6,000 은 회사 몫 | 같음 |

정산서 한 장 예(정산 뒤 반품 회차, 그 주 다른 매출 없음): 매출 0 − 수수료 0 − 수수료 부가세 0 − 환불 44,000 + 이월 0 + 반품 배송비 6,000 = **지급액 −38,000 → 이월**(다음 주 정산에서 뺌).

## 4. 동작 자세히
1. **언제 붙나** — 반품이 환불 끝남(REFUNDED)이 된 뒤 처음 하는 주 정산 마감(정기 작업: 매주 월요일 지난주 · 운영 「이번 주 마감」 단추 모두). 정산 전 반품(판매 SALE 이 없음)이어도 붙습니다 — 그 판매자는 그 주 다른 매출이 없어도 정산서가 한 장 생깁니다(매출 0 · 반품 배송비만 · 계산서 NOT_NEEDED).
2. **한 번만** — RETURN_SHIP 은 반품마다 하나(고유 색인). 같은 주를 다시 마감하거나 다음 주를 마감해도 다시 붙지 않습니다.
3. **이월** — 정산 뒤 반품으로 지급액이 음수가 되면 지금처럼 이월(CARRIED)하고 다음 주에서 뺍니다. 반품 배송비가 더해진 뒤의 금액으로 판단합니다.
4. **수수료 · 부가세** — RETURN_SHIP 은 수수료 0 · 수수료 부가세 0. 판매수수료 세금계산서(정산서 commission 기준)에는 영향이 없습니다.
5. **회계 전표** — 입점 주문 매출 · 환불은 회사 장부에 잡지 않고 판매수수료만 잡으므로(journal.ts `COMMISSION` · 정산서 commission 기준) 전표 변화는 없습니다. 직판 환불 전표(`MALL_REFUND`)도 그대로입니다.
6. **월 정산서** — 만든 정산서(이미 메일로 보낸 SENT 줄 포함)는 칸이 0 으로 남고, 「다시 셈」(보내기 전 줄만) 때 채워집니다. 지급액 합계(net)는 원래부터 주 정산서 합이라 바뀌지 않습니다.

## 5. 운영 반영
- **RDS 스냅샷 필요**(마이그레이션 D290 — 표 칸 · CHECK · 색인 · 함수 · 보기를 바꿈).
- 반영 전 확인(precheck 뒤 · 읽기만): 이미 환불 끝난 입점 회원 사정 반품이 있으면 D290 뒤 첫 마감에 한꺼번에 판매자에게 붙습니다.
  ```sql
  SELECT count(*), coalesce(sum(r.ship_deduction), 0)
    FROM hlt_returns r JOIN hlt_orders o ON o.id = r.order_id JOIN hlt_sellers h ON h.id = o.seller_id
   WHERE h.type IN ('TENANT', 'BRAND') AND r.state = 'REFUNDED' AND r.ship_deduction > 0;
  ```
  운영은 입점 · 주문 받기가 꺼져 있어 0 건으로 봅니다(0 이 아니면 대표 확인 뒤 반영).
- postcheck: `SELECT count(*) FROM pg_constraint WHERE conname IN ('ck_hltsi_return_ship', 'ck_hlts_return_ship')` = 2 · `SELECT to_regclass('public.v_hlt_return_ship_ready')` 있음.
- 되돌리기(rollback) 때는 스냅샷으로 — 옛 판 코드는 새 칸을 읽지 않으므로 화면은 그대로 열립니다.
