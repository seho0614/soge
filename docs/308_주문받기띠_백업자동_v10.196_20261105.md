## 1. 바뀐 것

| # | 무엇 | 내용 |
|---|---|---|
| 1 | 「주문 받기 켜짐」 띠 | 간주 결제(`assume.payment`)가 켜진 채 주문 받기(`mall.order_open`)가 켜져 있으면, 운영 화면 **모든 쪽 머리줄 아래에 빨간 띠**가 뜸: 「소개몰 「주문 받기」가 켜져 있습니다 — 간주 결제(시험 결제) 상태라 손님 주문이 실제 돈 없이 결제 완료됩니다. 첫 화면 「공개 직후 지켜보기」에서 끄기」. 이미 있는 공개 설정(`/site-settings/public`)을 **1분마다** 다시 읽고, 첫 화면에서 스위치를 바꾸면 바로 반영(`bo-settings` 사건). 설정을 못 읽으면 띄우지 않음 |
| 2 | 올린 파일 백업 cron 없이 | 배치 호출기(pm2 `sgb-jobs` · `scripts/scheduler-daemon.js`)가 매일 **04:30(한국 시간)을 지난 뒤 한 번** `deploy/aws/uploads-backup.sh` 를 부름(`scripts/uploads-backup-daily.js`). 운영은 `run-jobs.sh` 가 `UPLOADS_BACKUP_DAILY=04:30` 을 기본으로 넘김. 끄려면 운영 `.env` 에 `UPLOADS_BACKUP_DAILY=off`. 개발 도커 스케줄러는 이 값이 없어 돌지 않음 |
| 3 | mfa-reset 알림 출처 | `mfa-reset.sh off` 가 `updated_by = NULL` 로 저장하고 사유 「mfa-reset.sh off (서버에서 비상 끄기)」(`SET LOCAL app.setting_reason`)를 남김 → 중요 설정 바뀜 알림이 **via DB · 사유**로 바르게 나옴 |

**정한 기준**

1. 띠는 간주 결제가 꺼진 뒤(실제 결제 연결)에는 뜨지 않습니다. 그때는 주문 받기가 켜진 것이 정상입니다.
2. 백업은 한 번만 시도합니다(실패해도 그날 다시 하지 않음).
   - 디스크 부족 → 스크립트의 운영 알림 `UPLOADS_BACKUP_SKIPPED`
   - 그 밖의 실패 → 이미 있는 「36시간 넘음」 알림(`UPLOADS_BACKUP_STALE`)과 postcheck 줄
3. 오늘 묶음이 이미 있으면 스크립트가 건너뜁니다. 그래서 cron 을 함께 등록해도, 배치 호출기가 다시 떠도 하루 한 번만 묶입니다.
4. 배치 호출기가 뜰 때 이미 04:30 이 지났으면 **곧바로 한 번** 부릅니다. 운영 적용 직후 오늘 묶음이 생깁니다.
