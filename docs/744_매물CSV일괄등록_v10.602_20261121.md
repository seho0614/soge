# 744 매물 CSV 일괄 등록 — v10.602 (17차 ⑱ · 2026-11-21)

> 대표 11/21 「모두 개발진행」. 앞머리 lsq_ · 마이그레이션은 메인이 D292 ~ 중 한 번호에(`sql/lsq_listing_mall.sql` 한 파일 — 17차 일곱 판 공통).

## 1. 결론
- 회원이 CSV 로 여러 매물을 **미리보기 → 확정** 한다. 확정한 줄은 **기존 매물 등록 함수(ListingService.submit — POST /listings 와 같은 함수)** 를 줄마다 불러 검수 큐에 들어간다.
- 자동검수 · 제한업종 · 금칙어 · 슬롯 한도 · 가입 24시간 회원 하루 상한은 **그 함수와 DB 트리거가 판정**(두 곳에 두지 않음). 한 줄이 실패해도 나머지는 계속(FAILED + 사유).
- 스위치 `lsq.bulk` 처음 **off**. 처리방침 변경 없음(회원이 공개하려고 쓰는 매물 글 · 이름 · 전화 칸은 받지 않음).

## 2. 재사용한 기존 기능
| 기존 | 어떻게 |
|---|---|
| 파트너 직원 일괄 등록 CSV(v10.522 · papi/bulk.ts) | 미리보기 → 확정 흐름 · 받지 않는 칸 막기 · 200KB 상한 모양 |
| CSV 읽기 parseCsv(acct/bank.ts) | 따옴표 · 쉼표 · 줄바꿈 처리 그대로 import |
| 매물 등록 ListingService.submit · 검수 큐 review_items | 확정 줄마다 그대로 부름(검수 › 검수 큐에서 처리) |
| 지역 regions(시 · 도 코드) | region 칸 이름 → 코드 |

## 4. DB(lsq_ 표 2)
- `lsq_bulk_jobs` — 묶음(PREVIEW 24시간 → DONE · 안 하면 EXPIRED) · 줄 수 · 등록 · 실패 수 · 90일 뒤 `lsq_daily` 가 지움.
- `lsq_bulk_rows` — 줄마다 data(jsonb) · problems(10개) · listing_id · result_note.
- 확정은 먼저 `PREVIEW → DONE` 으로 잠가 두 번 눌러도 한 번만.

## 7. 켜는 순서 · 체크리스트
1. 운영 미리보기로 양식 확인(관 · 업종 이름이 맞는지).
2. 회원 안내(「확정하면 검수 큐로 · 24시간 안」) 게시.
3. 운영 화면 › 검수 › 매물 일괄 등록에서 `lsq.bulk` 켬(SUPER · 사유).
4. 첫 주 검수 큐 쌓임 확인(검수 › 검수 큐).
