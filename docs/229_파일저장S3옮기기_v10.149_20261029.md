# 229. 파일 저장 위치 S3 옮기기 — v10.149 (2026-10-29)

> 대표 「다음」 → 후보 2 「파일 저장 S3 선택」 → 「다음단계 전체」 · 「추천대로」(10/29).
> 앞 판: v10.148(docs/228) · **마이그레이션 D143 하나(181)** — 파일 행 지킴(`fn_files_guard`)이 저장 위치를 못 바꾸게 막고 있어(리허설 시험에서 발견) 옮기기 거래에서만 좁게 엶 · 서비스 동작은 그대로.
> 미정 사항: open-blockers 미정 7 「파일 저장 위치(서버 디스크 ↔ S3)」 — **이 문서는 「S3 로 정하면」의 순서**입니다. 정하는 것은 대표.

## 1. 결론

1. S3 저장은 **이미 만들어져 있습니다**(`src/modules/file/storage.ts` · v10.x D007). 운영 `.env` 에 `S3_BUCKET=버킷이름` 이 있으면 새 파일은 S3 로, 없으면 서버 디스크(`UPLOAD_DIR`)로 갑니다. 브라우저가 S3 로 **바로** 올리고 내려받습니다(서버가 만든 10분 · 5분짜리 주소).
2. 이번 판은 **바꾸는 날 쓸 도구**만 더했습니다.

| 곳 | 내용 |
|---|---|
| API | `GET /api/v1/admin/storage-status`(ADMIN · SUPER · 읽기만) — 지금 저장 위치 · 버킷 이름 · 저장 위치별 파일 수 · 쓰는 파일 크기 · 옮기기 덜 끝남 |
| 운영 화면 | 오픈 체크리스트 「파일 저장 위치: 서버 디스크 / S3 (버킷)」 한 줄 · 덜 끝났으면 「옮기기 덜 끝남」 |
| DB | `D143_files_move` — `fn_files_guard` 다시 만듦: 그 거래가 `SET LOCAL sgb.files_move = 'on'` 일 때만 저장 위치 LOCAL ↔ S3 (다른 열은 그대로 막음) |
| 스크립트 | `deploy/aws/files-to-s3.sh` — check(읽기만) · copy(디스크 → S3 · 지우지 않음) · verify(읽기만) · apply(DB 저장 위치를 S3 로 · yes) |

3. **권함: 오픈 전에 정하기.** 파일이 적을 때 옮기는 것이 가장 쉽습니다. 서버를 다시 설계할 때(운영 전환) 디스크를 비워 두면 서버를 바꿔도 파일이 따라옵니다. 비용 · 요금은 AWS 요금표 확인이 필요합니다(지금 파일 양이면 작을 것으로 보지만 확인 필요).

## 2. 준비 (사람 · AWS 화면 · 한 번)

### 2-1. 버킷
- 이름 예: `sgb-uploads-prod` · 지역 **서울(ap-northeast-2)**
- **공개 차단 4개 모두 켬**(기본값) · 버전 관리 켬(실수로 덮어써도 되살림) · 기본 암호화 SSE-S3

### 2-2. 서버 역할(IAM) 권한 — 운영 EC2 에 붙은 역할에 더함
```json
{ "Version": "2012-10-17", "Statement": [
  { "Effect": "Allow", "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"], "Resource": "arn:aws:s3:::sgb-uploads-prod/*" },
  { "Effect": "Allow", "Action": ["s3:ListBucket", "s3:GetBucketCors", "s3:GetBucketPublicAccessBlock"], "Resource": "arn:aws:s3:::sgb-uploads-prod" }
] }
```
- 액세스 키를 `.env` 에 넣지 않습니다 — 서버 역할을 씁니다(앱이 EC2 메타데이터에서 임시 열쇠를 받음).
- `aws` 명령(AWS CLI v2)이 운영 서버에 있어야 합니다(`aws --version`). 없으면 설치 — 설치 방법은 AWS 문서 확인.

### 2-3. CORS — 브라우저가 S3 로 바로 올리려면 꼭
```json
[ { "AllowedOrigins": ["https://sogaebank.com", "https://www.sogaebank.com"],
    "AllowedMethods": ["PUT", "GET"], "AllowedHeaders": ["content-type", "content-length"],
    "ExposeHeaders": ["ETag"], "MaxAgeSeconds": 3000 } ]
```
운영 화면 주소(관리자 도메인)에서도 파일을 올리면 그 주소를 `AllowedOrigins` 에 더합니다.

## 3. 바꾸는 날 순서 (사람 · ubuntu · 단계마다 결과 확인)

| 단계 | 명령 | 확인 |
|---|---|---|
| 0 | RDS 스냅샷 `sgb-before-s3-YYYYMMDD` | 「사용 가능」 |
| 1 | `S3_BUCKET=sgb-uploads-prod bash ~/sgb/deploy/aws/files-to-s3.sh` | 버킷 · 공개 차단 · CORS · 쓰기 권한 · 디스크 파일 **모두 통과** |
| 2 | `S3_BUCKET=sgb-uploads-prod bash ~/sgb/deploy/aws/files-to-s3.sh copy` | 「복사 끝」 |
| 3 | `S3_BUCKET=sgb-uploads-prod bash ~/sgb/deploy/aws/files-to-s3.sh verify` | 「쓰는 파일(READY)이 S3 에 다 있음」 |
| 4 | 운영 `.env` 에 `S3_BUCKET=sgb-uploads-prod` (UPLOAD_DIR 줄은 그대로 둠) → `pm2 restart sgb-api` | 운영 화면 오픈 체크리스트 「파일 저장 위치: S3 (sgb-uploads-prod) · 옮기기 덜 끝남」 |
| 5 | `bash ~/sgb/deploy/aws/files-to-s3.sh copy` 다시 → `verify` | 1 ~ 4 사이에 올라온 파일까지 S3 에 |
| 6 | `bash ~/sgb/deploy/aws/files-to-s3.sh apply` → `yes` | 「저장 위치 바꿈」 · 화면에서 「옮기기 덜 끝남」 사라짐 |
| 7 | 운영 화면에서 등기사항증명서 · 매물 사진 하나 열기 · 새로 하나 올리기 | 열림 · 올라감 |

- 4번 재시작 순간 올리던 중(UPLOADING)인 파일은 실패할 수 있습니다 — 회원이 다시 올리면 됩니다. 사람이 적은 시간에 하십시오.
- **디스크 파일은 지우지 않습니다.** 1주 동안 문제가 없으면 사람이 `~/sgb-data/uploads` 를 압축해 백업한 뒤 정리합니다.

## 4. 되돌리기
- 4번 뒤 문제가 있으면 `.env` 의 `S3_BUCKET` 줄을 지우고 재시작 → 다시 디스크.
- 6번(apply)까지 했으면 스냅샷 대신 다음 한 줄로 저장 위치만 되돌립니다(디스크에 파일이 그대로 있으므로):
  `BEGIN; SET LOCAL sgb.files_move = 'on'; UPDATE files SET storage_provider = 'LOCAL' WHERE storage_provider = 'S3' AND created_at < '<4번 시각>'; COMMIT;` — S3 로 바뀐 뒤 새로 올라온 파일은 S3 에만 있으니 그대로 둡니다.
