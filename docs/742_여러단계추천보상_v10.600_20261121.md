# 742. 여러 단계 추천 보상 (v10.600 · 2026-11-21 · 16차 회원 · 성장 ⑯)

## 1. 결론
추천인의 추천인(2단계) · 그 위(3 · 4단계)에게도 점수를 주는 **길만 만들고 꺼 둡니다**(`grw.tier_reward` 처음 **off**).
**법무 확인 필요 — 방문판매법상 다단계판매 해당 여부.** 11/9 대표 「법무 확인 이상없음 · 다단계 해당 안 됨」은 **직접 추천 1단계 보상(REFERRAL_DIRECT · D189)** 기준이고, 여러 단계 보상은 결정 기록 partner-affiliate **미정 #5 「법무 확인 대기」 그대로**입니다. 법무 확인 · 약관 · 안내 문구 게시 전에는 켜지 않습니다.

## 2. 법무 확인 요청할 것 (초안 · 확인 필요)
| 묻는 것 | 까닭 |
|---|---|
| 2단계 이상 보상이 방문판매법 「다단계판매」(판매원 가입이 여러 단계로 이어지고 그 실적에 따라 보상)에 해당하는지 | 단계 수 · 보상이 본인인증만으로 주어지는 점(판매 실적 아님) · 회원 가입비 없음이 판단에 어떻게 작용하는지 — **추가 확인이 필요합니다** |
| 해당한다면 등록 · 공제조합 · 후원수당 상한 등 의무 | 해당 시 켜지 않거나 1단계로만 운영 |
| 약관 · 추천 안내 문구 · 처리방침(추천 관계 이용 범위) 고칠 곳 | 보상 받는 사람이 넓어짐 |
| 포인트 현금화(D190 원천징수)와의 관계 | 이 판은 **현금화 안 됨**으로 고정 — 바꾸려면 따로 결정 |
- 법령 조문 · 해석은 바뀔 수 있어 **법무 확인 때 최신 여부를 확인**하십시오.

## 3. 만든 것 (D189 · D190 · D277 은 고치지 않음)
| 항목 | 내용 |
|---|---|
| 추천 관계 | `introducer_referrals` 그대로(칸 더하지 않음 · N-12 그대로 · 고리 막기 그대로) — 위로 따라 올라감 |
| 직접 보상 | `fn_referral_reward` 손대지 않음 · 그 함수가 넣은 REFERRAL_DIRECT 줄 뒤(AFTER INSERT) `trg_grw_tier_reward` 가 따라 붙음 → **직접 보상이 꺼져 있으면 여러 단계 보상도 없음** |
| 켜짐 조건(DB) | `grw.tier_reward` 와 `grw.tier_legal_ok` **둘 다 on** — 서버도 법무 확인 끝 표시 없이 켜기 422 `GRW_TIER_LEGAL` · 법무 확인을 끄면 보상도 꺼짐 |
| 점수 | `grw.tier_points` 처음 `300`(2단계만 · 일반 초안 · SUPER 가 정함) · 쉼표로 최대 3개(2 · 3 · 4단계) · 정규식 서버 = DB |
| 지킴(DB) | 가입한 사람 한 명 · 단계 하나에 한 번(`grw_tier_rewards` 고유) · **현금화 안 됨**(redeemable false · 가드) · REFERRAL_TIER 줄은 정한 함수 안에서만(`trg_grw_tier_guard`) · 탈퇴 · 정지 건너뜀 · 한 달 상한(point_rules REFERRAL_TIER.monthly_cap) · 기록 고칠 수 없음 |
| 보상 규칙 | point_rules `REFERRAL_TIER`(꺼진 채 · 표시용 · 켜짐 칸은 스위치와 맞춤) |

## 4. 켜는 순서 (대표 · 법무)
1. 법무 확인(2절) → 2. 약관 · 추천 안내 문구 게시 → 3. SUPER 가 「법무 확인 끝」 켬(사유에 확인한 곳 · 날짜) → 4. 점수 · 한 달 상한 → 5. 켜기 → 6. 운영 화면 「준 보상」 지켜보기.
