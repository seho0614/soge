## 1. 결함

| 단계 | 일어난 일 |
|---|---|
| 1 | 운영 화면 › 권한(`RoleAdmin` · `POST /admin/reports/roles` · SUPER)에서 역할을 주거나 뺌 |
| 2 | `account_roles` 에 INSERT · DELETE → 트리거 `fn_role_audit` 가 `role_changes`(권한 변경 기록)에 줄을 INSERT |
| 3 | 서버가 방금 생긴 줄에 사유 · 처리자를 **UPDATE** |
| 4 | `role_changes` 는 수정 · 삭제 금지(`trg_role_change_ro` — 감사 기록) → **오류 · 거래 전체 되돌림** |

결과: 운영 화면으로는 **관리 역할을 한 번도 주거나 뺄 수 없었음**. 10/21 첫 SUPER 를 SQL 로 직접 넣은 까닭. 시험이 이 API 를 부르지 않아 realcheck · 회귀에서 드러나지 않았음.

## 2. 고친 것

| # | 곳 | 내용 |
|---|---|---|
| 1 | DB **D153** `fn_role_audit()` 다시 정의 | INSERT 할 때 사유 = `app.role_reason` · 처리자 = `app.actor_id`(같은 거래의 설정 · uuid 모양일 때만) 를 함께 씀 |
| 2 | 서버 `report.service.ts` `setRole` | 거래 안에서 `set_config('app.role_reason', 사유, true)` · `set_config('app.actor_id', 처리자, true)` 를 먼저 하고 역할을 바꿈 · **UPDATE 문 삭제** |
| — | 그대로 | 수정 · 삭제 금지 트리거(감사 기록은 여전히 못 고침) · 사유 없음 422 `REASON_REQUIRED` · 자기 자신 422 `SELF_GRANT` · 없는 역할 회수 409 `NO_SUCH_ROLE` · SUPER 만 |

SQL 로 직접 역할을 넣는 경우(설정 없음)는 전처럼 사유 · 처리자 빈칸.
