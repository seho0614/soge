# 239. 운영 화면 「약관」 고치기 · 게시 · 보관된 판 잠금 — v10.157 (2026-10-31)

> 대표 「남은 개발건」 → 「추천대로」 → 계획 「승인」(10/31).
> 앞 판 v10.156(docs/237)은 약관을 **게시**하는 화면을 만들었지만, 법무가 〔미확정〕을 채우라고 하면 Claude 가 마이그레이션으로 새 판을 만들고 **운영 적용을 한 번 더** 해야 했음.
> 함께 찾은 위험: 초안 저장 API(`PUT /admin/terms/{code}`)가 같은 판 번호면 **게시된 판의 본문도 덮었음**(ON CONFLICT DO UPDATE · DB 도 막지 않음) — 회원 동의 기록의 근거 글이 바뀔 수 있음. 부르는 화면이 없어 실제 피해는 없었음.
> 마이그레이션 **D150 하나(188)**.

## 2. 「고치기」 쓰는 법

1. 약관 줄의 **「고치기」** → 편집 칸이 열림.
   - 초안 · 법무 검토 판: 판 번호가 **같은 번호**(그 초안을 고침)
   - 게시 · 보관 판: 그 약관의 가장 높은 번호 다음(예: 1.0 게시 → **1.1**) — 게시된 글은 그대로 남음
2. 본문의 〔…〕 를 법무가 정한 글로 바꿈 — 아래에 「〔미확정〕 N곳 남음: …」 이 줄어듦(〔시행일〕 은 게시할 때 채워지므로 남겨 둠).
3. **「바뀐 곳 보기」** — 원래 글과 줄 단위로 비교(초록 + 더함 · 빨강 − 뺌). 법무 확인용.
4. **「저장(게시 아님)」** → 확인 창 → 「저장했습니다(법무 검토 · 게시 전)」.
5. 〔미확정〕 이 없으면 같은 표에서 시행일을 넣고 **「게시」**(docs/237).

## 4. DB 를 직접 고쳐야 할 때 (사람 · 드묾)

게시된 글의 오탈자를 법무가 「새 판 없이 고쳐라」 고 한 경우처럼 **반드시 같은 판을 고쳐야** 할 때만, 그 거래 안에서:

```sql
BEGIN;
SET LOCAL sgb.terms_fix = 'on';
UPDATE terms SET body = … WHERE code = '…' AND version = '…';
COMMIT;
```

- API · 운영 화면은 이 표시를 쓰지 않습니다(D143 `sgb.files_move` 와 같은 방식).
- 고친 까닭 · 날짜 · 법무 지시를 결정 기록(terms-publishing)에 남기십시오. 동의 기록은 판 번호로 그 글을 가리킵니다.

## 5. 운영 적용

- v10.156(docs/238)을 아직 적용하지 않았으면 **v10.155 → v10.157 한 번**(D149 · D150 · 188) — 절차서는 병합 뒤 따로 만듦.
- 반영만으로 손님 화면 · 약관 글은 바뀌지 않습니다.

## 6. 하지 말 것

- 법무 확인 전에 「게시」 — 「저장」은 게시가 아니지만, 게시하면 계약 조건이 되고 동의 기록이 남음
- `sgb.terms_fix` 를 코드 · 스크립트에 넣기 — 사람이 DB 를 직접 고칠 때 그 거래에서만
- 게시된 판을 지우거나 덮어 「고친 것처럼」 만들기 — 새 판으로 저장해 게시하면 앞 판은 보관으로 남음
