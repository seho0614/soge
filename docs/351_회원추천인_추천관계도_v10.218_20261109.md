# 351. 회원 추천인 · 추천 관계도 — v10.218 (2026-11-09)

> 계기: 대표 「회원가입 때 추천인 입력을 받는다 · 파트너(제휴) 페이지에서 관계도를 트리 형태로 관리한다」(11/9).
> 정한 것(11/9 AskUserQuestion): 보상 **직접 추천 1단계만** · 트리는 **운영자 전체 · 제휴 파트너도 자기 아래 전체** · 입력은 **추천 코드** · 바꾸기는 **가입 때만(그 뒤 운영자 · 사유)** · 코드는 **모든 회원** · 보상은 **가입한 분 본인인증 뒤** · 계획 「승인」.
>
> **마이그레이션 1개 D189(226 → 227)** · 새 API 7개 · 새 화면 2개(SB-AFC-RCM-010 · SB-AFF-RCM-010) · 보상은 꺼진 채.

## 1. 다단계로 보이지 않게 — 지키는 것

| 지키는 것 | 어떻게 |
|---|---|
| 보상은 직접 추천 1단계만 | `point_ledger` 의 `REFERRAL_DIRECT` 줄은 DB 함수 `fn_referral_reward` 로만 들어감 — 그 가입자를 **직접** 추천한 한 사람 · 아직 안 받은 관계만(트리거 `trg_referral_reward_guard`). 추천인의 추천인에게 가는 길이 없음 |
| 표에 단계 · 부모 칸 없음 | `introducer_referrals` 에 칸을 더하지 않음(시험 N-12 「하위 수당 경로 부재」 그대로 통과) · 트리는 조회 때 위아래로 따라가 만듦 |
| 파트너 화면에 보이는 것 | 이름 첫 글자(김***) · 내가 직접 추천한 분은 가입일 · 그 아래는 가입 월만. **실적 · 금액 · 연락처 · 회원 번호 · 코드 없음** |
| 말 | 「하위 · 산하 · 직급 · 다운라인 · 상위」를 쓰지 않음 — 「내가 추천한 분 · 그분이 추천한 분 · n번째」 (브랜드 원칙 conversation-audit #3) |
| 법무 확인 | ① 추천한 사람에게 가입자의 가린 이름 · 가입일이 보임 — 가입 화면 안내 글을 넣었고, 처리방침 문구는 법무 확인 필요 ② 여러 대 트리 + 1단계 보상이 방문판매법상 다단계판매에 해당하지 않는지 법무 확인 필요 |

## 2. DB — D189_member_recommend

| 무엇 | 내용 |
|---|---|
| ① `accounts.recommend_code` | 6자 · `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`(0 · O · 1 · I 없음) · 겹치지 않음(`ux_accounts_recommend_code`) · 가입 때 트리거가 만들고 **바뀌지 않음** · 있는 회원은 이 마이그레이션이 채움 |
| ② `introducer_referrals` | 기존 초대 관계 표(가입한 사람 한 번)를 추천 관계로 · `fn_referral_no_chain` 을 넓힘 — 맞추천(A↔B)뿐 아니라 고리(A→B→C→A) · 운영자가 고칠 때(UPDATE)도 · 가입한 사람은 못 바꿈 · 보상 준 관계는 추천인 못 바꿈 |
| ③ `recommend_changes` | 운영자가 추천인을 고치거나 지운 기록(전 → 후 · 사유 2 ~ 300자 · 누가) · 고치거나 지울 수 없음 |
| ④ 보상 `REFERRAL_DIRECT` | `point_rules` 에 꺼진 채(점수 1000 은 임시) · 가입한 분이 **처음** 본인인증(`identity_verified_at` NULL → 값)할 때 `fn_referral_on_verify` → `fn_referral_reward` · 한 달 상한(비우면 없음) · 꺼져 있을 때 인증한 분은 나중에 켜도 주지 않음 · 현금화 안 됨(`redeemable` false) |
| DB 오류 | `RECOMMEND: …` → 422 `RECOMMEND_RULE` · `INV-1: …`(고리) → 422 `INV_1` |

## 3. API

| API | 권한 | 내용 |
|---|---|---|
| `POST /auth/signup` | 누구나 | `recommendCode` 선택 칸 · 소문자도 받음 · 없는 코드 422 `RECOMMEND_CODE_UNKNOWN`(계정 안 생김) |
| `GET /auth/recommend-code/{code}` | 누구나 | 가린 이름만 · 없으면 404 · IP 마다 1분 20번 |
| `GET /me/recommend` | 회원 | 내 코드 · 링크 `/signup?rc=코드` · 직접 추천한 분 수 · 나를 추천한 분(가린 이름) · 받은 보상 점수 |
| `GET /partner/affiliate/recommend-tree` | 활동 중 제휴 파트너 | 본인 아래 전체(30대 · 3,000명까지 · 넘으면 truncated) · 아니면 403 `AFF_REQUIRED` |
| `GET /admin/affiliates/recommend` · `GET …/{id}` | ADMIN · PARTNER_AFF | 회원 찾기(코드 · 이메일 · 이름 · 비우면 직접 추천 많은 20명) · 한 회원(위로 추천인 줄 · 아래 트리 · 변경 기록) |
| `PATCH /admin/affiliates/recommend/{id}` | ADMIN | 추천인 고치기 · 지우기(코드 비움) · 사유 필수 · 감사 `RECOMMEND_CHANGE` · 422 `REASON_REQUIRED · RECOMMEND_CODE_UNKNOWN · RECOMMEND_SELF · RECOMMEND_SAME · RECOMMEND_REWARDED · INV_1` |
| `GET` · `PUT /admin/affiliates/recommend-reward` | 보기 ADMIN · PARTNER_AFF / 바꾸기 SUPER | 켜짐 · 점수(1 ~ 100,000) · 한 달 상한 · 지금까지 준 수 · 감사 `RECOMMEND_REWARD_RULE` |
