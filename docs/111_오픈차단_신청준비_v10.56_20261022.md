## 1. 결론

**가장 먼저 할 일은 「사업자등록 업종 정정신고」입니다.**

- 까닭: 지금 사업자등록증에 적힌 업종이 **제조업뿐**입니다. 본인인증 · 1원 계좌인증 · 전자결제(PG, 카드 결제 대행) 업체는 **전자상거래 · 중개 업종이 들어간 새 등록증**이 있어야 신청을 받습니다(decisions/open-blockers.md 요약 2 · 미정 1).
- 그래서 업종 정정이 늦어지면 **모든 연동 일정이 그만큼 통째로 밀립니다.**
- 일정 감각: 본인인증 · 계좌인증을 **동시에 신청하면 6주, 차례로 하면 10주**(open-blockers #3). 오늘(10/22) 업종 정정이 끝났다고 쳐도 동시 신청으로 **빨라야 12/3 무렵**입니다. 그래서 **약관 시행일 11-11 과 실제 연동 완료는 맞지 않습니다**(7절 결정 1).

### 전체 순서 한눈에

1. **업종 정정신고** → 새 사업자등록증 받기 (전자상거래 소매업 525101 + 중개 업종 추가)
2. **동시 신청**(새 등록증 사본 · 발신 IP 3.37.95.217 을 같이 냄)
   1. 본인인증 + 1원 계좌인증 — NICE평가정보 묶음(안)
   2. 전자결제(PG) — 토스페이먼츠(결제 용도만)
   3. 알림톡 · 문자 — 대행사 미정
   4. 050 안심번호 — 업체 미정
   5. 전자서명(전자계약) — 업체 미정
   6. 국세청 사업자 상태 조회(공공데이터포털) · 전자세금계산서 업체(ASP, 예: 팝빌 · 바로빌)
   7. (같이) 국토부 중개사 대조 키(공공데이터) · 메일(SES) 구축
3. **키를 받으면 → 운영 `.env` 에 사람이 직접** 넣고, 개발자에게는 「변수 이름만」 알림(5절)
4. **연동 개발 · 시험** — docs/93 「새 연동 붙이는 법」 8단계 → kit → 집 PC `realcheck`
5. **간주 모드 4종 끄기**(6절) — `assume.etax` → `assume.broker` → `assume.payment` → `assume.bank`
6. **소개비 스위치 켜기**(`feature.referral_fee`) — 본인인증 · 계좌인증이 실제로 돌 때만
7. **약관 발행 · 오픈 직전 정리 → 오픈**(운영 적용 절차는 docs/109 참고)

## 5. 키를 받은 뒤 개발자에게 넘길 것

**원칙: 키 · 비밀번호 값은 채팅 · 메일 · 메신저에 붙이지 않습니다.** 사람(ubuntu 사용자)이 운영 `.env` 에 직접 넣고, 개발자에게는 **이름만** 알립니다. 개발자(sgbdev)는 운영 `.env` 를 볼 수 없고 보지도 않습니다.

### 5-1. 넘기는 방법

1. 사람이 운영 `.env` 에 키를 넣음(운영 적용 절차 docs/109 참고 — 이 문서에는 서버 명령을 적지 않음)
2. 개발자에게 아래 형식으로 **이름 · 업체 · 문서만** 보냄
3. 개발자는 업체 개발 문서를 보고 어댑터(연결 코드)를 맞춤 → kit → 집 PC `realcheck`

```text
[연동 넘김] 2026-__-__
- 연동: BANK (1원 계좌인증) / 업체: NICE평가정보
- 운영 .env 에 넣은 이름: BANK_VERIFY_KEY, BANK_VERIFY_URL   ← 값은 적지 않음
- 시험 환경 주소 있음: 예 / 아니오
```

### 6-2. 관리자 API (운영 화면과 같은 길)

- 위치: `PATCH /api/v1/admin/site-settings` — `src/modules/admin/admin.controller.ts:102-106`(권한 ADMIN · SUPER, 18행) → `src/modules/admin/admin.service.ts:505-522`

- 보내는 내용(예시 — 사무실 IP 에서 관리자로 로그인한 상태):

