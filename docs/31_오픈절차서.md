# 1. 오픈 판정 기준

## 1-1. 기계가 판정하는 것

```bash
DATABASE_URL=... ENVIRONMENT=prod npm run deploy:check
```

7항목 전부 통과해야 합니다. **하나라도 실패하면 오픈하지 않습니다.**

```
□ 타입 오류 0 · 생성 파일 최신
□ 마이그레이션 미적용·변조 없음
□ 불변식 위반 0건          ← 하나라도 있으면 즉시 중단
□ 코드 라벨 누락 0건
□ 오픈 차단 0건
□ 미확인 CRITICAL 경보 없음
□ 부팅 · 라우트 113 · 중복 0
```

## 1-2. 사람이 판정하는 것

**기계가 못 보는 것들입니다.**

```
□ 푸터에 자리표시자가 없는가        ← 눈으로 봅니다
□ 약관 본문에 〔 〕가 없는가
□ 공급측 매물이 20건 이상인가
□ 검수 담당자가 큐를 열 수 있는가
□ 정산 배치를 stg 에서 한 번 돌려 봤는가
□ DR 복구를 한 번 해 봤는가
```

**`v_open_blockers` 는 형식만 봅니다.** "(확정)" 같은 값이 들어가 있어도 통과하므로 실제 화면을 열어 확인하십시오.


# 6. 오픈 첫 주

## 6-1. 매일 보는 것

| 지표 | 쿼리 | 이상 신호 |
|---|---|---|
| **귀속률** | `v_attribution_health` | **급락 = link 누락** |
| **계약 발급률** | `v_contract_conversion` | **낮음 = 시스템 밖 거래** |
| 검수 처리량 | `v_review_throughput` | SLA 위반 |
| 자동화율 | `v_auto_review_rate` | 낮으면 검수 부담 |
| 개입 사유 | `v_manual_reasons` | 특정 사유 집중 |

**앞의 둘이 핵심입니다.** 둘 다 **시스템은 정상인데 사업 모델이 새는 형태**로 나타나 인프라 지표로는 잡히지 않습니다.

## 6-2. 금칙어 조정

```sql
SELECT unnest(manual_reasons) AS reason, count(*)
  FROM review_items WHERE submitted_at > now() - interval '7 days'
 GROUP BY 1 ORDER BY 2 DESC;
```

**`BANNED_WORD_WARN` 비중이 높으면** 관리자 화면에서 `직거래` · `수수료 없이` 를 먼저 끄십시오. 중고 장비에서 "직거래 가능"은 흔한 표현입니다.

## 6-3. 자동검수 조정

```sql
SELECT * FROM v_auto_review_rate;
```

자동화율이 낮으면 개입 사유를 하나씩 검토합니다. **`FIRST_LISTING` 이 가장 많을 텐데, 초기에는 정상입니다** — 모든 등록자가 첫 등록이니까요.

## 6-4. 하지 말아야 할 것

| 유혹 | 이유 |
|---|---|
| 트래픽이 적다고 자동검수 끄기 | 나중에 켜면 쌓인 것이 한꺼번에 옵니다 |
| 매물이 적다고 검수 건너뛰기 | 첫인상이 서비스 품질을 결정합니다 |
| 반응 보려고 광고 섞기 | 표시 의무 위반 |
| **정산 배치 수동 실행** | 수요일 절차를 지키십시오 |
