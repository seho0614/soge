## 2. 반영 날 순서 (보류를 풀면 · 단계별 블록)

| 단계 | 할 일 | 누가 | 운영 영향 | 되돌리기 |
|---|---|---|---|---|
| 1 | 새 개발 EC2 만들기 · 탄력적 IP · 보안 그룹(22 = 두 IP · 나머지 닫음) | 대표(콘솔) | 없음 | 지우면 끝 |
| 2 | 개발 환경 옮기기 — 3절 목록 · `~/sgb-check.sh main up` 으로 점검판이 뜨는지 | 대표 + Claude | 없음 | 옛 개발 환경이 그대로 있음 |
| 3 | 묶음 운영 반영 — precheck → RDS 스냅샷 → apply → postcheck(E8 절차서) | 대표(ubuntu) | 반영 시간 | 절차서 rollback |

## 4. 운영 서버에서 지울 것 · 남길 것

| 지움(개발 쪽) | 남김(운영 쪽 · 손대지 않음) |
|---|---|
| sgbdev 사용자 · `/home/sgbdev` | ubuntu 사용자 · `/home/ubuntu` |
| rootless 도커(sgbdev 소유) · 이미지 · 볼륨 | pm2 프로세스(API · 사용자 웹 · 운영 화면 · sgb-jobs) |
| 점검판 포트(13000 · 15173 · 15174 · 15432 · 13100 · 15175)를 쓰던 것 | Nginx(`/etc/nginx/sites-enabled/sgb` · 허용 IP) · 인증서 |
| 개발용 패키지 중 운영이 쓰지 않는 것(지우기 전 목록을 보여 드림) | Node 22 · 운영 킷 폴더 · 운영 로그 · 올린 파일 · `.env` |

- 지우기 전후로 같은 확인을 돌립니다: `pm2 ls` 4개 online · `curl https://sogaebank.com/api/v1/health` 200 · 운영 화면 로그인 · 디스크 사용량(줄어든 것 확인).
