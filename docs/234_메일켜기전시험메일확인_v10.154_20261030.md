# 234. 메일 켜기 전 시험 메일 확인 잠금 — v10.154 (2026-10-30)

> 오픈 전체 리허설(docs/228 4절) **발견 4**(보내는 주소 · SMTP 설정이 없거나 도착 확인 없이 메일 스위치를 켜면 회원 화면은 「메일을 보냈습니다」인데 메일이 안 나감 — 비밀번호 찾기 · 상담 신청)를 오픈 날 순서표(사람)에만 기대지 않도록, v10.153(docs/233) 잠금 2개와 같은 모양으로 **서버가 막고, 막을지는 최고 관리자가 운영 화면에서 정함**.
> 대표 「1 2 진행」 · 「모두진행」(10/30). 앞 판: v10.153(docs/233) · **마이그레이션 D147 하나(185)** · 설정 1개 · 새 API 없음.
> 운영 적용은 v10.152(docs/232)를 먼저 하고, v10.153 · v10.154 는 **그다음 운영 적용 때** 함께.
> 같은 묶음: realcheck 에 **[9] 운영 적용과 같은 빌드**(sgb-infra `docker/realcheck.sh` · `.ps1`) — 4절.

## 1. 결론

| 설정 | 처음 값 | 켜져 있을 때 서버가 거절하는 것 | 오류 |
|---|---|---|---|
| `notify.require_mail_test` 「메일 켜기 전 시험 메일 확인」 | **on** | 알림 메일 스위치(`notify.email_verified`) **켜기** — ① SMTP_USER · SMTP_PASS · 보내는 주소 중 빠진 것이 있으면 ② 최근 7일 안 「시험 메일」 성공이 없으면 | 422 `MAIL_CONFIG_FIRST` · `MAIL_TEST_FIRST` |

- 꺼져 있으면(off) 지금처럼 그대로 켜집니다.
- 바꾸기는 **최고 관리자(SUPER)** 만 — 운영(ADMIN)은 403 `INTEG_SETTING_SUPER`. 끌 때 확인 창 · 감사 기록(SITE_SETTING_UPDATE).
- **메일 끄기는 언제나 됩니다.** 이미 켜져 있는 운영 값은 건드리지 않습니다(켜는 순간만 봄).
- 받은편지함 도착 · spf · dkim · dmarc = pass 확인은 **여전히 사람이** 합니다(서버는 SES 가 받았는지까지만 앎).

## 2. 시험 메일 기록

| 항목 | 내용 |
|---|---|
| API | 기존 `POST /api/v1/admin/mail/test`(SUPER · 감사 MAIL_TEST · 하루 notify.mail_test_daily) — 이제 결과를 `integration_tests` 에 메일(MAIL) · `MAIL_TEST` 한 줄로 남김 |
| 남기는 것 | 성공 · 실패 까닭(AUTH · REJECTED · TIMEOUT · NETWORK · BAD_INPUT 등) · **받는 주소는 가린 것만**(앞 2글자 · 도메인) · 키 값은 남기지 않음 |
| 근거 | 최근 7일 안 성공한 줄 — NICE 키 확인(docs/233) · 결제 · 계좌 LIVE(docs/220)와 같은 기간 |
| 운영 화면 | 외부 연동 › 메일 — 「마지막 시험 메일」 줄 · 「메일 켜기 전 시험 메일 확인 — 켜짐 / 꺼짐」 줄(SUPER 단추 · 끌 때 확인 창) |
| 상태 API | `GET /admin/mail/status` 에 requireTest · lastTestOkAt · lastTest |

## 4. realcheck [9] 운영 적용과 같은 빌드 (sgb-infra)

| 항목 | 내용 |
|---|---|
| 왜 | 점검판은 API 를 ts-node(형식 검사 느슨) · 운영 화면을 vite 개발 서버로 돌려, 운영 `apply.sh` 의 빌드(API `tsc` · 운영 화면 `tsc -b && vite build`)에서만 나는 오류를 못 봄 — v10.153 운영 화면 문법 오류가 realcheck 21/21 을 통과하고 기능 점검에서야 드러남 |
| 하는 일 | 컨테이너 안에서 ① API `tsc --noEmit` ② 운영 화면 `tsc -b && vite build`(결과물은 컨테이너 /tmp) — 둘 다 합쳐 1분쯤 · 실패면 오류 줄을 결과 파일에 |
| 확인 | 오늘 문법 오류를 다시 넣으면 운영 화면 빌드 실패(TS1434) · export 를 빼면 API 빌드 실패(TS2459) · 정상 판은 통과 |
| 항목 수 | realcheck 21 → **23** |
| 허용 | 대표 「모두진행」(10/30) — 점검판 **컨테이너 안에서만** tsc · 서버 호스트 · 확인판 · 운영에서는 돌리지 않음 |
| 사용자 웹 | 이미 `SITE_MODE=prod` 로 `next build` 를 하므로 더하지 않음 |

## 6. 하지 말 것
- 운영에서 잠금을 끄고 메일을 켜지 마십시오 — 끄는 것은 SES 장애로 시험 메일이 안 되는데 꼭 켜야 하는 경우만(감사 기록에 남음).
- 시험 메일 성공(SES 가 받음)만으로 끝내지 마십시오 — 받은편지함 도착 · spf · dkim · dmarc 는 사람이 확인(docs/167 7단계).
