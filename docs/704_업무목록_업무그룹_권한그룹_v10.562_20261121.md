# 704 업무 목록 → 업무그룹 → 권한그룹 (v10.562 · D291)

## 1. 결론
업무(탭)를 업무그룹으로 묶고(업무 하나가 여러 그룹에), 권한그룹은 **업무그룹 × 수준**으로 만들고 업무 하나씩 더하거나 뺍니다. 함께 가질 수 없는 조합(승인 ↔ 지급 실행)은 서버가 막습니다(422 PERM_CONFLICT).

## 2. 표(D291)
| 표 · 칸 | 내용 |
|---|---|
| perm_tasks.description | 업무 설명(300자) |
| perm_task_groups.active · note | 끄기(끄면 그 업무그룹으로 붙인 권한 빠짐) · 메모 |
| perm_task_group_items(group_key, task_key) | 업무그룹에 든 업무 — 처음은 perm_tasks.group_key(기본 메뉴 그룹) · 새 업무 · 기본 메뉴 그룹 옮김은 트리거가 맞춤 |
| perm_role_group_sets(group_key, task_group_key, level) | 권한그룹 세트 |
| perm_role_group_items.effect | ALLOW(옛 항목 모두) · DENY(그 그룹 세트에서 빼기) |
| perm_conflict_rules · perm_conflict_items | 함께 못 갖는 조합 — 처음 3줄: 정산 승인 ↔ 지급 실행(C710) · 지급 실행 ↔ 안심 파트너(D173) · 지급 실행 ↔ 제휴 파트너(D173) |
| fn_perm_group_expand(key) | 세트 펼침 + 더하기 − 빼기(꺼진 업무 · 업무그룹 · 업무가 안 쓰는 수준 빼고) |
| fn_perm_effective · fn_perm_widen_effective | 새 판 — 붙은 권한그룹마다 펼친 것의 합 + 개별 더하기 − 개별 빼기(옛 데이터는 같은 결과) |

## 3. API(모두 SUPER)
| 방법 | 주소 | 오류 |
|---|---|---|
| GET · POST | /admin/perm/tasks | 422 PERM_TASK · PERM_GROUP · PERM_LEVELS |
| PUT | /admin/perm/tasks/{key} | 404 · 422 |
| GET | /admin/perm/task-groups | |
| PUT | /admin/perm/task-groups/{key} | 422 PERM_GROUP · PERM_TASK |
| GET · PUT | /admin/perm/role-groups/{key}/sets | 422 PERM_CONFLICT(같은 거래에서 펼쳐 검사 · 되돌림) |
| GET · PUT | /admin/perm/conflicts · /admin/perm/conflicts/{code} | 422 |
- 옛 PUT /admin/perm/role-groups/{key}(업무별 권한 표)는 이제 ALLOW 항목만 통째로 바꿈(DENY · 세트는 그대로).

## 4. 화면
직원 · 권한 › 권한그룹(업무그룹 × 수준 체크 표 · 업무 더하기/빼기 · 실제 여는 업무 · 조합 규칙) · 업무그룹(업무 체크 · 끄기) · 업무 목록(주소 연결 없음 · 탭에는 있는데 업무 없음 → 더하기).

## 5. 시험 test_v1562
업무그룹 두 곳 소속 · 세트 펼침(빼기 반영) · 사원 실제 권한 · 조합 422(권한그룹 · 사원) · ADMIN 403.
