# 352. 포인트 출금(현금 지급) — v10.219 (2026-11-09)

> 계기: 대표 「포인트 현금 가능」(11/9) · v10.218 추천 보상을 켜기 전 「포인트 쓰임」 결정(partner-affiliate 미정 #4).
> 정한 것(11/9 AskUserQuestion): 대상 **현금화 가능 포인트 모두** · 최소 출금 **10,000원** · 원천징수는 **운영 화면에서 비율(SUPER)** · 운영 반영은 **v10.216 → v10.219 한 번에** · 계획 「승인」.
>
> **마이그레이션 1개 D190(227 → 228)** · 새 API 4개(회원 3 · 운영 반려 1) · 지급 데스크에 종류 「포인트」 · 원천징수율이 비어 있어 **출금 신청은 막힌 채**.

## 1. 흐름

```
회원 신청(REQUESTED) ──확정(ADMIN)──► CONFIRMED ──이체 뒤 지급 기록(PAYOUT · 다른 사람)──► PAID
      │                         │
      └─ 회원 취소(CANCELED)     └─ 반려(REJECTED · 사유) — 신청 · 확정 상태에서 · 포인트는 출금 가능 잔액으로 돌아감
```

- 출금 가능 잔액 = 현금화 가능(`redeemable`) 포인트 합계 − 신청 · 확정 · 지급된 출금(`fn_point_cashable`).
- 1포인트 = 1원 · 원천징수 세액은 10원 미만 버림 · 실지급액 = 포인트 − 원천징수.
- 실제 송금은 은행 연동이 없어 지급 담당이 직접 이체하고 「지급 기록」에 이체 참조를 적음(제휴 정산과 같음).

## 2. DB — D190_point_cashout

| 무엇 | 내용 |
|---|---|
| ① 추천 보상 현금화 | `point_rules.REFERRAL_DIRECT.needs_valid` → false(가입한 분 본인인증이 곧 확인) · `fn_referral_reward` 가 `redeemable true` 로 넣음. `point_ledger` 는 고칠 수 없는 표라 이미 쌓인 줄은 그대로(운영은 보상이 꺼져 있어 줄 없음) |
| ② 설정 | `point.cashout_min` 10000 · `point.cashout_tax_rate` 비어 있음(= 신청 막힘 · 0 ~ 50 · 소수 한 자리) · 바꾸기 SUPER(`POINT_SETTING_SUPER`) |
| ③ `point_cashouts` | 포인트 · 원천징수율 · 세액 · 실지급액(신청 때 값) · 받을 계좌(`payout_accounts` 참조 + 은행 이름 · 뒤 4자리 · 예금주를 신청 때 값으로) · 상태 · 확정 · 지급 · 반려(사람 · 시각 · 이체 참조 · 사유). **계좌번호 칸 없음(INV-11)** · 처리 중 신청은 한 사람 하나(`ux_point_cashouts_open`) |
| INV-9 예외 | 원천징수 칸은 회사가 내는 돈(마케팅비)이라 소개비 공제가 아님 — 제휴(partner_) · 퍼블리셔(adx_)와 같은 까닭으로 `fn_is_fee_exempt` 에 `point_cashouts` |
| DB 가 막는 것 | 잔액 초과 · 최소 미만 · 처리 중 신청이 있는데 또 · 확인 안 된 · 남의 계좌 · 본인인증 전 · 원천징수율 비어 있음 · 금액 · 계좌 바꾸기 · 상태 건너뛰기(신청 → 지급) · 확정한 사람이 지급(2인 원칙 `fn_payout_two_person`) · 지급자 · 이체 참조 없이 지급 · 사유 없이 반려 · 끝난 줄 고치기 · 지우기 |
| 지급 대기열 | `v_payout_queue` 에 `POINT`(받는 사람 = 회원 이름 · 계좌 확인이 풀리면 「지급 불가」) |
| DB 오류 | `POINT: …` → 422 `POINT_RULE` · **`PAYOUT: …`(2인 원칙) → 422 `PAYOUT_RULE`** — 전에는 잡지 않아 제휴 · 소개몰 정산에서도 500 으로 나갔음(이번에 바로잡음) |

## 3. API

| API | 권한 | 내용 |
|---|---|---|
| `GET /me/points/cashout` | 로그인 | 출금 가능 포인트 · 최소 · 원천징수율 · 확인된 받을 계좌 · 내 신청 20건 · 못 하는 까닭 `blocker`(TAX_UNSET · IDENTITY · OPEN · ACCOUNT · BELOW_MIN) |
| `POST /me/points/cashout` | 로그인 | `points` · `payoutAccountId` · 422 `POINT_RULE` · 감사 `POINT_CASHOUT_REQUEST` |
| `POST /me/points/cashout/{id}/cancel` | 로그인 | 신청 상태만 · 422 `NOT_CANCELABLE` · 감사 `POINT_CASHOUT_CANCEL` |
| `GET /admin/payouts` | ADMIN · PAYOUT | 대기 · 확정 전 · 최근 지급에 `POINT` · `pointSetting`(최소 · 원천징수율) |
| `POST /admin/payouts/point/{id}/confirm` · `…/pay` | ADMIN / PAYOUT | 지금 있는 API 에 종류 `point` |
| `POST /admin/payouts/point/{id}/reject` | ADMIN · PAYOUT | 사유 2 ~ 300자 · 422 `REASON_REQUIRED · NOT_OPEN · REJECT_POINT_ONLY` · 감사 `PAYOUT_REJECT` |
| `PATCH /admin/site-settings` | SUPER(`point.cashout_*`) | 최소 출금 · 원천징수율 — 운영 알림(설정 바뀜)에 사유와 함께 남음 |

## 7. 운영 반영 · 남은 일

1. 운영 반영은 v10.216 → v10.219 한 번에(절차서 따로) — 마이그레이션 2개(D189 · D190) · apply 가 스냅샷 yes 를 물음.
2. **원천징수율은 세무 확인 뒤 대표가 운영 화면에서 넣어야 출금 신청이 열림.** 기타소득 · 사업소득 구분 · 과세최저한(얼마 이하 비과세)은 이번에 넣지 않음 — 비율 하나만. 세무 확인 결과에 따라 고칠 수 있음.
3. 앞선 법무 확인(11/9 이상 없음 · 다단계 해당 안 됨)은 「현금화 안 됨」 기준이었음 — 현금 지급으로 바뀐 것을 법무에 한 번 더 알릴 것을 권함.
4. 지급 명세 · 원천징수 신고 자료(지급조서) 내려받기는 없음 — 필요하면 다음 판.
