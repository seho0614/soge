# e3.7t 회계 · 세무 시험을 ERP 로 옮김 (2026-11-25 · 갈래 feature/e3.7t)

> 결론: 소개뱅크 sgb-infra `qa/test_v*.py` 회계 시험 46개 가운데 **37개를 `qa/test_erp_v<번호>.py` 로 옮김**, 공용 부품 `qa/erp_common.py` 1개.
> 9개는 옮기지 않음(ERP 에 끝점 · 정기 작업이 아직 없거나 회계 시험이 아님 — 4절). 시험은 **돌리지 않았고** `python3 -m py_compile` 만 통과(38개 파일).

## 1. 실행 (점검판 · 소개뱅크 v10.800 이상 + ERP 가 떠 있을 때)
```bash
cd <sgb-erp 저장소>
ERP_API=http://localhost:13100/api/v1 SGB_API=http://localhost:13000/api/v1 \
ERP_DB=postgresql://sgb:sgb@localhost:15432/sgb_erp SGB_DB=postgresql://sgb:sgb@localhost:15432/sgb \
python3 qa/test_erp_v1449.py            # 하나
for f in qa/test_erp_v*.py; do python3 "$f" || echo "FAIL $f"; done   # 전부(겹쳐 돌리지 말 것 — 설정을 바꾸는 시험이 많음)
```
- 주소는 `localhost`/`127.0.0.1` 의 13100 · 13000 · 15432(sgb_erp · sgb) 만 받음. 다른 곳이면 멈춤(종료 코드 2).
- 코드 검사는 ERP 저장소(`ERP_ROOT`, 처음은 `qa/` 위 폴더)의 `api/src/modules/acct/*.ts` 를 읽음 → **회계 코드(e3.2 ~ e3.5)를 합친 뒤** 돌려야 ①이 통과.
- 각 시험 끝에 「결과: n / m」, 모두 통과면 0 · 아니면 1.

## 7. 돌리기 전에 알아 둘 것(실패가 예상되는 곳 · 확인 필요)
1. `POST /admin/erp/handoff` 가 SUPER 만이면 지급 담당(PAYOUT)은 소개뱅크 증표를 그대로 ERP 에 보냄 — ERP 가 introspect 로 받는다고 보았음(auth.ts ①). 다르면 `erp_token_for` 만 고치면 됨.
2. test_erp_v1383: ERP `setTaxType` 이 `UPDATE hlt_products` — ERP 에는 svc(읽기만)만 있어 실패할 것(옮김 빈틈).
3. test_erp_v1437: ERP 가드에 세무사 읽기 규칙(accountantRead)과 접속 기록 미들웨어가 없음 → 「회계 GET 200 · 접속 기록 3」 실패 예상(옮김 빈틈).
4. test_erp_v1392: 「붙은 증빙 파일 지우기 막음」은 소개뱅크 `files` 트리거가 소개뱅크 매입 표를 봄 → ERP 매입에 붙은 파일은 못 막을 수 있음(분리 빈틈).
5. ExportGate: ERP 는 `svc.export_requests` 를 읽기만 — 승인 번호를 「썼음」으로 바꾸지 못함(한 번만 쓰기 규칙이 다름).
6. test_erp_v1440 월보는 소개뱅크가 자기 회계 표로 만듦 — E7 뒤 ERP 값을 보게 되면 판정 다시 볼 것.
