# 605. 은행 거래내역 자동 조회 (v10.467 · 2026-11-20)

## 1. 결론
회사 계좌의 거래내역을 **금융결제원 오픈뱅킹(㉙ 대량 이체와 같은 FIRMBANK)**으로 매일 06:40 가져와 ⑪ **은행 맞추기**(acct_bank_uploads · acct_bank_txns)에 넣습니다. CSV 를 올리던 일을 대신합니다. **처음 꺼짐**이고, 켜도 방식이 **간주(ASSUME)**면 금융결제원에 묻지 않습니다. 외부 연동 줄은 더하지 않습니다(**15종 그대로**). 위치: **회계 › 자금 › 은행 자동 조회** · SB-ADM-SAL-020 · API `/admin/acct/bank-feed`.

| 단계 | 누가 | 내용 |
|---|---|---|
| 1 계좌 등록 | SUPER | 이름 · 은행 표준코드 3자리 · **핀테크이용번호**(오픈뱅킹에 회사 계좌를 등록할 때 받은 번호 · 암호문으로만 저장 · 같은 번호 두 번 안 됨) · 끝 4자리(화면 표시) |
| 2 켜기 | SUPER | 정책 › 전체 설정 `acct.bank_feed` on |
| 3 자동 조회 | 정기 작업 `acct_bank_feed` 매일 06:40 | 오늘 포함 `acct.bank_feed_days`(처음 3)일 · 계좌마다 |
| 지금 조회 | SUPER · PAYOUT | 「지금 조회」(기간 31일 안) · 켜져 있을 때만 |
| 끄기 | SUPER | 계좌 「끄기」(지우지 않음 · 은행 · 번호는 못 바꿈 — 끄고 새로 등록) |

| 설정 | 처음 | 뜻 |
|---|---|---|
| `acct.bank_feed` | off | 자동 조회 · 지금 조회 켬 |
| `acct.bank_feed_mode` | ASSUME | ASSUME = 금융결제원에 묻지 않고 **간주 2줄**(마지막 날 입금 1 · 출금 3,000원 · 계좌마다 같은 값 — 다시 물으면 「이미 있음」) / LIVE = 금융결제원 |
| `acct.bank_feed_days` | 3 | 한 번에 묻는 날 수(1 ~ 31) |

| 키 · .env | 어디 | 뜻 |
|---|---|---|
| `FIRMBANK_CLIENT_ID` · `FIRMBANK_CLIENT_SECRET` | 연동 키(㉙ 그대로) | 이용기관 앱 키 |
| **`FIRMBANK_USER_TOKEN`**(새로) | 운영 화면 › 외부 연동 › 「연동 키」(SUPER · 암호화) | 거래내역조회용 **사용자 인증 토큰**(회사 계좌를 오픈뱅킹에 등록할 때 받음 · 알려진 유효기간 90일 → 다시 받아 넣음) |
| `FIRMBANK_ORG_CODE` · `FIRMBANK_ENV` · `FIRMBANK_API_BASE` · `FIRMBANK_TEST_BASE` · `FIRMBANK_TIMEOUT_MS` | .env(㉙ 그대로) | 거래고유번호 앞 10자 · 시험/운영 주소 |
| `FIRMBANK_FEED_MAP` | .env | 경로 · 칸 이름을 JSON 으로 바꿈(공식 가이드와 다를 때) |

## 2. 들여오기 규칙
1. 금융결제원 응답 줄 → 날짜 · 시각 · 입금/출금(`inout_type` 「입금」/「출금 · 지급」) · 금액 · 거래 뒤 잔액 · 적요(→ 상대) · 지점(→ 메모).
2. **같은 줄은 한 번** — 지문 = sha256(`kftc|계좌 번호|날짜|시각|입금|출금|잔액|내용|같은 줄 순번`) · 겹치는 기간을 다시 물어도 그대로.
3. **CSV 로 이미 올린 줄도 건너뜀** — 날짜 · 입금 · 출금 · 잔액이 모두 같은 줄(잔액이 있을 때만)은 「이미 있음」.
4. 한 번 조회 = 은행 맞추기 「올린 기록」 한 줄(파일 이름 「금융결제원 자동 조회 …」 · 은행 칸 「자동 003 ****1234」) + 조회 기록(acct_bank_feed_runs · 쌓기만 · 누가 · 비면 정기 작업).
5. 실패하면 기록(FAIL · 사유) · 계좌의 「마지막」 칸 · 정기 작업이면 운영 알림 **ACCT_BANK_FEED_FAIL**(계좌 · 날마다 한 번). LIVE 인데 사용자 토큰 · 키 · 이용기관코드가 없으면 422 **BANK_FEED_NOT_READY**(조용히 간주로 바꾸지 않음).
6. 들여온 줄을 전표와 맞추는 일은 그대로 **회계 › 은행 맞추기**(자동 맞춤 · 사람이 맞춤).

## 3. 금융결제원 흐름(코드 `src/modules/acct/bankfeed.ts` KftcBankFeed)
- `GET /v2.0/account/transaction_list/fin_num` — `bank_tran_id`(㉙ 와 같은 시퀀스 fn_acct_transfer_tran_id · 이용기관코드 + U + 9자리) · `fintech_use_num` · `inquiry_type=A` · `inquiry_base=D` · `from_date` · `to_date` · `sort_order=A` · `tran_dtime` · 토큰 `Authorization: Bearer {FIRMBANK_USER_TOKEN}`.
- 다음 쪽: `next_page_yn = Y` 이면 `befor_inquiry_trace_info` 로 이어서(최대 20쪽).
- 성공 판정: `rsp_code = A0000` · 줄 목록 `res_list`.

## 4. 대표 확인 필요(금융결제원) — 문서 591 3절과 같은 성격
1. **이용기관(일반 법인)이 자기 회사 계좌 거래내역을 오픈뱅킹 「거래내역조회」로 볼 수 있는지** — 사용자 인증(회사 대표 · 담당자 본인 인증)으로 계좌를 등록하는 방식인지 확인. **안 되면 거래 은행 펌뱅킹(거래내역 통지) · 연동 업체를 같은 어댑터 자리**(bankfeed.ts 의 `BankFeedAdapter` 한 곳)에 넣습니다.
2. 위 경로 · 칸 이름 · 토큰 방식(사용자 토큰 · 90일)은 「금융결제원 오픈뱅킹 v2.0 으로 알려진 값」입니다 — **2026-11-20 공식 개발자 가이드로 확인하지 못했습니다.** 다르면 `FIRMBANK_FEED_MAP` · 연동 키만 고칩니다.
3. 핀테크이용번호 자릿수(알려진 값 24자리)도 확인 필요 — 서버는 숫자 20 ~ 30자리를 받습니다.
4. 조회 수수료 · 하루 횟수 제한 · 조회 가능 기간은 계약 문서로 확인.

## 5. 주의
1. 점검판 · 시험은 간주만 씁니다(실제 금융결제원 호출 없음). 처음 LIVE 는 `FIRMBANK_ENV=TEST`.
2. 같은 날 CSV 와 자동 조회를 함께 쓰면 잔액이 비어 있는 CSV 줄은 겹쳐 들어올 수 있습니다 — 자동 조회를 켠 뒤에는 CSV 를 올리지 않는 것을 권합니다.
3. 은행 맞추기 표에는 계좌 칸이 없습니다(⑪ 그대로 · 한 계좌 기준) — 여러 계좌를 등록하면 줄이 함께 보이고, 어느 계좌 줄인지는 「올린 기록」의 은행 칸(끝 4자리)으로 봅니다.
4. 사용자 토큰 만료 전에 다시 받아 넣으십시오(만료되면 정기 작업이 실패 알림).
