# 379. 급한 알림 받는 길 · 알림 길 연속 실패 경보 · 대표 할 일 — v10.238 ~ v10.240 (2026-11-11)

> 대표 「다음개발」 → 후보 3가지 「모두」 → 계획 「승인 + 통과하면 병합」(11/11).
> **마이그레이션 없음**(238 그대로) · 스위치 · 설정 값을 바꾸지 않음 · 사용자 웹 바뀌지 않음.

## 1. 왜

지금 운영은 메일(NO_SMTP) · 텔레그램 · 슬랙이 모두 꺼져 있어, 급한 알림(CRITICAL)이 생겨도 운영 화면을 열기 전에는 아무 데도 가지 않습니다. 그런데 그 사실이 화면 어디에도 한 줄로 보이지 않았습니다. 또 길을 켠 뒤에 토큰 · 웹훅이 바뀌거나 지워지면, 실패는 정기 작업 기록에만 남아 **알림이 조용히 끊겼습니다.** 인계 메모의 대표 할 일도 무엇이 끝났는지 사람이 찾아봐야 했습니다.

### 알아 둘 것

1. 실패가 시작된 시각은 API 프로세스가 기억합니다. 그 사이 API 를 다시 띄우면 처음부터 다시 셉니다 — 경보가 늦어질 뿐 잘못 나지는 않습니다.
2. 길이 하나뿐이면(예: 슬랙만 켬) 그 길이 끊겼을 때 다른 길이 없어 경보도 운영 화면에만 남습니다. **길을 두 개 이상** 켜 두기를 권합니다(텔레그램 + 슬랙 등).
3. 「대표 할 일」은 값이 **있는지만** 봅니다(신고번호 · 소유 확인 값이 맞는지는 보지 않음). 외부 연동 줄은 LIVE 가 아닌 연동마다 신청일이 있고 예상일이 지나지 않았을 때 「됨」입니다.

## 4. 운영 적용

- 마이그레이션 없음 — 스냅샷은 꼭은 아님. `.env` · Nginx 그대로.
- 적용 직후 운영은 길이 0 이라 첫 화면 「급한 알림 받는 길 — 0 / 3」(○ 또는 ⚠)과 「대표 할 일」 아직이 여럿 보이는 것이 정상입니다.
