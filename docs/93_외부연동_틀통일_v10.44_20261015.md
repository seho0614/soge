⚠ 키를 넣고 LIVE 로 바꾸면 여전히 「보냈습니다」가 나갑니다. **알림톡 발송 어댑터를 붙이기 전에는 `ALIMTALK_KEY` 를 넣지 마십시오.** 붙이는 순서는 3절.

## 3. 새 연동 붙이는 법 (알림톡을 예로)

1. **목록표부터** — `src/common/integration/registry.ts` 의 그 연동 줄: `adapter`(NONE → REAL) · `files` · `otherEnv` · `doc`
2. **어댑터 파일 하나** — 같은 모양으로:
   ```ts
   // src/modules/notify/alimtalk.provider.ts (예)
   export abstract class AlimtalkProvider { abstract readonly configured: boolean; abstract send(to: string, template: string, vars: Record<string, string>): Promise<{ ok: boolean; errorKind?: IntegrationErrorKind; error?: string }>; }
   class StubAlimtalk extends AlimtalkProvider { readonly configured = false; async send() { return { ok: false, errorKind: 'NOT_CONFIGURED' as const }; } }
   class HttpAlimtalk extends AlimtalkProvider { /* httpJson(…) — common/http-json.ts · 키는 로그 · 응답에 싣지 않음 */ }
   export function resolveAlimtalkProvider(): AlimtalkProvider { const key = process.env.ALIMTALK_KEY; return key ? new HttpAlimtalk(key) : new StubAlimtalk(); }
   ```
   - 키가 없으면 스텁 · 스텁은 「보냈다」고 하지 않음(`ok: false` · `NOT_CONFIGURED`)
   - 오류 종류는 `IntegrationErrorKind` 에서 고름(새 이름 만들지 않기)
3. **판단은 switches 로** — 간주 스위치가 있으면 `assumeOn(db, '이름', 줄 없을 때 값)`, 상태는 `integrationLive(db, 'CODE')`
4. **쓰는 곳 바꾸기** — 상담 인증번호: `consult.service.ts` 의 `notifyReady()` 를 `resolveAlimtalkProvider().configured && integrationLive(…)` 로, 「알림톡 연동 후」 주석 자리에서 `send`
5. **운영 .env 예시** — 키 · 주소 줄(`deploy/aws/env.production.example`)
6. **오프라인 시험** — 가짜 서버로 정상 · 인증 실패 · 시간 초과 · 형식 이상(`scripts/test-mail-offline.ts` · `test-nts-offline.ts` 참고) → `verify-all.sh` 에 한 줄
7. `npm run check:integrations` 통과 → kit → PC realcheck
8. 운영: 키 넣기 → 시험 발송 → 운영 화면에서 상태 LIVE → (간주 스위치가 있으면) off
