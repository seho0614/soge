# 649. 운영 화면 일괄 처리 (v10.511 · D275 · 2026-11-20)

> 대표 11/20 「㊺ ③」. 화면: 운영 화면 **회원 › 「일괄 처리」**(SB-ADM-OPX-030 · ADMIN · SUPER · 검수 담당(REVIEWER)은 검수만).

## 1. 결론

검수 · 신고 · 1:1 문의 · 회원 목록에서 **여러 줄을 골라(한 번 최대 100) 사유와 함께** 상태를 바꿉니다. 줄마다 **기존 한 건 처리 함수**를 그 줄만의 거래 안에서 부르고, 같은 거래에서 **감사 한 줄**(한 건 처리와 같은 이름)을 남깁니다. 한 줄이 실패해도 다른 줄은 그대로이고, 실패한 줄은 결과에 오류 코드가 나옵니다.

| 종류 | 처리 | 부르는 함수 | 감사 이름 | 역할 |
|---|---|---|---|---|
| 검수 | 승인 · 반려(반려 사유 코드 필수) | ReviewService.decide | REVIEW_DECIDE | REVIEWER · ADMIN · SUPER |
| 신고 | 인정 · 기각(사유가 신고자에게 전달) | AbuseService.resolve | REPORT_RESOLVE | ADMIN · SUPER |
| 1:1 문의 | 닫기 · 다시 열기 · 담당 | InquiryAdminService.patch | INQUIRY_UPDATE | ADMIN · SUPER |
| 회원 | 정지 · 정상(자기 자신 · 최고 관리자 빼고 · 상태 바뀐 기록) | AdminMemberService.setAccountStatus | ACCOUNT_STATUS | ADMIN · SUPER |

- 감사 after_data 에 일괄 번호(bulkRun) · 처리 · 사유 · 그 줄 결과.
- 실행 기록 `opx_bulk_runs`(쌓기만 · 줄마다 결과).
- 사유 2 ~ 300자(서버 = DB CHECK 같음) · 101줄 이상은 400.

## 2. 화면

종류 단추 4개 → 지금 목록(검수 대기 · 신고 처리 큐 · 열린 문의 · 회원 100명)을 기존 API 로 불러 고르기 칸 → 처리 · 사유 → 「n줄 처리」 → 실패한 줄 까닭 · 최근 일괄 처리 기록. 기존 각 화면(검수 큐 · 1:1 문의 등)에 고르기 칸을 넣는 것은 다음 후보(이번에는 기존 화면 파일을 고치지 않음).
