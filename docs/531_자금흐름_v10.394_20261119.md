# 531. 자금 흐름 90일 (v10.394 · 2026-11-19)

> ⑫ 세 번째(D245). 대표 11/19 「자금 흐름 90일 — 잔액은 직접 넣거나 ⑪ 은행 CSV 마지막 잔액 · 모자라면 운영 알림」.

## 1. 결론

- 운영 화면 **회계 › 자금 흐름**(SUPER · PAYOUT · SB-ADM-ACC-090): 앞으로 **90일 날마다 예상 잔액**과 **가장 낮은 날**을 보여 줍니다(30 · 60 · 90 · 180일 고름).
- **시작 잔액** = 직접 넣은 잔액(SUPER) 과 회계 › 은행 맞추기에 올린 **통장 CSV 마지막 잔액** 중 **더 최근 것**(같은 날이면 직접 넣은 것) + 그날 뒤 오늘까지 장부 보통예금 줄의 들고 남.
- **확정된 돈만** 셉니다 — 앞으로 들어올 매출(구독 · 광고)을 짐작해 더하지 않습니다.
- 가장 낮은 날 잔액이 **`acct.cash_floor`(처음 0)** 밑이면 정기 작업 **`acct_cashflow`(매일 09:20)** 가 운영 알림 **ACCT_CASH_SHORT**(하루 한 번 · 마이너스면 CRITICAL · 다시 넉넉해지면 저절로 풀림 · 끄기 `acct.cash_alert` off). 시작 잔액이 없으면 알리지 않습니다.

## 2. 셈에 들어가는 것

| 구분 | 무엇 | 날짜 |
|---|---|---|
| 들어옴 | 광고 청구 받을 돈(발행 · 일부 입금 · 연체 · 남은 금액) | 납기일 · 지났으면 오늘(「납기 지남」) |
| 들어옴 | PG 정산 받을 돈(전표 PG 정산 받을 돈 줄 · 환불은 뺌) | 결제일 + `acct.pg_settle_days`(처음 2) 영업일 · 시작 잔액 날 뒤에 들어올 것만 |
| 들어옴 · 나감 | 직접 적은 예정(한 번 · 매달 · 끝 날짜) | 적은 날 |
| 나감 | 미지급금(매입 · 경비 — 전표 잔액을 최근 줄부터 남은 것으로) | 전표 날 + `acct.ap_pay_days`(처음 30) |
| 나감 | 법인카드 대금(전표 잔액) | 쓴 다음 달 `acct.card_pay_day`(처음 15일 · 영업일 아니면 다음 영업일) |
| 나감 | 부가세(`acct.vat_months` 25일 · 그 기간 부가세예수금 − 부가세대급금) | 기한(다음 영업일) · 기간이 안 끝났으면 「지금까지」 |
| 나감 | 원천세(매월 10일 · 지난달 예수금) | 기한(다음 영업일) |
| 나감 | 포인트 출금 신청 · 확정(지급 전 · 실지급액) | 오늘 |
| 나감 | 입점 판매자 정산 확정 · 미지급(판매자 돈이지만 통장에서 나감) | 확정일 + `acct.seller_pay_days`(처음 3) · 다음 영업일 |

- 입점 수수료는 정산 때 판매 대금에서 빼고 주므로 따로 들어오는 돈이 아닙니다(판매자 정산 금액이 이미 뺀 금액).
- 미지급금 · 법인카드는 ⑫ 매입 관리(v10.392) · 경비 청구(v10.393)가 만든 전표의 잔액으로 셉니다(갚은 것은 오래된 줄부터라고 봄).

## 5. 운영 확인 · 주의

1. 처음 한 번 **잔액 넣기**(대표 · SUPER) 또는 잔액 칸이 있는 통장 CSV 를 올려야 숫자가 맞습니다. 통장이 여러 개면 합을 넣습니다.
2. PG 정산 날짜(`acct.pg_settle_days`)는 PG 사 계약을 보고 맞춥니다(⑮ PG 정산 맞추기 뒤에는 실제 입금으로 바뀜).
3. 알림 기준(`acct.cash_floor`)은 「한 달 고정비」 정도로 올려 두기를 권합니다(처음 0 = 마이너스일 때만).
4. 반복 매출 · 급여 등 장부에 없는 것은 **예정 넣기**(매달)로 적습니다. ⑭ 급여 대장이 생기면 급여는 자동으로 들어갑니다(그때 고침).
