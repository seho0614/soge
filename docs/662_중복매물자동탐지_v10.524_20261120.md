# 662. 중복 매물 자동 탐지 (v10.524 · 2026-11-20)

## 1. 결론
매시간 최근 바뀐 매물을 **사진 지문(SHA-256) · 글 겹침 · 같은 연락처**로 견주어, 점수가 기준(`lsy.dup_threshold` 80)을 넘으면 **짝**으로 남기고 나중에 만든 매물을 **기존 검수 대기**에 올립니다(매물 상태는 그대로 · 자동으로 내리지 않음). 운영자가 짝을 나란히 보고 「같은 매물」 · 「다른 매물」을 정합니다. 스위치 `lsy.dup_detect` **처음 꺼짐**.

## 2. 흐름
| 단계 | 내용 |
|---|---|
| 고르기 | `lsy_hourly`(매시간) — 최근 2일 안에 바뀐 게시 · 검수 중 매물 중 그 판(version)을 아직 안 본 것 50건 · 40초 예산 |
| 견줄 상대 | 같은 관 · (같은 업종 또는 같은 주인) · `lsy.dup_window_days`(60일) 안에 만든 매물, 또는 같은 사진이 있는 매물(관 상관없이) · 최근 300건 |
| 사진 | 이미 있는 파일 SHA-256(올릴 때 서버가 계산 · `files.sha256`)이 같은 사진 수 — 1장 60점 · 1장 더할 때마다 +20 |
| 글 | 제목 · 본문 글자 두 개 묶음 겹침(Jaccard) · 제목 40 · 본문 60 — `pg_trgm` 은 로케일 C 에서 한글을 못 쪼개 쓰지 않음(B110 주석) |
| 연락처 | 같은 주인 · 다른 주인인데 계정 전화번호 같음 · 글 속 전화번호 같음 → +15 |
| 점수 | max(사진, 글) + 연락처 15 + (사진도 같고 글 50 이상) 10 · 100까지 |
| 검수 대기 | `lsy.dup_queue`(처음 on · 탐지가 켜졌을 때만) — 나중 매물에 검수 줄(`review_items`) · 이미 대기 · 진행 중이면 안 올림 · 신고 임계치(`fn_report_escalate`)와 같은 방식 |
| 운영 | 검수 › 매물 중복 의심(SB-ADM-LSY-010) — 짝 보기(두 매물 나란히 · 같은 사진 표시 · 주인 이름 가림 · 전화 끝 4자리) · 결정(사유 · 감사) · 「지금 보기」(매물 하나 바로 · 검수 대기에는 안 올림) |

- 결정한 짝은 다시 열지 않음(작업이 점수를 덮지 않음 · DB 트리거 `trg_lsy_dup_guard`).
- **지각 해시(비슷한 사진)** 는 그림을 풀 라이브러리가 필요(새 npm 없음 규칙) — 이번에는 같은 파일(SHA-256)만. 다음 후보.

## 3. 표 · API
| 종류 | 이름 |
|---|---|
| 표 | `lsy_dup_scans`(본 매물 · 판) · `lsy_dup_pairs`(a < b · 점수 · 글 점수 · 같은 사진 수 · 연락처 · PENDING · SAME · DIFFERENT · 검수 줄 id) |

## 4. 처리방침 · 법무 — **법무 확인 끝(11/20 · 11/21 대표)**
새로 모으는 개인정보 없음(이미 있는 계정 전화번호 · 매물 글을 운영 안에서 견줌 · 화면에는 끝 4자리만). 밖으로 보내지 않음.

## 5. 대표 결정 · 확인 거리
1. 켜는 때 · 기준 점수(처음 80) — 켠 뒤 1 ~ 2주 「다른 매물」 비율을 보고 조정 권함.
2. 「같은 매물」로 정한 뒤 자동 내림을 할지 — 지금은 사람이 검수 큐 · 신고 처리에서.
