## 3. 바뀌는 운영 설정

| 무엇 | 내용 |
|---|---|
| 운영 `.env` | **고치지 않음.** 새 업체 키는 업체 계약 뒤 운영 화면 › 외부 연동 › 연동 키에서. 업체 주소(`NICE_*` · `ALIMTALK_URL` · `ESIGN_URL` · `SAFENUM_URL`)는 그때 `.env` 에 더하고 재시작(각 문서 「켜는 순서」) |
| 웹훅 본문 | 전자계약 · 안심번호 웹훅 서명 검사를 위해 서버가 받은 본문을 그대로 둠(`main.ts` 의 `rawBody`) — 코드라 설정 없음 |
| Nginx | 고치지 않음 — 웹훅 주소는 지금 `/api/` 아래로 이미 넘어감 |
| 배치 | `sgb-jobs` 가 새 배치 2개를 스스로 읽음 — 할 일 없음 |
| 오픈 차단 수 | **늘어남(READY 2줄)** — 고장이 아니라 원래 보여야 했던 것(docs/225 3절). precheck · postcheck · open-prep 는 **경고만** 하므로 적용이 멈추지 않음 |

## 8. 하지 말 것

- `open-prep.sh apply` · 운영에서 `verify` · `attack` · `db:seed` · `nginx-render.sh` 다시 실행 — **특히 `fixture.sql` 은 검정 DB 전용**(운영 자료를 지움)
- `publish-terms.sh` 로 약관 게시 — 게시는 법무 확인 뒤 운영 화면에서
- 이번 반영과 함께 AI · 다국어 · 간주 스위치 · 메일 스위치 · **본인인증 · 알림톡 · 전자계약 · 안심번호 방식 · 연동 상태 · 소개비 스위치** 를 바꾸지 않음(반영 확인 뒤 따로)
- 운영 서버에서 방식을 MOCK 으로 — 서버가 막지만 고르지 않음(MOCK 은 점검판 전용)

## 9. 확인하지 못한 것

| 무엇 | 까닭 |
|---|---|
| 운영 서버의 디스크 · 지금 판 | sgbdev 는 운영 서버를 볼 수 없음 — 4-0 으로 |
| 운영 약관의 실제 상태 | docs/212 9절과 같음 — 시행일 11-11 로 게시한 약관이 있는지 대표 확인 대기 |
| 운영 `.env` 의 SMTP · PASS 값 | sgbdev 는 볼 수 없음 — 5절 14 · 15 번에서 어디서 왔는지로 확인 |
| 운영 연동 상태(integrations) | 리허설 DB 와 다를 수 있음 — 이번 반영은 바꾸지 않음. 운영에서 PG · BANK 가 이미 LIVE 라면 그대로 LIVE(시험 조건은 **올릴 때만** 봄) |
| 업체 요청 · 알림 형식(NICE · 알림톡 · 전자계약 · 050) | 공개 자료 기준 공통 모양 — 계약 뒤 업체 문서로 맞춤 |
| 업체 요금 · 1원 시험 비용 | 업체마다 다름 · 바뀔 수 있음 — 계약 때 확인 |
