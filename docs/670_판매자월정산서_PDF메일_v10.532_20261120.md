# 670. 판매자 월 정산서 PDF · 메일 (v10.532 · 2026-11-20)

## 1. 결론
입점 판매자(일반 입점 TENANT · 브랜드 직영관 BRAND)의 **주 정산서(hlt_settlements · 월요일 시작 7일)를 달마다 모은 「월 정산서」 한 장**을 만들고, 운영 화면 · 판매자센터에서 **인쇄용 화면 → 브라우저 「PDF로 저장」**으로 내려받습니다(서버 PDF 라이브러리 · 새 npm 없음 — 문서 PDF ㉝ `printDoc.ts` 와 같은 길). 메일은 **처음 꺼짐**(`mall.statement_mail`)이고, 켜면 매달 `mall.statement_day`(처음 5)일 09:10 에 지난달 정산서를 판매자 계정 메일로 **한 번만** 보냅니다 — 보낸 줄은 DB 트리거가 아무것도 바꾸지 못하게 막아 **같은 달 두 번 안 보냄**이 DB 에서 지켜집니다.

위치: 운영 **소개몰 › 판매자 월 정산서**(SB-ADM-SLX-010 · 탭 `slx-statements`) · 판매자센터 **월 정산서**(SB-HLT-SLX-010 · `/health/seller/center/statements` · 판매자센터 머리의 「월 정산서 · 인쇄」 단추).

| 항목 | 규칙 |
|---|---|
| 한 장의 범위 | 그 달에 **시작일(period_from)** 이 있는 주 정산서 — 달을 걸친 주는 시작한 달에 들어감(주 정산 1 ~ 5번) |
| 칸 | 매출 · 판매수수료 · 수수료 부가세 · 환불 조정 · 지급액 합계 · 지급 끝남(PAID) · 첫 주 이월 받음 · 마지막 주 다음 주로 이월 · 주별 줄(상태 · 세금계산서 번호 · 주문 줄 수) |
| 셈 | DB 함수 `fn_hlt_statement_calc(seller, ym)`(읽기만) · 저장은 `fn_hlt_statement_make` — 운영 화면 · 판매자센터 미리보기 · 정기 작업이 같은 함수 |
| 다시 셈 | 보내기 전까지는 늦게 마감한 주를 넣어 다시 셈(정기 작업이 만드는 날부터 매일 · 운영 「다시 셈」) · **보낸 뒤에는 못 바꿈**(HLT_STMT_SENT 409) |
| 미리보기 | 판매자센터에서 아직 만들지 않은 달은 지금 기록으로 셈한 미리보기(저장하지 않음 · 「미리보기」 표시) |
| 메일 | `mall.statement_mail` off(처음) · on 이고 메일 준비됨(알림 › 메일 설정)이면 지난달 것 중 보내기 전 · 실패(3번까지) · 꺼짐이었던 줄을 보냄 · 주 정산서 없는 달은 보내지 않음 |
| 받는 곳 | 판매자 계정(hlt_sellers.account_id)의 메일 — 기록에는 가린 주소(앞 2자 · 도메인)만 · 주소 없으면 NO_ADDR(운영 알림) |
| 겹침 막기 | 「보내는 중」 표시(`mail_claimed_at` · 10분) — 정기 작업과 운영 「지금 보내기」가 함께 보내지 않음 · 보낸 뒤 SENT(그 뒤 트리거가 막음) |

## 2. 전체 구조
1. 표 `hlt_seller_statements`(판매자 · 달 고유 · 금액 칸 · 주별 줄 jsonb · 메일 상태 · 지우지 않음) — 금액 칸 이름은 `fee_amount` · `fee_vat`(INV-9 감시 낱말을 새 표에 늘리지 않음).
2. 트리거 `trg_hlt_stmt_guard` — 지우기 막음 · 판매자 · 달 · 처음 만든 시각 고정 · **SENT 줄은 어떤 UPDATE 도 막음**.
3. 서버 `src/modules/slx/statements.ts` — 목록 · 한 장 · 만들기 · 보내기 · 정기 작업 `mallStatementJob`.
4. 정기 작업 `mall_statement`(매일 09:10 · job_schedules) — 만드는 날 전이면 아무것도 안 함(BEFORE_DAY) · 메일이 꺼져 있으면 보내기 전 줄을 OFF 로 표시만.
5. 운영 화면 `web/src/app/admin/Slx.tsx` `SlxStatements` — 달 고르기 · 이 달 만들기 · 판매자별 다시 셈 · **인쇄 · PDF**(`openPrint` · 파일 이름 `월정산서_YYYY-MM_판매자코드`) · 메일 보내기(스위치 · 준비됨일 때만 단추).
6. 판매자센터 `site/src/app/health/seller/center/statements/page.tsx` — 달 단추 · 정산서 한 장 · 「인쇄 · PDF 저장」(인쇄할 때 머리줄 · 길 안내 · 단추 숨김 `slx.css @media print`).

## 4. 설정 · 작업 · 알림
- `mall.statement_mail` off · `mall.statement_day` 5(1 ~ 28) — 정책 › 전체 설정(사유 · 바뀐 기록).
- 정기 작업 `mall_statement` 09:10 · 운영 알림 `MALL_STATEMENT_MAIL_FAIL`(실패 · 주소 없음이 있을 때).
- 권한(D258) `slx-statements`(소개몰 묶음 · VIEW · EDIT · APPROVE · EXPORT) — 만들기 · 보내기는 APPROVE.

## 6. 운영 · 보안 · 주의
1. 「주문 받기」가 꺼져 있어 지금은 주 정산서가 거의 없음 — 화면은 빈 표로 열림.
2. 메일 본문에는 금액 합계와 판매자센터 주소만(주문번호 · 구매자 정보 없음). 주별 명세는 로그인한 판매자센터에서만.
3. 세무사(ACCOUNTANT)는 /admin/acct/ 접두가 아니라 이 화면을 보지 않음 — 필요하면 다음 판에서 읽기 길을 따로.
4. **법무 확인 끝(11/20 · 11/21 대표)** · 세무 확인 권함: 월 정산서가 입점 약관 제19조(정산 명세) 통지 수단으로 충분한지 · 메일 통지 문구 · 세금계산서(판매수수료) 표시 방법.
5. 처리방침: 새로 모으는 개인정보 없음(판매자 계정 메일을 통지에 씀 — 이미 모은 항목의 이용 목적 「정산 통지」 포함 여부 — 법무 확인 끝(11/20 · 11/21 대표)).
