## 4. 운영에서 쓰는 순서 (반영 뒤 · 대표)

1. Anthropic 콘솔 › API Keys › **새 키 만들기**(10/25 대화에 붙인 키는 지움) · 콘솔 Limits 에 월 지출 한도도 걸어 두기
2. 운영 화면 › AI 운영 › AI 에이전트 › 「AI 키」 → 붙여 넣고 저장 → **키 확인** → 「키 확인 성공 — 쓸 수 있는 모델 N개」
3. 켜는 것은 따로 — 월 상한 → 처리방침 확인(AI 상담 docs/170 §2 · 검수 보조 docs/165 §2) → 스위치

`.env` 에 이미 키를 넣었다면 그대로 두어도 됩니다(운영 화면 키가 먼저 · 지우면 `.env` 키로 돌아감).

## 5. 운영 적용

- 마이그레이션 D122 하나 · `.env` · 패키지 변화 없음 · 적용 뒤 키가 없으면 지금과 같음(엔진 없음)
- 순서는 늘 같음(precheck → RDS 스냅샷 → apply → postcheck · 단계마다). 이번 판부터 apply 의 「yes」 질문이 남은 입력을 버리므로 **질문이 나온 뒤 yes 를 치면 됩니다**
- 운영 서버에서 api.anthropic.com(443)으로 나가는 연결이 열려 있어야 「키 확인」이 됨(보통 열려 있음)

## 6. 알아 둘 것

- 운영 계정을 뺏기면 키를 **지우거나 바꿀 수는** 있지만 **읽을 수는 없습니다**(화면 · API 가 돌려주지 않음). 바꾼 키는 감사 기록 · 「AI 에이전트」 화면의 날짜로 보입니다.
- PostgreSQL 이 오류 때 매개변수까지 기록하는 설정(`log_parameter_max_length_on_error`)은 기본이 0(끔)입니다. 운영 RDS 의 값은 확인하지 못했습니다(sgbdev 는 볼 수 없음) — 켜져 있으면 형식 오류로 거절된 값이 DB 기록에 남을 수 있습니다.
- 시험 엔진(`.env` MOCK)이 켜져 있으면 저장한 키를 쓰지 않습니다(화면에 그렇게 표시).
