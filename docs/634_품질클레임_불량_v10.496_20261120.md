# 634. 품질 클레임 · 불량 (v10.496 · 2026-11-20)

## 1. 결론
소개몰 상품의 **품질 클레임 · 불량**을 접수 → 확인 → 조치 → 끝냄으로 관리합니다. 클레임은 **상품 · 옵션 · 로트(633) · 공급사(632 · ⑯ 매입처) · 주문**에 잇고, **공급사 반품**은 원가 수불부(새 종류 SUP_RETURN) · 로트 · 전표에 한 번에 들어갑니다. 같은 상품 · 같은 불량이 되풀이되면 **재발 알림**. 위치: **소개몰 › 품질 클레임** · SB-ADM-QLT-030 · API `/admin/qlt/claims`.

## 2. 흐름
| 상태 | 넘어가는 길 |
|---|---|
| 접수(OPEN) | 접수 경로(고객 · 입고 검사 · 공급사 · 사내) · 불량 유형(파손 · 유통기한 · 이물 · 표시 · 라벨 · 품질 · 변질 · 수량 모자람 · 그 밖) · 수량 · 제목 · 내용 |
| 확인 중(CHECKING) · 조치(ACTION) | PUT 으로 자유롭게(보낸 칸만 바뀜 — 원인 · 조치 · 내용 · 공급사 · 로트) |
| 끝냄(CLOSED) | **원인 · 조치가 있어야**(서버 422 QLT_CLAIM_DONE · DB CHECK) |
| 반려(REJECTED) | **사유 필수** |
| 끝내거나 반려한 뒤 | 고치지 않음 · 반품 없음(409 · DB 도 막음) · 지우지 않음 · 기록(qlt_claim_logs)은 쌓기만 |

- 로트를 고르면 상품 · 옵션 · 공급사(로트의 공급사)가 따라옴 · 로트가 그 상품 · 옵션의 것이 아니면 막음(서버 + DB).
- 주문 번호를 넣으면 그 주문에 잇습니다(회원 정보는 클레임 화면에 보이지 않음).

## 3. 공급사 반품
| 항목 | 규칙 |
|---|---|
| 권한 | SUPER · PAYOUT(원가 장부를 움직임) |
| 조건 | 옵션 · 공급사가 있는 직판 상품 클레임 · 반품 합 ≤ 클레임 수량 · 창고 수량(비우면 본 창고) · 로트 남은 수량 |
| 원가 수불부 | 새 종류 **SUP_RETURN**(수량 −) — 지금 이동평균 원가로 나감. 재고가 모자라면 **DB 가 막음**(수불부 트리거가 셈한 원가 0 을 보고 `QLT_RETURN`) · 판매 출고처럼 원가 0 으로 내보내지 않음 |
| CHECK 바꿈 | `acct_stock_moves_kind_check` 에 SUP_RETURN 추가 · `ck_asm_sign` 에 SUP_RETURN 은 음수 — 옛 줄은 모두 그대로 통과 |
| 로트 | 클레임에 로트가 있으면 그 로트에서 같은 수량(SUP_RETURN) |
| 전표 | **QLT_SUP_RETURN** — 차변 외상매입금(AP) / 대변 상품(INVENTORY) · 금액 = 나간 원가 · 다음 전표 작업(sources.ts 끝에 덧붙임). 공급사가 대금에서 빼 주는(또는 돌려주는) 것으로 봄 — **계정은 세무사 확인**(규칙 확인표) |
| 회계 › 재고 화면 | 수불 이름표에 「공급사 반품」(Acct.tsx 한 줄) |
| 판매용 재고 | **바꾸지 않음** — 지금 구조(판매용 재고 `hlt_product_options.stock` 와 원가 장부는 따로 · 실사 조정도 판매용을 안 건드림)와 같게. 판매용 수량에 들어 있던 불량품이면 「소개몰 상품」에서 재고 수를 함께 고치십시오 |

## 4. 재발 · 집계
- 매일 07:20 `qlt_daily`: 반려 뺀 클레임 중 **같은 상품 · 같은 불량이 90일 안 `qlt.repeat_count`(처음 3 · 2 ~ 10)건 이상**이면 운영 알림 `QLT_CLAIM_REPEAT`(상품 · 불량 · 달마다 한 번) · 기준 아래로 줄면 풀림.
- `GET /admin/qlt/claims/stats?months=`(1 ~ 24 · 처음 6) — 불량 유형 · 상품(위 20) · 공급사(위 20 · 반품 수량) · 달마다 · 재발(90일 2건 이상). 공급사 클레임 수는 632 품질 점수 제안에 씀.
