## 0. 결론 (추천 1개)

- **A안 — 운영 전용 새 서버를 깨끗하게 만들고, 탄력적 IP 3.37.95.217 을 새 운영 서버로 옮깁니다.** 지금 서버는 개발 전용으로 남기고 새 IP 를 받습니다.
- 까닭
  1. 지금은 한 EC2(3.37.95.217 · t3.large)에 **개발(sgbdev · rootless 도커 · 점검판)과 운영 확인판(ubuntu · pm2 · 도메인)이 같은 디스크**를 씁니다 — 「운영 서버에서는 도커를 쓰지 않는다」는 원칙과 어긋나고, 개발 점검이 디스크 · CPU 를 쓰면 운영이 함께 느려집니다.
  2. 외부 연동 7건 신청서에 **발신 IP 3.37.95.217** 을 적었습니다 — IP 를 운영 쪽으로 옮기면 업체에 다시 알릴 필요가 없습니다.
  3. 새 서버를 구축 절차서대로 처음부터 만들면 **절차서가 맞는지 검증**되고, 문제가 생기면 **IP 를 지금 서버로 되돌리는 것만으로 되돌리기**가 됩니다.
- 시기: 정하지 않음. 권하는 때는 **오픈 직전(외부 연동 LIVE 전)** — 연동 업체가 IP 로 시험을 시작하기 전에 옮기는 것이 깔끔합니다.
