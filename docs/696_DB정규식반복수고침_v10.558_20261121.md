# 696. DB 검사 정규식 반복 수 고침 · 끌어올림 표시는 최신순만 (v10.558 · 2026-11-21)

## 1. 결론
점검 9(v10.557 · 1 ~ 8차 합친 점검) 회귀에서 서비스 결함 2가지를 찾아 고쳤습니다.

| # | 결함 | 영향 | 고침 |
|---|---|---|---|
| ① | DB 검사(CHECK) 정규식의 반복 수가 255 를 넘음(`{0,300}` · `{4,500}`) — PostgreSQL 은 255 까지만 받음 | 값을 넣는 순간 저장이 통째로 실패(500). 빈 칸이면 검사하지 않아 드러나지 않았음 | 마이그레이션 **D289**(327번째) — 같은 뜻으로 나눠 씀(`{0,300}` → `{0,250}` 뒤 `{0,50}` · `{4,500}` → `{4,250}` 뒤 `{0,250}`) |
| ② | 매물 목록 「끌어올림」 표시가 소개비순 · 인기순 등 모든 정렬에 붙음 | 설계서(docs/653)는 「소개비순엔 표시 없음」 — 자리가 바뀌지 않는 정렬에서 표시만 붙어 헷갈림 | 끌어올림이 자리를 바꾸는 **최신순에서만** 표시 |

## 2. ① 정규식이 걸린 곳
| 표 · 칸 | 처음 만든 판 | 운영에 있음 | 실패하던 일 |
|---|---|---|---|
| `biz_axis_items.source_url` | D054 | 예 | 운영 화면에서 소개창업 정책 글 「출처 주소」를 넣어 저장 |
| `affiliate_products.image_path` | D075 | 예 | 제휴상품 사진 주소(https) 저장(지금은 화면 · API 쓰기 길 없음 — DB 로만) |
| `prx_popups.link_url` | D277 | 아니오(이번 반영분) | 운영 화면 **노출 › 메인 팝업** 에서 단추 주소를 넣어 만들기 · 고치기 |

- 운영에 있는 두 칸은 **지금 값이 든 줄이 없습니다**(넣을 수 없었음) — D289 가 다시 붙일 때 검사가 바로 끝납니다.
- 받는 값은 그대로입니다. 팝업 주소는 서버 정규식(`POPUP_LINK_RE` · `{0,300}` — 자바스크립트는 255 제한 없음)과 같은 길이(사이트 안 주소 / 뒤 300자 · https 경로 300자)를 받습니다.
- 다른 마이그레이션 · DB 함수에는 255 를 넘는 반복 수가 없습니다(버리는 DB 의 `pg_constraint` · `pg_proc` 전부 찾음).

## 3. ② 끌어올림 표시
- `GET /listings` 의 `bumpLabel` — `sort` 가 RECENT(기본)일 때만 「끌어올림」 · 「유료 끌어올림」, 그 밖의 정렬 · 관련도순은 `null`.
- 끌어올림의 자리 효과(최신순 위로)는 그대로입니다.
