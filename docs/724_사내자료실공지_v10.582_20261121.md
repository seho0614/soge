# 724. 사내 자료실 · 공지 (v10.582 · 2026-11-21)

> 대표 11/21 「16개 모두 동시에」 — 13차 인사 · 회계 ②. 사무 › 사내 문서함 바로 뒤 새 탭 「사내 자료실 · 공지」(키 `hra-library`).

## 1. 결론

- 운영자에게만 보이는 **공지(본문)** 와 **자료(파일)** 를 올리고, **권한그룹별 공개 범위** · **꼭 읽기 · 기한** · **읽음 확인**을 남깁니다.
- 사내 문서함(D253)은 회사 법정 문서를 판으로 보관하는 곳이라 그대로 두고, 겹치는 「파일 보관」은 재사용했습니다:
  자료 파일은 사내 문서함과 **같은 파일 용도(CORP_DOC)** 로 올리거나, 사내 문서함 **문서를 골라** 붙입니다(그 문서의 가장 최근 판 · 두 번 올리지 않음).
- 운영자 게시판(D213)은 자동 알림 글 · 텔레그램 기록 중심이라 공개 범위 · 꼭 읽기를 넣지 않고 따로 만들었습니다(게시판 함수 · 정리 작업을 건드리지 않으려고).
- 새 파일 용도 없음(`ck_files_purpose` · `fn_file_can_read` 안 고침).

## 2. 공개 범위

| 값 | 보는 사람 |
|---|---|
| 비움 | 운영 역할(ADMIN · PAYOUT · REVIEWER · PARTNER_MAL · PARTNER_AFF) 모두 · SUPER · **세무사 빠짐** |
| 권한그룹 키(D258 `perm_role_groups`) | 그 그룹에 직접 붙은 사람(`perm_account_groups` · 기한 안) 또는 그 그룹의 처음 역할(`from_role`)을 가진 사람(`account_roles` · 기한 안) · SUPER 는 늘 |

- 판단은 DB 함수 `fn_hra_lib_can_read(글, 계정)` 하나 — 목록 · 본문 · 파일 · 읽음 현황이 모두 같은 함수를 씀.
- 공개 범위 밖이면 글이 있는지조차 알리지 않고 **404**(파일과 같은 규칙).

## 3. 화면 (SB-ADM-HRA-020)

- 위: 나에게 공개된 글 · 꼭 읽을 글 남은 수 · 종류 거르기 · 제목 누르면 본문 · 「읽었습니다」 · 파일 열기(5분 주소).
- 아래(ADMIN · SUPER 만): 글 올리기(공지 · 자료 · 꼭 읽기 · 기한 · 맨 위 고정 · 공개 범위 체크) · 모든 글의 읽음 / 대상 수 · 「읽음 현황」(이름 · 가린 메일 · 읽은 시각) · 보관 끝 · 기한 지남 알림 스위치(SUPER).

## 4. API

| 방법 | 주소 | 역할 | 감사 |
|---|---|---|---|
| GET | `/admin/hra/library?kind=&q=&unread=` | 운영 역할 모두(세무사 빠짐) | — |
| GET | `/admin/hra/library/{id}` | 같음(공개 범위 밖 404) | — |
| POST | `/admin/hra/library/{id}/read` | 같음 | — |
| GET | `/admin/hra/library/{id}/file` | 같음 | `HRA_LIB_FILE_OPEN`(글 · 파일 번호 · 이름만) |
| GET | `/admin/hra/library/manage?state=` | ADMIN · SUPER | — |
| POST | `/admin/hra/library` | ADMIN · SUPER | `HRA_LIB_POST`(고른 칸) |
| PUT | `/admin/hra/library/{id}` | ADMIN · SUPER | `HRA_LIB_EDIT` |
| POST | `/admin/hra/library/{id}/archive` | ADMIN · SUPER | `HRA_LIB_ARCHIVE` |
| GET | `/admin/hra/library/{id}/reads` | ADMIN · SUPER | `HRA_LIB_READS_VIEW`(번호만 · idOnly) |

- 파일 열기는 이 주소가 공개 범위를 본 뒤 저장소의 짧은 주소(5분)를 줌 — 매물 동영상(v10.526)과 같은 방식.
- 오류: `HRA_LIB_TITLE` · `_BODY` · `_KIND` · `_AUDIENCE` · `_DUE` · `_FILE` · `_STATE` · `HRA_REASON`.

## 5. DB (13차 SQL `hra_582_library.sql`)

- `hra_lib_posts` — 종류 · 제목 · 본문 · 공개 범위 · 꼭 읽기 · 기한 · 고정 · 파일(CORP_DOC) 또는 사내 문서 · 상태(보관 끝은 사유) · 지우지 않음.
- `hra_lib_reads`(쌓기만) · `hra_lib_revisions`(고치기 전 내용 · 쌓기만).
- 트리거 — 글 지킴(종류 · 쓴 사람 · 파일 못 바꿈 · 보관 끝 되돌리기 막음 · 없는 권한그룹 막음 · CORP_DOC READY 만) · 붙은 파일 지우기 막음(`trg_hra_lib_file_keep` · 기존 `fn_files_acct_guard` 는 안 고침).
- 설정 `hra.lib_unread_alert` 처음 off — on 이면 `hra_daily` 가 기한 지난 꼭 읽을 글마다 `HRA_LIB_UNREAD` 한 번(모두 읽거나 보관 끝이면 풀림).
- 권한 시드 `hra-library` — R_ADMIN 넷 · 나머지 운영 그룹 VIEW · 주소 맵에는 관리 주소만(읽기 주소는 내 인사처럼 넣지 않음).

## 6. 시험 (test_v1582)

① 코드 ② 쓰기(없는 그룹 · 파일 없는 자료 422 · 지급 담당 403) · 공개 범위(지급 담당 그룹 공지 보임 · 검수 담당 안 보임 · 404) · 읽음(두 번째 already · 대상 아님 404 · 지우기 막음) · 읽음 현황(가린 메일) · 고치기(고친 기록 · 보낸 칸만) · 보관 끝(다시 409 · 고치기 409 · 목록에서 빠짐) · 글 지우기 막음 ③ 화면.

## 7. 확인할 것

1. 글을 고쳐도 읽음 기록은 그대로입니다 — 내용이 크게 바뀌면 새 글로 올리고 옛 글은 보관 끝(다시 읽게 하려면).
2. 새 글 알림(텔레그램 · 메일)은 넣지 않았습니다 — 필요하면 10차 「운영 알림 받을 사람 규칙」과 이어 붙임.
