## 1. 결론

1. `@Audit(action, targetType, opts?)` 는 옵션이 없으면 **응답 전체**를 `audit.audit_logs.after_data`(쌓기만 · 고칠 수 없는 표)에 넣습니다. 보기 화면이나 개인정보가 섞인 응답이면 그 값이 감사 기록에 영영 남습니다.
2. src 전체 @Audit **808곳**을 모두 읽어 셋으로 나눴습니다.

| 분류 | 뜻 | 수 |
|---|---|---|
| A 그대로 | 응답이 작고(ok · id · 상태 · 합계 · 안내 글) 민감 값이 없음 | **778** |
| B idOnly | 보기 · 목록 · 내려받기처럼 응답이 통째로 민감 — 주소의 id 만 남김 | **3**(새로 2 · v10.559 사원 카드 1) |
| C pick | 쓰기 결과 중 감사에 필요한 칸(상태 · 번호 · 합계)만 남김 | **27** |

3. 이번에 **바꾼 곳 29**(B 2 · C 27) · 그대로 **779**(A 778 + 이미 idOnly 인 사원 카드 1).
4. interceptor 에 `pick?: string[]` 를 더했습니다 — 응답 객체 **최상위**에서 그 칸만 · 하나도 없으면 빈 객체 `{}` · 배열 응답이면 길이만 `{ n }` · `idOnly` 가 먼저. 옵션이 없으면 예전과 똑같이 응답 그대로입니다.
5. **이미 쌓인 기록은 그대로** 둡니다(쌓기만 표 · 위변조 확인 사슬(D235) · 고치면 사슬이 깨짐). 이번 판부터 새로 쓰는 줄만 줄어듭니다.

## 5. interceptor 바뀐 점

```ts
export type AuditOpts = { idOnly?: boolean; pick?: string[] };
export function auditAfter(meta, params, result) {
  if (meta.idOnly) return { id: String(params?.id ?? '') };
  if (meta.pick) {
    if (Array.isArray(result)) return { n: result.length };
    const out = {};   // 최상위에서 고른 칸만 · 없으면 {}
    ...
    return out;
  }
  return result ?? {};   // 옵션 없음 = 예전 그대로
}
```

- `target_id` 는 예전처럼 주소의 `:id` 가 uuid 일 때만 채웁니다(바뀜 없음).
- 새 @Audit 를 달 때: 보기 · 목록이면 `{ idOnly: true }` · 쓰기라도 응답에 사람 정보 · 증표가 섞이면 `{ pick: [...] }`.
