## 1. AI 상담 3단계 — 내 정보 조회 (읽기만)

### 1-1. 결론
로그인한 회원이 「제 주문 어디쯤이에요?」처럼 **자기 정보**를 물으면, AI 가 **정해 둔 조회 도구**로 그 회원의 정보만 읽어 답합니다. **바꾸기 · 취소 · 신청은 하지 않습니다**(그것은 4단계 · 사람 화면).

### 1-2. 조회 도구 (처음에는 5개 · 모두 읽기만 · 본인 것만)

| 도구 | 답하는 질문 예 | AI 에게 보내는 칸(최소) | 보내지 않는 칸 |
|---|---|---|---|
| 내 주문 상태(소개몰) | 「주문 언제 와요?」 | 주문 번호 끝 4자리 · 상태 · 택배사 · 예상일 | 받는 사람 이름 · 주소 · 전화 · 결제 수단 |
| 내 교환 · 반품 상태 | 「반품 접수됐나요?」 | 상태 · 접수일 · 다음 할 일 | 계좌 · 사유 원문 |
| 내 매물 · 요청 검수 상태 | 「제 글 왜 안 올라가요?」 | 제목 앞 20자 · 검수 상태 · 반려 사유 코드 | 본문 · 연락처 |
| 내 1:1 문의 상태 | 「문의 답 왔어요?」 | 접수일 · 상태 · 답변 여부 | 문의 본문 · 답변 본문(화면 링크만) |
| 내 구독 · 소개코드 | 「이번 달 소개코드 몇 개 남았어요?」 | 요금제 이름 · 다음 결제일 · 남은 수 | 카드 · 결제 키 |

- 회원 번호는 **AI 가 고르지 않습니다** — 서버가 로그인한 사람으로 고정(AI 가 다른 번호를 넣을 칸이 없음).
- 답에는 **화면 링크**를 붙여 자세한 것은 회원이 직접 봄(예: 「나의공간 › 주문」).
- 정산 · 소개비 금액 · 분쟁 · 환불 판단은 도구를 만들지 않음 → 지금처럼 「담당자에게 넘기기」.

### 1-3. 흐름
1. 손님 → AI 상담(로그인 상태) → 서버가 회원 확인
2. Claude 에 도구 5개를 알려 줌(도구 사용 · tool use) → Claude 가 필요한 도구만 고름
3. 서버가 그 회원 것만 읽어 **위 「보내는 칸」만** 돌려줌 → Claude 가 답
4. 비회원 · 로그인 만료 → 도구를 주지 않음(지금 2단계와 같음 · 「로그인하면 확인해 드려요」)

### 1-4. 안전장치

| 위험 | 막는 법 |
|---|---|
| 남의 정보 | 회원 번호는 서버 고정 · 도구 결과에 다른 회원 칸이 없음 · 시험에서 다른 회원 번호로 부르는 시도를 넣어 확인 |
| 개인정보가 AI 로 감 | 「보내는 칸」만 · 이름 · 주소 · 전화 · 계좌 · 카드는 도구에서 아예 빼고 만듦 · 대화 저장도 지금처럼 가림 |
| AI 가 꾸며 답함 | 도구 결과에 없는 상태는 「확인할 수 없어요」 · 답에 화면 링크 필수 |
| 손님 글로 AI 를 속이기 | 손님 글은 자료로만(지금 2단계 규칙 그대로) · 도구 인자에 회원 번호 · 다른 사람 정보 칸 없음 |
| 비용 | 도구를 부르면 대화 한 번에 Claude 호출이 2회가 될 수 있음 → 하루 한도 · 월 상한 그대로 · 사용량에 「조회」 따로 셈 |
| 기록 | 어느 도구를 언제 불렀는지 감사 기록(값은 남기지 않음) |

### 1-5. 켜기 전에 정할 것 · 확인할 것
1. **법무** — 「AI 상담이 회원 주문 · 문의 상태를 읽어 답함」을 처리방침 · 위탁 안내에 넣을지(국외 이전 고지는 #17 로 이미 함)
2. 도구 5개 범위 확정(더하거나 뺄 것)
3. 3단계 스위치는 **2단계를 1주 쓴 뒤** — 답 비율 95% · 넘길 문항 100% 넘김(미정 3 제안값)을 보고

### 1-6. 개발 크기(예상)
마이그레이션 1(조회 기록 표 · 사용량 칸) · API 1파일(도구 5) · AI 상담 서비스 고침 · 운영 화면(조회 기록 보기) · 시험. **약 1 ~ 2판**.

## 2. AI 검수 보조 다음 단계

### 2-1. 비교

| | 가. 사람 결정 그대로 · 검수 빠르게 (**추천**) | 나. 좁은 범위 자동 승인 |
|---|---|---|
| 내용 | AI 의견으로 **검수 대기 줄을 정렬**(AI 「승인」 · 근거 깨끗한 것 위로) · 운영자가 **「AI 의견과 같게 확인」 한 번 누르기** · 반려 사유 코드를 AI 의견으로 미리 채움(운영자가 고침) | 업종 · 위험도가 낮은 글 중 AI 「승인」 + 금칙어 · 연락처 검사 통과를 **사람 없이 승인** |
| 결정 기록 | #7 · #15 그대로 | **#7 을 바꿔야 함**(대표 결정) |
| 책임 | 승인 · 반려는 늘 사람 | 자동 승인 글의 문제는 회사 책임 — 표시광고 · 업종 법령(의료 · 보험 · 중개 등) 위험 |
| 효과 | 검수 시간 절반 이하(예상 · 측정 필요) | 대기 0 에 가까움(범위 안 글만) |
| 되돌리기 | 쉬움 | 이미 노출된 글을 회수해야 함 |

**추천: 가.** 소개뱅크는 의료 · 보험 · 중개처럼 법령이 걸린 업종이 많고(결정 기록 · 자동검수 규칙), 오픈 직후에는 사람 확인이 신뢰의 근거입니다. 가로 운영해 일치율이 계속 높으면 그때 나를 따로 결정하는 순서가 안전합니다.

### 2-2. 가 의 세부
1. 검수 대기 목록 정렬 — 「AI 승인 · 사유 없음」 → 「모름」 → 「AI 반려」 순 · 칸에 AI 의견 표시(지금은 상세에서만)
2. 「AI 의견과 같게 확인」 단추 — 누르면 지금과 같은 사람 승인(감사 기록에 「AI 의견 참고」 표시) · AI 「반려」는 사유 코드만 미리 채우고 **반려는 사람이 사유를 확인한 뒤**
3. 일치율 표를 업종별로(어느 업종에서 AI 가 자주 틀리는지)
4. 개발 크기(예상): 마이그레이션 0 ~ 1 · 운영 화면 2 · API 1 · **약 1판**

### 2-3. 나 를 고를 때 더 필요한 것
대표의 #7 변경 결정 · 법무(자동 승인 글의 책임 · 표시) · 자동 승인 업종 목록 · 하루 자동 승인 상한 · 표본 감사(자동 승인 글의 일부를 사람이 다시 봄) · 즉시 끄는 스위치.
