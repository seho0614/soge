# 129. 소개광장 운영 「댓글 감추기 · 되살리기」 (v10.75 · 2026-10-23)

> 대표 결정(2026-10-23 「병합,승인」 — A안: 운영자 감추기 · 되살리기만, 회원 댓글 신고는 나중에)
> 계기: 기능 점검 후보 ③ — 댓글 표에 「감춤」 상태와 회원 화면 문구는 있으나 **감추는 기능이 어디에도 없음**. 댓글은 신고 대상도 아님
> 앞 판: docs/128(v10.72) · v10.73 · v10.74 는 sgb-infra 시험 도구만 · **마이그레이션 없음**(146 그대로)

## 1. 결론

| # | 전 | 후 |
|---|---|---|
| 1 | 문제 댓글이 달려도 운영자가 손쓸 방법이 없음 | 운영 화면 「소개광장 검수 › 글 찾기」 표의 **댓글 수**를 누르면 그 글의 댓글이 펼쳐지고, 줄마다 「감추기」 · 「되살리기」 |
| 2 | — | 사유 필수(없으면 422). 감추기는 공개 댓글만, 되살리기는 감춘 댓글만(아니면 409). 감사 기록 `COMMENT_HIDE` · `COMMENT_UNHIDE` |
| 3 | 회원 화면 「신고가 들어와 가려진 댓글입니다.」(댓글 신고 기능이 없어 사실과 다름) | 「운영 기준에 따라 가려진 댓글입니다.」 |
| 4 | 감춘 댓글도 공개 API 에는 **본문이 그대로** 나감(화면만 가림) | 감춘 댓글은 본문 없이 자리만(감춘 글과 같음). 운영자는 운영 API 로 봄 |
| 5 | 글 되살리기(v10.72)의 사유가 감사 기록에 남지 않음 — 감사 기록은 **답**(after_data)만 남김 | 글 되살리기 · 댓글 감추기 · 되살리기 모두 답에 `reason` 을 담아 감사 기록에 남김 |

댓글 표에는 사유 칸이 없습니다 — 칸을 만들면 마이그레이션이 생기므로 **사유는 감사 기록에만** 둡니다. 글의 댓글 수는 기존 트리거(fn_comment_count)가 공개 댓글만 다시 셉니다.
