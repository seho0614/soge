# 763. 배치가 이 판에 없는 작업을 「성공」으로 적지 않음 — v10.620 (2026-11-22)

## 1. 결론

- docs/760 7절 「확인 안 됨」(옛 판으로 되돌렸을 때 새 정기 작업 12개가 어떻게 되는지)을 코드로 확인했습니다. 배치 실행기(`src/worker/scheduler.service.ts` `run`)는 모르는 작업 이름을 받으면 **아무 일도 안 하고 「성공 · 0건」으로 적었습니다**. 그 시각 차례는 쓴 것이 되어, 돌지 않은 것을 알 수 없었습니다.
- 이번 판부터 모르는 작업은 **실패(`UNKNOWN_JOB …`)** 로 적습니다. 되돌린 상태에서 「멈춘 배치」 · 실행 기록에 보여 알 수 있고, 새 판을 다시 올리면 다음 차례부터 돕니다.
- 한계: 이 보호는 **v10.620 이상으로 되돌릴 때부터** 동작합니다. v10.558 같은 옛 판은 예전 방식(성공 · 0건) 그대로입니다. 실행 기록은 쌓기만(DB 트리거)이라 지난 차례를 「안 잡은 것」으로 되돌리지는 않습니다.

## 2. 바뀐 것

| 항목 | 내용 |
|---|---|
| 서버 | `run(job)` switch 에 `default:` — `throw new Error('UNKNOWN_JOB …')` → tick 이 ok=false · detail 에 적음 |
| DB · 화면 | 없음 |

## 3. 운영 적용

- 마이그레이션 없음. 지금 모든 작업 이름(job_schedules)은 switch 에 있어 운영에서 실패가 새로 생기지 않습니다.
- 운영 절차서 5절(되돌리기)에 「되돌린 동안 새 판에서 생긴 정기 작업은 돌지 않음(v10.620 이상이면 실행 기록에 UNKNOWN_JOB)」 한 줄을 넣습니다.

## 4. 되돌리기

- 앞 판으로 되돌리면 예전처럼 모르는 작업을 성공 · 0건으로 적습니다.
