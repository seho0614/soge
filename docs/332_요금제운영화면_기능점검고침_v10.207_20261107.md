## 2. 요금제

| 곳 | 내용 |
|---|---|
| 운영 화면 | 정산 › 청구 현황 맨 아래 「요금제 금액 · 한도」 — 요금제 3줄 · 이용 중 구독 수 · 원래 금액으로 내는 수 · 「고치기」(SUPER) · 사유 필수 · 확인 창에 「올림 — 이용 중 n명은 원래 금액」 / 「내림 — n명 다음 결제부터」 · 최근 변경 20건 |
| 바꿀 수 있는 칸 | 월 요금 · 포함 소개코드 · 추가 코드 금액 · 소개 제안 / 월 · 열람 / 월 · 매물 슬롯 · 우선노출 · 성사 수수료(빈칸 = 무제한은 제안 · 열람 · 슬롯만) |
| 막는 것 | 무료 ↔ 유료 전환 · 음수 · 사유 없음 · 무료 요금제 열람 한도(운영 설정 `request.view.free_monthly` 를 따름 · D015) · 요금제를 새로 만들거나 지우기 |
| 올림 | 그 요금제를 쓰는 이용 중(ACTIVE · PAST_DUE) 구독에 옛 금액을 묶음(`subscriptions.locked_price`) · 갱신 결제 = 묶인 금액과 지금 금액 중 **작은 값** · 새 구독은 새 금액 |
| 내림 | 모두 다음 결제부터 새 금액(묶인 값이 새 금액 이상이면 묶음을 풂) |
| 묶음이 풀릴 때 | 요금제가 바뀜(다음 요금제 적용 · 트리거) · 다시 구독(그때 금액으로 결제) |
| 회원 화면 | 나의공간 › 구독 관리 — 실제로 낼 금액 + 「지금 요금 n원 — 구독 중에는 원래 금액으로 결제됩니다」 |
| 기록 | `subscription_plan_changes`(전 → 후 · 사유 · 묶은 수 · 내림 적용 수 · 누가) — 고치거나 지울 수 없음 · 감사 `PLAN_SAVE` |
| 시작값 | 지금 값 그대로(베이직 0 · 스탠다드 49,000 · 프로 149,000원) — **금액은 대표가 오픈 전에 운영 화면에서 정함** |

- 기존 구독자에게도 올린 금액을 받으려면 미리 알리고 동의를 받는 흐름이 필요합니다(전자상거래법의 정기결제 증액 규정 — **조문 · 기간은 법률 확인 필요**). 이번 판은 만들지 않음.
- 약관(이용약관 제9조)은 금액을 적지 않고 「서비스 안에 표시」라 약관은 바뀌지 않음.
