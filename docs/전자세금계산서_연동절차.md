# 전자세금계산서 연동 절차 (v10.34 · D093)

**지금 상태**: 업체(ASP)를 아직 정하지 않았습니다. 계약 · 공동인증서 · 키가 없습니다. 그래서 연결 자리(어댑터)와 간주 모드만 있습니다.

- 대상: 소개뱅크(운영 법인)가 발행하는 세금계산서 두 가지입니다.
  - 법률 · 세무 정액 노출료: `consult_directory_invoices`
  - 리드 이용료: `lead_cash_invoices`
  - 소개자가 발행하는 정산 세금계산서(`settlements.tax_invoice_*`)는 대상이 아닙니다.
- 설정 `assume.etax = on`(기본값)일 때 운영이 「발행」을 누르면 국세청에 보내지 않습니다. 「간주 발행」으로만 기록되고 승인번호는 없습니다.
  - 업체 화면에는 「전송 대기 — 연동 전」으로 보입니다.
  - 이 설정은 오픈 체크리스트의 「간주 모드 켜짐」에 남습니다.
- 손으로 번호 넣기(홈택스 등에서 따로 발행한 뒤 번호를 적는 방식)는 연동 전 임시 방식으로 남아 있습니다(`etax_mode = MANUAL`). 이렇게 넣은 줄은 전송하지 않습니다. 전송하면 같은 세금계산서가 두 번 발행되기 때문입니다.
- 외부 연동 표: `integrations.ETAX`. 상태는 NOT_STARTED이고 오픈을 막는 항목입니다. 키 이름은 `ETAX_KEY`이고 값은 환경 변수에만 둡니다.

## 업체 연동 전 발행 방법 (2026-10-12 대표 확인)

1. 입금 확인으로 생긴 「발행 요청」 줄을 봅니다(운영 「법률·세무 정액 노출 › 세금계산서」 · 「리드 이용료 › 세금계산서」).
2. **홈택스에서 직접 발행**합니다. 공급자 = 운영 법인, 공급받는 자 = 그 줄의 업체 상호 · 사업자번호, 공급가액 · 세액은 그 줄의 값 그대로.
3. 그 줄의 「홈택스 발행 번호 넣기」에 **승인번호 · 발행일**을 적고 「발행됨으로」를 누릅니다(etax_mode = MANUAL · 업체 화면에 번호 · 일자가 보임).
4. 「발행(간주 · 시험용)」은 실제 세금계산서가 아니므로 운영에서 쓰지 않습니다.
5. **작성일자는 입금 확인일과 달라도 됩니다**(대표 확인) — 지금은 「발행한 날」이 작성일자입니다.

## 업체를 정하면 할 일

1. **계약**: ASP(예: 팝빌 · 바로빌)와 연동 계약을 맺습니다. 운영 「외부 연동」 화면의 ETAX 줄에 업체 이름을 적고, 상태를 CONTRACT로 바꿉니다.
2. **공동인증서 등록**: 운영 법인 명의의 전자세금계산서용(또는 범용) 공동인증서를 업체 쪽에 등록합니다. 인증서 파일과 비밀번호는 이 저장소 · DB · 화면에 두지 않습니다.
3. **키**: 업체가 발급한 연동 키를 Secrets Manager의 `ETAX_KEY`에 넣고, 업체 주소를 `ETAX_URL`에 넣습니다. 필요하면 `ETAX_TIMEOUT_MS`(기본 10000)도 정합니다. 그다음 「외부 연동」에서 「키 등록」을 체크합니다. 키 값은 화면에 나오지 않습니다.
4. **어댑터 형식 맞추기**: `sgb/src/modules/etax/etax.http.ts` 한 파일만 업체 문서대로 고칩니다.
   - 고칠 곳: 발행 · 상태 조회 · 취소의 경로, 본문, 응답 읽기
   - 업체가 요구하는 칸(업태 · 종목 · 주소 · 담당자 메일 등)은 `EtaxDoc`에 더합니다.
   - 서비스 · 화면 · DB는 바꾸지 않습니다.
   - 승인번호는 24자리 숫자만 받습니다. 형식이 다르면 실패로 남습니다.
5. **고정 IP**: 업체가 발신 IP 등록을 요구하면 운영 「외부 연동」의 「발신 IP」(NAT 고정 IP)를 등록하고 승인일을 적습니다.
6. **시험 전송**: 업체의 시험 환경 주소로 `ETAX_URL`을 두고 한 건을 보냅니다.
   - 운영 「세금계산서」 탭에서 「발행」을 눌러 승인번호 · 상태 조회 · 취소 · 수정 발행을 확인합니다.
   - 화면 없이 확인하려면 `qa/test_v1034_etax.py`처럼 가짜 서버 자리에 업체 시험 주소를 둡니다.
   - 이때 상태를 TESTING으로 바꿉니다.
7. **`assume.etax` off**: 시험 전송을 확인한 뒤 off로 바꿉니다. 간주로 발행된 줄은 「다시 보내기」로 실제 전송할 수 있습니다. 문서 번호는 그대로이고 승인번호가 새로 붙습니다.
8. **LIVE**: 운영 주소로 바꾸고 실제 한 건을 확인한 뒤 ETAX 상태를 LIVE로 바꿉니다. 이렇게 하면 오픈 체크리스트에서 빠집니다.

## 장애 때

- **실패**: 줄에 사유가 남습니다. 「다시 보내기」를 쓰십시오.
- **시간 초과**: 업체 쪽에서는 이미 발행됐을 수 있습니다. 「다시 보내기」는 먼저 상태를 조회하고, 업체 쪽에 이미 있으면 그 결과를 씁니다. 같은 문서 번호로 다시 발행하지 않습니다.
- **승인 대기**: 상태가 SENDING으로 남습니다. 「상태 조회」로 승인번호를 읽습니다.
- **전송 기록**: `etax_send_log`에 시도마다 한 줄씩 남습니다(고치거나 지울 수 없음). 감사 기록의 액션은 `ETAX_SEND` · `ETAX_RESEND` · `ETAX_REFRESH` · `ETAX_CANCEL`입니다.
