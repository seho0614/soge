# 483. Nginx 적용 알림 (v10.349 · 2026-11-18)

> 대표 11/18 「다음개발」 → ① Nginx 적용 알림 · ② 임시 허용 IP(기한) · ③ 지난 판 보기 · 되돌리기 · ④ 고객센터 주간 보고 「모두」 → 계획 「승인 + 통과하면 병합」(v10.348 과 한 묶음 점검). 이 문서는 ①. 마이그레이션 없음.

## 1. 왜

- v10.348 「적용」은 운영 서버 감시 서비스가 처리합니다. 실패하거나 서비스가 멈추면 화면을 열기 전에는 알 수 없었습니다. 목록을 고치고 반영을 잊어도 몰랐습니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 정기 작업 `sla_alert`(매시간) | Nginx 상태를 보고 운영 알림 셋 — **NGINX_APPLY_FAILED**(급함 · 적용 결과가 실패면 결과마다 한 번 · 다음 성공 때 풂) · **NGINX_WATCH_STUCK**(급함 · 요청 뒤 10분 결과 없음 · 결과가 나오면 풂) · **NGINX_NOT_APPLIED**(경고 · 허용 IP 를 고친 뒤 24시간 반영 안 함 · 반영하면 풂). 급한 것은 지금처럼 텔레그램 · 슬랙 · 메일 |
| 운영 화면 **위험감지 › 「운영 알림」** | 위 셋 이름 |
| 공용 `nginx-allow-script.ts` | 상태 읽기(목록 · 지문 · 감시 서비스 결과) · 요청 쓰기를 화면과 정기 작업이 함께 씀 |

## 3. 시험 (test_v1349)

1. ① 코드 — 알림 셋 · 풂 · 같은 종류 한 번만 · 운영 알림 이름 · 문서 483 · 판 v10.349
2. ② 정기 작업 — 시험 IP(25시간 전 더함 · 반영 안 함)로 정기 작업 sla_alert 실행 → 고친 지 24시간이 넘었으면 NOT_APPLIED 한 건(다른 시험이 24시간 안에 IP 를 뺐으면 0 이 맞음 · 감사 기록은 고치지 않음) · 다시 돌려도 같음 · 「반영했음」 뒤 다시 돌리면 풂. FAILED · STUCK 은 운영 서버 결과 폴더가 있어야 해서 코드로만 확인

## 4. 운영 적용

- 마이그레이션 · 설정 없음. 감시 서비스를 설치하기 전에는 FAILED · STUCK 은 생기지 않습니다(결과 · 요청 파일 없음). NOT_APPLIED 는 「반영했음」 · 「적용」 기록과 목록이 다르면 생깁니다 — v10.348 적용 직후 「Nginx 반영」을 한 번 하면 풀립니다.
- 되돌리기(rollback): 앞 판 정기 작업은 이 알림을 만들지 않습니다. 열린 알림은 「확인」합니다.
