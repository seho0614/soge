## 1. A — 서버 리눅스 계정을 바꿀 때 (사람 + Claude · 반나절)

### 1-1. 사용자에 묶인 것 (2026-10-31 조사)

| 무엇 | 지금(sgbdev) | 새 계정에서 |
|---|---|---|
| 홈 · 작업 폴더 | `/home/sgbdev/sogaebank` | `/home/<새계정>/sogaebank` |
| **Claude 대화 · 기억 폴더** | `~/.claude/projects/-home-sgbdev-sogaebank/` | **`-home-<새계정>-sogaebank/` 로 이름을 바꿔 넣음**(경로에서 이름이 만들어짐) |
| Claude 작업방(scratchpad) | `/tmp/claude-1001/-home-sgbdev-sogaebank/…` | 자동으로 새 uid · 새 이름 |
| 점검판 도커 | rootless · `unix:///run/user/1001/docker.sock`(sgb-check.sh 는 `$(id -u)` 로 찾음) | 새 계정에 rootless 도커 설치 · 이미지 다시 받음/만듦(`sgb-dev-checks` · `sgb-qa:v1`) |
| 백업 스크립트 | `backup-full.sh` 가 `-home-sgbdev-sogaebank` 를 고정으로 썼음 | **10/31 고침** — `$HOME` 에서 이름을 만듦(아래 1-4) · 새 계정에서 그대로 씀 |
| 문서 속 이름 | CLAUDE.md · project-rules.md 의 「sgbdev」 | 새 계정 이름으로(sgb-docs `claude/` 고친 뒤 `~/sogaebank/CLAUDE.md` 로 복사) |
| AWS 자격 증명 | `~/.aws`(백업에 없음) · CodeCommit 용 IAM | **새 계정용 IAM 사용자 · 키 새로 발급**(옛 키 복사 금지) |
| GitHub 보내기 열쇠 | `~/.ssh/gh_soge` | 새 열쇠 만들어 GitHub 배포 키로 등록 · 옛 키 삭제 |
| 예약(crontab) | 지금 없음 | 새 계정에 대표가 `!` 로 등록 |
| 점검판 포트 | 13000 · 15173 · 15174 · 15432 | **두 계정이 동시에 점검판을 띄우면 포트가 부딪힘** — 옮기는 동안 한쪽만 띄움 |

### 1-2. 순서

| # | 할 일 | 누가 | 명령 · 확인 |
|---|---|---|---|
| 1 | 새 계정 만들기 · 운영 계정(ubuntu)과 분리 | 사람(sudo) | `sudo adduser dev2` |
| 2 | rootless 도커 · tmux · git · AWS CLI · git-remote-codecommit · Claude Code 설치 | 사람 | 각 공식 안내(설치할 때 확인) · `sudo loginctl enable-linger dev2`(로그아웃해도 점검판 유지) |
| 3 | 저장소 4개 받기 — **CodeCommit 에서 새로 clone 을 권함**(백업 묶음은 CodeCommit 이 망가졌을 때만) | 새 계정 | `git clone codecommit::ap-northeast-2://sgb-core ~/sogaebank/sgb-core` … 4개 |
| 4 | 작업 스크립트 · Claude 설정 · 기억 | 새 계정 | docs/250 3-2 · 3-3 과 같고, **기억 폴더만 새 이름으로**: `cp -r <백업>/claude/memory ~/.claude/projects/-home-dev2-sogaebank/` |
| 5 | 지난 대화(선택) | 새 계정 | docs/250 5-2 — 넣을 곳만 `-home-dev2-sogaebank` |
| 6 | 문서의 계정 이름 고치기 | Claude(풀 리퀘스트) | sgb-docs `claude/CLAUDE.md` · `project-rules.md` 의 sgbdev → dev2 |
| 7 | 로그인 · AWS · GitHub 열쇠 | 사람 | `claude`(로그인) · `aws configure` · `ssh-keygen` → GitHub 배포 키 |
| 8 | 확인 | Claude | docs/250 3-6 의 6가지 + `bash ~/sgb-check.sh main realcheck` 통과 · `backup-full.sh` 성공 |
| 9 | 옛 계정 정리(확인 1 ~ 7일 뒤) | 사람 | 옛 IAM 키 비활성 → 삭제 · GitHub 옛 배포 키 삭제 · `sudo loginctl disable-linger sgbdev` · 계정 잠금(`sudo usermod -L sgbdev`) — **바로 지우지 않음** |

### 1-3. 같은 서버에서 옮길 때 주의

- 옛 계정의 점검판을 먼저 내림: `~/sgb-check.sh main down`(sgbdev).
- 옛 계정 홈을 통째로 복사하지 않음 — `.env` · `.aws` · `.ssh` · `.claude.json` 이 따라감(금지 규칙).
- 확인판(ubuntu · pm2)과 운영 RDS 는 계정과 상관없이 **건드리지 않음**.

### 1-4. `backup-full.sh` 는 계정에 상관없게 고쳐 둠 (10/31 · sgb-infra)

```bash
CP=$(echo "$HOME/sogaebank" | sed 's#/#-#g')       # /home/dev2/sogaebank → -home-dev2-sogaebank
cp -r $HOME/.claude/projects/$CP/memory $B/claude/memory
SP=$(ls -td /tmp/claude-$(id -u)/$CP/*/scratchpad 2>/dev/null | head -1)
```

## 2. B — Claude(claude.ai) 계정을 바꿀 때 (대표 · 1시간)

### 2-1. 무엇이 따라가고 무엇이 안 따라가나 (확인 필요 — 제품 정책은 바뀔 수 있음)

| 무엇 | 새 계정으로 | 방법 |
|---|---|---|
| 서버 Claude Code 의 설정 · 기억 · CLAUDE.md | **그대로**(서버의 파일) | 로그인만 바꿈 |
| 서버 Claude Code 의 지난 대화(`--resume`) | **그대로 열릴 것으로 봄**(서버의 파일) — 실제로 바꿔 본 적 없음 | 바꾼 뒤 `claude --resume` 으로 확인 |
| claude.ai 프로젝트 · 대화 · 기억 | **옮겨지지 않음**(계정 사이 이전 기능 없음으로 알고 있음) | 옛 계정에서 **데이터 내보내기 먼저** → 새 계정에 docs/250 5-4 로 프로젝트 다시 만들기 |
| claude.ai 아티팩트 · 공유 링크 | 옮겨지지 않음 | 필요한 것은 sgb-docs `artifacts/` 사본이 기준 |
| 원격 제어(휴대폰 · 다른 기기에서 서버 대화 보기) | 새 계정으로 다시 연결 | `start-claude.sh` 다시 실행 → 새 계정 앱에서 「소개뱅크」 |
| 사용량 · 요금 · 한도 | 새 계정 요금제를 따름 | 바꾸기 전 새 요금제 확인 |
| 운영 서비스의 AI 키(Anthropic API · 운영 화면 › AI 운영) | **별개**(콘솔 API 키 · 회사 결제) | 계정을 바꿔도 그대로. 콘솔 조직을 바꾸면 운영 화면에서 새 키 저장 → 키 확인 → 옛 키 폐기 |

### 2-2. 순서

1. **옛 계정에서 데이터 내보내기**(claude.ai 설정 › 데이터 내보내기 → 목록 json · zip 7개 → `D:\sgb\new`). 10/31 에 한 번 받아 둠 — 그 뒤 대화가 있으면 다시.
2. 서버에서 로그인 바꾸기(사람 · 대화형):
   ```bash
   tmux attach -t sgb      # 작업방이 있으면 · Claude 안에서 /logout 하고 나옴
   cd ~/sogaebank && claude    # 새 계정으로 로그인 · 끝나면 /exit
   bash ~/start-claude.sh      # 작업방 · 원격 제어 다시
   ```
3. 확인: 「목록」에 한국어 · 결론 먼저로 답함(설정 · 기억 그대로) · `claude --resume` 에 지난 대화.
4. 새 claude.ai 계정에 「소개뱅크」 프로젝트 다시 만들기 — docs/250 5-4(지침 원문 · decisions · 인계 메모).
5. 옛 계정: 내보내기 원본을 PC 에 보관한 뒤 정리(지울지는 대표 판단).

## 3. C — 다른 담당자(사람)에게 넘길 때 (대표 + 새 담당 · 1 ~ 2일)

### 3-1. 넘길 계정 · 권한 목록 (열쇠는 새로 발급 · 옛 것은 끔)

| # | 무엇 | 지금 | 넘기는 방법 |

| 1 | AWS 계정(루트) | 대표 | 루트는 넘기지 않음 · 봉인. 새 담당에게 **IAM 사용자**(필요한 정책만) |

## 4. 하지 말 것

- 옛 사용자의 `~/.aws` · `~/.ssh` · `.env` · `~/.claude.json` 을 복사해 쓰기 — 새로 발급 · 새로 로그인
- 새 쪽 확인 전에 옛 계정 · 옛 키 지우기
- 열쇠 · 비밀번호를 대화 · 메일 · 메신저로 보내기(10/13 · 10/15 대화에 AWS 키가 붙어 있었음 — 그 키가 쓰이는지 IAM 확인)
- 두 계정에서 동시에 점검판 띄우기(포트 13000 · 15173 · 15174 · 15432 충돌)
- 운영 서버 · 확인판(ubuntu · pm2) · 운영 RDS 를 새 개발 계정으로 건드리기
