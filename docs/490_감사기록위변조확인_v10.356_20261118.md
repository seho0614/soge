# 490. 감사 기록 위변조 확인 — SHA-256 사슬 (v10.356 · 2026-11-18)

> 대표 11/18 「다음개발」 → ① 막힌 접속 기록 · ② 월간 보안 보고 · ③ 운영자 활동 요약 · ④ 감사 기록 위변조 확인 「모두」 → 계획 「승인 + 통과하면 병합」(감사 · 감시 목록 정리의 빈 곳). 이 문서는 ④. 마이그레이션 **D235**.

## 1. 왜

- 감사 기록은 프로그램에서 고치거나 지울 수 없지만(트리거), DB 관리자 권한으로 트리거를 끄고 고치면 흔적이 남지 않았습니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 마이그레이션 **D235** | `audit.audit_logs` 칸 셋 `chain_seq · chain_prev · chain_hash` · 넣을 때 트리거 `trg_zz_audit_chain`(가림 트리거 뒤) — 지문 = sha256(앞 줄 지문 · 이 줄 내용). **IP · User-Agent 는 1년 뒤 마스킹되므로 지문에서 뺌.** 사슬 순서를 위해 쓰기는 한 줄씩 줄을 섬(거래 잠금 · 지금 규모에서 느려짐 거의 없음) |
| 같은 마이그레이션 | `fn_block_audit_write` 에 사슬 칸도 고칠 수 없게(마스킹만 허용은 그대로) · 확인 기록 `audit.chain_checks`(쌓기만) · 확인 함수 `audit.fn_audit_chain_verify` |
| 정기 작업 `sla_alert`(매시간) | 마지막으로 온전했던 지점부터 다시 계산 → 끊기면 운영 알림 **AUDIT_CHAIN_BROKEN**(급함 · 같은 것 한 번 · 다시 온전하면 풂) |
| 새 API `GET /admin/security/audit-chain` · `POST …/check` | ADMIN · SUPER 읽기 · SUPER 지금 확인(감사 `AUDIT_CHAIN_CHECK`) |
| 운영 화면 **위험감지 › 「감사」** 맨 위 | **「감사 기록 위변조 확인 — 사슬 온전 · 마지막 확인」** · 사슬 줄 · 사슬 전 줄 · 24시간 확인 수 · 30일 끊김 · 「지금 확인」(SUPER) |

- 잡는 것: 줄 내용 고침 · 사슬 칸 고침 · 가운데 줄 지움 · 지난 확인 지점 줄 지움. D235 **전** 기록은 사슬이 없어 확인하지 못합니다(칸이 빈 줄).
- 시험(v10.348 · 349)은 감사 기록을 고치지 않게 바꿨습니다(판마다 다른 시험 IP).
