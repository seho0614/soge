## 3. 개발 계정

비밀번호는 **모두 같습니다**: `sgb-dev-1234`

| 계정 | 유형 | 역할 | 쓰임 |
|---|---|---|---|
| `admin@x.com` | 사업자 | **ADMIN · SUPER** | 관리자 화면 전체 |
| `seller@x.com` | 사업자 | — | 등록·판매 |
| `buyer@x.com` | 사업자 | — | 요청·구매 |
| `intro@x.com` | 사업자 | — | 소개자 · **인증 완료** |
| `person@x.com` | **개인** | — | 개인회원 흐름 |

```bash
npm run db:seed:dev      # ★ 이것을 빠뜨리면 로그인이 안 됩니다
```

픽스처는 `password_hash` 를 자리표시자로 두므로, 이 명령 없이는
**401 이 납니다.** 로그인 안 되면 여기를 먼저 의심하십시오.

`intro@x.com` 만 사업자 인증이 끝나 있습니다 — 파트너센터·소개자 흐름을
볼 때 이 계정을 쓰십시오.

## 4. 환경변수

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:54329/sgb
JWT_SECRET=dev-only-secret-change-me-0123456789abcdef
JOB_TOKEN=                 # 32자 이상. openssl rand -hex 24
```

### JOB_TOKEN

배치 스케줄러 전용입니다. **사람 계정의 JWT 를 쓰지 마십시오** —
만료되면 배치가 조용히 멈추고, 새면 관리자 전 권한이 넘어갑니다.

없거나 32자 미만이면 **항상 거부**합니다. 설정을 빠뜨린 채 배포하면
배치가 안 도는 편이 아무나 부를 수 있는 것보다 낫습니다.

## 5. 실행

### 로컬

```bash
npm install && (cd web && npm install) && (cd site && npm install)
cp .env.example .env

npm run db:embedded &     # DB
npm run db:migrate        # 기준선 11개
npm run db:seed           # 픽스처
npm run db:seed:dev       # ★ 개발 계정 비밀번호

npm run dev &             # API      :3000
(cd web && npm run dev) & # 관리자    :5173
(cd site && npm run dev)  # 사용자    :5174
npm run scheduler &       # 배치 (선택)
```

### Docker

```bash
docker compose up -d --build
docker compose logs -f api
```

`db → migrate → api → web·site·scheduler` 순으로 뜹니다.
`sgb-migrate` 가 `exited (0)` 인 것은 **정상**입니다 — 한 번 돌고 끝납니다.

## 7. 운영 배포 시

이 문서의 값은 **하나도 그대로 쓰지 마십시오.**

| 항목 | 운영에서 |
|---|---|
| `JWT_SECRET` | Secrets Manager · 32자 이상 무작위 |
| `JOB_TOKEN` | Secrets Manager · `openssl rand -hex 24` |
| DB 비밀번호 | RDS · Secrets Manager |
| 개발 계정 5종 | **생성하지 마십시오** |
| 배치 | EventBridge (`infra/eventbridge-jobs.yaml`) |

`npm run verify` 의 비밀값 검정이 소스에 키가 박히는 것을 막습니다 —
현재 **안전 5 · 위험 0** 입니다.
