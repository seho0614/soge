# 785. 미리 검사 소음 줄이기 — verify-docs DB 대조를 버리는 DB 로 · 옛 시험 비교는 숫자를 지우고 — v10.641 (2026-11-22)

## 1. 결론

- 미리 검사(`qa/pre_check.sh`)를 돌릴 때마다 두 가지 「거짓 실패」가 나와 진짜 실패를 가릴 수 있었습니다.
  1. **verify-docs rc=1** — 마지막 「DB 대조」가 DB 없이(`--network none`) 돌아 늘 접속 오류였습니다. 그래서 화면 레지스트리 · 권한 · OpenAPI 쪽에서 진짜 실패가 나와도 rc 로는 구별이 안 됐습니다.
  2. **「작업 트리에서만 FAIL」에 옛 시험 20줄** — 판 번호 글자(v10.637 ↔ v10.640)만 다른 줄이 새 실패처럼 보였습니다(11/22 v10.638 미리 검사).
- 이번 판부터
  1. ③ verify-docs 는 ② 에서 띄운 **버리는 DB**(자기 네트워크 · 포트를 열지 않음 · 끝나면 지움)에 붙여 「DB 대조」까지 돌립니다. 마이그레이션이 넣는 기준 자료(code_labels · review_reason_codes)로 대조하므로 rc=0 이 정상이고, rc=1 이면 진짜 실패입니다. 결과 끝에 `③ verify-docs rc=… · DB 대조 = 버리는 DB` 한 줄.
  2. ④ 「작업 트리에서만 FAIL」은 **「시험 | FAIL 확인 이름」만 숫자를 지우고 견줍니다** — 판 번호 · 개수 · 「 — 」 뒤 자세한 값만 다른 줄은 빠지고, 확인 이름이 다른 새 실패만 남습니다. 11/22 v10.638 미리 검사 출력으로 다시 돌려 거짓 20줄 → **0줄**(test_v1122 포함) · 일부러 넣은 새 실패 1줄은 그대로 잡힘.
- 점검판(15432) · 확인판 포트 · RDS 는 그대로 쓰지 않습니다.
