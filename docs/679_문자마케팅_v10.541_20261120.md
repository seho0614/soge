# 679 문자 마케팅 — v10.541 (D283 · 2026-11-20)

> 대표 11/20 「(53) ④ 문자 마케팅」 · ㊳ 문자 · 메일 캠페인(D268 · docs/621) 위 · 법무 확인 끝(11/20 대표 · 이상 없음) · 스위치 처음 꺼짐

## 1. 결론
- 광고 문자는 **㊳ 캠페인이 이미 지키는 것을 그대로** 씁니다: 「(광고)이름」 앞머리 · 「무료거부 080…」 끝 · 마케팅 수신 동의자만 · 21 ~ 8시 야간 동의자만(DB 트리거) · 문자 대행 어댑터(CampaignSmsHttp · 알림톡 대행사 문자 주소) · 간주(campaign.send_mode ASSUME) · campaign.enabled 처음 off.
- (53) 이 더한 것 4가지:

| 더한 것 | 어떻게 |
|---|---|
| 소개몰 대상 | 캠페인 대상 MALL_BUYERS(180일 안 결제) · MALL_REBUY(재구매 알릴 날 7일 전 ~ 30일 뒤 · v_mkx_rebuy_due) — 마케팅 동의 JOIN 은 ㊳ 그대로 |
| 회원별 7일 상한 | mkx.sms_weekly_max(처음 2 · 0 = 없음) — 받는 사람 고정 때 넘는 회원은 SKIPPED(FREQ_CAP · 트리거 trg_mkx_sms_freq_cap) |
| 080 수신 거부 반영 | 대행사가 준 번호 붙여 넣기(ADMIN) · 웹훅 POST /site/optout080(X-Optout-Token · mkx.optout080_hook 처음 off) → 그 번호 회원의 MARKETING · MARKETING_NIGHT 철회 · 대기 문자 멈춤 · 처리 결과 알림 CONSENT_OPTOUT · 번호는 지문 · 끝 4자리만 |
| 바이트 · 비용 | 문자 캠페인마다 바이트 · SMS / LMS · 단가(mkx.sms_price_sms · lms · 처음 0 = 모름) × 대기 수 |

## 2. 화면 · API · DB
- 화면 SB-ADM-MKX-040(회원 › 문자 마케팅)
- API GET /admin/mkx/sms · POST /admin/mkx/sms/optout080 · POST /admin/mkx/sms/optout080/token(SUPER) · POST /site/optout080(웹훅)
- DB mkt_campaigns_audience_check(다섯 값) · mkt_campaign_sends_skip_reason_check(+ FREQ_CAP) · trg_mkx_sms_freq_cap · mkx_optout080(쌓기만)
- 코드: campaign.ts 3줄 · MktCampaigns.tsx 1줄(patches/2 — 6차 b280 위면 2b)

## 3. 켜는 순서
1. ㊳ 설정(보낸 곳 연락처 · 080 번호 · 발신번호) 확인 → 단가 넣기(대행사 계약 단가 — 확인 필요)
2. 080 대행사 일일 거부 목록을 붙여 넣는 습관(또는 웹훅 토큰 만들기 → 대행사에 등록 → mkx.optout080_hook on)
3. 캠페인 대상 「소개몰 구매 회원」으로 초안 → 나에게 시험 → 최고 관리자 보내기(㊳ 절차 그대로)

## 4. 직접 정한 것
- 7일 상한은 받는 사람 고정 때만 셈(보낼 때 다시 세지 않음) · 상한 기본 2통.
- 080 반영은 같은 번호의 계정 모두에 적용 · 이미 철회한 회원은 0건으로 기록.

## 5. 법무
- **법무 확인 끝(11/20 대표 · 이상 없음)** — 표기 · 080 수신 거부 처리 · 처리 결과 통지(알림) · 야간 동의. 080 처리 결과를 14일 안에 알리는 방식은 나의공간 알림(CONSENT_OPTOUT).
