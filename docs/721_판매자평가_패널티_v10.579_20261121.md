# 721 · 판매자 평가 · 패널티 (v10.579 · 2026-11-21)

> 12차 소개몰 · 파트너 ③. 기준은 **일반 초안 · SUPER 가 고침 · 처음 off**(`smq.penalty` · `smq.penalty_exposure`). SQL `sql/smq.sql` ③ · 시험 `qa/test_v1579.py`.

## 1. 결론

달마다 입점 판매자(TENANT · BRAND · 판매 중 · 정지)마다 **배송 지연 · 판매자 사정 취소 · 반품 · 문의 답 늦음**을 셈해 등급과 경고를 정하고, **잇달아 넘으면 노출 제한을 제안 → 운영이 승인**해야 적용합니다. 실제로 목록에서 빠지는 것은 노출 제한 스위치(`smq.penalty_exposure`, SUPER)를 켠 뒤뿐입니다.

## 2. 기준(일반 초안 · 대표 · 법무 확인 전)

| 항목 | 셈 | 초안 | 설정 키(SUPER) |
|---|---|---|---|
| 배송 지연 | 결제 뒤 N일(달력 날) 안에 발송하지 않은 주문 비율(늦게 발송 · 아직 안 보냄 모두) | N=3일 · 10% 넘음 | `smq.penalty_ship_days` · `smq.penalty_late_pct` |
| 판매자 사정 취소 · 반품 | 사유 DEFECT · WRONG_ITEM · MISMATCH · DELAY 인 취소 · 반품 · 교환 신청(반려 뺌)이 있는 주문 비율 — 회원 사정(CHANGE_MIND · WRONG_ORDER)은 뺌 | 5% 넘음 | `smq.penalty_cancel_pct` |
| 문의 답 늦음 | 그달 보이는 문의 가운데 기한(v10.577 `due_at`) 지나도 답 없음 · 기한 뒤 답 | 20% 넘음 | `smq.penalty_qna_pct` |
| 표본 | 주문 N건 미만이면 지연 · 취소 판정 안 함 · 문의 5건 미만이면 문의 판정 안 함 | 10건 | `smq.penalty_min_orders` |
| 등급 | 넘은 것 0 · 모든 비율이 기준 절반 이하 = A · 0 = B · 1 = C · 2 이상 = D · 판정할 것 없음 = N(표본 부족) | — | — |
| 경고 · 제안 | 넘은 것 1 이상 = 경고(WARN) · N달 잇달아 경고 = 노출 제한 제안(LIMIT) | 2달 | `smq.penalty_limit_months` |
| 노출 제한 기간 | 운영 승인한 날부터 | 30일 | `smq.penalty_limit_days` |

기준 값 무늬(DB `site_settings.value_pattern`)와 서버 검사(`common.ts SMQ_RULE_PATTERNS` · `SmqRulesSaveDto`)는 글자까지 같습니다(규칙 2). 저장한 평가에는 그때 기준이 `rules` 칸에 박혀 기준을 바꿔도 지난 평가는 그대로입니다.

## 3. 노출 제한과 INV-11(광고 · 노출 분리) — 확인 결과

- INV-11 은 「기본 정렬에 대가(광고비 · 구독) 가중치를 넣지 않는다 · 광고와 일반 목록을 나눈다」(docs/09 API 설계서 · 전자상거래법 노출 순위 표시 의무)입니다.
- 이 노출 제한은 **대가와 상관없는 품질 기준으로 목록에서 빼는 것**이고, 순위를 올려 주는 유료 요소가 없으며 광고 영역은 건드리지 않습니다 → **INV-11 과 부딪히지 않음**.
- 방식은 판매자 자격 만료(INV-H10 — 노출 즉시 멈춤 · 받은 주문은 이행)와 같습니다: **목록 · 검색 · 성분별 · 고민별 · 순위(오늘의 건강상품 · 많이 찾는 상품)에서만 빠지고, 상품 상세 · 장바구니 · 이미 받은 주문은 그대로**.
- 노출 엔진에 거는 곳은 DB 보기 하나(`v_smq_exposure_limited` — 승인 · 기간 안 · 스위치 on 일 때만 줄)이고, 목록 SQL 3곳이 `NOT EXISTS` 로 봅니다(`health-catalog.service.ts` products · concern, `health-review.service.ts` rankings).
- **남은 일(법무)**: 전자상거래법상 노출 기준 공개 — 입점 약관에 평가 기준 · 노출 제한을 적고(약관 고침 · 법무 확인), 판매자센터 › 판매 평가 화면에 기준을 늘 보여 줌(만듦). `smq.penalty_exposure` 는 **약관 반영 뒤에 켜기**.
- 통합 검색(`public.service`)의 소개몰 결과는 이번에 넣지 않음 — 켜기 전에 함께 넣을지 확인 필요(NOTES 5절).

## 4. 흐름

1. 정기 작업 `smq_daily`(매일 09:20 · `smq.penalty` on): 1일부터 지난달 셈 · 저장(알리기 전까지 날마다 다시 셈 — 늦은 발송 · 반품이 들어감) → 3일부터 알리지 않은 줄을 알림(경고 이상만 판매자 알림 `SMQ_SELLER_WARN`) · LIMIT 이면 제안(`smq_seller_limits` PROPOSED) + 운영 알림 `SMQ_LIMIT_PROPOSED`
2. 운영 › 소개몰 › **판매자 평가 · 패널티**(SB-ADM-SMQ-020): 달 고르기(저장 전 · 이번 달은 미리보기) · 다시 셈(끝난 달 · 알린 줄 그대로) · 제안 승인(오늘부터 기간 · 판매자 알림 `SMQ_SELLER_LIMIT`) · 반려(사유) · 풀기(사유 · 알림) · 기준 고치기(SUPER)
3. 기간 끝나면 정기 작업이 저절로 풀림(LIFTED · 「기간 끝」)
4. 판매자센터 › **판매 평가**(SB-HLT-SMQ-020): 공개 기준 · 이번 달 미리보기 · 알린 최근 6달 · 적용 중 제한

## 5. 재사용

- 판매자 정지 · 폐점(v10.222 ~ 224 `health-seller-manage`) — 알림 방식 · 사유 필수 규칙 같음. **정지(PAUSED)와 노출 제한은 다름**(정지는 판매 중단 · 상품 내림, 노출 제한은 목록에서만 빠지고 판매 계속).
- 판매자 월 정산서(D281) · 리뷰 답글(v10.555)의 판매자센터 화면 모양 · NOT_SELLER 규칙
- 상품 문의 기한(v10.577 `due_at`)

## 6. 대표가 정할 것

1. 기준 값 7개(2절 초안 그대로 할지) — 노무 · 법무 확인 아님(상거래 운영 기준) · 대표 결정
2. 노출 제한 방식 — 목록에서 빼기(지금) vs 목록 맨 뒤로 내리기
3. 입점 약관에 기준을 넣는 시점(법무)
4. `smq.penalty`(평가 · 경고) 를 먼저 켜고, 노출 제한은 1 ~ 2달 지켜본 뒤 켤지

## 7. 오류가 나면

1. 평가가 저장되지 않음 → `smq.penalty` on · `job_schedules.smq_daily` · 1일 이후인지.
2. 승인했는데 목록에 그대로 → `smq.penalty_exposure` off(정상) — 화면 표에 「실제 적용 꺼짐」.
3. 기준 저장 403 → SUPER 만.
