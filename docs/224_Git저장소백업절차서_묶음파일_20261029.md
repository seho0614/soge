## 2. 전제

- 개발 서버 sgbdev 에서 `git-remote-codecommit` 이 동작함 (`export PATH=$HOME/.local/bin:$PATH` 를 먼저 — 빠뜨리면 받아오기 실패).
- 디스크에 여유 1GB 이상 (`df -h ~`). 묶음 한 벌은 약 55MB.
- 집 PC 에 `sgb-dev` 별칭으로 `scp` 가 됨 (열쇠 `C:\sgb_key\sgb-key.pem`).

## 3. 절차

> 명령은 **한 블록씩** 붙여 넣고, 블록마다 「기대」와 같은지 본 뒤 다음으로.

### 3-1. 미리 확인 (sgbdev)

```bash
export PATH=$HOME/.local/bin:$PATH
for r in sgb-core sgb-infra sgb-adx sgb-docs; do
  cd ~/sogaebank/$r && git fetch -q --all
  echo "$r 지금갈래=$(git branch --show-current) main=$(git rev-parse --short main) origin=$(git rev-parse --short origin/main) 커밋안됨=$(git status --porcelain | wc -l)"
done
df -h ~ | tail -1
```

기대: 저장소마다 `main` 과 `origin` 이 같음. `커밋안됨` 이 0 이 아니면 무엇인지 본다(`git status --porcelain`) — 점검 사진처럼 커밋하지 않을 것이면 그대로 두고, 남겨야 할 작업이면 갈래에 커밋해 풀 리퀘스트부터.

### 3-2. 묶기와 검사 (sgbdev)

```bash
export PATH=$HOME/.local/bin:$PATH
T=$(date -u +%Y%m%d_%H%M); B=~/backup/full_$T; mkdir -p $B/repos $B/claude $B/tools; echo "T=$T"
for r in sgb-core sgb-infra sgb-adx sgb-docs; do
  cd ~/sogaebank/$r && git bundle create -q $B/repos/$r.bundle --all \
  && git bundle verify -q $B/repos/$r.bundle \
  && echo "$r main=$(git rev-parse --short origin/main) 갈래=$(git bundle list-heads $B/repos/$r.bundle | grep -c refs/heads)"
done
```

기대: 저장소마다 `… is okay` 한 줄과 main 커밋 한 줄. 네 개의 main 이 3-1 의 `origin` 과 같음.

### 3-3. 서버 스크립트 · Claude 설정 더하고 압축 (sgbdev)

```bash
T=<3-2 에서 나온 값>; B=~/backup/full_$T
cp ~/sgb-check.sh ~/make-kit.sh ~/import-kit.sh ~/start-claude.sh ~/step17.sh $B/tools/
cp ~/.claude/CLAUDE.md ~/.claude/settings.json $B/claude/
cp -r ~/.claude/projects/-home-sgbdev-sogaebank/memory $B/claude/memory
cp ~/sogaebank/CLAUDE.md $B/claude/project-CLAUDE.md
cd ~/backup && tar -czf full_$T.tar.gz full_$T && rm -rf full_$T
sha256sum full_$T.tar.gz; ls -la full_$T.tar.gz
```

기대: sha256 한 줄 · 크기 약 55MB. **sha256 값을 인계 메모나 이 문서 6절에 적는다.**

### 3-4. 되살리기 시험 (sgbdev · 매번 권장 · 약 1분)

```bash
T=<3-2 값>; C=$(mktemp -d -p ~/backup)
tar -xzf ~/backup/full_$T.tar.gz -C $C
for r in sgb-core sgb-infra sgb-adx sgb-docs; do
  git clone -q $C/full_$T/repos/$r.bundle $C/r_$r \
  && echo "$r $(git -C $C/r_$r rev-parse --short HEAD) 커밋$(git -C $C/r_$r log --oneline | wc -l) 오류$(git -C $C/r_$r fsck --no-progress 2>&1 | grep -c error)"
done
rm -rf $C
```

기대: 네 줄 모두 커밋 번호가 3-2 의 main 과 같고 `오류0`.

### 3-5. 집 PC 로 받기 (대표 · PowerShell)

```powershell
$T = "<3-2 값>"
mkdir C:\sgb\backup\$T -Force
scp sgb-dev:backup/full_$T.tar.gz C:\sgb\backup\$T\
Get-FileHash C:\sgb\backup\$T\full_$T.tar.gz -Algorithm SHA256
```

- [ ] sha256 이 3-3 값과 같음
- [ ] 외장 디스크 또는 클라우드 드라이브에 한 번 더 복사 (집 PC 한 곳만 두지 않음)
- [ ] 최근 3벌은 남기고 그보다 오래된 것만 지움

### 3-6. 서버 사본 정리 (Claude · 대표 「백업 지워」 뒤에만)

```bash
ls -la ~/backup
rm -f ~/backup/full_<지울 값>.tar.gz      # 이름을 하나씩 확인하고 지움 · ~/backup 밖은 지우지 않음
df -h ~ | tail -1
```

## 4. 되살리기

### 4-1. CodeCommit 저장소가 지워졌거나 망가짐 (사람 + Claude)

```bash
#  1) AWS 콘솔 → CodeCommit(서울) → 같은 이름으로 빈 저장소 만들기 (사람)
#  2) 개발 서버 sgbdev
export PATH=$HOME/.local/bin:$PATH
T=<쓸 묶음 값>; mkdir -p ~/restore && tar -xzf ~/full_$T.tar.gz -C ~/restore
R=sgb-core      # 되살릴 저장소
git clone --mirror ~/restore/full_$T/repos/$R.bundle ~/restore/$R.git
cd ~/restore/$R.git && git remote set-url origin codecommit::ap-northeast-2://$R
git push origin 'refs/heads/*:refs/heads/*'
git push origin --tags
```

기대: 갈래 수가 3-2 의 `갈래=` 값과 같음. 콘솔에서 main 커밋 확인.

> 빈 저장소로 보내는 첫 push 는 main 직접 push 가 된다 — 되살리기에 한해 **대표 승인 뒤** 사람이 하거나 Claude 가 한다(2026-10-15 첫 가져오기와 같은 예외).

### 4-2. 개발 서버의 작업 폴더만 망가짐 (Claude)

CodeCommit 이 살아 있으면 묶음이 필요 없다: `git clone codecommit::ap-northeast-2://<저장소>`. CodeCommit 도 안 되면:

```bash
git clone ~/restore/full_$T/repos/sgb-core.bundle ~/sogaebank/sgb-core
git -C ~/sogaebank/sgb-core remote set-url origin codecommit::ap-northeast-2://sgb-core
```

### 4-3. 지운 갈래 · 커밋 하나만 찾기

```bash
git bundle list-heads ~/restore/full_$T/repos/sgb-core.bundle | grep <갈래이름>
git -C ~/sogaebank/sgb-core fetch ~/restore/full_$T/repos/sgb-core.bundle <갈래이름>:restore/<갈래이름>
```

## 5. 생길 수 있는 문제

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | `git fetch` 가 `codecommit` 을 모른다고 함 | PATH 빠짐 | `export PATH=$HOME/.local/bin:$PATH` 뒤 다시 |
| 2 | `does not look like a v2 or v3 bundle file` | `.tar.gz` 를 바로 검사함 | 먼저 `tar -xzf` 로 풀고 `repos/*.bundle` 을 검사 |
| 3 | `verify` 가 `lacks these prerequisite commits` | `--all` 없이 일부만 묶음 | 3-2 를 `--all` 로 다시 |
| 4 | main 이 `origin` 과 다름 | 받아오기 안 됨 · 로컬 main 이 뒤처짐 | `git fetch` · `git merge --ff-only origin/main` 뒤 다시 묶기 |
| 5 | 디스크 부족 | 서버에 옛 백업이 쌓임 | 집 PC 로 받은 것 확인 → 「백업 지워」 |
| 6 | 집 PC sha256 이 다름 | 받다 끊김 | 다시 받기 · 그래도 다르면 서버에서 3-3 다시 |
