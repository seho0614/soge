# 216. 전자계약 연동 틀 — 설계 (2026-10-28)

> 대표 「다음」 → 「추천대로」 → (정정 뒤) 「1번 그대로」 → **「승인, 추천대로」(결정 ① 전자서명만 · ② 웹훅 + 10분 조회 · ③ 문서 id + 지문만)** → v10.143(docs/217).
> 목적: 업체 계약이 끝나면 **키만 넣고 시험**하도록 흐름을 미리 만든다. **꺼진 채로** 올라가고, 꺼져 있으면 지금과 똑같다.
> ⚠ 전자계약 업체(모두싸인 · 이폼사인 · 글로싸인 등)는 **미정**이다. 요청 형식 · 완료 알림(웹훅) 서명 방식 · 칸 이름은 업체마다 달라 **계약 뒤 업체 개발 문서로 맞춰야 함**(지금은 알림톡 v10.142 처럼 공통 HTTP 모양 · 확인 필요).
> ⚠ 정정(10/28): 전자계약은 **오픈을 막는 항목이 아님** — `integrations.blocks_open = false` · `v_contract_stub` 를 보는 곳 없음 · 사용자 화면은 지금 전자계약 API 를 부르지 않음.

## 1. 지금 상태 (코드 확인)

| 항목 | 지금 | 문제 |
|---|---|---|
| 계약 흐름 | 발급(SENT) → 양측 조건 합의(AGREED) → **화면 안 「서명」 단추**(`POST /deals/:id/contract/sign` · 양측) → SIGNED → 이행 확인 → FULFILLED | 서명 = 우리 서버가 찍은 시각 · 이력(`contract_revisions`). 분쟁 때 「우리가 만든 기록」이라 증거력이 약함 |
| 전자계약 API | `POST · GET /deals/:id/contract/esign` · `esign.provider.ts`(스텁: 바로 SIGNED · 실제: 「아직 붙지 않음」) | **화면에서 부르지 않음** · 서명 완료가 계약 상태에 반영되지 않음 · 서명자 이름이 「매수자 · 매도자」 고정 |
| DB | `deal_contracts.esign_doc_id · esign_stub` · 뷰 `v_contract_stub` · 알림 트리거(`CONTRACT_ESIGN_SENT`) | 요청 · 완료 기록 표 없음 · 계약서 내용 지문(해시) 없음 |
| 연동 목록 | ESIGN = **STUB** · 키 `ESIGN_API_KEY` 하나 · 연동 기간 2주 | 주소 · 웹훅 비밀값 칸 없음 |

## 2. 흐름 (v10.143)

```
양측 합의(AGREED)
  → 회원 「전자서명 요청」  POST /deals/:id/contract/esign
       서버: 계약서 본문 + 합의 조건 + 당사자로 문서 만들기 → 지문(SHA-256) 저장
             → 업체에 서명 요청(서명자 2명 · 이름 · 휴대폰 또는 메일) → 문서 id
       계약: 조건 잠금(합의 · 수정 제안 막힘 — 요청 취소 전까지)
  → 양측이 업체 화면에서 서명(업체가 문자 · 메일로 링크를 보냄 · 우리 화면에도 「서명하러 가기」)
  → 업체 → 우리  POST /webhooks/esign   서명 검사(HMAC) → 같은 알림 두 번 와도 한 번만 처리
       한쪽 서명 → signed_by_*_at(업체 시각) · 상대에게 알림
       양쪽 서명 → state SIGNED · 서명본 지문 · 완료 시각 기록
  → 웹훅이 안 오면 10분마다 업체에 상태를 물어봄(예약 작업 esign_poll · 대기 10분 넘은 것만)
```

## 3. 방식 스위치 `esign.provider` (처음 `STUB`)

| 값 | 동작 | 쓰는 곳 |
|---|---|---|
| `STUB`(처음 · **지금과 같음**) | 화면 안 「서명」 단추 그대로 · 전자계약 요청 API 는 지금처럼 스텁 기록 | 운영(계약 전) |
| `MOCK` | **우리 사이트 안의 가짜 서명 화면**(`/contract/mock-sign`) — 요청 · 서명 · 웹훅(같은 서명 검사) · 상태 조회 전체를 시험 · **운영(production)에서는 막힘** | 점검판 · 시험 |
| `HTTP` | 실제 업체 — 키 · 주소 · 웹훅 비밀값 필요(없으면 422 · 빠진 칸 표시) | 계약 뒤 |

`MOCK` · `HTTP` 일 때는 **화면 안 「서명」 단추 대신 「전자서명 요청」** 이 나온다(한 계약에 두 종류 서명이 섞이지 않게 — 결정 ①). 바꾸기는 **SUPER** · 감사 기록.

## 5. 오류 처리

| 상황 | 처리 |
|---|---|
| 업체 연결 실패(시간 초과 · 5xx · 인증 401/403 · 거절 4xx) | 요청 기록 FAILED + 오류 종류 · 계약은 AGREED 그대로 · 회원에게 「잠시 뒤 다시」 · 운영 화면 실패 까닭 |
| 웹훅 서명 틀림 · 시각이 5분 넘게 어긋남 | 401 · `esign_events` 에 기록(검사 실패) · 처리 안 함 |
| 같은 웹훅 두 번 | 이벤트 id 로 한 번만 처리 |
| 서명 거절 · 만료(7일) | 문서 REJECTED · EXPIRED → 계약 AGREED 로 · 조건 잠금 풂 · 이력에 남김(알림은 체결 · 한쪽 서명만 — 기존 알림 종류) · 다시 요청 가능 |
| 요청 뒤 계약 파기 | 업체 문서 취소 요청(실패해도 우리 쪽은 CANCELLED · 기록) |
| 서명 완료인데 지문이 다름(업체가 돌려준 문서 지문 ≠ 우리가 만든 것) | SIGNED 로 올리지 않음 · `HASH_MISMATCH` 기록 · 운영 화면 경보 |
| 당사자 연락처 없음 | 요청 전 422 `ESIGN_CONTACT_MISSING`(휴대폰 또는 메일 필요) |
| 키를 넣었는데 방식이 STUB | 그대로 STUB — 키만으로 켜지지 않음(본인인증 v10.141 과 같은 규칙) |

## 7. 법무 · 운영 확인 (계약 전)

1. 업체에 당사자 이름 · 휴대폰(또는 메일)을 넘김 → **처리방침 위탁 목록에 전자계약 업체 추가** 필요(약관 게시 전 법무 확인 · 업체 정해진 뒤).
2. 전자서명법상 효력 · 업체가 주는 감사 추적(서명 시각 · 접속 기록) 범위는 **업체 문서로 확인 필요**.
3. 웹훅 주소 `https://sogaebank.com/api/v1/webhooks/esign` 을 업체에 등록 — 발신 IP 제한이 있으면 업체 IP 를 받아 둠.
