# 657. 광고 성과 보고서 (v10.519 · 2026-11-20)

## 1. 결론
광고주마다 **기간(하루 · 주 · 달) 노출 · 클릭 · 광고비**를 보고서로 만들어 **인쇄 PDF**와 **메일**로 전합니다. **새 추적 없음** — 노출 · 클릭은 이미 있는 광고 기록(`ad_events` · 과금 근거 · 고치지 않음), 광고비는 이미 있는 청구서(`ad_invoices`)를 읽기만 합니다. 숫자만 담고 회원 정보는 넣지 않습니다.
대표 11/20 「법무 확인 · 메일 허용 · 매일 허용」 → 「모두」:
1. 보고서 메일은 **법무 확인(대표 11/20)** 끝.
2. **보내는 주기** `prx.ad_report_cycle` = DAILY · WEEKLY · MONTHLY(**처음 MONTHLY**) — 같은 기간은 두 번 보내지 않음(보고서 표에 기간 열쇠).
3. 메일 스위치 `prx.ad_report_mail` 은 **처음 off 그대로** — 켜는 것은 운영 화면에서 SUPER(메일 준비가 된 뒤).

위치: 운영 **광고 › 광고 성과 보고서**(SB-ADM-PRX-030) · API `/admin/prx/ad-reports` · `/admin/prx/ad-owners/{소재}`.

## 2. 주기 · 기간 열쇠
| 주기 | 정기 작업(매일 08:10)이 만드는 기간 | 기간 열쇠(period_key) | 첫날 ~ 끝날 |
|---|---|---|---|
| DAILY | 어제 하루 | `2026-11-19` | 그날 |
| WEEKLY | 지난주(월 ~ 일) — 월요일 아침 첫 실행에 생김 | `W2026-11-16`(그 주 월요일) | 월 ~ 일 |
| MONTHLY(처음) | 지난달 — 1일 아침 첫 실행에 생김(지금 동작) | `2026-10` | 1일 ~ 말일 |

- 날짜는 한국 시각. 정기 작업은 그 기간 보고서가 **없는 광고주만** 만들고, 메일이 켜져 있으면 **아직 안 보낸 것만** 보냄.
- 광고주 · 기간 열쇠마다 한 줄(UNIQUE) · 열쇠와 첫날 · 끝날이 맞는지 DB CHECK(주는 월요일 · 7일 · 달은 말일까지).
- **같은 기간 두 번 안 보냄**: 보낸(SENT) 보고서는 다시 보내기 409 · 숫자 · 기간 고치기와 보낸 표시 되돌리기를 DB 가 막음.
- 주기를 바꿔도 이미 만든 보고서는 그대로(열쇠가 달라 서로 겹치지 않음). 운영자는 화면에서 아무 기간이나 골라 만들 수 있음(아직 시작하지 않은 기간은 422).

## 3. 셈
| 항목 | 규칙 |
|---|---|
| 소재 → 광고주 | `prx_ad_owner`(운영자가 이음) 먼저 · 없으면 소재의 광고주 이름 = 광고주 이름(대소문자 · 앞뒤 빈칸 무시). 못 찾은 소재는 보고서에 안 들어감(화면 「못 찾음」 · 이어 주기) |
| 노출 · 클릭 | 그 광고주 소재들의 `ad_events` 종류별 건수 · 첫날 0시 ~ 끝날 다음 날 0시 |
| 광고비 | VOID 아닌 청구서 중 그 기간에 걸친 것 — 공급가 × (기간에 든 날수 ÷ 청구 기간 날수) 반올림 · 부가세 포함도 같은 셈 |
| 비율 | 클릭률 = 클릭 ÷ 노출(소수 둘째) · 클릭당 = 광고비 ÷ 클릭 · 천 회 노출당 = 광고비 × 1000 ÷ 노출 |

- 광고 기록과 광고주 표가 나뉘어 있어(`ad_placements.advertiser` 글자 · `ad_bookings.advertiser_id` 는 사업자 표) 잇는 표를 새로 뒀습니다 — 기존 표는 고치지 않음.
- 분리한 광고 플랫폼(sgb-ads · `sgb_ads` DB)의 외부 송출 숫자는 넣지 않습니다(본체 지면만) — 합치는 것은 다음 후보.

## 4. 만들기 · 보내기
| 일 | 규칙 |
|---|---|
| 만들기 | 운영자 「보고서 만들기」(고른 기간 · 숫자가 있는 광고주 모두 또는 한 곳) · 다시 만들면 덮어씀 · **메일로 보낸 것은 그대로** |
| 메일 | `prx.ad_report_mail` 처음 off · 켜기 · 끄기 · 주기 바꾸기는 SUPER(사유 · 감사 기록) · 기존 메일 길(SES · `notify.email_verified`) · 받는 곳 = 광고주 담당 메일(advertisers.contact_email) · 결과 SENT · FAILED · NOT_READY · NO_ADDRESS · 보낸 주소는 가린 값만 · 제목에 기간 이름(예: 「2026-11-16 ~ 2026-11-22(주)」) |
| 인쇄 PDF | 운영 화면 `printDoc.openPrint`(D264) — A4 · 「PDF 로 저장」 · 서버 PDF 라이브러리 없음 |

## 5. 표 · 설정 · API
| 이름 | 내용 |
|---|---|
| `prx_ad_owner` | 소재 → 광고주 · 누가 · 언제 |
| `prx_ad_reports` | 광고주 · 주기 · 기간 열쇠(광고주마다 고유) · 첫날 · 끝날 · 노출 · 클릭 · 광고비 · 부가세 포함 · 소재별 줄 · 만든 때 · 메일 결과 · 가린 주소 |
| `prx.ad_report_mail` | 처음 off · SUPER |

| API | 권한 |
|---|---|
| GET /admin/prx/ad-reports?period= (비우면 지금 주기의 지난 기간) · GET /{id} | ADMIN · SUPER |
| POST /admin/prx/ad-reports/make { period } · PUT /admin/prx/ad-owners/{id} | ADMIN · SUPER |
| POST /{id}/send · PUT /ad-reports/switch { on?, cycle?, reason } | SUPER |

## 6. 광고 불변식에 미치는 것
- `ad_events` · `ad_invoices` · `ad_slots` · `ad_placements` 를 **고치지 않음**(읽기만 · 잇는 표만 새로). 노출 기록 삭제 금지(AD-05 · trg_ad_events_ro) 그대로.
- 보고서 표에 회원 · 세그먼트 · 연락처 칸 없음(`v_ad_stats_for_advertiser` 와 같은 원칙 · 시험이 칸 이름을 봄).
- DAILY 로 두면 매일 광고주 수만큼 셈(소재별 ad_events 집계 한 번 · 청구 한 번) — 지금 규모에서는 가벼움.

## 7. 처리방침 · 법무
- 회원 개인정보 새로 모음 · 외부 제공 **없음**(숫자 묶음만 · 회원을 알아볼 수 없음).
- 광고주 담당자 메일로 보내는 것 — **법무 확인(대표 11/20)**: 메일 보내기 · 매일 보내기 허용. 광고 계약서 · 광고주 약관에 「성과 보고서를 담당 메일로 보냄(주기)」 문구를 넣는 것은 계약 갱신 때.
