## 6. 4단계 — 바깥 주소 (Nginx · 인증서)

지금 Nginx(절차서 v2.5 8-1)는 전부 3000(API)으로 넘깁니다. **사용자 웹(5174)이 앞에 서도록 바꿔야** 메인이 열립니다.

### 6-1. 운영 화면 주소 · 폴더 권한

```bash
# 운영 화면은 별도 주소입니다. DNS 를 관리하는 곳에서 A 레코드를 하나 더 — admin → 서버 IP (사용자 웹과 같은 IP)
dig +short admin.sogaebaenk.co.kr      # 서버 IP 가 나오면 반영된 것

# Nginx 가 홈 폴더를 지나가야 운영 화면 파일을 읽습니다(Ubuntu 24.04 의 홈은 750 — 그대로 두면 운영 화면이 500)
chmod o+x /home/ubuntu
```

`chmod o+x` 는 「지나가기」만 허용합니다(목록은 못 봅니다). `.env` 는 600 이라 읽히지 않습니다.

### 6-2. Nginx 설정 바꾸기

```bash
cp /etc/nginx/sites-available/sgb ~/sgb-data/nginx_sgb_before.conf         # 지금 설정 보관
bash ~/sgb/deploy/aws/nginx-render.sh sogaebaenk.co.kr admin.sogaebaenk.co.kr <내 IP> | sudo tee /etc/nginx/sites-available/sgb > /dev/null
sudo nginx -t && sudo systemctl reload nginx
```

`<내 IP>` 는 PC 에서 https://checkip.amazonaws.com 을 열면 나옵니다. 집 · 사무실 둘이면 쉼표로(`1.2.3.4,5.6.7.8`). IP 가 바뀌면 같은 명령을 새 IP 로 다시 하고 6-3 을 한 번 더 합니다.

| 전(v2.5) | 지금 | 이유 |
|---|---|---|
| 전부 3000(API)으로 | 사용자 웹 주소 → 5174 | `/api` 는 사용자 웹이 로그인 토큰 · 방문자 쿠키를 붙여 API 로 넘깁니다. Nginx 가 바로 넘기면 로그인 필요 동작이 전부 403 |
| 운영 화면 없음 | `admin.…` → 빌드한 파일 + `/api` 만 3000 | 운영 화면은 한 장짜리 앱 |
| 접근 제한 없음 | 사용자 웹 · 운영 화면 모두 사무실 IP 만 | 간주 모드가 켜진 채 공개되면 누구나 가입 · 결제 간주 |
| `X-Forwarded-For $proxy_add_…` | `$remote_addr` 로 덮어씀 | 서버가 이 헤더의 첫 값을 접속자 IP 로 봅니다. 덮어쓰지 않으면 비로그인 투표의 하루 한도를 헤더 조작으로 피합니다 |
| 업로드 20MB | 60MB | 마케팅 영상 50MB |

접근 제한은 `location` 안에 있어 **인증서 발급 · 갱신 확인(`/.well-known/acme-challenge/`)은 막지 않습니다**.

### 6-3. 인증서 (HTTPS)

```bash
sudo certbot --nginx -d sogaebaenk.co.kr -d www.sogaebaenk.co.kr -d admin.sogaebaenk.co.kr
sudo nginx -t && sudo systemctl reload nginx
```

전에 인증서를 받았더라도 **6-2 에서 파일을 덮었으므로 한 번 더** 합니다(같은 인증서를 다시 붙이거나 `admin` 을 더해 넓힙니다). 리디렉션을 물으면 2(HTTPS 로 전환).

**HTTPS 가 먼저여야 하는 이유** — 운영에서는 로그인 쿠키가 Secure 라서 `http://` 주소에서는 로그인해도 유지되지 않습니다(리허설에서 확인 — http 에서는 쿠키가 심기지 않고 로그인 필요 호출이 403).

### 6-4. 인증서 전에 미리 보고 싶을 때

| 다른 사이트 요청 | Origin 이 다르면 403 CSRF · 우리 주소(https)의 Origin 은 통과 |
| 파일 올리기 | 올리기 → 확정 → 내려받기 · 파일이 앱 폴더 밖에 저장 |
| 운영 서버만의 동작 | 정의에 없는 입력 항목 400 · 알림톡 연동 전 상담 신청 422(인증번호가 응답에 없음) |

### 12-2. 전수 검정 — API 를 운영 방식(`dist/main.js`)으로 띄우고
