# 503. DB 복원 시험 기록 (v10.368 · 2026-11-18)

> 대표 11/18 「다음개발」 → ① 회원 활동 한 줄 기록 · ② 개인정보 대량 내려받기 승인 · ③ 신고 처리 기한 경보 · ④ DB 복원 시험 기록 「모두」 → 계획 「승인 + 통과하면 병합」(다섯 번째 묶음 · 운영은 v10.361 ~ 364 와 함께 다음 묶음). 이 문서는 ④. 마이그레이션 **D238**(표 하나 · 설정 하나 · 업무 안내 한 판 · v10.366 과 같은 파일).

## 1. 왜

- RDS 스냅샷은 매일 만들어지지만 실제로 되살려 본 적이 없으면 사고 때 걸리는 시간 · 빠진 자료를 모릅니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 마이그레이션 **D238** | 표 `restore_drills`(한 날 · 스냅샷 · 걸린 분 · 행 수 맞음 · 이상 없음 · 메모 · 쌓기만) · 설정 `ops.restore_drill_days`(30 · 7 ~ 180) · 업무 안내 `RESTORE_DRILL` 1판(6단계) |
| 새 API | `GET /admin/restore-drills`(ADMIN · SUPER · 최근 12 · 마지막 · 지난 날 · 넘김) · `POST /admin/restore-drills`(SUPER · 감사 `RESTORE_DRILL_ADD` · 422 `RESTORE_DRILL_DATE` · `RESTORE_DRILL_SNAPSHOT`) |
| 정기 작업 `sla_alert` | 마지막 시험이 주기를 넘으면(없으면) 운영 알림 **`RESTORE_DRILL_DUE`**(WARN) · 적으면 풂 |
| 운영 화면 **관 관리 › 「업무 안내」** | 맨 위 **「DB 복원 시험 기록」** 상자 · 아래 업무 「DB 복원 시험(월 1회)」 순서 |
| 월간 보안 보고 | 「… · DB 복원 시험 날짜」(v10.366 과 같은 줄) |

- 복원 시험 자체는 사람이 AWS 콘솔에서 합니다(이 서버 · Claude 는 RDS 에 손대지 않음). 시험용 DB 는 끝나면 지웁니다(요금).
