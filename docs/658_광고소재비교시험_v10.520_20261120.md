# 658. 광고 소재 비교 시험 (v10.520 · 2026-11-20)

## 1. 결론
한 광고의 **소재 두 개(A · B)** 를 정한 기간 동안 **노출마다 번갈아** 내고, 기간이 끝나면 **클릭률**을 비교해 결과를 고정합니다. 두 소재 모두 이미 있는 광고 소재(`ad_placements`)이고, 기록은 이미 있는 `ad_events`(소재마다)라 **새 추적 · 새 칸이 없습니다**. **「광고」 표기 · 추천 순위 제외는 그대로**(인피드 표기 규칙 — sgb-adx AD-01 · AD-02 와 같은 뜻 · 본체 `ck_ad_slot_not_in_ranking` · 응답 label). 결과는 숫자만이고 누가 봤는지는 남기지 않습니다.
위치: 운영 **광고 › 광고 소재 비교**(SB-ADM-PRX-040) · API `/admin/prx/ab-tests`.

## 2. 번갈아 내는 방법
| 단계 | 규칙 |
|---|---|
| 짝 조건 | 같은 슬롯 · 같은 광고주(이름) · 같은 세그먼트 지정 · 차단 · 준비 중 · 끝난 소재 아님(422 PRX_AB_PAIR) |
| 시작 | 두 소재 모두 노출 중(ACTIVE · 409 PRX_AB_NOT_ACTIVE) · 한 소재는 진행 중 시험 하나에만(DB `PRX_AB_BUSY`) |
| 뽑기 | 진행 중에는 **B 를 뽑기 목록에서 뺌**(`fn_prx_ab_hidden`) — 짝이 다른 소재보다 두 배 뽑히지 않게 |
| 번갈아 | A 가 뽑히면 `fn_prx_ab_pick` 이 차례(served)를 하나 올려 홀수 A · 짝수 B — `ads.service.ts` serve(성향 · 기본 두 곳) · 인피드에 끼움 |
| B 가 못 나가면 | B 가 지금 노출 조건(v_ad_serving · 인피드 조건) 밖이면 A 그대로 |
| 기록 | 화면이 받은 소재 id 로 기존 `/ads/{id}/impression` · `/click` — 소재마다 따로 쌓임 |

## 3. 결과
| 칸 | 셈 |
|---|---|
| 노출 · 클릭 | 기간(시작 ~ 끝 · 진행 중이면 지금까지) 소재별 `ad_events` |
| 클릭률 | 클릭 ÷ 노출 |
| z | 두 비율 차이 검정(합친 비율) · \|z\| ≥ 1.96(95%)이면 차이 있음 |
| 판단 | 소재마다 `prx.ab_min_impr`(처음 1,000) 미만 노출이면 **표본 부족** · 아니면 A · B · 차이 없음 |
| 고정 | 끝내기(운영자) · 기간 끝(정기 작업 `prx_hourly`) 때 결과를 `result` 에 고정 · 끝난 결과는 DB 가 못 고치게 막음 · 운영 알림 `PRX_AB_DONE`(INFO) |

- 진 소재를 멈추는 것은 기존 「광고 관리」의 중지 단추로(자동으로 멈추지 않음 — 광고주와 이야기할 일).

## 4. 표 · 함수 · API
| 이름 | 내용 |
|---|---|
| `prx_ab_tests` | 이름 · A · B · 슬롯 · 기간(최대 92일) · 상태(DRAFT · RUNNING · ENDED · CANCELED) · 번갈아 낸 수 · 결과 |
| `fn_prx_ab_hidden(소재)` | 진행 중 시험의 B 인가 |
| `fn_prx_ab_pick(소재)` | 낼 소재(A 면 차례대로) |

| API | 권한 |
|---|---|
| GET /admin/prx/ab-tests · GET /{id} | ADMIN · SUPER |
| POST /admin/prx/ab-tests · POST /{id}/start · /end · /cancel | ADMIN · SUPER |

## 5. 광고 불변식에 미치는 것
- `ad_slots`(인피드 표기 · `in_ranking` CHECK) · `ad_events`(쌓기만) · 규제 소재 게이트(`fn_ad_slot_gate`)를 고치지 않음. 표기 「광고」는 serve · 인피드 응답이 그대로 붙임(시험 1520 이 네 번 모두 확인).
- 진행 중에는 A 차례마다 `prx_ab_tests` 한 줄을 고침(served + 1) — 시험이 없는 소재는 읽기 한 번만 더함. 트래픽이 크면 줄 잠금이 생길 수 있어 다음에 차례를 확률(무작위 반반)로 바꿀지 판단(문서 · NOTES 위험 줄).

## 6. 처리방침 고칠 곳
- 해당 없음 — 새로 모으는 회원 정보 없음(기존 노출 · 클릭 기록을 소재별로 세기만 · 결과는 숫자).
