# 644. 소개몰 현금영수증 (v10.506 · 2026-11-20)

## 1. 결론
소개몰 **직판(DIRECT) 주문**을 **계좌이체(TRANSFER) · 가상계좌(VBANK)** 로 결제하면 현금영수증을 발급합니다. 회원은 주문마다 **소득공제(휴대폰 번호)** 또는 **지출증빙(사업자등록번호)** 을 고르고, 결제가 확인되면 정기 작업이 발급합니다. 주문이 **취소 · 반품**되면 DB 가 「취소 대기」로 바꾸고 다음 차례에 취소합니다. 처음에는 **꺼짐**(`mall.cash_receipt` off) · **간주**(`mall.cash_receipt_mode` ASSUME — 업체를 부르지 않고 「간주 발급」으로만 기록)이고, 실제 발급(LIVE)은 **세무사 · PG 확인 뒤 SUPER** 가 켭니다. 위치: **소개몰 › 현금영수증** · SB-ADM-MLX-020 · 회원 API SB-HLT-MLX-020(회원 화면은 「주문 받기」를 켤 때).

| 항목 | 규칙(처음 값) |
|---|---|
| 대상 | 직판 · 계좌이체 · 가상계좌 결제만(카드는 카드 전표가 증빙 → 422 `HLT_CR_CARD` · 입점 판매자 상품은 그 판매자가 발급 → 422 `HLT_CR_DIRECT_ONLY`) |
| 번호 | 휴대폰 `^01[016789][0-9]{7,8}$` · 사업자번호 `^[0-9]{10}$` — 서버(health-cashrcpt CR_PHONE · CR_BIZNO)와 DB(`fn_hlt_cr_request`)가 **같은 정규식**(숫자만 남긴 뒤) |
| 저장 | 번호는 **암호화**(`pgp_sym_encrypt` · `fn_enc_key`) · 화면 · 응답 · 감사 기록에는 **가린 값**(010-****-5678 · 123-**-67890)만 · 업체로 보낼 때만 DB 에서 풂 |
| 신청 기간 | 결제 전 언제든(REQUESTED) · 결제 뒤 `mall.cash_receipt_req_days` 5일까지 회원 화면 · 그 뒤는 운영이 「운영 발급 신청」 |
| 금액 | 결제 금액(환불 뒤 남은 금액) · 면세 몫 = 쿠폰 뒤 면세 상품 금액(결제 금액까지) · 과세 몫 부가세 = round(과세 ÷ 11) · 공급가액 = 과세 − 부가세(CHECK: 공급가액 + 부가세 + 면세 = 금액) |
| 자진발급 | `mall.cash_receipt_self` off · on 이면 회원 신청이 없는 대상 결제 중 `mall.cash_receipt_self_min` 100,000원 이상을 국세청 지정 번호 **010-000-1234** 로(회원 알림 없음) |
| 보관 | 번호(암호화)는 `mall.cash_receipt_keep_years` 5년 뒤 정기 작업이 지움 · 가린 값 · 금액 · 승인번호는 남김 · 줄은 지우지 않음(DB 지킴) |
| 정기 작업 | `mall_cash_receipt` 10분마다(스위치 on) · `mlx_daily_purge` 04:35(번호 보관 끝) |

## 2. 흐름 (DB 트리거 · 정기 작업)
| 상태 | 언제 | 다음 |
|---|---|---|
| REQUESTED | 결제 전 회원 신청 | 결제 승인(`trg_hlt_cr_on_pay`) → PENDING · 카드면 SKIPPED |
| PENDING | 결제 뒤 신청 · 결제 승인 · 자진발급 · 운영 발급 신청 | 정기 작업 → ISSUED(실제) · ASSUMED(간주) · FAILED |
| FAILED | 업체 거절 · 연결 실패 | 30분 뒤 다시(5번까지 · 5번째 실패 운영 알림 `MALL_CASH_RECEIPT_FAIL`) · 운영 「다시」 |
| ISSUED · ASSUMED | 발급됨 · 회원 알림 `HLT_CASH_RECEIPT`(끌 수 없음 · 거래 증빙) | 주문 취소 · 반품(`trg_hlt_cr_on_order`) · 운영 취소 → CANCEL_PENDING |
| CANCEL_PENDING | | 정기 작업 → CANCELED(회원 알림) · **반품 차감**(반품 배송비 등)으로 일부만 돌려줬으면 남은 금액으로 새 줄(REISSUE · 세무사 확인) |
| SKIPPED · CANCELED | 닫힘 | 바꾸지 않음(번호 지우기만) |

- 실제(LIVE)인데 결제 연동 키(`TOSS_SECRET_KEY`)가 없으면 **NOT_READY** — 발급하지 않고 줄에 사유만 · 운영 알림 `MALL_CASH_RECEIPT_NOT_READY` 하루 한 번(조용히 간주로 돌아가지 않음).
- 감시 보기 `v_hlt_cr_cancel_missing`(취소 · 반품 주문인데 발급 상태로 남은 영수증 · 늘 0).

## 4. 확인할 것 (켜기 전)
1. **세무사 확인**
   - 통신판매업(소개몰 직판)의 **현금영수증 의무발행업종 해당 여부** — 해당하면 건당 10만 원 이상 현금 거래는 소비자가 요청하지 않아도 발급(자진발급 010-000-1234) · 발급 기한(거래일부터 5일 안 · 확인 필요) · 미발급 가산세. 지금 처음 값: 자진발급 off · 기준 100,000원 — 해당하면 `mall.cash_receipt_self` on(SUPER).
   - 반품 차감분(반품 배송비) 다시 발급이 맞는지 · 배송비 · 면세 몫 나눔 · 적립금 · 상품권으로 낸 몫(현금 아님 — 결제 금액에서 이미 빠짐) 처리.
   - 부가세 신고서 「(3) 신용카드 · 현금영수증 발행분」 — 운영 화면 달마다 합(실제 발급만 · 간주 빼고)을 회계 › 부가세 신고서 미리보기에 잇는 것은 다음 후보.
2. **PG(토스페이먼츠) 확인**
   - 현금영수증 API 사용 계약 · 요청 칸 이름 · 응답(issueNumber · issueStatus) · 취소 금액 칸 — 이 문서의 모양은 공개 문서 기준(어댑터 머리말) · **계약 뒤 개발 문서로 대조**.
   - **결제창 현금영수증과 겹침** — 계좌이체 · 가상계좌 결제창이 현금영수증 신청을 받도록 설정돼 있으면 PG 가 따로 발급함 → 두 번 발급되지 않게 둘 중 하나만(상점 관리자 설정 확인 · 이 기능을 쓰면 결제창 쪽 끄기).
3. **켜는 순서**(운영 반영 절차서 4-3 권함): 세무사 · PG 확인 → `mall.cash_receipt` on(ASSUME 그대로 · 화면 확인) → 키 확인 → `mall.cash_receipt_mode` LIVE(SUPER) → (해당하면) 자진발급 on.
