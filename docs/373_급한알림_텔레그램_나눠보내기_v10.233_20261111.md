# 373. 급한 알림 텔레그램 나눠 보내기 — v10.233 (2026-11-11)

> **마이그레이션 없음(237 그대로)** · 새 API 없음 · 화면 바뀜 없음 · 정기 작업 `launch_watch` 의 텔레그램 보내기만 바뀜.

## 1. 왜

- 텔레그램은 한 통에 4,096자까지 받습니다. 지금까지 `send()` 는 글을 4,000자에서 **잘라 보내면서**, 급한 알림 대기 목록(최대 50건)을 **모두 「보냄」(`pushed_at`)으로 적었습니다.**
- 제목이 긴 알림이 많으면 잘린 뒤쪽 알림은 다음 차례에도 다시 오지 않았고, 끝의 「보내지 못한 알림 n건 더」 · 「확인을 누르십시오」 줄도 잘렸습니다(인계 메모 67절 알아 둘 것 ②).

## 2. 바뀐 것

| 곳 | 내용 |
|---|---|
| `telegram.service.ts` | `TG_MAX = 4000` · `packLines(줄들, 한 통 칸, 최대 통 수)` — 앞에서부터 한 통씩 묶음 · `send()` 가 잘랐으면 결과 `truncated` · 로그 한 줄 |
| `scheduler.service.ts` `alertPush` | 머리 · 끝 줄 자리를 먼저 잡고 남은 칸에 알림 줄을 채워 **최대 3통**으로 나눔 · 여러 통이면 머리에 `(1/3)` · 끝 안내 줄은 마지막 통에만 · 제목 200자 넘으면 「…」 |
| 기록 | **보내기에 성공한 통의 알림만** 「보냄」 · 둘째 통이 실패하면 거기서 멈추고 나머지는 다음 차례 · 3통에 못 든 알림은 「n건 더」로 셈(24시간 안에는 다음 차례에 이어서) |
| 작업 기록 | `alertPush` 에 `parts`(보낸 통 수) |

- 메일은 길이 제한이 없어 그대로입니다. 하루 요약 · 접속 인증번호 · 시험 메시지는 짧아 한 통 그대로입니다(넘으면 잘리고 로그에 남음).
- 대화방에 한 번에 3통이 연달아 갈 수 있습니다(같은 대화방 1초에 1통 남짓 — 텔레그램 기준 안).

## 3. 시험

- `qa/test_v1233.py`(서버에서 직접 · 회귀 HOST 목록) — ① 코드 ② 가짜 텔레그램 서버로: 긴 제목 알림 60건 → 2 ~ 3통 · 각 4,000자 이하 · `(k/n)` · 글 안 알림 수 = 「보냄」 수 · 마지막 통에만 「n건 더」(60 − 보낸 수) · 다음 차례에 남은 것 한 통 · 40건에서 둘째 통 502 → 첫 통 알림만 「보냄」 · 다시 열리면 나머지.
- `qa/test_v1200.py` — 한도 글자 검사를 `TG_MAX` 도 받게.

## 4. 운영 적용

- 마이그레이션 없음 · 스냅샷 물음은 skip 가능 · 절차서는 병합 뒤 따로.
