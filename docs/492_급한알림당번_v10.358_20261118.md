# 492. 급한 알림 당번 (v10.358 · 2026-11-18)

> 대표 11/18 「다음개발」 → ① 운영 화면 자동 로그아웃 · ② 급한 알림 당번 · ③ 개인정보 열람 사유 · ④ 운영자 비밀번호 정책 「모두」 → 계획 「승인 + 통과하면 병합」(세 번째 묶음 · 운영 반영은 v10.356 까지 한 번에 한 뒤). 이 문서는 ②. 마이그레이션 **D236**.

## 1. 왜

- 급한 알림은 운영 대화방(텔레그램 · 슬랙)으로만 가서, 누가 맡을지 정해져 있지 않았고 아무도 안 보면 그대로였습니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 마이그레이션 **D236** | 표 `staff_oncall`(요일 1 월 ~ 7 일 → 운영자 · 처음 비어 있음) · `ops_alerts` 칸 `oncall_pushed_at` · `escalated_at` |
| 새 API `GET /admin/oncall` · `PUT /admin/oncall/{dow}` | ADMIN · SUPER 읽기 · SUPER 정하기(감사 `ONCALL_SET` · 운영 역할만 · 422 `ONCALL_NOT_STAFF`) |
| 정기 작업 `launch_watch` | 급한 알림(CRITICAL · 확인 · 풀림 전 · 24시간 안)을 **오늘 당번 개인 텔레그램**으로 한 번(대화방 보내기는 그대로) · **30분 안에 「확인」이 없으면 SUPER 개인 텔레그램**(당번 뺌)으로 한 번 |
| 운영 화면 **위험감지 › 「운영 알림」** 맨 위 | **「급한 알림 당번」** — 오늘 당번 · 요일 7칸 · 고르기(SUPER) · 개인 텔레그램 없는 사람 표시 |

- 개인 텔레그램 번호는 권한 계층 › 접속 인증 › 「운영자별 받을 곳」(v10.226)에 적은 것을 씁니다.
