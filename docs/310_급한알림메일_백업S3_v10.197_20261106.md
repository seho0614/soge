## 1. 바뀐 것

| # | 무엇 | 내용 |
|---|---|---|
| 1 | 급한 알림 메일 | 정기 작업 `launch_watch`(10분마다)가 끝날 때 **CRITICAL 전부 + 중요 설정 바뀜(SETTING_CHANGED)** 중 확인 안 한 것 · 24시간 안 · 아직 안 보낸 것을 하루 요약 받는 주소(`ops.digest_to`)로 **한 통**에 묶어 보냄. 같은 종류는 **1시간에 1통**(그사이 것은 다음 메일에). 고르는 기준은 DB 함수 `fn_ops_alert_mail_pending()` 하나. 보낸 알림은 `ops_alerts.mailed_at` 에 시각 → 운영 알림 화면 「메일 보냄 MM-DD HH:MM」 |
| 2 | 메일이 안 될 때 | 받는 주소가 비었거나(`NO_TO`) 메일이 준비 안 됐거나(`MAIL_NOT_READY` · SMTP · `notify.email_verified`) 보내기 실패(`SEND_…`)면 **보낸 것으로 적지 않음** — 작업 기록(`job_runs` launch_watch 의 `alertMail`)에 까닭만. 24시간 기준이라 메일이 나중에 준비돼도 옛 알림이 쏟아지지 않음 |
| 3 | 백업 디스크 밖(S3) | `uploads-backup.sh` 가 묶음을 만든 뒤(또는 오늘 묶음이 이미 있으면) `.env` 의 `BACKUP_S3_BUCKET` 이 있을 때 `aws s3 cp` 로 `s3://버킷/uploads-backup/`(`BACKUP_S3_PREFIX`)에 올림. 서버 역할(IAM) 권한을 씀(열쇠를 .env 에 넣지 않음). 올린 표시 파일 `uploads_YYYYMMDD.tar.gz.s3` 로 두 번 올리지 않음. 실패 → 운영 알림 `UPLOADS_BACKUP_OFFSITE_FAILED`(WARN · 하루 한 번) · 종료 값 3. **값이 없으면 꺼짐(지금과 같음)**. 앱 파일 저장 위치 `S3_BUCKET`(미정 #7)과 **다른 값** |
| 4 | 확인 줄 | `uploads-backup.sh check` · postcheck 끝에 「디스크 밖(S3) — 켜짐 · 마지막 올린 묶음 / 꺼짐」(postcheck 통과 · 확인 수에 넣지 않음). postcheck 백업 「확인」 줄 안내가 cron 대신 배치 호출기(pm2 logs sgb-jobs) |
| 5 | 개발 서버(sgb-infra) | `sgb-check.sh` 점검 전 정리에 「`~/kits/out` · `~/kits/release` 는 판 번호가 큰 3판만」 |

**정한 기준**

1. 대상은 CRITICAL 과 중요 설정 바뀜뿐 — WARN 전부는 메일이 너무 많아짐.
2. 메일은 10분 안(정기 작업 주기). 메일 한 통에 50건까지.
3. 확인(「확인」 단추)한 알림은 보내지 않음.
4. S3 쪽 오래된 묶음은 버킷 보관 규칙(수명 주기)으로 지움 — 스크립트는 S3 에서 지우지 않음.

## 2. 시험 (sgb-infra · 회귀 109개)

`qa/test_v1197.py`(시험 컨테이너)
- 코드: 마이그레이션 · 정기 작업 · 운영 화면 · 백업 스크립트 · sgb-check.sh
- DB: 보낼 것 고르기(CRITICAL · SETTING_CHANGED 만 · WARN 아님 · 확인한 것 아님 · 24시간 넘은 것 아님 · 같은 종류 1시간 안에 보냈으면 미룸) · mailed_at 은 확인한 알림에도 적힘
- API: 정기 작업 launch_watch → 개발은 메일 준비 전 → `alertMail.reason = MAIL_NOT_READY`(또는 받는 주소 없음 NO_TO) · 보낸 것으로 안 적힘 · 운영 알림 목록에 `mailedAt`
- 백업: 가짜 `aws` 로 올림 성공(표시 파일 · 다시 돌리면 「이미 올림」) · 실패(종료 값 3 · 운영 알림 하루 한 번) · 값 없으면 꺼짐
- 킷 정리: 임시 폴더에서 3판만 남음

## 3. 운영 적용

- docs/309(v10.196)는 따로 적용하지 않고 **v10.195 → v10.197 한 번에**(대표 11/6 「두 판을 모두 한 번에 적용」) — 절차서 따로
- 마이그레이션 1개 → **스냅샷 필수**(apply 가 물음)
- 운영 `.env` · Nginx 고치지 않음. S3 백업을 켤 때만 대표가:
  1. S3 버킷 만들기(예: `sgb-uploads-backup` · 공개 차단)
  2. 운영 EC2 역할(IAM)에 `s3:PutObject` 권한(그 버킷 · `uploads-backup/*`)
  3. 버킷 수명 주기 규칙(예: 30일 뒤 지움)
  4. 운영 `.env` 에 `BACKUP_S3_BUCKET=버킷이름`(스크립트가 부를 때마다 .env 를 읽어 재시작 필요 없음)
  5. `bash ~/sgb/deploy/aws/uploads-backup.sh` → 「디스크 밖(S3)에 올림」
  - 운영 서버에 `aws` 명령이 있는지는 **추가 확인 필요**(`aws --version`)
- 메일은 `ops.digest_to` 와 메일 준비(docs/167)가 되면 저절로 켜짐
