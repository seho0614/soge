## 1. 무엇이 바뀌나

| 곳 | 내용 |
|---|---|
| 보내는 길 `admin.ip_verify_channel` | `TELEGRAM`(처음 · v10.226 그대로) · `SMS`(확인한 운영자 휴대폰 · 알림톡 STAFF_IP_OTP · 대행사가 알림톡 실패면 문자) · `SMS_THEN_TELEGRAM`(문자가 안 되면 텔레그램). SUPER 만 · 접속 인증이 켜진 채 바꾸면 새 길로 모든 운영자가 받을 수 있어야(422) |
| 운영자 휴대폰 | 「접속 인증」 탭 「내 휴대폰」 — 번호 → 확인 번호(알림톡) → 넣으면 등록. **확인한 번호만** 들어감(DB 검사) · 바꾸기는 접속 인증을 마친 뒤에만 · SUPER 는 지우기만(분실 · 퇴사) |
| 문자 준비 | `notify.alimtalk_ready` on · 방식 HTTP(키 · 주소) · 템플릿 STAFF_IP_OTP **심의 승인** · 대행사 코드 — 하나라도 없으면 SMS 길은 받을 곳이 없음(켜기 422 `IP_VERIFY_NO_SMS`) |
| 켜기 검사 | v10.226 의 「모든 운영자 받을 곳」이 길에 따라 — SMS: 확인한 휴대폰 · SMS_THEN_TELEGRAM: 휴대폰 또는 텔레그램 |
| 기록 | 감사 `STAFF_PHONE_CODE_SENT` · `STAFF_PHONE_VERIFIED` · `STAFF_PHONE_REMOVED`(끝 4자리만) · 알림톡 보낸 기록 목적 `STAFF_OTP` · 받는 번호 끝 4자리 |

## 2. 알림톡 템플릿(대행사 · 카카오 심의에 이 글 그대로)

```
[소개뱅크 운영] 운영 화면 접속 인증번호는 #{인증번호} 입니다.
#{분}분 안에 넣어 주십시오. 직접 요청하지 않았다면 최고 관리자에게 알리십시오.
```

- 운영 화면 › 외부 연동 › 「알림톡」 표에 5번째 줄로 나옴 → 대행사 템플릿 코드 · 심의 상태를 넣음.

## 3. Nginx IP 제한을 풀기까지(대표 · 순서)

1. 문자 대행사 계약 · 템플릿 심의(STAFF_IP_OTP) · 알림톡 켜기(docs/215 · 167)
2. 운영자마다 「접속 인증」 탭에서 휴대폰 확인
3. 보내는 길 `SMS_THEN_TELEGRAM`(권함 — 문자 장애 때 텔레그램) → 접속 인증 켜기 → 핫스팟으로 확인
4. docs/363 5절대로 Nginx `allow · deny` 지움
