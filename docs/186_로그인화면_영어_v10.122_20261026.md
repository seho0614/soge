# 186. 로그인한 화면의 영어 — v10.122 (2026-10-26)

> 대표 「둘다」 2026-10-26 — 로그인 화면 남은 한국어 270개 중 ①(API 안내 · 오류) · ②(코드 이름표) · ④(은행 이름)를 이 판에서, ③(DB 기준표 문구)은 v10.123(D126 · 계획 먼저).
> **마이그레이션 없음**(163) · 사용자 웹만 · API · 운영 화면 그대로. **한국어 화면은 글자 하나 바뀌지 않음**(바꾸기 전 · 뒤 떠서 비교 — 3절).

## 1. 결론

| 갈래 | 고친 방법 |
|---|---|
| ② 코드 이름표(DB `code_labels` — 거래 상태 · 분쟁 사유 · 소개자 등급 · 중개 서류 · 요청 상태 …) | 사전 `codes`(i18n/messages/{ko,en}/codes.json · 손님 · 회원에게 보이는 128개)를 새로 두고, **사용자 웹이 API 응답을 받는 한 곳(`lib/api.ts` → `lib/codeLabels.ts`)에서** 화면 언어가 한국어가 아니면 `label` · `…Label` 칸의 값이 사전의 한국어 이름표와 **똑같을 때만** 그 언어 글자로 바꿈. 같은 한국어가 갈래마다 다르게 옮겨지면 바꾸지 않음. 25곳 넘는 API 를 하나하나 고치지 않음 |
| ① API 안내(note) | 사전 글자와 서버 글자가 같으면 사전으로 · 다르면 `f.srv(서버, 사전)` — 한국어는 서버 글자 그대로, 다른 언어는 사전 |
| ① 파트너 등록 방식 · 단계 · 블록 · 단가 구간 | 코드(formType · kind · 단계 순서)로 사전 `partnerOps.svcForm` · `billing.pricing` — 위자드는 갈래를 고를 때 서버 한국어 단계 이름을 그대로 쓰고, 보이는 이름만 따로 넘김(`stepNames`) |
| ① 추천 가중치 이름 | 코드(loc · cat · win · spd · trust)로 사전 `join.ai.match.w` |
| ① 제휴 수익 메모 | DB 트리거가 정한 두 모양만 사전으로(그 밖 메모는 그대로) |
| ① 건강몰 화면의 서버 오류 글 | 한국어 화면만 서버 글 · 다른 언어는 화면의 기본 오류 글 |
| ④ 은행 이름 | 사전 `bank.<은행 코드>`(모든 화면) — 고르는 칸의 글자만 · 서버로 보내는 `bankName` 은 한국어 그대로 |

## 2. 이번에 하지 않은 것

| 남은 것 | 까닭 · 다음 |
|---|---|
| ③ DB 기준표 문구(알림 설정 이름 · 신고 사유 · 요금제 혜택 · 소개자 등급 조건 · 업무 등록 안내 · 알림 채널 안내 · 광고 자리 문구 …) | v10.123 — 번역 대상(D126)에 더해 운영 화면 「번역」에서 입력 · 계획 따로 |
| 신뢰지표 배지(이름 · 상태 · 설명) | DB 함수 `fn_partner_badges` 가 글을 지어 냄 — 코드 · 숫자로 내리게 바꾼 뒤(v10.123 과 함께 검토) |
| 구독 안내(해지 예약 · 결제 실패 · 요금제 변경 예약 …) | 서버가 여러 상태를 합쳐 글을 지음 — 상태 코드로 내리게 API 를 바꾼 뒤 |
| 단추를 누른 뒤 서버가 주는 결과 · 오류 글(저장했습니다 · 반려 사유 …) | API 쪽 다국어(오류 코드 → 화면 사전) — 범위가 커서 따로 |
| 회원 · 시험 자료(업체 이름 · 상품 · 주소 · 거래 제목) | 회원이 쓴 내용 — 번역 대상(LISTING · POST …)이거나 그대로 |

- 빌드: 이름표 바꾸기에서 `getLocale()` 오류를 잡으면 Next 가 요청마다 그릴 화면을 알아채지 못해 **빌드가 60초 제한으로 멈춤**(이번에 한 번) — 쿠키를 읽는 함수에서만 부르고 오류는 잡지 않음
