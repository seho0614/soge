### 4-2. 검색 등록 (대표 · 적용 확인 뒤)

1. 구글 서치 콘솔 → 속성 추가 → **URL 접두어** `https://sogaebank.com` → 「HTML 태그」 → `content="…"` 따옴표 안 값만 복사 → 운영 화면 설정 **`seo.verify_google`** 에 붙여 넣기 → 5분 뒤 「확인」 → Sitemaps 에 `sitemap.xml` 제출
2. 네이버 서치어드바이저 → 사이트 등록 `https://sogaebank.com` → 「HTML 태그」 → 같은 방식으로 **`seo.verify_naver`** → 「소유 확인」 → 요청 → 사이트맵 제출 `https://sogaebank.com/sitemap.xml`
3. 확인이 끝나도 **두 값은 지우지 마십시오**(지우면 소유 확인이 풀림) · 등록 화면은 바뀔 수 있음 — 막히면 화면을 알려 주십시오

### 4-3. 올린 파일 하루 백업 등록 (대표 · ubuntu · 한 번 · 적용 확인 뒤)

```bash
date                                                   # 서버 시간대 확인(UTC 이면 아래 19:30 = 한국 04:30)
bash ~/sgb/deploy/aws/uploads-backup.sh check          # 읽기만 — 파일 수 · 크기 · 디스크 여유
bash ~/sgb/deploy/aws/uploads-backup.sh                # 첫 묶음 — 「만듦 — …uploads_YYYYMMDD.tar.gz」
crontab -e                                             # 맨 아래에 한 줄 더하고 저장
30 19 * * * bash /home/ubuntu/sgb/deploy/aws/uploads-backup.sh >/dev/null 2>&1
crontab -l | tail -2                                   # 들어갔는지
```

- 같은 디스크 안의 백업입니다(실수로 지운 파일만 되살림). 디스크 통째 보호는 **EBS 스냅샷 예약**(콘솔 · docs/273 5절)을 함께 권합니다.
- 「올린 파일이 없습니다」면 아직 올린 파일이 없는 것 — 그대로 두면 됩니다.
- 되살리기가 필요할 때: `bash ~/sgb/deploy/aws/uploads-restore.sh`(목록) · 파일 하나 `… file latest 2026/11/a.jpg`(이미 있으면 거절) · 통째로 `… extract latest`(따로 있는 폴더에 풂 · 올린 파일 폴더는 그대로) — docs/275

### 4-4. 알아 둘 것

1. 서버 오류 몰림 알림은 운영 알림으로 남습니다(메일은 SES 를 켠 뒤 하루 요약에 함께). 너무 자주 울리면 운영 화면 설정 `ops.server_error_per_10min` 을 올리고, 끄려면 0.
2. 손님이 「요청이 너무 많습니다」를 본다는 말이 있거나 「한도 걸림」이 자주 늘면 운영 화면 설정 `abuse.api_per_ip_min` 을 올리고(예: 1200), 끄려면 0 — 1분 안에 반영.
3. 주소에 `%00`(빈 글자)이 들어가면 서버 오류가 나던 결함은 v10.175 에서 「형식 오류(400)」로 고쳤습니다(알림이 헛울리지 않음).
4. **회원 투표 켜기는 대표 결정** — 운영 화면 › 소개광장 › 「이건 어때? 투표」 › 「켜기」(오픈 뒤 권함 · 켜면 회원이 만들자마자 열리고 신고 3건이면 감춰짐).
5. **정책 보고는 1 ~ 2주 모읍니다** — 「지켜보기」 「정책 보고」의 많이 걸린 출처를 알려 주시면 막는 정책 판을 만듭니다(지금은 화면을 막지 않음).
6. 「느린 응답」 알림 `SLOW_API` 가 자주 울리면 느린 주소 5곳을 알려 주십시오 · 너무 잦으면 `ops.slow_p95_ms` 를 올리고 끄려면 0.
7. **개인정보 접속기록 점검(SUPER · 매달)** — 5일 무렵 지난달을 열어 「살펴볼 것」 운영자의 조회가 업무였는지 확인 → 메모(5자 이상)를 남겨 「점검 완료」. 완료 기록은 고칠 수 없습니다. 점검 주기 · 접속기록 보관 기간은 **최신 「개인정보의 안전성 확보조치 기준」 고시 확인이 필요합니다**(지금은 월 1회 · 기록 지우지 않음 · docs/279 5절).
8. 「살펴볼 것」 기준(하루 50건)이 너무 낮거나 높으면 운영 화면 설정 `pii.review_flag_daily` 를 바꾸십시오.
9. **적용 뒤 첫 하루 요약(09:00)에 운영 알림 `ROLE_REVIEW_DUE`(2026-Q3)가 한 번 뜹니다** — 지난 분기 권한 점검 기록이 아직 없어서입니다(정상). 위험감지 › 「운영자 권한」에서 내용을 본 뒤 분기 「2026-Q3」 메모로 「점검 완료」를 남기면 다시 뜨지 않습니다(완료 기록은 고칠 수 없음).
10. 「90일 안 쓴 계정」 기준은 운영 화면 설정 `ops.role_idle_days` 로 바꿉니다. 권한 점검 주기 · 파기 기록 보관 기간은 **최신 고시 확인이 필요합니다**(docs/281 5절).

### 4-5. 운영자 2단계 인증 켜기 (대표 · 적용 확인 뒤 · 서두르지 않아도 됨)

순서 · 비상 초기화는 **docs/281 3절**이 기준입니다. 요점:

1. (ubuntu · 읽기만) `timedatectl | grep synchronized` → `System clock synchronized: yes` — 아니면 멈추고 알려 주십시오(번호가 계속 틀림).
2. SUPER 계정 → 권한 계층 › 「내 2단계 인증」 → 「2단계 인증 등록」 → 휴대폰 인증 앱(구글 OTP · Microsoft Authenticator 등)에 「설정 키 입력」 → 6자리로 등록.
3. **예비 번호 10개 내려받아 휴대폰이 아닌 곳에 보관** — 다시 볼 수 없습니다.
4. 운영 화면 설정 `admin.mfa_required` = `SUPER` → 저장(등록 안 했으면 막힘). 다른 운영자 등록이 끝나면 `ALL`.
5. 아무도 못 들어오게 되면 ubuntu 에서 `bash ~/sgb/deploy/aws/mfa-reset.sh off`(yes 확인 · 1분 안에 꺼짐).
