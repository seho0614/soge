# 210. 메일 구축 설계 (2026-10-28 · 설계만)

> 대표 「메일 구축 설계」. 기준 문서: 절차서 v1.2(docs/167) · 결정 기록 mail-ses #1 ~ #6 · 코드 v10.43(docs/92) · v10.85(docs/139) · v10.128(docs/192).
> **코드 · 마이그레이션 없음** — 4절 결정을 받은 뒤 만듭니다.

## 0. 먼저 짚을 것

**메일을 보내는 코드는 이미 거의 다 있습니다.** 남은 일의 대부분은 **사람이 AWS · 가비아에서 하는 일**(docs/167 1 ~ 8단계)과 **대표 결정 3개**입니다.
이 설계에서 새로 개발을 제안하는 것은, 사람 작업을 쉽게 하고 켠 뒤 상태를 볼 수 있게 하는 **운영 화면 하나(v10.140)** 뿐입니다.

| 이미 있는 것 | 판 | 지금 상태 |
|---|---|---|
| 메일 발송기(SES SMTP 465 · 새 패키지 없음) | v10.43 | 설정 전이라 보내지 않음 |
| 상담 신청 인증번호를 메일로 | v10.43 | 운영에서 상담 신청 닫힘(`NOTIFY_NOT_READY`) |
| 모든 알림 메일 실제 발송(3번 다시 시도 · 3일 넘은 것 닫음) | v10.85 | 스위치 `notify.email_verified` 꺼짐 |
| 비밀번호 찾기 — 30분 1회용 링크 메일 | (있음) | 메일 준비 전이라 `MAIL_NOT_READY` → 고객센터로 |
| SMTP 비밀번호를 운영 화면(외부 연동 › 연동 키)에서 | v10.128 | 비어 있음 |

## 1. 전체 구조

```
[회원 · 상담 신청자]                         [직원]
      │ 인증번호 · 알림 · 비밀번호 링크            │ 회사 메일 주고받기
      ▼                                           ▼
 소개뱅크 API ──SMTP 465──▶ Amazon SES(서울)    외부 메일함(Google Workspace 등)
  보내는 주소 no-reply@mail.sogaebank.com        help@ · admin@ · dmarc@ · 직원@sogaebank.com
      │                         │                           ▲
      │                억제 목록(반송 · 신고)          가비아 DNS: MX(@) · SPF
      ▼                         ▼
 notification_deliveries   CloudWatch 경보(반송 5% · 신고 0.1%)
 (SENT · FAILED · 까닭)
```

- 서비스 메일(`mail.` 하위 도메인)과 회사 메일(`@sogaebank.com`)을 나눠 서로의 평판에 영향을 주지 않음(docs/167 결론).
- 운영 서버에 메일 서버를 두지 않음(mail-ses #3 — EC2 25번 포트 차단 · WorkMail 지원 종료).

## 2. 빈틈 — 지금 구조로 켤 때 불편한 곳

| # | 빈틈 | 영향 |
|---|---|---|
| ① | SMTP 주소 · 사용자 이름은 아직 운영 `.env` | 사람이 서버 파일을 고치고 `pm2 restart` 해야 함(docs/167 5단계) |
| ② | 시험 발송 길이 「상담 신청 화면」뿐 · 스위치를 켜야 보내짐 | 시험하려고 켜는 순간 쌓인 회원 알림도 나가기 시작(샌드박스면 거절로 쌓임) |
| ③ | 무엇이 빠졌는지 한눈에 안 보임 | 「준비 중」이 왜인지 `.env` · 설정 · 스위치를 하나씩 봐야 함 |
| ④ | 실패 기록은 운영 DB 를 직접 봐야 함 | docs/167 8단계 「`notification_deliveries` 의 FAILED 까닭」을 담당이 서버에서 조회 |
| ⑤ | 반송 · 신고 주소를 회원 쪽에 표시하지 않음 | 지금은 SES 억제 목록으로 충분(docs/167 5절) — **이번 설계에서도 뒤로** |

## 3. 추천 개발 — v10.140 「메일」 운영 화면

**어디**: 운영 화면 › 외부 연동 › **메일**(외부 연동 표의 MAIL 줄에서 들어감) · 보기는 ADMIN · 바꾸기 · 시험 발송은 SUPER

| 칸 | 하는 일 | ①~④ |
|---|---|---|
| 준비 상태 | 주소(HOST) · 사용자 이름 · 비밀번호 · 보내는 주소 · 스위치 — 다섯 줄 ✓ / ✗ · 빠진 것은 어디서 넣는지 링크 · **「465 연결 확인」 단추**(서버가 SES 에 접속만 해 봄 · 메일 안 보냄) | ③ |
| 키 넣기 | **SMTP 사용자 이름도 연동 키로**(암호화 · 끝 4자리) · 주소는 기본값 `email-smtp.ap-northeast-2.amazonaws.com`(`.env` 에 있으면 그 값이 우선) → **`.env` 수정 · 재시작 없이** 운영 화면에서 끝 | ① |
| 시험 발송 | SUPER 가 받을 주소를 넣고 「시험 메일 보내기」 → 결과를 바로 보여 줌(보냄 · `AUTH` 자격 증명 · `REJECTED` 샌드박스/미인증 주소 · `TIMEOUT` · `NETWORK`) · **스위치가 꺼져 있어도 시험은 됨**(회원 알림은 그대로 안 나감) · 하루 20통 · 감사 기록 | ② |
| 발송 기록 | 최근 7일 보냄 · 실패 · 대기 수 · 실패 까닭별 수 · 최근 실패 50줄(받는 주소는 앞 2글자 · 도메인만) | ④ |

| 항목 | 내용 |
|---|---|
| 마이그레이션 | 1개(D136 예정) — 연동 키 이름에 `('MAIL','SMTP_USER')` 더함 · 시험 발송 하루 횟수 설정 · 지우는 문장 없음 |
| 바뀌는 코드 | `MailService.config`(사용자 이름 · 주소 기본값) · 메일 운영 API 4개(상태 · 연결 확인 · 시험 발송 · 기록) · 운영 화면 1곳 · 시험 1개 |
| 바뀌지 않는 것 | 보내는 방식(SMTP 465) · 알림 · 인증번호 · 비밀번호 찾기 · 스위치 하나로 켜는 규칙 |
| 크기 | v10.131(비율 화면)보다 조금 큼 · 점검 약 1시간 20분 |
| 절차서 | v10.140 을 운영에 올리면 docs/167 5 · 7단계가 짧아짐 → **절차서 v1.3** 으로 고침(같은 판에서) |

## 4. 대표 결정

| # | 정할 것 | 추천 | 다른 길 · 비고 |
|---|---|---|---|
| ① | 회사 메일함 서비스 | **Google Workspace**(절차서 기본안 · SPF · DKIM 안내가 표준이라 3단계가 쉬움) | 네이버웍스 · 하이웍스(국내 지원 · 결제가 편함). **요금 · 약정은 바뀔 수 있어 신청하는 날 확인 필요** |
| ② | 공용 주소 | `help@`(고객) · `admin@`(운영) · `dmarc@`(보고서) 3개 그룹 | 계정 수는 결정 #3 의 6 ~ 20개 안에서 |
| ③ | 기존 `@sogaebank.com` 메일이 있는가 | **확인 부탁** — 있으면 MX 를 바꾸는 순간 기존 메일 받기가 끊김 | 없으면 바로 진행 |
| ④ | v10.140 「메일」 운영 화면을 만들지 | **만듦** — `.env` 수정 · 재시작 없이 · 켜기 전에 시험 발송 | 만들지 않고 docs/167 그대로(사람이 `.env` · DB 조회) |

## 5. 순서 (추천대로일 때)

| 단계 | 할 일 | 누가 | 걸림 |
|---|---|---|---|
| 1 | v10.140 개발 · 점검 · 병합 · 절차서 v1.3 | Claude | 반나절 |
| 2 | 운영 적용 — docs/207(v10.138)을 아직 안 했으면 v10.140 까지 한 번에 | 사람(ubuntu) | 대표 결정 |
| 3 | SES 도메인 인증 · 억제 목록 · 경보 · 가비아 DNS(서비스 메일 1 ~ 6줄) | 사람(AWS · 가비아) | 1 ~ 2시간 + DNS 반영 |
| 4 | SMTP 자격 증명 → **운영 화면 「메일」에 사용자 이름 · 비밀번호** → 465 연결 확인 → 시험 발송 | 사람(SUPER) | 10분 |
| 5 | 샌드박스 해제 신청 → 승인 | 사람 → AWS | 보통 1일 안팎(**확인 필요**) |
| 6 | 스위치 `notify.email_verified` 켜기 → 상담 신청 · 비밀번호 찾기 열림 | 운영자 | — |
| 7 | 회사 메일함 가입 → 가비아 MX · SPF(7 · 8줄) → 공용 주소 | 사람 | 4절 ① ③ 뒤 |
| 8 | 1주 지켜보기 — 「메일」 화면 발송 기록 · SES 평판 · DMARC 보고서 → 2 ~ 4주 뒤 DMARC `p=quarantine` | 운영자 | — |

3 ~ 6(서비스 메일)과 7(회사 메일함)은 따로 진행해도 됩니다 — 서로 다른 DNS 줄입니다.

## 6. 비용 · 자원

| 항목 | 내용 |
|---|---|
| SES | 보낸 양만큼(1천 통 단위) — 하루 2천 통이면 한 달 약 6만 통 규모. **요금은 적용일 AWS 요금표로 확인 필요** |
| 회사 메일함 | 계정 수 × 월 요금 — 서비스 · 약정에 따라 다름 · **확인 필요** |
| 개발 서버 · 운영 서버 | 추가 자원 없음(SMTP 465 바깥으로 나가기만) |

## 7. 위험 · 대비

| 위험 | 대비 |
|---|---|
| 반송 · 신고가 쌓여 SES 계정 정지 | 억제 목록(반송 · 신고) · CloudWatch 경보 · 「메일」 화면 실패 기록 · 트랜잭션 메일만(광고 메일 안 보냄) |
| DNS 를 잘못 넣어 기존 메일 · 사이트가 끊김 | 넣기 전 캡처 · 호스트 이름에 도메인 중복 금지 · `@` SPF 한 줄(docs/167 3단계) |
| 자격 증명이 새어 나감 | 운영 화면 연동 키(암호화 · SUPER · 끝 4자리) · 채팅 · 메신저에 붙이지 않음 · 새면 SES 에서 지우고 다시 만듦 |
| 샌드박스 중 켜서 회원 알림이 거절로 쌓임 | v10.140 시험 발송은 스위치와 따로 · 승인 뒤에만 스위치를 켬 |
