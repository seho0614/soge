# 260. 소개몰 입점 5단계 — 결제대행사 하위가맹점 · 정산 확정 · 지급 요청 틀 (간주 모드) (v10.169 · 2026-11-01)

> 대표 결정(11/1 · decisions/mall-return-refund #15 **A 판매대금은 판매자에게 직접 귀속** — 회사는 남의 돈을 보관하지 않음 · business-entity #12) · 계획 「승인」(판 5개 중 마지막).
> 마이그레이션 **1개(D158)** · 196. 앞 판: v10.168(docs/259). **실제 결제대행사 호출 없음.**

## 1. 무엇을 하나

입점 판매자의 하위가맹점 번호를 운영이 적거나(결제대행사 화면에서 받은 번호) 결제대행사에 등록하고, 마감된 입점 정산서를 확정한 뒤 결제대행사에 「판매자 하위가맹점으로 지급」을 요청한 기록을 남긴다. **결제대행사의 하위가맹점 · 지급대행 API 는 결제대행사마다 모양이 달라 계약 전에 만들지 않는다** — 지금은 간주 모드(`assume.payment` = on)일 때만 시험 공급자가 시험 번호로 「등록됨 · 지급됨」을 남기고, 간주 모드가 꺼져 있으면 「연동 전」으로 막는다. 돈은 움직이지 않는다.

## 3. 계약 뒤 할 일 (결제대행사)

1. 하위가맹점(오픈마켓) · 지급대행 상품이 있는 결제대행사와 계약 — 판매대금이 회사 계좌를 거치지 않는지 확인(전자금융업 등록 부담)
2. 그 결제대행사의 하위가맹점 등록 · 지급대행 API 문서를 받아 `submerchant.provider.ts` 에 실공급자를 붙임(Claude)
3. 결제 승인(구매) 때 판매대금이 판매자 하위가맹점으로 가도록 결제 요청에 하위가맹점 번호를 넣는 부분(결제대행사 방식에 따라 다름)
4. 간주 모드 `assume.payment` off
