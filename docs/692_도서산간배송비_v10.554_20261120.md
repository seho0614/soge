# 692. 소개몰 도서산간 배송비 (v10.554 · 2026-11-21)

## 1. 결론
**우편번호 범위 표**(제주 · 도서 · 산간 · 그 밖)에 운영이 **추가 배송비**를 정하면, 직판 주문 때 배송지 우편번호로 찾아 직판 · 입점 판매자 주문 모두 **배송비에 자동으로 더하고** 주문서 · 내 주문에 **따로 표시**합니다. 처음에는 꺼져 있습니다(`smx.remote_ship` off). 위치: 운영 **소개몰 › 도서산간 배송비**(SB-ADM-SMX-020 · 탭 `smx-remote`).

| 항목 | 규칙 |
|---|---|
| 구역 | 이름 · 종류(JEJU · ISLAND · MOUNTAIN · OTHER) · 우편번호 처음 ~ 끝(5자리 · 둘 다 포함) · 금액 0 ~ 100,000원 · 켬/끔 · 같은 범위 두 줄 안 됨 |
| 고르기 | 켠 구역 가운데 우편번호가 드는 것 — 겹치면 **큰 금액 하나**(`fn_smx_remote_fee`) |
| 범위 | **직판 · 입점 판매자 주문 모두**(대표 11/21) — 직판은 기본 배송비 0 + 추가 몫 · 입점은 판매자 배송비 + 추가 몫 · 공동구매(b283) · 정기 배송 주문에는 아직 붙이지 않음 |
| 입점 정산 | 추가 몫은 **판매자 몫** — 주 정산 대상 보기 `v_hlt_settle_ready` 의 goods_amount 에 `remote_ship_fee` 를 더해 주 정산서(fn_hlt_settle_close)의 매출 · 지급액 · 정산 뒤 환불 · 월 정산서(b281 · 주 정산서 합)가 그대로 따라감 · **수수료는 매기지 않음**(품목 수수료 합 그대로) · **입점 판매자 기본 배송비도 판매자 몫**(11/21 대표 · 아래 「입점 기본 배송비 정산」 절) |
| 세무 | 일반 원칙(대표 11/21) — **면세 상품만 담은 주문의 추가 몫은 면세 · 과세 · 면세 섞이면 상품 금액 비율로 나눔**(`fn_smx_remote_exempt` · 설정 `smx.remote_tax_mode` RATIO · SUPER 만 TAXABLE 로 바꿈) · 쓰는 곳: 현금영수증 금액 나눔(`fn_hlt_cr_amounts`) · 직판 매출 · 환불 전표(journal.ts MALL_SALE · MALL_REFUND) |
| 주문 금액 | `hlt_orders.ship_fee` 안에 들어가고 `remote_ship_fee` · `remote_zone`(구역 이름 복사)에 따로 적음 — 금액 규칙(total = 상품 + 배송비 − 쿠폰 − 적립금 − 상품권)은 그대로 · `remote_ship_fee ≤ ship_fee` CHECK · 주문 뒤 바꾸지 못함(트리거) |
| 표시 | 주문서: 「도서산간 추가 배송비」 줄 + 합계 · 결제 단추에 더함(`GET /me/health/remote-fee` 미리보기 — 결제 금액은 주문 때 서버 값) · 주문 응답 `remoteShipFee` · 안내 문장 · 내 주문 상세 줄 |
| 처음 구역 | 제주특별자치도 63000 ~ 63644 · 3,000원 / 울릉도 · 독도 40200 ~ 40240 · 5,000원 — 금액은 대표 11/21 확정(스위치가 꺼져 있어 아직 안 붙음) |
| 고치기 | 구역을 고치거나 지워도 이미 받은 주문은 그대로(주문 때 복사) |
| 취소 · 반품 | 결제 금액째 돌려주는 기존 규칙 그대로(추가 배송비 포함) · 고객 사정 반품의 왕복 배송비 차감은 기존 규칙 |

## 5. 법무 · 세무
1. **법무 확인 끝(11/21 대표)** — 도서산간 추가 배송비(직판 · 입점) · 판매자 몫 정산.
2. **「직판 전 상품 무료 배송」 문구는 도서산간을 켤 때 고침** — 약관 배송비 조항 · 이용안내 · 상품 상세 배송비 표시(전자상거래법 표시 사항)를 `smx.remote_ship` 을 켜는 날 함께 고침.
3. **세무(일반 원칙 · 대표 11/21)** — 면세만 면세 · 섞이면 금액 비율(위 1절 · SUPER 가 설정으로 바꿈). 입점 주문의 추가 몫은 판매자 매출(판매자가 신고) · 회사 전표에는 들어가지 않음(직판 매출 전표만 DIRECT).
4. 처리방침 고칠 곳 없음 — 이미 받는 배송지 우편번호로 찾기만 하고 새 개인정보를 모으거나 밖으로 보내지 않음.
5. 처음 구역 금액은 그대로(제주 3,000 · 울릉 5,000 · 대표 11/21) — 범위는 우체국 도서산간 목록과 맞는지 켜기 전 한 번 확인.

## 7. 입점 기본 배송비 정산 (11/21 대표: 입점 기본 배송비도 판매자 정산)
1. **규칙** — 입점(TENANT · BRAND) 주문의 판매자 몫 = 상품 금액 + **기본 배송비**(배송비 `ship_fee` 가운데 도서산간 몫을 뺀 것) + 도서산간 몫. 수수료는 지금처럼 **상품 금액에만**(품목 수수료 합 그대로 · 배송비에는 매기지 않음). 직판은 그대로(상품 금액 + 도서산간 몫 · 직판 기본 배송비는 0).
2. **어디서** — D287 이 다시 만드는 정산 대상 보기 `v_hlt_settle_ready` 의 `goods_amount`(정산 대상 금액)에 더함. 칸을 따로 보임: `base_ship_fee`(기본 배송비 · 직판 0) · `remote_ship_fee`(도서산간 몫). 칸 이름 · 차례는 앞 판 그대로 두고 끝에만 더함.
3. **같은 값을 보는 곳** — 주 정산서(`fn_hlt_settle_close` · 매출 gross · 지급액 net) · 정산 항목(SALE 의 goods_amount) · **정산 뒤 환불**(정산 항목의 goods_amount − 수수료 − 수수료 부가세를 되돌림 → 배송비 몫도 함께 되돌림) · 월 정산서(b281 · 주 정산서 합) · 운영 「정산 대기 금액」(보기 합). 함수 · 서버 코드는 고치지 않음.
4. **반품 때 배송비(지금 규칙 그대로 · 바꾸지 않음)**
   - 정산 전 반품(승인 · 환불됨)은 보기에서 빠져 그 주문의 판매자 몫이 0(기본 배송비 포함).
   - 정산 뒤 반품은 판매자 몫 전부(배송비 포함)를 다음 정산에서 되돌림.
   - 고객 사정 반품의 왕복 배송비 차감(`hlt_returns.ship_deduction` · 입점은 판매자가 정한 `return_ship_fee` · 6,000원 상한)은 고객 환불에서만 빠짐. 판매자 정산에 다시 얹는 길은 아직 없음.
   - 판매자 귀책 반품(고객 부담 0)도 같은 규칙.
   - **확인 거리(대표)**: 고객 사정 반품의 차감액 · 이미 쓴 첫 배송비를 판매자에게 돌려줄지. 돌려주면 정산 항목에 반품 배송비 줄을 새로 둬야 함(다음 후보).
5. **쿠폰 · 적립금 할인**은 앞 판처럼 판매자 몫에서 빼지 않음(회사 부담).
