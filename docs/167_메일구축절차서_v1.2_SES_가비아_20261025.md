샌드박스(6단계)가 풀리기 전에는 **SES 에 미리 인증한 주소로만** 메일이 갑니다. 7단계 시험은 그 주소로 합니다. 샌드박스 중에 스위치를 켜면 회원 알림은 거절(FAILED)로 남습니다 — **6단계 승인 전에는 시험만 하고 다시 끕니다.**

### 1단계 — SES 도메인 인증

1. AWS 콘솔 오른쪽 위 지역 → **아시아 태평양(서울) ap-northeast-2**
2. Amazon SES → 「자격 증명(Identities)」 → 「자격 증명 생성」
   - 유형 **도메인** · 이름 `mail.sogaebank.com`
   - 「사용자 지정 MAIL FROM 도메인 사용」 체크 → `bounce.mail.sogaebank.com` · MX 실패 시 동작은 기본값
   - DKIM **Easy DKIM · RSA 2048 비트**
3. 만들면 나오는 **DNS 레코드 표(DKIM CNAME 3줄 · MAIL FROM MX · TXT)를 화면 그대로 저장**(캡처) → 3단계에서 씀
4. 시험용 주소 인증: 「자격 증명 생성」 → 유형 **이메일 주소** → 시험받을 내 주소 → 받은 메일의 확인 링크 누름

### 2단계 — 수신 거부 목록 · 경보 (v1.2 새로)

반송(없는 주소)이나 스팸 신고가 쌓이면 SES 가 계정을 **검토 · 일시 정지**합니다. AWS 문서 기준(적용일 재확인): 반송률 **5% 이상 검토 · 10% 이상 정지될 수 있음**, 신고율 **0.1% 이상 검토 · 0.5% 이상 정지될 수 있음**. 소개뱅크 코드는 반송 · 신고를 받아 목록에서 빼지 않으므로, SES 가 대신 막게 합니다.

1. SES → 「구성(Configuration)」 → 「억제 목록(Suppression list)」 → 「계정 수준 억제 목록」 편집 → **반송(Bounce) · 불만(Complaint) 둘 다 체크** → 저장
   - 이렇게 하면 한 번 반송 · 신고된 주소로는 SES 가 더 보내지 않습니다. SES 는 메일을 일단 받은 뒤 걸러 내므로 **앱 기록에는 `SENT` 로 남습니다**(실제로는 가지 않음) — 특정 회원에게 안 간다는 문의는 4절 「특정 회원에게만 안 감」으로 확인
   - (같은 일 · CLI · 담당만) `aws sesv2 put-account-suppression-attributes --region ap-northeast-2 --suppressed-reasons BOUNCE COMPLAINT`
2. CloudWatch → 경보 만들기 — 지표 **SES → Reputation.BounceRate ≥ 0.05**, **Reputation.ComplaintRate ≥ 0.001** · 알림은 운영 메일(SNS 주제) — CloudWatch 1 · 2단계(docs 의 경보 주제)가 있으면 같은 주제
3. 확인 칸: ☐ 억제 목록 반송 · 불만 켜짐 ☐ 경보 2개 「데이터 부족」 상태로 만들어짐(보내기 전이라 정상)

### 3단계 — 가비아 DNS

가비아 → My가비아 → 도메인 → `sogaebank.com` → **DNS 정보 → DNS 설정**. **「호스트 이름」 칸에는 `sogaebank.com` 을 빼고 적습니다.**

**넣기 전에 지금 레코드 화면을 통째로 캡처**해 두십시오(되돌릴 때 필요 · 도메인 결정 #2 원칙).

**0번(v1.4) — 지금 쓰는 메일 레코드 확인.** PC PowerShell:
```powershell
Resolve-DnsName -Type MX  sogaebank.com
Resolve-DnsName -Type TXT sogaebank.com
Resolve-DnsName -Type TXT _dmarc.sogaebank.com
Resolve-DnsName -Type TXT _dmarc.mail.sogaebank.com
```
☐ MX 값(예: `…google.com` · `…hiworks.co.kr` · `…worksmobile.com` · `…gabia.com`)으로 지금 메일 서비스를 적어 둠 ☐ `@` 의 `v=spf1` 줄 수(0 또는 1) ☐ `_dmarc.mail` 에 이미 줄이 있는지 — **있으면 6번을 새로 만들지 말고 알려 주십시오**


| # | 타입 | 호스트 | 값 | 용도 | 언제 |
|---|---|---|---|---|---|
| 1 ~ 3 | CNAME | `xxxx._domainkey.mail` (1단계 표 그대로 3줄) | `xxxx.dkim.amazonses.com` | DKIM 서명 | 지금 |
| 4 | MX | `bounce.mail` | `10 feedback-smtp.ap-northeast-2.amazonses.com` | 반송 받기(MAIL FROM) | 지금 |
| 5 | TXT | `bounce.mail` | `v=spf1 include:amazonses.com ~all` | SPF | 지금 |
| 6 | TXT | `_dmarc.mail` | `v=DMARC1; p=none; rua=mailto:dmarc@sogaebank.com` | 서비스 메일(`mail.`)만의 DMARC — 2 ~ 4주 `p=none`(보고만) → 문제없으면 `p=quarantine` | 지금 |
| ~~7~~ | ~~MX~~ | `@` | **넣지 않음 · 바꾸지 않음(v1.4)** — 지금 메일함의 값 그대로 | 회사 메일 받기 | — |
| ~~8~~ | ~~TXT~~ | `@` | **넣지 않음 · 바꾸지 않음(v1.4)** — 서비스 메일은 `bounce.mail` 의 SPF(5번)로 통과하므로 `@` SPF 에 SES 를 더할 필요 없음 | 회사 메일 SPF | — |

- ⚠ 4 · 5 는 **1단계 SES 표에 나온 값이 우선**(위는 서울 지역의 흔한 값)
- ⚠ 호스트에 `xxxx._domainkey.mail.sogaebank.com` 을 통째로 넣으면 `…sogaebank.com.sogaebank.com` 이 됩니다(10/12 www · admin 과 같은 실수)
- ⚠ `@` 의 TXT 는 **한 줄만** — SPF 가 두 줄이면 둘 다 무효가 됩니다. v1.4 에서는 `@` 에 아무것도 더하지 않으므로 0번에서 본 줄 수가 그대로여야 합니다
- ⚠ (v1.4) DMARC 를 `_dmarc`(뿌리 도메인)가 아닌 `_dmarc.mail` 에 두는 까닭 — 뿌리에 두면 나중에 `p=quarantine` 으로 올릴 때 **지금 메일함에서 보내는 직원 메일까지** 영향을 받습니다(그 서비스의 DKIM · SPF 설정을 모름). 뿌리 도메인 DMARC 는 지금 메일 서비스 안내대로 따로 정합니다
- ⚠ `dmarc@sogaebank.com` 은 지금 메일함에 만들어 둡니다(없으면 보고서만 못 받음 · 발송에는 영향 없음)
- 넣은 뒤 PC PowerShell 로 확인(반영은 수 분 ~ 수 시간):
  ```powershell
  Resolve-DnsName -Type TXT _dmarc.mail.sogaebank.com
  Resolve-DnsName -Type MX  bounce.mail.sogaebank.com
  Resolve-DnsName -Type TXT bounce.mail.sogaebank.com
  ```
  ☐ 세 줄 모두 넣은 값이 나옴 ☐ (v1.4) `Resolve-DnsName -Type MX sogaebank.com` 이 0번과 같음 — 기존 메일 그대로

### 4단계 — SES 「확인됨」

SES → 자격 증명 → `mail.sogaebank.com` — ☐ 자격 증명 상태 **확인됨(Verified)** ☐ DKIM **성공** ☐ MAIL FROM **성공**. 하루가 지나도 「보류」면 3단계 호스트 이름(중복 도메인)부터 봅니다.

### 5단계 — SMTP 자격 증명 → 운영 화면(v10.140 · SUPER) · 또는 운영 `.env`(v10.140 전 · 담당 · ubuntu)

**v10.140 부터(권장)** — 아래 1번으로 자격 증명을 만든 뒤:
1. 운영 화면 › 외부 연동 › 「연동 키」 › 메일 줄에 **SMTP 사용자 이름** · **SMTP 비밀번호** 붙여 넣고 저장(암호화 · 끝 4자리만 보임 · 바로 반영)
2. 같은 화면 아래 「메일」 — 준비 상태에서 사용자 이름 · 비밀번호 ✓ 확인(주소는 기본값 서울 SES)
3. 「연결 확인」 → 「연결됨 — email-smtp.ap-northeast-2.amazonaws.com:465」(메일은 안 보냄) — 실패면 운영 서버의 465 바깥 연결(아래 3번)
4. 아래 2 · 4번(`.env` · 재시작)은 하지 않습니다.

**v10.140 전**:

1. SES → 「SMTP 설정」 → 「SMTP 자격 증명 생성」 → IAM 사용자 이름 `ses-smtp-sogaebank` → 만들기
   - **사용자 이름 · 비밀번호는 이 화면에서 한 번만 보입니다.** CSV 를 안전한 곳에 두고 메신저 · 메일 · 채팅(Claude 포함)에 붙이지 마십시오. IAM 액세스 키와는 다른 값입니다.
2. 운영 서버 `~/sgb/.env` 에 넣기(sgbdev · Claude 는 이 파일을 보지 않습니다):
   ```
   SMTP_HOST=email-smtp.ap-northeast-2.amazonaws.com
   SMTP_PORT=465
   SMTP_USER=(CSV 의 사용자 이름)
   SMTP_PASS=(CSV 의 비밀번호)
   MAIL_FROM_NAME=소개뱅크
   ```
3. 서버에서 465 로 나갈 수 있는지(EC2 의 25번 제한은 465 와 무관):
   ```bash
   timeout 5 bash -c '</dev/tcp/email-smtp.ap-northeast-2.amazonaws.com/465' && echo OK
   ```
   ☐ `OK`
4. 다시 읽히게: `pm2 restart sgb --update-env` (적용 절차서의 이름 그대로)
5. 이 단계에서는 아직 아무것도 나가지 않습니다 — `notify.email_verified` 가 off 이기 때문(정상)

### 6단계 — 샌드박스 해제 신청

SES → 「계정 대시보드」 → 「프로덕션 액세스 요청」. 칸 예시:

| 칸 | 예시 |
|---|---|
| 메일 유형 | 트랜잭션(Transactional) |
| 웹사이트 | https://sogaebank.com |
| 사용 설명 | 회원 · 상담 신청자에게 인증번호와 거래 알림만 보냅니다. 광고 메일은 보내지 않습니다. 받는 사람은 스스로 주소를 입력한 회원 · 신청자뿐입니다. 반송 · 스팸 신고 주소는 SES 계정 수준 억제 목록으로 다시 보내지 않으며, 반송률 · 신고율은 CloudWatch 경보로 지켜봅니다. 회원은 알림 설정에서 알림 메일을 끌 수 있습니다. |
| 예상 발송량 | 하루 300 ~ 2,000통 |

- v1.1 의 「반송 · 수신 거부는 SES 알림으로 받아 목록에서 뺌」은 **코드에 없는 내용**이었습니다 — 위처럼 실제로 한 것(2단계)만 씁니다.
- ☐ 승인 메일 받음(한도 · 초당 발송 수가 적혀 옴)

### 7단계 — 시험 → 켜기 (운영자)

**v10.140 부터(권장)** — 스위치를 켜지 않고 시험합니다:
1. 사이트 설정 `notify.mail_from` = `no-reply@mail.sogaebank.com` → 「메일」 준비 상태 다섯 줄 중 스위치만 ✗
2. 「메일」 › 받을 주소(샌드박스 중이면 1단계 4번에 인증한 주소) → **「시험 메일 보내기」** → 「보냄」 · 받은편지함 도착 · 원본 보기 `spf=pass` · `dkim=pass` · `dmarc=pass`(아래 4번과 같음). 「보내지 못함 — AUTH」면 5단계 값 · 「REJECTED」면 샌드박스 · 도메인 「확인됨」
3. **6단계 승인 뒤에** `notify.email_verified = on` → 상담 신청 · 비밀번호 찾기 · 알림 메일이 열림 → 「메일」 발송 기록에 「보냄」이 쌓이는지

**v10.140 전**:

1. 운영 화면 → 사이트 설정 → `notify.mail_from` = `no-reply@mail.sogaebank.com`
2. 상담 신청 화면에서 **1단계 4번에 인증한 내 주소**로 신청 → 「준비 중」(`NOTIFY_NOT_READY`)이 맞음(스위치 off)
3. `notify.email_verified = on` → 다시 신청 → ☐ 메일이 **받은편지함**에 옴 ☐ 보낸 사람 「소개뱅크 <no-reply@mail.sogaebank.com>」 ☐ 인증번호로 확인됨
4. 받은 메일 「원본 보기」 → ☐ `spf=pass` ☐ `dkim=pass` ☐ `dmarc=pass` — 하나라도 fail 이면 **바로 off** 하고 3단계를 다시 봅니다
5. **6단계 승인 전이면 여기서 off 로 되돌립니다**(회원 알림이 거절로 쌓이지 않게). 승인 뒤 다시 on.
6. ⚠ on 으로 두면 **대기 중인 알림 메일도 보내기 시작**합니다 — 3일 넘은 알림 · 쓰지 않는 계정 · 회원이 끈 알림은 보내지 않고 닫습니다(docs/139). 오래 쌓인 알림이 한꺼번에 나가지는 않습니다.

### 8단계 — 켠 뒤 1주

| 볼 것 | 어디서 | 기준 |
|---|---|---|
| 반송률 · 신고율 | SES 계정 대시보드 「평판 지표」 | 반송 5% 미만 · 신고 0.1% 미만(가능하면 훨씬 낮게) |
| 실패 기록 | **v10.140 부터 운영 화면 › 외부 연동 › 「메일」 발송 기록**(보냄 · 실패 · 대기 · 까닭 · 최근 실패) · 그 전에는 운영 DB `notification_deliveries` 의 `FAILED` 까닭(운영 서버 · 담당) | `AUTH` 면 5단계 · `REJECTED` 가 많으면 샌드박스 · 발신 도메인 |
| DMARC 보고서 | `dmarc@` 메일함 | 2 ~ 4주 문제없으면 `_dmarc.mail` 만 `p=quarantine` 으로 |

## 4. 잘 안 될 때 확인 순서

| 증상 | 확인 순서 |
|---|---|
| 상담 신청이 계속 「준비 중」 | ① `.env` SMTP_HOST · USER · PASS ② `notify.mail_from` ③ `notify.email_verified = on` ④ `pm2 restart … --update-env` |
| `OTP_SEND_FAILED` | `pm2 logs sgb` 의 `[Mail] 보내지 못함 …` — `AUTH`(자격 증명) · `REJECTED`(샌드박스 · 인증 안 된 받는 주소 · 발신 도메인 미확인) · `TIMEOUT` · `NETWORK`(465 아웃바운드) |
| 스팸함으로 감 | 7단계 4번 결과 · 3단계 호스트 중복 · `@` SPF 두 줄 |
| 기존 회사 메일이 안 옴 · 스팸으로 감 | 3단계 0번 캡처와 지금 `@` MX · TXT 를 비교 — 다르면 캡처대로 되돌림(v1.4 는 `@` 를 건드리지 않음) |
| 특정 회원에게만 안 감(앱 기록은 `SENT`) | 그 주소가 억제 목록에 있는지(SES → 억제 목록 → 주소 검색) — 주소가 살아 있으면 목록에서 지움 |
| SES 에서 「검토 중」 메일이 옴 | 8단계 지표 · 반송 원인(오래된 주소 · 오타) — 답장 기한 안에 원인 · 조치를 회신 |

## 5. 하지 않은 것 · 다음 후보

| 무엇 | 까닭 |
|---|---|
| 반송 · 신고를 받아 회원 주소에 「받지 못함」 표시(SNS → API) | 지금은 억제 목록으로 충분 · 발송량이 늘면 코드로(SES 이벤트 → 회원 주소 표시 → 화면 안내) |
| 회사 메일함 설정(계정 · 공용 주소) | 지금 쓰는 메일함에서 그 서비스 안내대로(v1.4) |
| 광고 · 소식 메일 | 하지 않음(트랜잭션만) — 하게 되면 수신 동의 · 수신 거부 링크 · 별도 하위 도메인이 먼저 |
