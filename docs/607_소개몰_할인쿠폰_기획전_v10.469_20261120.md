# 607. 소개몰 할인 쿠폰 · 기획전 (v10.469 · 2026-11-20)

## 1. 결론
소개몰 **직판 상품** 주문에 쓰는 **할인 쿠폰**(정액 · 정률)과 상품을 묶는 **기획전**을 운영 화면에서 만들고 관리합니다. 주문서는 쿠폰 코드를 받으면 결제 금액에서 빼고(주문 total = 상품 + 배송비 − 할인), 주문이 취소 · 반품되면 **DB 가 쿠폰을 되돌립니다.** 지금은 「주문 받기」(mall.order_open)가 꺼져 있어 **운영 화면 먼저**이고, 주문서의 쿠폰 받기는 `mall.coupon`(처음 off)으로 켭니다. 위치: **소개몰 › 쿠폰 · 기획전** · SB-ADM-SAL-040 · API `/admin/health/coupons` · `/admin/health/promotions`.

| 쿠폰 칸 | 규칙 |
|---|---|
| 코드 | 영문 대문자 · 숫자 · 붙임표 4 ~ 20자(DB CHECK 와 같음 · 주문서 입력은 대문자로 바꿔 봄) · 바꾸지 못함 |
| 종류 | 정액(FIXED · 1원 ~ 1천만 원) · 정률(RATE · 1 ~ 90% · 최대 할인 선택) |
| 최소 주문 | 쿠폰이 걸린 **상품 금액**(배송비 빼고) 기준 |
| 한도 | 전체(장 · 비우면 없음) · 한 사람(처음 1번) — 되돌린 것은 셈에서 빠짐 |
| 기간 | 시작 ~ 끝(시각) · 멈춤(PAUSED)으로 잠시 끔 |
| 기획전 | 고르면 그 기획전 상품에만 할인 · 기획전이 꺼졌거나 기간 밖이면 못 씀 |
| 쓴 뒤 | 할인 모양(종류 · 금액 · 비율 · 최대 · 최소 주문 · 기획전)은 못 바꿈(409 · DB 도 막음) — 멈추고 새 쿠폰 · 이름 · 기간 · 한도 · 멈춤은 언제나 |

| 할인 셈 | |
|---|---|
| 대상 금액 | 기획전 쿠폰이면 주문 중 기획전 상품 금액 · 아니면 주문 상품 전부 |
| 정액 | min(쿠폰 금액, 대상 금액) |
| 정률 | floor(대상 금액 × 비율 ÷ 100) → 최대 할인까지 |
| 막는 것 | 배송비에는 걸지 않음 · 상품 금액을 넘지 않음 · **결제 금액은 음수가 되지 않음**(DB CHECK `hlt_orders_total_check` — `discount_amount ≤ goods_amount` · `total = goods_amount + ship_fee − discount_amount` · `total ≥ 0`) |

## 2. 직판만 — 왜
입점 판매자 정산은 주문의 **상품 금액(goods_amount)**으로 셉니다. 쿠폰을 입점 주문에 쓰면 누가 할인을 부담하는지 정해야 하므로 **직판(DIRECT) 주문에만** 씁니다(서버 · DB 둘 다 막음 · COUPON_DIRECT_ONLY). 기획전에 입점 상품을 넣을 수는 있지만 쿠폰 할인은 없습니다(화면에 「입점(쿠폰 할인 없음)」).

## 3. 쓰기 · 되돌리기
1. 주문(POST /health/orders)에 `couponCode`(선택) — `mall.coupon` on 일 때만(꺼져 있으면 422 COUPON_OFF).
2. 서버가 할인을 셈 → 주문 금액에 반영 → 품목을 넣은 뒤 **쿠폰 쓴 기록**(hlt_coupon_uses · 주문 하나에 하나) — DB 가 **쿠폰 줄을 잠그고** 기간 · 한도 · 본인 · 결제 전 · 직판 · 금액을 다시 확인(동시에 와도 한도를 넘지 않음 · 넘으면 주문째 되돌아감).
3. 주문이 **취소 · 반품**(결제 취소 · 반품 승인 · 결제 전 취소 — 모든 길)되면 DB 트리거가 쓴 기록을 **RESTORED**(사유 「주문 취소」 · 「반품」)로 — 한도에서 빠져 다시 쓸 수 있음(기간 안이면).
4. 주문의 할인 금액은 주문한 뒤 바꾸지 않습니다(DB 가 막음). 반품 환불은 지금처럼 **낸 금액 기준**(할인 뒤 금액 − 왕복 배송비)입니다.

## 4. 전표(초안 · 세무사 확인)
| 돈 흐름 | 차변 | 대변 | 언제 |
|---|---|---|---|
| MALL_SALE(그대로) | PG 받을 돈(낸 금액) | 상품 매출(과세 ÷ 1.1 · 부가세예수금) · 상품 매출(면세) | 결제 |
| **MALL_DISCOUNT**(새) | **SALES_DISC 매출할인**(할인 중 면세 몫 + 과세 몫 ÷ 1.1) | 상품 매출(면세) · 상품 매출(과세) | MALL_SALE 이 있는 쿠폰 주문 |
| **MALL_DISCOUNT_CANCEL**(새) | 위 반대 | | MALL_REFUND(취소 · 환불)가 생기면 |

- 매출 합계는 그대로이고 매출(총액)과 매출할인이 나뉘어 보입니다. **부가세는 실제 받은 금액 기준**(쿠폰 할인 = 에누리 · 공급가액에서 뺌)이라 부가세예수금은 건드리지 않습니다.
- 면세 몫: 쿠폰 할인이 있으면 MALL_SALE · MALL_REFUND 의 면세 몫을 **할인 뒤 상품 금액 비율**로 셈(면세 상품 금액 × (상품 − 할인) ÷ 상품) · 할인의 면세 몫은 면세 상품 금액 × 할인 ÷ 상품 — 둘을 더하면 면세 상품 금액(할인 없는 주문은 전과 같음).
- 계정 `SALES_DISC`(매출할인 · 403 · draft) — **계정 코드 · 부가세 처리(에누리인지 · 매출할인인지)는 세무사 확인**(회계 › 규칙 확인표로 보냄).

## 5. 설정 · 권한
| 설정 | 처음 | 뜻 |
|---|---|---|
| `mall.coupon` | off | 주문서에서 쿠폰 코드를 받음(쿠폰 만들기 · 기획전 · 할인 미리 셈은 꺼져도 됨) |
| `mall.order_open` | (그대로 off) | 주문 받기 — 꺼져 있으면 쿠폰과 상관없이 주문 안 받음 |

- 탭 `hlt-coupons` — 소개몰 탭과 같게 ADMIN · SUPER. ㉕ 권한 시드: 업무 `hlt-coupons`(소개몰 묶음) · 주소 8.
- 회원 화면(사이트 주문서)에 쿠폰 입력 칸은 **이번 판에 넣지 않음** — 주문 받기를 켤 때 같이(서버는 준비됨 · 운영 화면 「할인 미리 셈」으로 확인).
