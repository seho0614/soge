# 691. 소개몰 묶음(세트) 할인 (v10.553 · 2026-11-21)

## 1. 결론
소개몰 **직판 상품 · 옵션 여럿을 한 묶음**으로 묶어 **묶음가 하나**로 팝니다. 묶음은 재고를 따로 두지 않고, 주문하면 **구성 옵션마다 주문 품목 한 줄**이 들어가 기존 재고 트리거가 그대로 뺍니다. 구성 하나라도 품절이면 묶음도 품절이고, 취소 · 반품은 소개몰 규칙대로 **주문 통째(= 묶음 단위)** 입니다. 처음에는 꺼져 있습니다(`smx.bundle` off). 위치: 운영 **소개몰 › 묶음 할인**(SB-ADM-SMX-010 · 탭 `smx-bundles`).

| 항목 | 규칙 |
|---|---|
| 구성 | 직판(DIRECT) 상품의 옵션만 · 1 ~ 10줄 · 옵션마다 수량 1 ~ 20 · 같은 옵션 두 번 안 됨(DB 고유) |
| 판매 시작 | 구성 **두 줄 이상** · **수량 1 인 줄 하나 이상**(묶음가를 원 단위로 나눠 적는 자리) · 모두 직판 — DB 트리거 `fn_smx_bundle_guard` 가 다시 봄 |
| 판매 중 | 구성은 못 바꿈(먼저 멈춤) · 이름 · 설명 · 값 · 한 번에 살 수 있는 수(1 ~ 20 · 처음 5)는 바꿈(값은 새 주문부터) · 판매했던 묶음은 지우지 않고 멈춤 · 초안으로 못 되돌림 |
| 재고 | 만들 수 있는 수 = 구성마다 ⌊재고 ÷ 구성 수량⌋ 의 가장 작은 값(`v_hlt_bundle_stock.can_make`) — 0 이면 품절 · 판매 중 아님 · 옵션 끔도 0 |
| 주문 | `POST /health/orders` 의 `bundles: [{ code, qty }]`(선택 · 한 주문 열 가지) · 일반 품목과 함께 담을 수 있음(같은 판매자 = 직판) · **쿠폰과 함께 씀**(대표 11/21) — 쿠폰 대상 금액은 **묶음가 기준**(구성 품목의 나눈 금액 · 정가 아님) · 할인 ≤ 대상 금액 ≤ 상품 금액이라 주문 금액 규칙(`hlt_orders_total_check` · 할인 ≤ 상품 금액)을 넘지 않음 · 기획전 쿠폰은 구성 상품이 기획전에 있을 때 그 몫만 · 적립금 · 상품권은 그대로 |
| 단가 나눔 | 구성 1개당 단가 = ⌊묶음가 × 정가 ÷ Σ(정가 × 구성 수량)⌋ · 나머지 원은 수량 1 인 첫 줄에 · 구성 품목 금액 합 = 묶음가 × 수량(거래 끝에 DB 가 다시 셈 — `trg_smx_order_bundle_sum`) |
| 반품 · 취소 | 소개몰 취소 · 반품 · 교환 신청(hlt_returns)은 주문 하나 통째 — 묶음이 쪼개지지 않음 · 취소 · 반품되면 구성 옵션 재고가 기존 `fn_hlt_order_restock` 으로 한 번 되돌아감 |
| 리뷰 | 리뷰는 기존대로 품목(= 구성 상품)마다 |

## 2. 전체 구조
1. 표 `hlt_bundles`(코드 · 이름 · 설명 · 묶음가 · 상태 DRAFT → ON_SALE ⇄ STOPPED · 한 주문 최대) · `hlt_bundle_items`(옵션 · 수량 · 상품은 옵션에서 채움).
2. 보기 `v_hlt_bundle_stock`(구성 수 · 만들 수 있는 수 · 정가 합).
3. 표 `hlt_order_bundles`(주문에 담긴 묶음 — 코드 · 이름 · 묶음가 · 수량 · 정가 합 복사 · 고치지 못함) · `hlt_order_items.bundle_line_id`(구성 품목 표시 · 같은 주문만 · 못 바꿈).
4. 트리거 `trg_smx_bundle_item_guard`(직판만 · 판매 중이면 구성 못 바꿈) · `trg_smx_bundle_guard`(판매 시작 조건 · 코드 · 지우기) · `trg_smx_order_bundle_guard`(스위치 · 판매 중 · 결제 전 주문 · 묶음가 그대로) · 늦춘 확인 `trg_smx_order_bundle_sum` · `trg_smx_order_item_bundle`.
5. 서버 `src/modules/smx/bundles.ts` — 운영 목록 · 만들기 · 고치기 · 판매 시작 · 멈춤 / 공개 목록 · 하나 / 주문 흐름 `smxBundleQuote` · `smxBundleInsert`(health-checkout.service.ts 패치 3-1 ~ 3-8).
6. 운영 화면 `web/src/app/admin/Smx.tsx` 의 `SmxBundles` — 새 묶음(옵션 번호 · 수량) · 묶음가 · 정가 합 · 할인율 · 정가보다 비쌈 경고 · 만들 수 있는 수 · 판매 시작 전 막힘 까닭.
7. 회원 화면은 「주문 받기」를 켤 때(규칙 25) — 공개 API(`GET /health/bundles`)와 주문 입력은 준비됨.

## 3. API
| 방법 | 주소 | 누가 | 오류 |

| PUT | /admin/smx/bundles/{id} | ADMIN · SUPER(감사 SMX_BUNDLE_SAVE) | 404 · 409 SMX_BUNDLE_ON_SALE · SMX_BUNDLE_CODE · SMX_BUNDLE_DUP · 422 |
| POST | /admin/smx/bundles/{id}/state `{ state: ON_SALE · STOPPED }` | ADMIN · SUPER(감사 SMX_BUNDLE_STATE) | 404 · 409 SMX_BUNDLE_SAME · SMX_BUNDLE_DRAFT · 422 SMX_BUNDLE |

## 4. 설정 · 권한
- `smx.bundle` off(ADMIN 범위 · 처음 꺼짐) — 꺼져 있으면 공개 목록 `on:false` · 주문 422 · 운영 화면에서는 만들어 두기만.
- ㉕ 권한: perm_tasks `smx-bundles`(admhlt) · R_ADMIN 4 수준 · perm_route_map 4.

## 5. 세무 · 법무
1. **세무(일반 원칙 · 대표 11/21)**: 구성 품목마다 단가를 정가 비율로 나눠 품목의 과세 구분(tax_type)이 그대로 따라감 — 과세 · 면세 섞인 묶음은 금액 비율로 나뉨(현금영수증 · 전표가 품목 금액으로 셈).
2. **법무 확인 끝(11/21 대표)**: 묶음 할인 · 쿠폰 함께 쓰기 · 「정가 합 대비 할인」 표시(실제 정가 합 기준 · 운영 화면이 정가보다 비싼 묶음을 경고).
3. 처리방침 고칠 곳 없음(새 개인정보를 모으지 않음).
