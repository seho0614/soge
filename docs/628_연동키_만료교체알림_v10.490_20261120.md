# 628. 외부 연동 키 만료 · 교체 알림 (v10.490 · 2026-11-20)

## 1. 결론
외부 연동 키(결제 · 계좌 · 국세청 · 메일 · 알림톡 · 금융결제원 등 「연동 키」 목록 그대로)마다 **만료일 · 교체 주기 · 마지막 교체 · 담당 메모**를 적고, 다음 기한 **30 · 7일 전과 지난 뒤**에 운영 알림(ITS_KEY_EXPIRY)을 보냅니다. 위치: **외부 연동 › 연동 키 아래 「키 만료 · 교체」 표**(SUPER) · SB-ADM-ITS-010.
**키 값은 읽지도 보여 주지도 않습니다** — 새 표에는 값 · 끝 4자리 칸이 없고, 서버 코드는 integration_secrets 를 부르지 않습니다.

| 칸 | 뜻 |
|---|---|
| 만료일 | 업체 콘솔에 적힌 키 만료일(없으면 비움) |
| 교체 주기 | 회사 규칙으로 바꾸는 주기(7 ~ 1095일 · 예: 90) |
| 마지막 교체 | 이 화면 「연동 키」에서 넣으면 **저절로**(DB 트리거) · .env 로 쓰는 키는 「바꿨음」 단추 |
| 다음 기한 | 만료일 · (마지막 교체(없으면 줄 만든 날) + 주기) 중 이른 날 |

## 2. API (SUPER · 외부 연동이라 권한 넓히기 금지 주소 /admin/integration-keys 아래)
| 방법 | 주소 | 설명 |
|---|---|---|
| GET | /admin/integration-keys/life | 키마다 출처(화면 · .env · 없음) · 만료일 · 주기 · 마지막 교체 · 다음 기한 · 남은 날 · 단계(OVER · SOON · OK · UNSET) |
| PUT | /admin/integration-keys/life/{code}/{name} | expiresOn · rotateDays · ownerNote — 보낸 칸만(null = 비움) · 저장 뒤 알림 다시 셈 · 감사 ITS_KEY_LIFE_SET |
| POST | /admin/integration-keys/life/{code}/{name}/rotated | 화면 밖에서 바꾼 키 「바꿨음」 + 새 만료일(선택) · 감사 ITS_KEY_ROTATED |

오류: 404(없는 키 이름) · 400(주기 7 미만 등 형식) · 422 ITS_KEY_DATE · ITS_KEY_CYCLE · ITS_KEY_NOTE.

## 3. 표 · 트리거 · 설정 · 정기 작업 (D270)
- its_key_life(연동 코드 · 키 이름 PK · expires_on · rotate_days · rotated_at · rotate_source ADMIN_KEY · MANUAL · owner_note) — **값 칸 없음**.
- its_key_events — ROTATED · MANUAL_ROTATED · LIFE_SET · 날짜 · 메모만 · 쌓기만.
- trg_its_key_rotated(integration_secrets AFTER INSERT OR UPDATE OF value_enc) — NEW.integration_code · NEW.name · NEW.updated_by 만 씀 · 만료일을 비움(새 키의 만료일을 다시 적음) · 실패해도 키 저장은 그대로(경고만).
- 보기(VIEW)를 만들지 않음 → MAP-2 v_secret_leak 0 그대로 · 외부 연동 줄 15 그대로.
- 설정 its.key_alert(on) · its.key_alert_days(30,7) · 정기 작업 its_key_expiry 매일 08:40 · 운영 알림 ITS_KEY_EXPIRY(키 · 기한 · 단계마다 한 번 · 지남은 CRITICAL · 기한이 바뀌거나 꺼지면 풀림).

## 4. 주의
1. 같은 키를 다시 저장해도 「교체함」으로 셉니다(암호문이 매번 달라 값이 같은지 알 수 없음 — 값을 비교하지 않는 것이 원칙).
2. 담당 메모에 키 값을 적지 마십시오(200자 · 화면에 그대로 보임).
3. 업체마다 만료 정책이 다릅니다(토스 · 금융결제원 사용자 토큰 90일 등) — **업체 콘솔에서 확인 필요**. 이 기능은 사람이 적은 날짜로만 셉니다.
