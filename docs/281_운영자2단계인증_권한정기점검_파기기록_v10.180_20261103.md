# 281. 운영자 2단계 인증 · 운영자 권한 정기 점검 · 파기 실행 기록 (v10.180 · 2026-11-03)

> 대표 「다음 개발」 → 「모두」 → 계획 「승인」(11/3). 운영 화면을 지키는 수단이 허용 IP · 비밀번호뿐이던 것을 보강하고, 권한 · 파기를 정기적으로 확인할 화면을 둡니다.
> **2단계 인증은 꺼진 채(`admin.mfa_required` off)로 들어갑니다.** 켜기는 대표가 3절 순서대로.

## 1. 무엇을 하나

| # | 부분 | 내용 |
|---|---|---|
| 1 | **운영자 2단계 인증**(SB-ADM-MFA-010 · 권한 계층 › 내 2단계 인증) | 휴대폰 인증 앱(구글 OTP · Microsoft Authenticator 등)의 **6자리 번호**(TOTP · RFC 6238 · 30초)를 비밀번호 다음에 한 번 더. 로그인(비밀번호)은 그대로이고, 운영 화면이 번호를 받으면 「2단계 확인됨」이 붙은 새 증표를 줌 — `admin.mfa_hours`(12시간) 동안 다시 묻지 않음 · refresh 로 다시 받아도 이어짐. 설정이 켜져 있으면 **운영 역할만 요구하는 API** 는 확인 전 `403 MFA_REQUIRED`(회원 기능은 그대로). 등록 때 **예비 번호 10개**(한 번씩 · 그때만 보임 · 내려받기). 5번 틀리면 15분 잠금. 같은 번호 두 번 못 씀. 외부 서비스 · 새 패키지 없이 서버 안에서 계산 · 비밀값은 DB 에 암호화(`fn_enc_key`) |
| 2 | **운영자 권한 정기 점검**(SB-ADM-ROLE-010 · 위험감지 › 운영자 권한 · **SUPER 만**) | 운영 역할(검수 · 운영 · 지급 · 최고)이 있는 계정마다 역할 · 받은 날 · 마지막 로그인 · 2단계 등록. `ops.role_idle_days`(90)일 넘게 로그인하지 않은 계정은 **「정지 권함」**(표시만 · 자동 정지 없음). 최근 권한 변경 50건(`role_changes`). 분기마다 메모로 **「점검 완료」**(`audit.role_reviews` · 분기 한 줄 · 고칠 수 없음 · 그때 요약 함께). 분기 **15일째부터** 지난 분기 점검이 없으면 하루 요약 때 운영 알림 **`ROLE_REVIEW_DUE`**(그 분기 한 번) |
| 3 | **파기 실행 기록**(SB-ADM-PRG-010 · 위험감지 › 파기 기록) | 매일 03:00 개인정보 파기 작업(`pii_purge`)이 지운 건수(탈퇴 계정 · IP 가리기 · 리드 연락처 · 상담 신청 · 인증 기록 · 기한 넘김)를 날짜별 · 달별로(`job_runs` 그대로 · **건수만**). 하루 요약 때 마지막 실행이 실패면 **`PII_PURGE_FAILED`**(CRITICAL · 실행마다 한 번) · 30시간 넘게 돌지 않았으면 **`PII_PURGE_MISSED`**(하루 한 번) |

## 3. 운영에서 (v10.180 적용 뒤 · 대표)

### 3-1. 2단계 인증 켜는 순서

1. SUPER 계정으로 운영 화면 › 권한 계층 › **「내 2단계 인증」 → 「2단계 인증 등록」** → 휴대폰 인증 앱에 키를 넣고(「설정 키 입력」 · 시간 기준) 6자리 번호로 등록.
2. 나온 **예비 번호 10개를 내려받아 휴대폰이 아닌 곳에 보관**(종이 · 금고 · 비밀번호 관리 프로그램). 다시 볼 수 없습니다.
3. 운영 화면 설정 **`admin.mfa_required` = `SUPER`** → 저장(등록 안 했으면 422 로 막힘). 다음 운영 API 부터 번호를 묻습니다.
4. 다른 운영자(ADMIN · REVIEWER · PAYOUT)도 각자 「내 2단계 인증」 등록을 마치면 **`ALL`**. 등록 안 한 운영자는 로그인 뒤 등록 화면이 먼저 나옵니다.
5. 하루 한 번 묻는 것이 번거로우면 `admin.mfa_hours`(1 ~ 24)를 조정.

### 3-2. 휴대폰을 잃어버리거나 바꿨을 때

| 상황 | 할 일 |
|---|---|
| 예비 번호가 있음 | 번호 칸에 예비 번호(12345-67890)를 넣고 들어온 뒤, 다른 SUPER 에게 초기화를 요청 → 다시 등록 |
| 다른 SUPER 가 있음 | 그 SUPER 가 회원 상세 › 「2단계 초기화」(사유 · 본인 확인 뒤) → 다음 로그인 때 다시 등록 |
| 아무도 못 들어옴 | 3-3 서버 비상 초기화 |

### 3-3. 서버 비상 초기화 (ubuntu · 사람이)

```bash
bash ~/sgb/deploy/aws/mfa-reset.sh                    # 등록한 계정 목록 · 지금 설정(읽기만)
bash ~/sgb/deploy/aws/mfa-reset.sh 대표이메일@도메인     # 그 계정 등록을 지움(yes 확인) → 다음 로그인 때 다시 등록
bash ~/sgb/deploy/aws/mfa-reset.sh off                # 또는 설정을 off 로(yes 확인 · 1분 안에 반영)
```

한 일은 감사 기록 `MFA_RESET_SERVER` · `MFA_OFF_SERVER` 로 남습니다.

### 3-4. 정기 점검

1. **분기마다**(1 · 4 · 7 · 10월 15일 무렵) 위험감지 › 「운영자 권한」 — 「정지 권함」 · 2단계 미등록 · 최근 권한 변경을 보고 필요하면 회원 상세에서 정지 · 권한 회수(사유) → 메모로 「점검 완료」.
2. **수시로** 위험감지 › 「파기 기록」 — 실패 · 「30시간 넘게 돌지 않음」 · 「기한 넘긴 건」이 보이면 알려 주십시오.

## 4. 넣지 않은 것

| 무엇 | 까닭 |
|---|---|
| QR 코드 그림 | 외부 QR 서비스는 쓰지 않고, 그림 라이브러리를 더하면 운영 적용 때 설치가 늘어남 — 키 글자 · 「앱에서 열기」 주소로 등록(인증 앱 모두 지원) |
| 회원 2단계 인증 | 이번에는 운영자만. 회원은 본인인증 · 로그인 잠금이 있음 |
| 오래 안 쓴 운영자 자동 정지 | 표시만 — 정지는 사람이 사유를 남겨(실수로 운영자를 막지 않게) |
| 문자 · 메일 인증번호 | 외부 연동(알림톡 · 메일) 미완 · 비용 — 인증 앱만 |

## 5. 확인이 필요한 것

| 무엇 | 까닭 |
|---|---|
| 법이 정한 기준 | 「개인정보의 안전성 확보조치 기준」의 **2단계(안전한) 인증 의무 범위 · 접근 권한 점검 주기 · 권한 변경 기록 보관 기간 · 파기 기록 보관** 은 **최신 고시로 확인이 필요합니다**. 이번에는 「운영자 2단계 선택 → 켜기 권함 · 권한 분기 점검 · 기록 지우지 않음」으로 만들었습니다 |

| 휴대폰 앱 화면 | 앱마다 메뉴 이름이 다를 수 있음(「설정 키 입력」 · 「키 입력」 · 「Enter a setup key」) |
