# 622. 운영자 패스키(WebAuthn) (v10.484 · 2026-11-20)

## 1. 결론
운영 역할 계정이 **패스키**(지문 · 얼굴 · 보안 키 — WebAuthn · FIDO2)를 등록하고, 로그인 뒤 확인 단계에서 씁니다. **처음 꺼짐(admin.passkey off)**. 방식은 SUPER 가 고릅니다 — **EXTRA(처음 · 추가 확인)**: 비밀번호 · 2단계 인증 뒤 **한 번 더**(패스키를 등록한 사람만) / **REPLACE_MFA**: 패스키 확인이 **2단계 인증(인증 앱 번호)을 대신**함. **새 npm 패키지 없음** — Node 내장 crypto 만 씁니다(2절). 위치: **권한 계층 › 내 2단계 인증** 화면 아래 「패스키」 구역 · 로그인 뒤 「패스키로 확인」 화면 · SB-ADM-SCU-020 · API `/auth/passkey/*` · SUPER `/admin/passkeys*`.

| 설정 | 처음 | 뜻 |
|---|---|---|
| `admin.passkey` | off | 등록 · 확인 켬(켜려면 도메인이 있어야) |
| `admin.passkey_mode` | EXTRA | EXTRA = 추가 확인 / REPLACE_MFA = 2단계 인증 대신(세무사 포함) |
| `admin.passkey_rp_id` | (빔) | 패스키를 묶을 도메인 — 운영은 운영 화면 주소의 도메인(예 `sogaebank.com` — 하위 도메인 admin.… 도 됨) · 점검판 `localhost` · **비면 NOT_READY** · 바꾸면 그 전 패스키는 쓸 수 없음 |
| `admin.mfa_hours`(그대로) | 12 | 패스키 확인 유효 시간(2단계 인증과 같음) |

| 흐름 | 누가 | 내용 |
|---|---|---|
| 등록 | 운영 역할 본인 | 「패스키 등록」(이름 · 예: 사무실 노트북 지문) → 브라우저가 기기 확인(지문 · PIN) → 저장. **2단계 · 접속 인증 · (EXTRA 이고 이미 있으면) 패스키 확인을 마친 증표로만**(훔친 비밀번호만으로 패스키를 붙이지 못하게) · 한 사람 10개 |
| 확인(EXTRA) | 패스키를 등록한 운영자 | 로그인 → 2단계 → 접속 인증 → **「패스키로 확인」** → 이 로그인 기기(login_sessions.passkey_at)가 12시간 확인됨 · 안 하면 운영 API 403 **PASSKEY_REQUIRED** |
| 확인(REPLACE_MFA) | 패스키를 등록한 운영자 | 로그인 → 「패스키로 확인」(또는 「인증 앱 번호로」) → **2단계 확인된 증표(ma)** |
| 끄기 | 본인 · SUPER | 기기 분실 · 바꿈 — 본인은 끝까지 확인한 증표로 · 잃어버렸으면 SUPER 가 「끄기」(사유 5자 이상) · 지우지 않음(revoked_at) |

## 2. 확인 방법(코드 `src/modules/identity/passkey.ts` · 새 npm 없음)
- **등록** — 브라우저 `response.getPublicKey()`(SPKI DER) · `getPublicKeyAlgorithm()` · `getAuthenticatorData()` 를 받음 → CBOR(attestationObject)을 읽지 않음. 확인: clientDataJSON(type `webauthn.create` · 문제 · **출처**) · authenticatorData(**도메인 지문 sha256(rp_id)** · UP · **UV**(지문 · PIN) · AT · 자격 번호 = rawId) · 공개 키가 알고리즘과 맞는지(ES256 P-256 · EdDSA Ed25519 · RS256 2048 비트 이상).
- **증명(attestation)은 `none`** — 기기 제조사를 확인하지 않음(운영자 본인 기기 · 일반 웹 서비스와 같은 수준).
- **확인** — `navigator.credentials.get` → authenticatorData · clientDataJSON · signature → 문제(5분 · 한 번 · 지문만 저장) · 출처 · 도메인 지문 · UP · UV · **서명**(authData ‖ sha256(clientDataJSON) · Node `crypto.verify`) · **서명 횟수**(줄거나 같으면 복제 의심 → 403 + 운영 알림 **PASSKEY_CLONE_SUSPECT** · 둘 다 0 인 기기(동기화 패스키)는 통과).
- 출처: `https://{도메인}` 또는 그 하위 도메인(https 만) · 점검판 localhost 는 http 도. 다른 사이트 안(crossOrigin)은 받지 않음.
- `getPublicKey` 가 없는 옛 브라우저는 등록할 수 없음(최근 크롬 · 엣지 · 사파리 · 파이어폭스는 됨) — 확인은 모든 WebAuthn 브라우저.
- **npm 판단**: `@simplewebauthn/server` 를 쓰지 않음 — 위 방식으로 CBOR · COSE 를 직접 읽지 않아도 돼서(서버 npm install 없이 · package-lock 그대로). 증명 확인(제조사)이 필요해지면 그때 패키지로.

## 3. 판단
1. **비밀번호 없이 로그인하지 않음** — 로그인은 늘 비밀번호(로그인 잠금 · 요청 제한 · 해외 접속 판정 · 낯선 로그인 알림을 한 길로). 패스키는 확인 단계에서만.
2. **처음 방식 EXTRA** — 패스키는 2단계 인증을 대신하지 않음(대표 계약 「기본은 추가 확인」). REPLACE_MFA 는 SUPER 가 켬 — 인증 앱 번호보다 피싱에 강한 수단이라 대신해도 보안이 낮아지지 않음.
3. EXTRA 는 **패스키를 등록한 사람만** 확인을 요구 — 켜도 아무도 잠기지 않음(등록 안 한 운영자는 지금처럼).
4. 확인한 것은 증표가 아니라 **로그인 기기 줄(login_sessions.passkey_at)** 에 둠 — 증표 모양(JWT)을 바꾸지 않음 · v10.380 전 증표(sid 없음)는 다시 로그인해야(409 PASSKEY_NO_SESSION).
5. 설정은 서버 메모리에 30초(다른 서버 프로세스는 30초 안에 따라옴 · 바꾼 프로세스는 바로).

## 4. 켜는 순서(운영 · 대표 승인 뒤)
1. SUPER 가 「내 2단계 인증 › 패스키 설정」에서 도메인(`sogaebank.com`) → 켜기(방식 EXTRA 그대로) → 2. 운영자마다 패스키 등록 → 3. 익숙해지면(원하면) REPLACE_MFA.
- 아무도 들어오지 못할 때: 서버에서 `admin.passkey` off(설정 · 30초) 또는 SUPER 가 그 사람 패스키 「끄기」.
