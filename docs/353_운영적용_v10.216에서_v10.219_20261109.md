### 4-2. 알아 둘 것

1. **포인트 출금은 적용 순간부터 신청을 받습니다**(원천징수율 3.3 이 들어 있음). 신청에는 본인인증 · 확인된 본인 계좌 · 현금화 가능 포인트 10,000 이상이 필요합니다. 운영 화면에 신청을 잠시 막는 스위치는 없습니다. **돈은 ADMIN 확정 → 다른 사람(PAYOUT) 지급 기록을 거쳐야만 나갑니다** — 법무 · 세무 재확인 전에는 들어온 신청을 확정하지 말고 반려(사유)하십시오.
2. **법무 재확인 필요** — 11/9 법무 「이상 없음」은 현금 지급이 없는 전제였습니다. 현금 지급 · 3.3%(사업소득 · 과세최저한 처리)는 세무 확인이 필요합니다.
3. **주민등록번호 받기는 꺼진 채** — 처리방침에 「주민등록번호(암호화)」 수집 줄을 넣어 **게시한 뒤에만** SUPER 가 켤 수 있습니다(그 전에는 운영 화면이 막음 · TAX_ID_PRIVACY_FIRST). 그 전에 지급한 건은 신고 자료에 주민등록번호 칸이 비어 나옵니다. 5년 보관 근거는 법무 확인이 필요합니다.
4. 추천 보상 규칙 `REFERRAL_DIRECT` 는 꺼진 채입니다 — 켜기 전에 가입자가 인증한 경우는 나중에 켜도 보상이 없습니다.
5. 개발 서버 `~/kits/release` 에 다른 판 킷(v10.216 · v10.217 · v10.218)이 있어도 **v10.219 킷만** 올립니다.

## 5. 되돌리기

| 상황 | 할 일 |
|---|---|
| 화면이 이상함 | `bash ~/sgb/deploy/aws/rollback.sh` → `yes` — 코드만 v10.216 으로 돌아갑니다. DB 는 228 그대로 남지만 더한 것만 있어(표 · 칸 · 설정) v10.216 코드가 그대로 돕니다. 단 포인트 출금 · 추천 화면은 사라지고, 이미 들어온 출금 신청은 DB 에 남습니다 |
| 되돌린 뒤 다시 v10.219 로 | `bash ~/sgb/deploy/aws/rollback.sh` 를 한 번 더 → `yes`(v10.219 판 폴더가 남아 있음) |
| DB 까지 | 보통 필요 없습니다. 하려면 RDS → `sgb-before-v10-219-YYYYMMDD` 복원 → `.env` 접속 주소 교체 → `pm2 restart sgb sgb-site sgb-jobs` 순서로 합니다. 스냅샷 뒤에 생긴 자료(가입 · 출금 신청 등)는 사라집니다 |

## 6. 하지 말 것

- 법무 · 세무 재확인 전 포인트 출금 「확정」 · 「지급」
- 처리방침 게시 전 「주민등록번호 받기」 켜기(막히지만 시도하지 않음)
- 적용 확인 중 약관 편집 칸 「저장」 · 「게시」 확인 창에서 「확인」
- 결제대행사 연결 전 「주문 받기 켜기」
- 운영에서 `verify` · `attack` · `db:seed` · `open-prep.sh apply`
- 목록을 보기 전 `cleanup.sh --apply`
- 실패가 없는데 `pm2 restart`
