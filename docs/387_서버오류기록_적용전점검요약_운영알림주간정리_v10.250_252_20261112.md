# 387. 서버 오류 30일 기록 · 적용 전 점검 요약 · 운영 알림 주간 정리 — v10.250 ~ v10.252 (2026-11-12)

> 대표 「다음개발」 → 후보 3가지 「모두」 → 계획 「승인 + 통과하면 병합」(11/12). v10.247 ~ 249(docs/386) 위에 만듦.
> **마이그레이션 D204 하나(241 → 242)** — 표 하나 더함 · 지우는 것 없음 · 스위치 · 설정 값을 바꾸지 않음 · **적용 스크립트(apply · precheck · postcheck · rollback) 바뀌지 않음** · 사용자 웹 바뀌지 않음.

## 1. 왜

「최근 서버 오류」는 API 기억에 1시간만 있어 운영 적용 · 다시 띄우기 때마다 사라졌습니다. 적용 전 점검(precheck) 결과는 터미널에서 복사해야만 볼 수 있었고, 운영 알림은 지난 한 주에 무엇이 몇 번 났는지 한눈에 볼 곳이 없었습니다.

## 2. 바뀐 것

| 판 | 곳 | 내용 |
|---|---|---|
| v10.250 | 정기 작업 `launch_watch`(10분) · 운영 화면 「서버 오류」 · 하루 요약 | 5xx 오류를 **날짜(한국) · 방법 · 주소 · 오류 종류 · 응답 번호마다 건수**로 `ops_server_error_days`(D204)에 더함 — 마지막 시각 · 가린 설명 · 요청 번호는 가장 최근 것 · **30일 지난 줄은 지움** · 요청 내용 · 개인정보 없음. 「서버 오류」 화면 아래 **「최근 7일」**(날짜별 건수 · 많이 난 것 20줄) · 하루 요약 「어제 서버 오류 n건 · 많이 난 곳 …」 |

### 알아 둘 것

1. API 가 다시 뜰 때 **아직 DB 에 넣지 않은 몫(최대 10분)** 은 빠집니다 — 「지난 1시간」 목록은 전처럼 다시 띄우면 비워집니다.
2. 같은 날 · 같은 주소 · 같은 종류는 한 줄에 건수만 늘어납니다(설명 · 요청 번호는 가장 최근 것).
3. precheck 요약은 파일을 읽기만 합니다 — precheck 를 돌리지 않았거나 `cleanup.sh` 가 지웠으면 「결과 파일 없음」. 중간에 멈춘 파일(마지막 「적용 전 점검 — 통과 …」 줄이 없음)도 「없음」으로 보입니다.
4. 결과 파일 시각은 **운영 서버 시각**(파일 이름)입니다.
