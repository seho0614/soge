# 733. 유출 비밀번호 막기 (v10.591 · 2026-11-21)

> 15차 보안 · 기반 ⑦. 어댑터 + 스위치(처음 off) + 간주(ASSUME). **법무 확인 · 처리방침 1.2 문구 게시 뒤 LIVE.**

## 1. 결론

- 가입 · 비밀번호 재설정 · 변경 · 간편 가입 첫 비밀번호에서, 새 비밀번호가 **다른 곳에서 새어 나간 비밀번호 목록**에 있으면 422 `PWNED_PASSWORD` 로 막습니다(강도 검사 바로 뒤).
- **비밀번호 원문 · 전체 해시는 밖으로 보내지 않습니다**(k-익명 범위 조회).
- 처음 `off`. 점검판 · 시험은 `ASSUME`(서버 안 짧은 목록 · 밖으로 아무것도 안 보냄)까지만.
- 조회가 실패하면(3초 넘김 · 업체 오류) **막지 않고** 건수에 ERROR 만 남깁니다(가입 · 재설정이 멈추지 않게).

## 2. k-익명 범위 조회 — 무엇이 밖으로 나가나

| 단계 | 어디서 | 무엇 |
|---|---|---|
| 1 | 우리 서버 | SHA-1(비밀번호) → 대문자 16진 40글자 |
| 2 | 우리 → 조회 서비스 | **앞 5글자만**(예 `21BD1`) — `GET https://api.pwnedpasswords.com/range/21BD1` · 머리글 `Add-Padding: true`(답 크기로도 짐작 못 하게) |
| 3 | 조회 서비스 → 우리 | 같은 앞 5글자를 가진 수백 개 「뒤 35글자:번수」 목록(덧댄 가짜 줄은 번수 0) |
| 4 | 우리 서버 | 뒤 35글자를 목록과 견줌 → 번수 ≥ `sec2.pwned_min`(처음 1)이면 막음 |

- 조회 서비스는 **앞 5글자 하나에 수백 개 비밀번호가 묶여** 어느 것을 찾는지 모릅니다. 키 · 계정 · 이메일 · IP 를 보내지 않습니다(우리 서버 IP 와 앞 5글자만 보임).
- 업체: Have I Been Pwned 「Pwned Passwords」 범위 API(무료 · 키 없음 · 해외). 바꾸려면 `SEC2_PWNED_RANGE_URL` 한 곳.

## 3. 방식 · 설정

| 키 | 처음 | 값 | 뜻 |
|---|---|---|---|
| `sec2.pwned_check` | off | off · ASSUME · LIVE | 방식 |
| `sec2.pwned_min` | 1 | 1 ~ 9999 | 이 번 이상 나온 것만 막음 |
| `sec2.pwned_legal_ok` | off | on · off | 법무 확인 — off 면 LIVE 로 못 바꿈(422 SEC2_PWNED_LEGAL) · 직접 DB 로 LIVE 를 넣어도 서버가 ASSUME 으로 봄 |

- ASSUME 목록(서버 안 · SHA-1 로만 둠 · 강도 규칙은 통과하지만 흔한 것): `Password123!` · `P@ssw0rd123` · `Qwerty123!@#` · `Admin1234!@` · `1q2w3e4r!@#$` · `Passw0rd!23` · `Welcome123!` · `Sogaebank1!` · `Abcd1234!@#$` · `Iloveyou123!`.
- 기록 `sec2_pwned_log` — 어디서(SIGNUP · RESET · CHANGE · SOCIAL_PW · TEST) · 방식 · 결과(PASS · BLOCK · ERROR)만. **비밀번호 · 해시 · 계정 · IP 없음** · 400일 뒤 지움.

## 4. 고친 곳(재사용)

| 곳 | 패치 |
|---|---|
| 가입 `AuthService.signup` | `assertStrongPassword` 뒤 `sec2AssertNotPwned(…, 'SIGNUP')` |
| 재설정 `AccountSecurityService.reset` | 강도 검사 뒤(링크 증표를 쓰기 전 — 막혀도 링크는 그대로) |
| 변경 `AccountSecurityService.change` | 지금 비밀번호 확인 뒤(남의 비밀번호로 판정 도구처럼 쓰지 못하게) · 운영자 비밀번호 정책(12자 · 최근 3개) 앞 |
| 간편 가입 첫 비밀번호 `SocialAuthService.createPassword` | 강도 검사 뒤 |

운영 화면 위험감지 › 이상 행동 감지 › 설정 · 「판정 시험」(SUPER · `POST /admin/sec2/pwned/test` · 비밀번호 저장 안 함 · 건수만 TEST).

## 5. 처리방침 1.2 에 더할 문장(초안 — docs/699 3-8 제9조 안전 조치 아래 · 3-6 제6조 국외 이전 표)

> **제9조(안전 조치)** — 새 비밀번호를 정할 때, 다른 서비스에서 새어 나간 비밀번호 목록에 있는지 확인합니다. 이때 비밀번호 자체나 비밀번호 전체를 바꾼 값은 보내지 않고, 비밀번호를 바꾼 값(SHA-1)의 **앞 5글자만** 확인 서비스에 보내 같은 앞 글자를 가진 목록을 받아 회사 서버 안에서 견줍니다. 회원을 알아볼 수 있는 정보(이메일 · 계정 · 접속 IP)는 보내지 않습니다.

> **제6조(국외 이전) 표 한 줄 — 법무 판단에 따라**: 이전받는 자 Have I Been Pwned(Pwned Passwords — 운영 법인 이름 · 나라 · 서버 위치는 게시 전 추가 확인 필요) · 항목: 비밀번호 해시값 앞 5글자(개인을 알아볼 수 없음) · 목적: 유출 비밀번호 확인 · 방법: 새 비밀번호를 정할 때 인터넷 조회 · 보유: 보관하지 않음(조회만).
> (앞 5글자는 개인정보가 아니라고 볼 여지가 커 국외 이전 표에 넣지 않아도 된다는 의견이 가능 — 법무 판단)

## 6. 법무에 물을 것

1. 해시 앞 5글자(개인 식별 불가)를 해외 조회 서비스로 보내는 것이 개인정보 국외 이전 · 처리 위탁에 해당하는가 — 해당하지 않으면 제9조 문장만으로 충분한가.
2. 막힌 경우 안내 문구(「다른 곳에서 새어 나간 목록에 있습니다」)가 회원에게 오해(소개뱅크에서 새었다)를 주지 않는가.
3. 조회 실패 때 막지 않는 것(가용성 우선)이 안전성 확보 조치 기준에 맞는가.

## 7. 시험 (test_v1591)

① 코드 — 앞 5글자만 보냄 · Add-Padding · 원문 · 전체 해시를 바깥 호출에 넣지 않음 · 네 곳 패치 · 설정 무늬 · 문서 733 · 처리방침 문장

(두 번 돌아도 통과 — 시험 계정 · 설정은 시작 · 끝에 되돌림)

## 8. 켜는 순서

1. ASSUME 으로 하루 — 건수 BLOCK 이 이상하게 많지 않은지.
2. 법무 확인 · 처리방침 1.2 게시 → `sec2.pwned_legal_ok` on → `sec2.pwned_check` LIVE(SUPER).
3. 운영 서버에서 `api.pwnedpasswords.com`(443) 나가는 길이 열려 있는지(보안 그룹 · 방화벽) 확인 — 막혀 있으면 모두 ERROR(막지 않음).
