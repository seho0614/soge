# 617. 소개몰 적립금 (v10.479 · 2026-11-20)

## 1. 결론
소개몰 **직판 상품** 주문을 **구매확정**하면 DB 가 적립금을 쌓고, 다음 직판 주문에서 결제 금액 대신 씁니다. 취소 · 반품되면 쓴 적립금은 **DB 가 되돌리고**, 구매확정 뒤 반품이면 그 주문으로 쌓인 적립금을 회수합니다. 유효 기간이 지나면 매일 00:20 소멸하고, 30일 전에 회원에게 알립니다. 지금은 「주문 받기」(mall.order_open)가 꺼져 있어 **운영 화면 · 서버 준비까지**이고, 적립금 자체도 `mall.points`(처음 off)로 켭니다. 위치: **소개몰 › 적립금** · SB-ADM-MBS-010 · API `/admin/health/points` · 회원 `/me/health/benefits`.

★ **회원 포인트(D190 · point_ledger · 현금화 출금)와 다른 장부**입니다. 소개몰 적립금은 현금으로 바꾸지 않고, 직판 주문에만 씁니다(표 이름 `hlt_point_*`).

| 항목 | 규칙(처음 값 · 운영이 고침) |
|---|---|
| 적립 때 | 주문이 구매확정(CONFIRMED)될 때 — 구매자 확정 · 자동 확정 모두(DB 트리거 `trg_hlt_benefit_on_status`) · 주문 하나에 한 번 |
| 적립 금액 | floor((상품 − 쿠폰 할인 − 적립금 사용) × 적립률 ÷ 100) — 상품권으로 낸 몫은 결제로 보고 적립 · 배송비 제외 |
| 적립률 | `mall.points_rate` 1% · 회원 등급(`mall.tiers`)이 켜져 있으면 **등급 적립률**(618) |
| 유효 기간 | `mall.points_valid_days` 365일(30 ~ 1825) · 묶음(lot)마다 소멸 시각 |
| 쓰기 | 주문서 `usePoints` · `mall.points_min_use` 1,000원 이상 · **결제 금액 1원은 남김**(결제 금액 > 0 · `hlt_pay_amount_check`) · 소멸이 가까운 묶음부터 |
| 직판만 | 입점 판매자 정산이 상품 금액 기준이라 직판(DIRECT) 주문만(서버 · DB 둘 다 · HLT_BENEFIT_DIRECT_ONLY) |
| 음수 없음 | 묶음 남은 금액 ≥ 0 · ≤ 금액(CHECK) · 기록 금액은 늘 양수(종류가 방향) · 주문 total ≥ 0 |

## 2. 주문 금액 차례 (앞 묶음 ㉝ 쿠폰에 기댐)
1. 상품 + 배송비(직판 0)
2. **㉝ 쿠폰 할인**(`discount_amount`)
3. **적립금**(`point_amount`)
4. **상품권**(`gift_amount` · 620)
5. 남은 금액(최소 1원)을 결제 — DB CHECK `hlt_orders_total_check`: `total = goods_amount + ship_fee − discount_amount − point_amount − gift_amount` · 각 칸 ≥ 0 · `total ≥ 0`

주문의 적립금 · 상품권 칸은 **주문할 때 한 번만**(`fn_hlt_benefit_apply` · 결제 전 본인 주문) — 그 밖에 고치면 DB 가 막습니다(HLT_BENEFIT).

## 3. 되돌림 · 회수 · 소멸
| 일 | 무엇 | 어디서 |
|---|---|---|
| 취소 · 반품 | 쓴 적립금을 그 묶음으로 되돌림 · 그 묶음이 이미 소멸 · 회수됐으면 새 묶음(RESTORE · `mall.benefit_restore_days` 30일) | DB 트리거(결제 취소 · 반품 승인 · 결제 전 취소 모든 길) |
| 확정 뒤 반품 | 그 주문으로 쌓인 묶음의 **남은 금액만** 회수(REVOKE) · 이미 쓴 몫은 회수하지 못함 → 운영 알림 `MALL_POINT_REVOKE_SHORT` | DB |
| 소멸 | 유효 기간 지난 묶음 → EXPIRE 기록 · 있으면 운영 알림 `MALL_BENEFIT_EXPIRED` | 정기 작업 `mall_benefit_expire` 매일 00:20 |
| 사전 알림 | 30일 안에 소멸할 묶음이 있으면 회원 알림 `HLT_POINT_EXPIRE_SOON`(묶음마다 한 번) | 같은 작업 · `mall.points` on 일 때 |
| 운영 지급 · 회수 | 지급 = 새 묶음(ADMIN) · 회수 = 소멸이 가까운 묶음부터(모자라면 422) · 사유 · 감사 기록 HLT_POINT_ADJUST | 소개몰 › 적립금 |

## 4. 전표(초안 · 세무사 확인)
| 돈 흐름 | 차변 | 대변 | 근거 |
|---|---|---|---|
| MALL_POINT_EARN | EXP_MALL_PROMO 판매촉진비 | MALL_POINT_LIAB 적립금 충당부채 | 적립 · 운영 지급 기록 |
| MALL_POINT_LAPSE | MALL_POINT_LIAB | EXP_MALL_PROMO(환입) | 소멸 · 회수 기록 |
| MALL_POINT_USE | MALL_POINT_LIAB | 상품 매출(면세 몫) · 상품 매출(과세 · **부가세 없음**) | MALL_SALE 이 있는 적립금 주문 |
| MALL_POINT_USE_CANCEL | 위 반대 | | 되돌림 기록이 생기면 |

- 적립금 사용분은 **자기적립마일리지**로 보아 공급가액에서 뺀 초안(부가가치세법 시행령 61조 — **세무사 확인**). 적립 때 비용 · 충당부채로 둘지, 이연수익(K-IFRS 1115)으로 둘지도 세무사 확인.
- 면세 몫: 「쿠폰 뒤 면세 상품 금액」을 낸 돈 → 적립금 → 상품권 차례로 나눔(낸 돈 몫은 MALL_SALE 이 이미 잡음 · 합계 맞음). journal.ts 의 MALL_SALE 줄은 고치지 않음.
- 계정 4개는 `draft = true`(GIFT_ADV · MALL_POINT_LIAB · EXP_MALL_PROMO · INC_GIFT_LAPSE) — 회계 › 계정 · 규칙 확인표에 「초안」으로 보임.

## 5. 법무 · 확인할 것
1. 적립금 소멸 전 안내 기간(30일)과 방법(회원 알림) — **법무 확인**(전자상거래 소비자 보호 지침 · 약관에 적립 · 소멸 규칙을 적어야 함 · 이용약관 소개몰 조항 고칠 것).
2. 확정 뒤 반품 때 이미 쓴 적립금(모자람)을 어떻게 할지 — 지금은 회수하지 않고 운영 알림만(환불 금액에서 빼는 것은 이번 판에 없음).
3. 회원 화면(site/)은 이번 판에 없음 — 주문 받기를 켤 때 주문서 「적립금 쓰기」 칸 · 내 혜택 화면(SB-HLT-MBS-010)을 만듦.
