# 소개뱅크 — 아키텍처 설계서 v1

**작성일** 2026-09-03
**성격** 인프라 구성은 `13_시스템설계서`, 여기는 **왜 그렇게 정했는가**입니다.

## 1. 아키텍처를 지배하는 제약 5가지

기술 선택은 취향이 아니라 여기서 파생됩니다. "왜 이렇게 정했지"가 생기면 이 표로 돌아오십시오.

| # | 제약 | 파생된 결정 |
|---|---|---|
| 1 | **개발 소수 인원 · 자금 제약** | 관리형 서비스 · **EKS 금지 · 마이크로서비스 금지** |
| 2 | **플랫폼이 자금을 만지지 않음** (INV-9·11) | 에스크로 배제 · PG는 구독료만 · **금액 컬럼 부재** |
| 3 | **귀속 기록이 모델의 급소** (INV-2) | append-only · 불변 보관 · 정책 버전화 |
| 4 | **검수 1명이 최대 병목** | 자동검수 · BO 별도 배포 · k값 경보 |
| 5 | **외부 연동 5종이 IP 화이트리스트 요구** | NAT EIP 고정이 W2 임계 작업 |

## 2. 핵심 결정 10건

### D1. 모듈형 모놀리식 · 배포 4개

| 후보 | 판단 |
|---|---|
| 마이크로서비스 | **정산·귀속이 서비스를 가로지릅니다.** 분산 트랜잭션을 직접 만들게 됩니다 |
| 단일 배포 | 검수 BO 배포가 사용자 트래픽에 영향을 줍니다 |
| **채택: 모듈형 모놀리식** | 코드 경계는 폴더, 배포 경계는 ECS 태스크 |

**되돌리는 비용** — 낮음. 모듈이 분리돼 있어 나중에 떼어낼 수 있습니다.

### D2. 규칙을 DB에 둡니다

불변식·제한업종·한도를 트리거와 CHECK로 강제합니다.

**이유** — 앱 코드에만 두면 데이터 보정 한 번에 조용히 깨집니다. 운영 중 DB를 직접 만지는 순간(마이그레이션·보정) 무력화되고, **그때 아무도 모릅니다.**

**대가** — 서비스 코드가 얇아 처음 보면 "검증이 빠졌다"고 오해합니다. 대량 이관 시 트리거를 끄고 싶어집니다(→ D-14 절차로 대응).

**되돌리는 비용** — 높음. 이미 90건의 검증이 이 위에 서 있습니다.

### D3. 컬럼의 부재로 지킵니다

`settlements` 에 공제 컬럼이 없고, `deal_payment_records` 에 금액·계좌가 없습니다.

**이유** — 컬럼이 있으면 언젠가 화면에 나타납니다. **없으면 띄우려 해도 데이터가 없습니다.** INV-9·11을 코드 리뷰가 아니라 스키마로 지킵니다.

### D4. 트랜잭션을 인자로 넘기지 않습니다

`AsyncLocalStorage` 로 전달합니다.

**이유** — 인자로 넘기면 한 곳만 빠뜨려도 그 쿼리가 트랜잭션 밖에서 돌고 컴파일도 테스트도 통과합니다. 정산에서는 나중에 잔액으로 드러납니다.

**대가** — 암묵적 전달이라 추적이 덜 명시적입니다. 대신 **빠뜨릴 자리가 없습니다.**

### D5. 토큰을 믿지 않습니다

principal 을 매 요청 DB에서 재조립합니다.

**이유** — 구독 만료·사업자 승인이 15분 뒤에 반영되면 안 됩니다. 조회 1회 비용보다 "만료됐는데 통과"가 훨씬 비쌉니다.

**대가** — 요청당 쿼리 1회. 캐시가 필요해지면 Redis로 옮깁니다.

### D6. 자동 처리를 기본값으로

검수·성사 확정·정산 신청이 자동입니다. 관리자는 **필수 개입 사유가 있을 때만** 봅니다.

**이유** — 검수 1명이 최대 병목이고 증원에 2~3개월이 걸립니다. 자동화율 70%면 실질 처리량이 3배가 됩니다.

**안전장치** — 표본 감사 5% · 정책 스위치로 전건 수동 전환 · 배지는 자동화 제외.

### D7. 문서를 손으로 쓰지 않습니다

`spec/*.json` 과 코드에서 생성합니다.

**이유** — 화면·API·권한을 각각 손으로 쓰면 반드시 어긋납니다. 하나의 레지스트리에서 뽑으면 **어긋날 자리가 없습니다.** CI가 `git diff --exit-code` 로 드리프트를 막습니다.

### D8. 반응형 단일 코드베이스

**이유** — `m.` 분리면 화면이 90개 이상으로 늘고, 더 중요하게는 **PC 문의 단절이 화면 수만큼 재발합니다.** 상세 화면이 하나면 그 결함이 생길 자리가 없습니다.

### D9. 3관 우선 · 리드관 보류

**이유** — 리드관은 개인정보·보험·의료 부담을 함께 들고 옵니다. 미루면 그 부담도 미뤄지고, `pii` 스키마가 비면서 N-08(개인정보 격리)이 대폭 축소됩니다.

**되돌리는 비용** — 낮음. `100_lead` 마이그레이션을 폴더만 옮기면 됩니다. `LED` 관은 `is_active=false` 로 남아 있습니다.

### D10. 백업 기반 DR

멀티 리전을 하지 않습니다.

**이유** — 비용 2배인데 자금 가정이 이미 안전지대 가장자리입니다. RPO 5분 · RTO 4시간으로 충분합니다.

### D11. 문구도 데이터입니다

FAQ · 안내 문구 · 관별 폼 문구 · 코드 라벨을 소스에서 걷어내 레지스트리로 옮겼습니다.

**이유** — 문구 하나 고치는 데 배포가 필요하면 안 됩니다. 법정 고지 문구라면
**배포 대기 시간이 곧 위반 기간**이 됩니다. `ui_messages.basis` 에 근거를 함께 두어
왜 있는 문구인지 모른 채 지우는 일을 막습니다.

**되돌리는 비용** — 낮음. 화면이 서버 값을 쓰고 있어 기본값만 넣으면 됩니다.

### D12. 문서를 코드에서 생성합니다

23종 중 15종이 자동 생성입니다 — 화면·권한·API·DB·Flow·코드·문구·방침·프로토타입.

**이유** — 손으로 쓰면 반드시 어긋나고, 어긋난 문서는 없는 것보다 나쁩니다.
CI 가 재생성 후 `git diff --exit-code` 로 드리프트를 막습니다.

**남은 수기 8종**은 전부 "왜 그렇게 정했는가"를 담은 것이라 자동화 대상이 아닙니다.

## 3. 아키텍처 계층

```
표현    Next.js SSR (사용자) · Vite SPA (BO)
        └ 라벨·권한·판정을 서버에서 받음. 재계산하지 않음
────────────────────────────────────────────────
계약    OpenAPI — 레지스트리(경로·권한) + 데코레이터(스키마) 병합
────────────────────────────────────────────────
앱      NestJS — core / engines / modules / worker
        └ 상태 전이만. 규칙 재검사 없음
────────────────────────────────────────────────
규칙    PostgreSQL — 트리거 37 · CHECK · 부분 인덱스
        └ 최종 방어선. 어떤 경로로도 우회 불가
────────────────────────────────────────────────
데이터  71 테이블 · append-only 9 · 감사 로그
```

**아래 계층이 위 계층을 신뢰하지 않습니다.** 앱이 게이트를 빠뜨려도 DB가 막고, 프런트가 검사를 빠뜨려도 앱이 막습니다.

## 4. 확장 지점

지금은 필요 없지만 **어디서 갈아탈지**를 정해 둡니다.

| 지점 | 현재 | 전환 시점 | 대안 | 비용 |
|---|---|---|---|---|
| 검색 | pg_trgm | 매물 5만 | OpenSearch + Nori | 월 $200+ |
| DB 읽기 | 단일 | 읽기 포화 | Aurora 복제 | 2배 |
| 캐시 | Redis 단일 | **오픈 전** | Multi-AZ | +$25 |
| 컴퓨트 | Fargate | 운영 인력 확보 | (전환 불필요) | — |
| 모듈 분리 | 모놀리식 | 팀 3개 이상 | 서비스 분해 | 높음 |

**한국어 검색이 가장 먼저 한계에 닿습니다.** `pg_trgm` 은 형태소 분석이 없어 조사·복합어가 약한데, 통합 검색이 P0입니다.

## 5. 아키텍처 리스크

| # | 리스크 | 성격 | 완화 |
|---|---|---|---|
| A1 | **DB에 규칙이 몰려 있음** | 구조적 | 이관 시 트리거를 끄고 싶어짐 → D-14 6단계 절차 |
| A2 | **Redis 단일 장애점** | 운영 | 오픈 전 Multi-AZ 또는 세션 DB 폴백 |
| A3 | 커넥션 풀 고갈 | 운영 | 태스크×풀 계산. **CPU 한가한데 멈추는 형태**라 진단이 어려움 |
| A4 | 자동화 오판 누적 | 구조적 | 표본 감사 5% · `v_manual_reasons` 분포 |
| A5 | 검색 품질 | 기능 | 5만 건 시 전환 |

**A1이 가장 큽니다.** 규칙을 DB에 둔 것이 이 설계의 강점이자 유일한 구조적 부담입니다. 대량 이관에서 트리거를 끄면 무결성이 무너지고, **그때 아무도 모릅니다.** `fn_verify_invariants()` 전건 재대조가 유일한 방어입니다.

## 6. 되돌리기 어려운 결정

| 결정 | 되돌리는 비용 | 지금 확인할 것 |
|---|---|---|
| 규칙을 DB에 (D2) | **높음** | 90건 검증이 이 위에 있습니다 |
| append-only 9종 | **높음** | 데이터 쌓인 뒤 제약 추가는 위험 |
| 관 3개 (D9) | 낮음 | 폴더 이동 |
| 모듈형 모놀리식 (D1) | 낮음 | 나중에 떼어냄 |
| 반응형 (D8) | 중간 | 화면 ID 체계 |
| 백업 DR (D10) | 낮음 | 언제든 추가 |

**높음 2건은 지금 검증돼 있습니다.** 나머지는 필요할 때 바꾸면 됩니다.

## 7. 하지 않기로 한 것

| 항목 | 이유 |
|---|---|
| EKS | 소수 인원이 클러스터를 운영할 수 없습니다 |
| 마이크로서비스 | 정산·귀속이 서비스를 가로지릅니다 |
| GraphQL | 화면 71개에 쿼리 최적화보다 계약 명확성이 중요합니다 |
| Aurora Serverless v2 | 최소 ACU 과금이 t4g보다 비쌉니다 |
| 이벤트 소싱 | 감사 로그 + append-only 로 충분합니다 |
| 멀티 리전 DR | 비용 2배 |
| 앱 내 cron | ECS 태스크가 2개면 두 번 실행됩니다 |
| 자체 이체 구현 | PG·펌뱅킹 위탁. INV-11과도 맞습니다 |
