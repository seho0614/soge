# 474. 1:1 문의 답변 만족도 (v10.341 · 2026-11-17)

> 대표 11/17 「다음개발」 → ② 답변 만족도(docs/473 머리말의 네 가지 중 둘째) · 「승인 + 통과하면 병합」. 마이그레이션 **D231**(268 → 269 · 스냅샷 필요).

## 1. 왜

- 답을 보낸 뒤 회원 문제가 풀렸는지 알 길이 없었습니다. 풀리지 않은 회원은 새 문의를 다시 넣어 같은 이야기를 처음부터 해야 했습니다.

## 2. 바뀐 것

| 곳 | 바뀐 것 |
|---|---|
| 마이그레이션 **D231** `inquiries` | 칸 셋 — `feedback`(RESOLVED 해결됨 · UNRESOLVED 아직 해결 안 됨) · `feedback_at` · `reopen_count`(회원이 다시 연 횟수). 지우는 문장 없음 |
| 새 API `POST /me/inquiries/{id}/feedback` | 회원 · 답을 받은 **내 문의**만(ANSWERED · CLOSED) · `resolved` true = 해결됨(표시만) · false = **문의가 다시 열림**(OPEN · 기한 다시 영업일 1일 · 다시 연 횟수 +1) · 감사 `INQUIRY_FEEDBACK` · 남의 문의 404 · 답 전 409 `INQUIRY_NO_ANSWER` |
| API `GET /me/inquiries` | 줄마다 `feedback` |
| 사용자 웹 **고객센터 › 내 문의 내역** | 답변을 펼치면 아래 **「답변으로 해결되셨나요? 해결됨 · 아직 해결 안 됨」** → 「해결되었다고 남기셨습니다」 · 「문의를 다시 열었습니다. 영업일 1일 안에 다시 답변드립니다」 |
| 운영 API 답변(`POST /admin/inquiries/{id}/answer`) | 다시 답하면 만족도를 비움(회원이 새 답에 다시 고름) |
| 운영 화면 **회원 › 「1:1 문의」** | 목록 제목 옆 **「다시 열림」**(횟수 2 이상이면 숫자) · 「해결됨」 표시 · 지표 상자에 **해결률 %**(남긴 것 중) |
