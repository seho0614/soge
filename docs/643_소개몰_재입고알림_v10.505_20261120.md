# 643. 소개몰 재입고 알림 (v10.505 · 2026-11-20)

## 1. 결론
품절 옵션(재고 0)에 회원이 **「입고되면 알림」**을 신청하면, 그 옵션 재고가 **0 → 양수**가 되는 순간 **DB 트리거**가 기다리는 회원에게 회원 알림 `HLT_RESTOCK` 을 **한 번** 보냅니다. 알림은 기존 `fn_notify` 로 보내므로 회원이 나의공간 › 알림 수신 설정에서 「재입고 알림」을 끄면 보내지 않습니다(신청은 「알림 보냄」으로 닫힘 — 한 번만). 스위치 `mall.restock_alert`(처음 **off** · 공개 설정)가 켜져 있을 때만 상품 화면에 단추가 보이고 알림이 나갑니다. 위치: **소개몰 › 재입고 알림** · SB-ADM-MLX-010 · 회원 SB-HLT-MLX-010(상품 상세 SB-HLT-PRD-010 옵션 줄).

| 항목 | 규칙(처음 값 · 운영이 고침) |
|---|---|
| 신청 | 로그인 회원 · 품절 옵션만(재고 있음 422 `HLT_RESTOCK_IN_STOCK`) · 판매 중 · 품절 표시 상품 · 같은 옵션 기다림은 하나(다시 누르면 `already`) |
| 기다림 기한 | `mall.restock_keep_days` 90일(7 ~ 365) — 지나면 정기 작업이 「기한 지남」으로 닫음 |
| 회원당 상한 | `mall.restock_max` 30개(1 ~ 200) — 넘으면 DB 가 막음(`HLT_RESTOCK_MAX`) |
| 알림 때 | 옵션 `stock` 0 → 양수 · 또는 꺼진 옵션을 재고 있게 다시 켬(`trg_hlt_restock_fire` · AFTER UPDATE OF stock, is_active) — 운영 재고 고침 · 주문 취소 재고 되돌림 모두 |
| 한 번만 | 알림을 보내면 신청은 `NOTIFIED` 로 닫힘 — 재고가 다시 0 이 됐다 들어와도 새로 신청한 사람에게만 |
| 따라잡기 | 스위치를 켜기 전에 이미 재고가 돌아온 옵션의 기다림 → 운영 「지금 보내기」 · 매일 04:35 `mlx_daily_purge` 가 같은 일(`fn_hlt_restock_catchup`) |
| 기록 | 지우지 않음(취소 · 기한 지남으로 닫음) · 닫힌 줄은 바꾸지 않음 · 회원 · 옵션 · 신청 시각은 바꾸지 않음(DB 지킴) |

## 2. 화면 · API
| 누가 | 무엇 | API |
|---|---|---|
| 회원 | 상품 상세 품절 옵션 옆 「입고되면 알림」(RestockButton · 로그인 필요하면 로그인 뒤 돌아옴) | `POST /me/health/restock` |
| 회원 | 내 신청 · 취소(목록 화면은 「주문 받기」를 켤 때 — 계약 25) | `GET /me/health/restock` · `DELETE /me/health/restock/{id}` |
| 운영 | 스위치 · 기다림 수 · 최근 30일 알림 · 기다리는 옵션 순위 50 · 최근 신청 50(이름 가림) · 지금 보내기 | `GET /admin/health/restock` · `POST /admin/health/restock/run` |

## 3. 알림
- 종류 `HLT_RESTOCK`(끌 수 있음 · 회원이 신청한 안내) · 템플릿 `HLT_RESTOCK_INAPP` 「다시 들어왔습니다 — {product}」 · 링크 `/health/p/{상품 코드}`.
- 광고가 아님(회원이 신청한 정보) — 이름에 MARKETING · AD_ 를 넣지 않음. 문자 · 메일로 넓힐 때는 **법무 확인**(정보통신망법 제50조 — 영리 목적 광고성 정보 해당 여부).

## 4. 판단
- 트리거 안에서 바로 알림(정기 작업 대기 없음) — 운영이 재고를 넣는 그 트랜잭션에서 신청이 많으면 그만큼 알림 줄이 생김(옵션 하나에 수천 명이면 저장이 조금 늦어짐 · 지금 규모에서는 문제없음 — 커지면 대기열로 바꿀 후보).
- 「주문 받기」가 꺼진 채 재고가 돌아와도 알림은 나감(상품 화면은 볼 수 있음) — 켜기는 운영 판단(`mall.restock_alert` off 가 처음).
