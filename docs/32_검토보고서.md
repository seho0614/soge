# 2. 발견과 조치

## 2-1. 개발 환경 — 해결

**① Windows 에서 `npm run smoke` · `docs:swagger` 가 실패했습니다.**
ts-node 옵션을 작은따옴표 JSON 으로 인라인해 두었는데 cmd.exe 는 작은따옴표를 벗기지 않습니다. `tsconfig.scripts.json` 을 두고 `ts-node -P` 로 바꿨습니다. `verify-all.sh` · `deploy-check.sh` 도 같은 파일을 씁니다.

**② psql 이 없으면 마이그레이션을 못 걸었습니다.**
`scripts/migrate.js` 를 추가했습니다. `migrate.sh` 와 **같은 `schema_migrations` 테이블 · 같은 16자리 SHA-256 체크섬**을 쓰므로 둘을 섞어 써도 이력이 갈리지 않습니다. 빈 DB 적용 · 재실행 · 변조 감지(변경감지 1) 를 확인했습니다. 파일 하나가 한 트랜잭션이라 중간 실패 시 그 파일만 되돌아갑니다.

**③ 환경 변수를 매번 export 해야 했습니다.**
`.env.example` 과 `scripts/load-env.js` 를 두고, dev-server 와 DB 를 쓰는 생성 스크립트 전부가 `.env` 를 읽게 했습니다. 이미 설정된 값은 덮지 않습니다. `docker-compose.yml`(PG 16) 과 `npm run db:embedded`(Docker 도 PG 도 없는 PC) 를 추가했습니다.

## 2-2. 검증 스크립트 — 해결

**④ `verify-invariants.sh` 를 단독으로 돌리면 3건이 실패했습니다.**
약관 본문 검사 3건이 `gen-terms-draft.js` 가 DB 에 본문을 써 넣은 뒤에만 통과합니다. `verify-all.sh` 는 그 순서를 지키지만 `npm run db:verify` 는 아니었습니다. `db:verify` 가 생성기를 먼저 돌리도록 했습니다.

**⑤ 오픈 차단 항목 출력이 깨졌습니다.**
`SELECT key, description FROM v_open_blockers` — 뷰 컬럼은 240 마이그레이션부터 `kind · item · reason` 입니다. 판정에는 영향이 없고 출력만 오류였습니다. 고쳤습니다.

## 2-3. 코드 — 해결

**⑥ refresh 토큰이 access 토큰으로 통했습니다. (보안)**
`AuthService.verify()` 가 `typ` 을 보지 않아 14일짜리 refresh 토큰을 `Authorization: Bearer` 에 넣으면 그대로 인증됐습니다. access 15분 만료가 무의미했습니다. refresh 토큰을 거부하도록 했고(실측 403), 반대로 access 토큰으로 재발급을 시도해도 403 입니다.

**⑦ 재발급 엔드포인트가 없었습니다.**
refresh 토큰을 발급하고 사용자 웹이 쿠키에 저장하는데, 쓸 곳이 없었습니다. 15분 뒤 조용히 로그아웃되는 구조였습니다.
- API: `POST /api/v1/auth/refresh` 추가. principal 을 DB 에서 다시 조립하므로 정지·구독 만료가 즉시 반영됩니다.
- 사용자 웹: `site/src/middleware.ts` 추가. access 쿠키가 없고 refresh 쿠키가 있으면 응답에 새 쿠키를 싣고, **같은 요청의 서버 컴포넌트도 새 토큰을 보도록** request 헤더를 바꿔 넘깁니다. 서버 컴포넌트 렌더 중에는 쿠키를 쓸 수 없어 `session.ts` 안에서는 할 수 없는 일입니다.

**⑧ `GET /me/summary` 가 문서와 달랐습니다.**
`MeSummaryDto` 는 `unreadNotifications · publishedListings · openDeals · blockedBy` 를 약속하는데 실제 응답은 `principal` 뿐이었습니다. `MeService.summary()` 가 이미 그 수를 계산하고 있었지만 연결돼 있지 않았습니다. 연결하고 `blockedBy` 를 게이트 순서(본인인증 → 사업자 → 구독)로 채웠습니다.

**⑨ 오류 응답 모양이 두 가지였습니다.**
`AppError` 는 `{code, message}` 인데 Nest 내장 예외(ValidationPipe 400 · 라우트 없음 404)는 `{statusCode, message[], error}` 였습니다. 프런트는 `code` 로 분기합니다. `DbErrorFilter` 에서 한 모양으로 맞췄습니다 — 400 은 `VALIDATION_ERROR` 와 첫 필드명, 404 는 `NOT_FOUND`.

**⑩ Idempotency-Key 가 사용자 간에 공유됐습니다.**
키가 전역 PK 라 다른 사용자가 같은 키를 보내면 **남의 저장된 응답**이 돌아갑니다. 요청자 ID 를 접두로 붙여 격리했습니다. 비로그인 경로(PG 웹훅)는 그대로입니다.

**⑪ 헬스체크가 없었습니다.**
아키텍처는 ALB 뒤 ECS 인데 헬스체크 경로가 없었습니다. `GET /api/v1/health` 를 추가했습니다. DB 까지 확인하고 실패 시 `status: degraded` 입니다.

새 API 2건은 `spec/screens.json` 에 연결했습니다 (로그인 화면 · 관리자 대시보드). 레지스트리에 없는 API 는 문서 생성이 거부하기 때문입니다.

## 2-4. 설계 확인 사항 — 코드 수정 없음

**⑫ 약관 개정 사이에 공백이 생깁니다.**
새 버전을 발행하면 이전 버전이 즉시 `ARCHIVED` 되는데, `GET /terms` 는 `effective_from <= now()` 만 내려줍니다. 시행일을 7일 뒤로 잡으면 **그 7일 동안 노출되는 개인정보처리방침이 없습니다.** 법정 고지 공백입니다. 이전 버전을 새 버전 시행일까지 유지하도록 트리거를 고치는 편이 맞습니다 — 법무 판단이 섞여 있어 손대지 않았습니다.

**⑬ 비밀번호 길이 검사가 DTO 에 없습니다.**
`LoginDto.password` 는 `@IsString()` 뿐이고 10자 검사는 서비스(422 WEAK_PASSWORD)에 있습니다. 동작은 맞지만 Swagger 의 `minLength: 10` 과 검증 위치가 어긋납니다. 의도적일 수 있어 두었습니다.

**⑭ CORS 설정이 없습니다.**
사용자 웹은 Next rewrite, 운영 BO 는 Vite proxy 로 같은 출처가 되므로 로컬에서는 문제가 없습니다. 운영에서 API 를 별도 도메인으로 두면 `enableCors` 가 필요합니다.

# 4. 이 킷으로 개발을 시작하는 순서

```bash
npm install && (cd site && npm install) && (cd web && npm install)
cp .env.example .env
docker compose up -d                 # 또는 npm run db:embedded
npm run db:migrate
npm run verify                       # 전체 검증 통과 확인
npm run start:dev                    # API
(cd site && npm run dev)             # 사용자 웹 :5174
(cd web  && npm run dev)             # 운영 BO  :5173
```

그 다음은 `docs/29_오픈선행업무` 와 `28_오픈차단항목` 입니다. 코드가 아니라 값 입력 · 약관 발행 · 외부 계약입니다.
