## 5. 운영 적용

### 5-1. 앱 v10.89 → v10.90 (docs/144 와 같은 절차)

precheck 기대 `적용됨 152 · 새 킷의 파일 152 · 올릴 것 0 · 바뀐 파일 0` → apply `적용 0 · 기존 152 · 변경감지 0` → `152 / 152` · 마이그레이션이 없어도 스냅샷은 같은 방식으로.

### 5-2. 필터가 색 코드가 붙은 줄을 잡는지 (CloudShell · 읽기만 · 5-1 전에 해도 됨)

```bash
E=$(printf '\033[33m[Nest] 1  - \033[39m10/24/2026, 6:25:43 AM \033[33m   WARN\033[39m \033[38;5;3m[SchedulerService] \033[39m\033[33mREVIEW_SLA_BREACH 검수 기한 넘김 1건\033[39m')
aws logs test-metric-filter --filter-pattern '"REVIEW_SLA_BREACH"' --log-event-messages "$E" --query 'length(matches)'
R=$(printf '\033[31m[Nest] 1  - \033[39m10/24/2026 \033[31m  ERROR\033[39m \033[38;5;3m[X] \033[39m\033[31mboom\033[39m')
aws logs test-metric-filter --filter-pattern '"ERROR"' --log-event-messages "$R" --query 'length(matches)'
```

두 줄 모두 `1` 이면 맞음. `0` 이면 멈추고 알려 주십시오(필터를 `?"REVIEW_SLA_BREACH" ?"*REVIEW_SLA_BREACH*"` 식으로 바꿔야 함).

### 5-3. 경보 더하기 (CloudShell · 5-1 뒤)

새 setup.sh 를 올린 뒤 `ALERT_EMAIL=sh0614park94@gmail.com RDS_MAX_CONNECTIONS=81 bash setup.sh check` → `apply`(이제 `RDS_FREE_MEM_MB` 를 붙이지 않아도 64MB). 할일에 필터 `SGB/ReviewSlaBreach` · 경보 `sgb-review-sla` 가 보이고 끝 줄 `sgb-* 경보 13개`.
