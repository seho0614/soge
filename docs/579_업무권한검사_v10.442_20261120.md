## 1. 결론
- 새 전역 가드 **PermGuard** — AuthGuard(역할 · 2단계 · 접속 인증) **다음**에 한 번 더 봅니다. 둘 다 통과해야 합니다(권한그룹은 역할 범위 안에서 더 좁힘).
- 운영 역할만 요구하는 API(회원 역할이 섞인 API 는 보지 않음) · SUPER 는 늘 통과 · `perm_route_map` 에 없는 주소는 지금처럼 역할만.
- 주소 → 업무 · 수준: GET = 보기 · 등록 · 수정 = 고치기 · 결재 · 확정(decide · approve · paid · fix · close · confirm · accept · reopen · book · send · run) = 승인 · CSV · export = 내려받기. 같은 주소가 여러 업무(탭)면 하나라도 있으면 통과.
- 검사 모드 `perm.enforce`: OFF(안 봄) · **SHADOW(처음 — 막지 않고 「막혔을 것」만 perm_shadow_log)** · ON(403 PERM_DENIED).
- `perm.*` 설정은 SUPER 만 바꿈(PERM_SETTING_SUPER).
- 서버 기억: 모드 30초 · 주소 표 60초 · 사람 권한 15초(권한 화면에서 저장하면 그 서버는 바로 지움).

## 2. 켜는 순서(SUPER)
1. 운영 반영 뒤 SHADOW 로 며칠 — 「사무 › 권한 관리 › 막혔을 요청」에서 막히면 안 되는 것이 있는지 봄.
2. 있으면 그 사람 권한그룹에 더함 · 없으면 정책 › 전체 설정 `perm.enforce` = ON.
3. 문제가 생기면 `perm.enforce` = OFF(바로 역할만으로 돌아감).
