## 2. 전자세금계산서 — 연결 자리 · 간주 모드

- 대상: 소개뱅크(운영 법인)가 발행하는 세금계산서 — 법률 · 세무 정액 노출(`consult_directory_invoices`) · 리드 이용료(`lead_cash_invoices`). **소개자가 발행하는 정산 세금계산서(settlements.tax_invoice_*)는 대상 아님**(발행 주체가 소개자 · 10/11 결정).
- 「발행」 동작: `assume.etax` on(기본) → 국세청에 보내지 않고 「간주 발행」 기록(승인번호 비움 · 내부 문서 번호만) / off + 업체 연동 → 어댑터로 전송 · 승인번호 · 전송 상태(SENT · FAILED) · 실패 사유 · 시각 기록 · 「다시 보내기」(보낸 적 있으면 먼저 상태 조회 — 업체 발행 요청은 1번뿐) / off + 연동 없음 → 422 ETAX_NOT_CONFIGURED(조용히 간주로 돌아가지 않음).
- 「홈택스 발행 번호 넣기」(MANUAL) — 업체 연동 전 운영 방법. 이렇게 넣은 줄은 전송하지 않음(같은 세금계산서 두 번 발행 막음) · 전송을 시작한 줄에는 손으로 넣을 수 없음.
- 업체를 정하면 `sgb/src/modules/etax/etax.http.ts` 한 파일만 업체 형식으로(지금 요청 · 응답 형식은 자리표시) · 업태 · 종목 · 주소 · 담당자 메일 칸 추가 · 키는 `ETAX_KEY`(환경 변수 · 화면 가림) · 오픈 전 `assume.etax` off(오픈 체크리스트 「간주 모드 켜짐」).
- 새 API(ADMIN · SUPER): `GET /admin/etax/status` · `POST /admin/etax/{directory|lead-cash}/{id}/send · resend · refresh · cancel` — 감사 기록 4종.
- D093: 두 세금계산서 표에 전송 결과 칸 10개 · `etax_send_log`(시도마다 한 줄 · 고치기/지우기 거부) · 승인번호 · 문서 번호 바뀌지 않게 · 보낸 줄은 취소로만.
- 업체 화면: 「발행됨 · 국세청 전송」(승인번호) / 「전송 대기 — 연동 전」 · 간주 줄의 내부 번호는 숨김.

## 3. 수화 오류(#418) — 원인 · 고침

- 현상: 창 6개 동시 부하에서 손님으로 연 /money/list · /mall/list 에 540번 중 5 ~ 6번. 혼자 열면 0번.
- 원인: 화면 코드가 아니라 **Next 15.5.25 에 묶인 React 19.2 canary 의 결함**. 돌아가기 줄(`BackBar` · `<div class="pc-bkbar">` 안 `next/link`)의 JS 조각이 늦게 오면 React 가 그 자리에서 멈췄다 다시 그리는데, 19.2 canary 는 다시 그릴 때 지나간 자리를 되돌리지 않아 #418. react-dom 19.3.0 은 같은 곳을 고쳤습니다(두 판 원본 비교). 부하에서만 나는 까닭 = 혼자 열면 JS 조각이 먼저 와 그 경로를 타지 않음.
- 고침: `sgb/site/next-loaders/hydration-replay-fix.js` — 브라우저용 react-dom 에 19.3.0 의 4줄을 빌드 때 붙임(이미 고쳐진 React 면 그대로 · **붙일 자리를 못 찾으면 빌드를 멈춤** — Next 를 올렸을 때 고침이 조용히 빠지지 않게) · `next.config.js` 에서 브라우저 번들에만. 개발 모드(next dev)에도 들어감.
- Next 15 최신(15.5.27)도 같은 React 를 묶고 있어 판 올림으로는 해결되지 않음 — Next 16(React 19.3 이상)으로 올리면 이 고침은 저절로 빠집니다.
