# 377. 급한 운영 알림 · 하루 요약 슬랙 — v10.237 (2026-11-11)

> 대표 「슬랙 추가」 → 「운영 알림을 슬랙으로(권장)」 → 계획 「승인」(11/11).
> **마이그레이션 D200(237 → 238)** · 처음에는 **꺼진 채**(웹훅 주소가 없으면 보내지 않음) — 켜는 것은 대표.

## 1. 왜

급한 운영 알림은 메일(준비 안 됨 · NO_SMTP)과 텔레그램(아직 켜지 않음)으로만 나갔습니다. 회사 대화를 슬랙에서 하면 같은 알림을 슬랙 채널에서도 보는 편이 빠릅니다.

## 2. 방법 — 슬랙 「Incoming Webhook」(들어오는 웹훅)

| | 웹훅(고름) | 슬랙 봇 토큰 |
|---|---|---|
| 준비 | 슬랙 앱 하나 · 채널 고르면 주소 하나 | 앱 · 권한 · 채널 초대 · 채널 번호 |
| 받을 곳 | 주소에 채널이 묶여 있음 — 설정 없음 | 채널 번호 설정 |
| 할 수 있는 일 | 보내기만 | 보내기 · 읽기 |

## 4. 켜는 법(대표 · 적용 뒤)

1. api.slack.com/apps → Create New App → From scratch → 이름(예 「소개뱅크 알림」) · 워크스페이스
2. Incoming Webhooks → 켬 → Add New Webhook to Workspace → 받을 채널 → 허용 → 「Webhook URL」 복사
3. 운영 화면 › 외부 연동 › 연동 키 › 메일 칸 「슬랙 웹훅 주소」에 붙여 넣기 → 1분 안에 API 가 읽음
4. 「운영 알림」 › 「급한 알림 슬랙」 → 「시험 메시지 보내기」 → 채널에 왔는지 확인

> 슬랙 화면의 메뉴 이름은 바뀔 수 있습니다 — 켤 때 화면 기준으로 다시 확인하십시오.
> 웹훅 주소가 새면 누구나 그 채널에 글을 올릴 수 있습니다. 그러면 슬랙 앱에서 주소를 지우고 새로 만들어 연동 키를 바꿉니다.
> 비용 — 슬랙 무료 요금제에서도 웹훅을 쓸 수 있는 것으로 알지만 요금제 조건은 바뀔 수 있어 추가 확인이 필요합니다(무료는 오래된 메시지가 보이지 않음).

## 6. 운영 적용

- **마이그레이션 D200 하나**(237 → 238) — 스냅샷을 만들고 적용(절차서 docs/378).
- `.env` · Nginx 그대로. 서버에서 hooks.slack.com 으로 나가는 HTTPS(443)가 열려 있어야 함(텔레그램 · SES 와 같은 길).
- 적용 직후에는 웹훅 주소가 없어 「준비 안 됨 — 웹훅 주소 없음」이 정상.
