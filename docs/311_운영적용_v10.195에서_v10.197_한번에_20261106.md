### 4-2. 급한 알림 메일 — 처음 10분

1. 운영 메일이 준비돼 있고(docs/167) 하루 요약 받는 주소가 있으면, 적용 뒤 **10분 안에** 지난 24시간의 확인 안 한 CRITICAL · 중요 설정 바뀜 알림이 **한 통**으로 갈 수 있습니다. 정상입니다.
2. 메일이 오면 운영 알림 화면 그 줄에 「메일 보냄」이 붙습니다.
3. 메일이 안 오면 준비가 안 된 것이고, 보내지 않은 까닭은 정기 작업 기록에만 남습니다(서비스에는 영향 없음).
4. 운영 메일 준비 상태는 sgbdev 가 볼 수 없어 **확인할 수 없습니다** — 메일이 오는지만 봐 주십시오.

### 4-3. S3 백업을 켤 때 (대표 · 이번 적용과 별개 · 나중에)

docs/310 3절 그대로입니다.
1. S3 버킷 만들기(예: `sgb-uploads-backup` · 공개 차단)
2. 운영 EC2 역할(IAM)에 그 버킷 `uploads-backup/*` 의 `s3:PutObject` 권한
3. 버킷 수명 주기 규칙(예: 30일 뒤 지움)
4. 운영 `.env` 에 `BACKUP_S3_BUCKET=버킷이름` — 재시작 필요 없음
5. `bash ~/sgb/deploy/aws/uploads-backup.sh` → 「디스크 밖(S3)에 올림」

3-0 의 `aws --version` 이 「command not found」였다면 먼저 AWS CLI 를 설치해야 합니다(설치 방법은 그때 알려 주십시오). S3 요금은 크기에 따라 바뀌어 **확인이 필요합니다**.

### 4-4. 알아 둘 것

1. 개발 서버 `~/kits/release` 에 다른 판 킷이 남아 있어도 **v10.197 킷만** 올립니다.
2. 대표 할 일 「uploads cron 등록」은 **필요 없습니다.** 이미 등록했다면 그대로 둬도 됩니다(하루 한 번만 묶임).
3. S3 를 켜기 전까지 백업은 **같은 디스크 안**입니다. 디스크 통째 보호(EBS 스냅샷 예약)는 docs/273 4절 그대로입니다.

- 이번 적용 중에 `.env` 에 `BACKUP_S3_BUCKET` 넣기(버킷 · 권한이 준비된 뒤 4-3 으로)
