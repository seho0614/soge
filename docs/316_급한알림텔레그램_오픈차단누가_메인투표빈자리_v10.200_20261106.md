# 316. 급한 운영 알림 텔레그램 · 오픈 차단 「누가」 · 메인 투표 빈 자리 — v10.200 (2026-11-06)

> - 운영 메일이 아직 준비되지 않아(NO_SMTP) 급한 알림(D175 · D176)이 운영 화면 안에만 쌓임 — 11/5 · 11/6 주문 받기 켜짐도 사람이 늦게 앎
> - 오픈 차단 21건이 대부분 개발 밖(대표 결정 · 업체 계약)이라 누가 무엇을 할지 한눈에 보여야 함
> - 운영 사용자 웹 메인 투표가 0건이라 세 자리가 「준비 중」(postcheck 「메인에 나가는 투표 0건」)
>

## 1. 바뀐 것

| # | 무엇 | 내용 |
|---|---|---|
| 1 | 급한 알림 텔레그램 | 메일과 **같은 알림 · 같은 기준**(CRITICAL · 중요 설정 바뀜 · 주문 받기 저절로 꺼짐 · 백업 실패 · 묶음 깨짐 · 풀린 것 · 확인한 것 빼고 · 24시간 안 · 같은 종류 1시간에 1통 · 12시간 넘게 확인 안 한 긴급 「[다시]」 한 번)을 정기 작업 `launch_watch`(10분마다)가 메일 다음에 텔레그램 대화방 하나로 한 통. **메일과 따로 기록**(`pushed_at` · `repushed_at`) — 메일이 준비 안 돼도 감 · 준비 안 됨 · 실패는 보낸 것으로 안 적고 작업 기록 `alertPush.reason` 에만 |
| 2 | 봇 토큰 · 대화방 | 토큰은 **외부 연동 › 연동 키 › 메일 칸 「텔레그램 봇 토큰」**(SUPER · 암호화 · 끝 4자리 · 형식 「숫자:영문」) — 새 연동 줄을 만들지 않음(외부 연동 목록 · 약관 초안 생성기에 번지지 않게) · 넣고 지워도 메일 연동의 「키 등록」 표시는 그대로. 대화방은 설정 `ops.telegram_chat`(빈 값 = 꺼짐) |
| 3 | 운영 알림 화면 | 「급한 알림 메일」 줄 아래 「급한 알림 텔레그램」 줄 — 준비됨 / 준비 안 됨(봇 토큰 없음 · 대화방 없음) · 대화방(가운데 가림) · 마지막 정기 작업 · 마지막 시험. SUPER 「대화방 찾기」(봇에게 말을 건 대화방 · 고르면 설정) · 「시험 메시지 보내기」(1분에 한 번) |
| 4 | 보내는 글 | 알림 **제목 · 등급 · 시각만** — 알림 내용(detail)은 보내지 않음. 토큰은 주소 안에 들어가므로 오류 글 · 로그에 주소를 남기지 않음 |
| 5 | 오픈 차단 「누가」 | `GET /admin/open-blockers` 줄마다 `owner`(CEO 대표 결정 · 법무 / VENDOR 업체 대기 / SCREEN 운영 화면에서 바로 / DATE 날짜만) · `how`(풀리는 방법 한 줄). 판단 기준(`v_open_blockers`) · 줄 수는 그대로. 오픈 체크리스트 화면 위에 「대표 결정 N · 업체 대기 N …」 요약 · 기본은 누가별 보기(종류별로 바꿀 수 있음) |
| 6 | 메인 투표 빈 자리 | 투표가 없을 때 「준비 중」 카드는 시안 기준이라 그대로. ① 지켜보기 「메인 투표(3자리 중)」 칸(3 아래면 노란 칸 → 투표 관리) ② 하루 요약에 빈 자리 줄 ③ 투표 관리 SUPER 「확정 질문으로 빈 자리 채우기」 — **비어 있는 종류만** 2026-10-03 확정 질문(scripts/seed-polls.sql 과 같은 글 · 카드 그림과 짝)으로 만들고 바로 엶(표 0) · 같은 질문이 이미 있으면(마감 · 감춤 포함) 만들지 않고 알려 줌 · 감사 `POLL_FILL_HOME` |

## 3. DB (D178)

1. `integration_secrets` 받는 키에 `('MAIL','TELEGRAM_BOT_TOKEN')` · `fn_integ_secret_set` 형식 검사(`^[0-9]{5,15}:[A-Za-z0-9_-]{30,64}$`) · 텔레그램 토큰은 `integrations.secret_registered` 를 바꾸지 않음
2. 설정 `ops.telegram_chat`(빈 값 · ADMIN · 형식 `^-?[0-9]{5,20}$`)
3. `ops_alerts.pushed_at` · `repushed_at`
4. `fn_ops_alert_push_pending()` · `fn_ops_alert_repush_pending()` — 메일 함수(D177)와 같은 기준 · 칸만 다름
5. 지우는 문장 없음 · 재실행 안전 · **이미 쌓인 알림은 pushed_at 이 비어 있음** — 토큰 · 대화방을 넣으면 첫 정기 작업이 지난 24시간의 확인 안 한 급한 알림을 한 통으로 보낼 수 있음(정상 · 메일과 같음)
