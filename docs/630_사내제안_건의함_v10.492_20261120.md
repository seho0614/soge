# 630. 사내 제안 · 건의함 (v10.492 · 2026-11-20)

## 1. 결론
운영 계정 누구나 업무 · 도구 · 복지 · 안전 제안을 내고, ADMIN · SUPER 가 검토 · 답변합니다. **「익명으로」를 고르면 쓴 사람과 넣은 시각을 저장하지 않습니다** — 화면에서 감추는 것이 아니라 **DB 에 칸이 비어 있습니다**. 쓴 사람은 한 번만 보이는 **접수 번호**로 진행 · 답변을 봅니다. 위치: **사무 › 제안함** · SB-ADM-ITS-030(검토) · 031(쓰기 · 내 제안).

| 상태 | 뜻 |
|---|---|
| 접수 → 검토 중 | 검토 시작(되돌릴 수 있음) |
| 채택 | 하기로 함 — **답변 필요** |
| 반영 안 함 | 하지 않음 — **답변 필요** · 끝 |
| 실행 끝 | 채택한 것을 마침 · 끝 |

## 2. 익명을 지키는 방법(DB 설계)
1. 넣는 문장에 계정 번호를 보내지 않음(author_id NULL) · **BEFORE INSERT 트리거가 한 번 더 지움**(서버가 실수로 보내도) · CHECK ck_its_sug_anon 이 다시 막음.
2. 넣은 **시각을 저장하지 않음**(created_at NULL · 날짜 created_on 만) — 로그인 기록과 시각을 맞춰 보지 못하게.
3. 번호는 **무작위 uuid**(넣은 차례가 드러나지 않음) · 목록은 날짜 · 제목 순.
4. 접수 번호 원문은 저장하지 않고 sha256(receipt_hash)만.
5. 넣는 API · 내 제안 · 접수 번호 API 에는 **감사 기록(@Audit) · 권한 주소 맵(perm_route_map → 권한 검사 기록 perm_shadow_log) · 넣을 때 운영 알림을 붙이지 않음**. 접수 대기 알림은 하루 한 번 **수만**.
6. 고치기 · 지우기 막음(트리거) — 익명 줄에 나중에 작성자를 넣는 것도 막음.

남는 한계(확인 필요): 웹 서버(Nginx) 접속 기록 · DB 내부 줄 순서 같은 운영 기록은 이 기능 밖입니다 — 운영 Nginx 접속 기록 보관 기간은 domain-dns 결정을 따릅니다. 제안 내용 자체(말투 · 담당 업무)로 짐작되는 것은 막을 수 없습니다.

## 3. API
| 방법 | 주소 | 누가 | 설명 |
|---|---|---|---|
| POST | /admin/its/suggestions | 운영 계정 | 분류 · 제목 2 ~ 100 · 내용 10 ~ 3000 · anonymous → 접수 번호(한 번) |
| GET | /admin/its/suggestions/mine | 운영 계정 | 이름 밝힌 내 제안 |
| POST | /admin/its/suggestions/lookup | 운영 계정 | 접수 번호 → 진행 · 답변 |
| GET | /admin/its/suggestions?state=&q= | ADMIN | 검토 목록(익명은 쓴 사람 없음) |
| GET | /admin/its/suggestions/{id} | ADMIN | 내용 · 검토 기록 · 옮길 상태 |
| POST | /admin/its/suggestions/{id}/decide | ADMIN | to · answer · 감사 ITS_SUGGEST_DECIDE(검토한 사람만) |

오류: 404 · 400 · 409 ITS_SUGGEST_STATE · 422 ITS_SUGGEST_CATEGORY · TITLE · BODY · RECEIPT · ANSWER.
