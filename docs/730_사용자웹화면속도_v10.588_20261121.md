# 730. 사용자 웹 느린 화면 측정(웹 바이탈) (v10.588 · 2026-11-21 · 14차 운영 ④)

> 대표 11/21 「모두 개발진행」. 기존 「회원 화면 사용 통계」(D274 · v10.508 · `UsageBeacon` · `site-usage.ts`)와 **같은 방식**(공개 주소 · 주소 묶기 `normPath` 재사용 · DNT · GPC · 로봇 · 1분 요청 한도)으로 만들었습니다.

## 1. 결론

- 사용자 웹이 브라우저에서 잰 **LCP**(큰 그림 · 글이 보이기까지) · **INP**(누르고 반응까지) · **CLS**(화면 밀림) · FCP(첫 글자) · TTFB(서버 첫 응답)을 하나씩 보내고, 운영 화면 **위험감지 › 화면 속도**(새 탭 `web-vitals`)에서 화면별 **75번째 값**(100번 중 75번째로 느린 값 · 구글 기준과 같은 셈) · 좋음 · 나쁨 비율을 봅니다.
- **방문자 키 없이 화면 · 시간만**: 남기는 것은 날 · 시 · 화면 주소 묶음 · 지표 · 값 · 등급뿐입니다(계정 · IP · 브라우저 정보 · 쿠키 · 물음표 뒤 없음).
- 스위치 `ops2.web_vitals` **처음 off** · 켜기는 SUPER 만(전체 설정의 SUPER 목록에 더함 · 끄기는 ADMIN 도). **처리방침 1.2 게시 뒤** 켭니다(5절).

## 2. 동작

| 곳 | 내용 |
|---|---|
| 사용자 웹 | `WebVitalsBeacon`(루트 layout · `next/web-vitals` 의 `useReportWebVitals` — 새 패키지 없음) · 스위치 off · DNT · GPC · 표본 밖이면 아무것도 안 함 · 표본 `ops2.web_vitals_sample`(10퍼센트 · 탭마다 한 번 · sessionStorage `sgb_vitals` 는 표본 여부만) · `sendBeacon` 또는 `fetch keepalive` |
| 받는 길 | `POST /api/v1/site/vitals` {p, n, v} — 로그인 없이 · 주소는 `normPath`(D274)로 `/community/:id` 처럼 · 등급은 **서버가** 값으로(화면 값 믿지 않음) · 한 줄 INSERT · 보관 지난 줄은 받는 길에서 한 시간에 한 번 지움(`ops2.web_vitals_keep_days` 30) |
| 보기 | `GET /api/v1/admin/ops2/web-vitals?days=1·7·30`(ADMIN · SUPER · 읽기만) — 지표마다 표본 · 75번째 · 좋음 · 나쁨 / 화면 묶음 50(LCP · INP · CLS · TTFB · 나쁨) / 날마다 LCP · INP |

### 등급 기준(좋음 이하 · 나쁨 초과)
| 지표 | 좋음 | 나쁨 | 단위 |
|---|---|---|---|
| LCP | 2500 | 4000 | ms |
| INP | 200 | 500 | ms |
| CLS | 0.1 | 0.25 | 없음 |
| FCP | 1800 | 3000 | ms |
| TTFB | 800 | 1800 | ms |

> 기준은 web.dev 공개 값(2024)을 따랐습니다 — 바뀌었는지 **확인이 필요합니다**(바꾸려면 `vitals.ts` OPS2_THRESH).

## 5. 처리방침 · 법무(켜기 전)

- 「처리방침 1.2 게시 뒤」 — 「서비스 이용 기록」 항목에 **화면 표시 속도(화면 주소 · 측정 값 · 시각)** 를 넣고, 개인을 알아볼 수 없는 통계용임을 적습니다(법무 확인 권함). 회원 화면 사용 통계(D274)와 같은 줄에 넣을 수 있습니다.
- 켜는 순서: 처리방침 게시 → SUPER 가 전체 설정 `ops2.web_vitals` on → 하루 뒤 화면 속도 탭에서 표본 수 확인 → 표본이 너무 적거나 많으면 `ops2.web_vitals_sample` 조정.
