## 3. 순서

### 3-0. 운영 판 확인 (ubuntu · 읽기만)

```bash
cat ~/sgb/VERSION
pm2 ls
ls ~/sgb-releases
df -h / | tail -1
```

| 줄 | 맞으면 |
|---|---|
| VERSION | 판별 절차서에 적힌 「지금 운영 판」 |
| pm2 ls | `sgb` · `sgb-site` · `sgb-jobs` 3개 `online` |
| ls ~/sgb-releases | 판 폴더 2개(지금 판 · 직전 판) |
| df | 여유 3GB 이상 |

다르면 멈추고 출력을 Claude 에게 보냅니다.

### 3-1. 킷 받기 · 올리기 (집 PC PowerShell)

```powershell
scp sgb-dev:~/kits/release/<킷 이름>.zip C:\sgb\
certutil -hashfile C:\sgb\<킷 이름>.zip SHA256
scp -i C:\sgb_key\sgb-key.pem C:\sgb\<킷 이름>.zip ubuntu@3.37.95.217:~/
```

- certutil 값이 판별 절차서의 zip sha256 과 **글자 하나까지 같아야** 합니다. 다르면 세 번째 줄을 치지 않고 멈춥니다.
- 마지막 줄이 100% 로 끝나면 됩니다.

### 3-1 ②. 풀기 · 적용 전 점검 (ubuntu)

```bash
cd ~ && unzip -q -o <킷 이름>.zip
cat ~/<킷 이름>/sgb/VERSION
bash ~/<킷 이름>/sgb/deploy/aws/precheck.sh
```

precheck 는 **읽기만** 합니다(아무것도 바꾸지 않음). 볼 줄:

| 칸 | 맞으면 | 다르면 |
|---|---|---|
| 맨 끝 | `통과 N · 실패 0 · 확인 0` | 실패가 있으면 멈춤 |
| [5] 마이그레이션 | `적용됨 A · 새 킷의 파일 B · 올릴 것 B−A · 바뀐 파일 0` — 판별 절차서의 수와 같음 | 「바뀐 파일」이 0 이 아니면 **적용 금지**(이미 올린 파일이 바뀐 킷) |
| [5] 올릴 것 | 판별 절차서의 마이그레이션 이름과 같음 | 다르면 멈춤 |
| [4] 판 보관 폴더 | 지금 판 · 직전 판 · **「되돌린 상태」 줄 없음** | 「되돌린 상태」가 나오면 멈춤(6-3) |
| [6] Nginx | 「sgb 따로 있는 파일」 · 「사용자 웹 — 누구나 열림 · 운영 화면 — 허용 IP 만」 | 다르면 멈춤 |
| [1] aws CLI 없음 | 정보 줄(지금 운영은 aws CLI 를 쓰지 않음) | — |

### 3-2. RDS 스냅샷 (마이그레이션이 있는 판은 꼭)

```
AWS 콘솔 → RDS → 데이터베이스 → sgb-db → 작업 → 스냅샷 생성
→ 이름: sgb-before-v10-<판>-<YYYYMMDD>   (예: sgb-before-v10-202-20261106)
→ 상태가 「사용 가능」이 될 때까지 기다림
```

- [ ] 목록에 있음 · [ ] 「사용 가능」 · [ ] 만든 시각이 3-1 ② precheck 뒤
- 마이그레이션이 없는 판도 apply 는 스냅샷을 묻지 않지만, 큰 판이면 만들어 두는 편이 안전합니다.
- 스냅샷은 DB 만 담습니다. **올린 파일(uploads)은 들어가지 않습니다** — 매일 04:30 `uploads-backup.sh` 묶음이 따로 있음.

### 3-3. 적용 (ubuntu)

```bash
bash ~/<킷 이름>/sgb/deploy/aws/apply.sh
```

apply 가 하는 일(앞 단계가 실패하면 거기서 멈추고, **돌던 서비스는 그대로 돕니다**):

| 단계 | 내용 | 서비스 |
|---|---|---|
| [0] 전제 확인 | Node 22 · 메모리 · 디스크 · DB 접속 · 바뀐 마이그레이션 0 · 되돌린 상태 아님 | 그대로 |
| [1] 새 판 놓기 | `~/sgb-releases/<판>_<시각>/` 에 복사 · 지금 `.env` 를 가져옴 | 그대로 |
| [2] 설치 · 빌드 | API · 사용자 웹(2분쯤) · 운영 화면 | 그대로 |
| [3] DB 마이그레이션 | 올릴 것을 보여 주고 **「RDS 스냅샷을 방금 만들었습니까?」** → `yes` 일 때만 적용 | 그대로 |
| [4] 배포 점검 | 타입 · 마이그레이션 · 불변식 · 미확인 CRITICAL 경보 · 라우트 — 「배포 가능」 | 그대로 |
| [5] 교체 | `~/sgb` 를 새 판으로 돌리고 pm2 3개 다시 등록 | **몇 초 끊김** |
| [6] 기동 확인 | API · 사이트가 안 뜨면 **전 판으로 저절로 복귀** · 뜨면 옛 판 1개 정리(지금 · 직전 판만 남김) | — |
| [7] postcheck | 적용 후 확인이 이어서 돎 | — |

- 스냅샷 물음은 **화면에 나온 뒤에** `yes` 를 칩니다. 미리 치지 않습니다.
- `ASSUME_YES=1` 은 리허설 전용입니다. 운영에서는 쓰지 않습니다(스냅샷 물음을 건너뜀).

### 3-4. 적용 후 정리 (ubuntu)

```bash
cat ~/sgb/VERSION
ls ~/sgb-releases
rm -rf ~/<킷 이름> ~/<킷 이름>.zip
df -h / | tail -1
```

기대: 새 판 번호 · 판 폴더 2개(새 판 · 직전 판) · 디스크 여유가 3-0 과 비슷하거나 늘어남.

## 4. postcheck 읽는 법

맨 끝 `적용 후 확인 — 통과 N · 실패 0 · 확인 M` 에서 **실패 0** 이 기준입니다.

| 줄 종류 | 뜻 | 할 일 |
|---|---|---|
| 통과 | 기대대로 | — |
| **실패** | 고쳐야 함 | 멈추고 출력 전체를 Claude 에게 |
| 확인 | 열기 전에는 정상인 상태 · 대표 결정으로 둔 것 | 아래 표와 같으면 그대로 |
| 정보(앞에 표시 없음) | 수만 보여 줌 | 판별 절차서의 기대와 다르면 알려 주기 |

지금(v10.202) 평소 「확인」 5줄:

| # | 줄 | 왜 확인인가 |
|---|---|---|
| 1 | 간주 모드가 켜져 있음(assume.payment · broker · bank · etax) | 외부 연동 7건이 끝나지 않음 — 연동 뒤 끔 |
| 2 | 사용자 웹이 누구나 열림 · 간주 모드 켜짐 | 11/1 대표 「전체 공개」 결정 · 소개몰 주문 받기 꺼짐 |
| 3 | 오픈 차단 N건 | 오픈 체크리스트(운영 화면)에서 풀어 감 |
| 4 | 약관 — 게시 N(시행 중 N · 새 판 시행 예정 N · 첫 판 시행일 전 N · 가장 빠른 MM-DD) · 초안 N(초안 이름) — v10.214 부터 · 전에는 「발행 N · 초안 N」 · 첫 판은 게시 순간부터 지금 판(동의 기준) | 법무 확인 뒤 운영 화면 약관에서 게시 · 초안이 0 이면 「통과」 |
| 5 | 처리방침 게시 판 없음 | 처리방침 게시 전에는 AI 전체를 켤 수 없음 |

- 「올린 파일 백업」이 확인이면 `52 · 0 · 6` 도 정상입니다(백업이 아직 한 번도 안 돈 새 서버 등).
- **처리방침이 게시된 뒤**(11/8 · v10.213 적용부터)는 5번 줄이 「통과」가 되어 평소 **55 · 0 · 4** 입니다. 오픈 차단 · 약관 숫자가 지난번과 다르면 v10.214 부터 precheck · postcheck 가 항목 이름 · 초안 이름까지 보여 줍니다(docs/344).
- [9] 「주문 받기가 켜짐」이 **실패**로 나오면: 운영 화면에서 「주문 받기」를 끄고 `bash ~/sgb/deploy/aws/postcheck.sh` 를 다시 칩니다.
- 정보 줄 「메인에 나가는 투표 N건」이 3 이 아니면 운영 화면 › 소개광장 › 「이건 어때? 투표」에서 「확정 질문으로 빈 자리 채우기」(SUPER).

## 5. 멈췄을 때

| 어디서 · 무엇 | 뜻 | 할 일 |
|---|---|---|
| precheck 「바뀐 파일 N」(N > 0) | 이미 운영에 올린 마이그레이션 파일이 킷에서 바뀜 | **적용 금지** · Claude 에게 |
| precheck · apply [0] 「되돌린 상태」 | 지금 판이 보관 폴더의 가장 새 판보다 옛 판(rollback 뒤) | 아무것도 바뀌지 않았음 · Claude 에게(6-3) |
| apply [3] 스냅샷 물음에 `yes` 가 아님 | 「쓰지 않은 새 판 폴더를 지웠습니다」와 함께 멈춤 | 스냅샷을 만든 뒤 **같은 apply 명령을 다시**(rollback 아님) |
| apply [2] 빌드 실패 | 새 판 폴더만 지워짐 · 서비스는 옛 판 그대로 | 출력과 `~/sgb-data/logs/apply_…_build.log` 끝 50줄을 Claude 에게 |
| apply [3] 마이그레이션 실패 | 실패한 파일은 한 거래라 반영되지 않음 · 서비스는 옛 판 | 출력 전체를 Claude 에게 · 스냅샷 복원은 하지 않음 |
| apply [4] 「배포 불가」 | 미확인 CRITICAL 경보 등 | 운영 알림 화면에서 그 알림을 확인 · 처리한 뒤 apply 다시 |
| apply [6] 「전 판으로 자동 복귀」 | 새 판이 뜨지 않아 옛 판 코드로 돌아감(DB 는 새 구조) | 출력 · `pm2 logs sgb --lines 80 --nostream` 을 Claude 에게 |
| postcheck 실패 | 판은 바뀜 | 4절 표 · 출력 전체를 Claude 에게 |

## 6. 되돌리기

> 적용 블록과 같이 치지 않습니다. 필요할 때 이 절만 따로 봅니다.

### 6-1. 코드만 전 판으로 (보통 이것)

```bash
bash ~/sgb/deploy/aws/rollback.sh
```

- 한 번 묻습니다 → `yes`. `~/sgb` 바로가기를 직전 판 폴더로 돌리고 pm2 를 다시 띄웁니다.
- **DB 는 그대로**입니다. 마이그레이션은 전진 전용이라 전 판 코드가 새 DB 구조 위에서 돕니다. 판별 절차서 5절에 「남는 것」이 적혀 있습니다.

### 6-2. 되돌린 뒤 다시 새 판으로

```bash
bash ~/sgb/deploy/aws/rollback.sh
```

한 번 더 → `yes`. 새 판 폴더가 남아 있어 그쪽으로 돌아갑니다.

### 6-3. 되돌린 상태에서 다음 판을 올릴 때

apply 는 기본으로 멈춥니다(11/4 운영: 되돌린 채 적용 → 정상 판 폴더가 정리됨). 먼저 6-2 로 새 판에 돌아간 뒤 적용합니다. 일부러 되돌린 상태에서 올려야 하면 Claude 와 먼저 상의합니다(`ALLOW_FROM_ROLLBACK=1`).

### 6-4. DB 까지 (드묾)

1. RDS → 스냅샷 `sgb-before-v10-<판>-<날짜>` → 「스냅샷 복원」(새 인스턴스)
2. 운영 `.env` 의 DB 접속 주소를 새 인스턴스로 바꿈
3. `pm2 restart sgb sgb-site sgb-jobs`
4. 스냅샷 뒤에 생긴 자료(가입 · 글 · 주문 등)는 사라집니다 — 대표 결정 뒤에만

## 7. 하지 말 것

1. 대표 승인 없이 적용
2. 적용 블록과 rollback 을 한 번에 붙여 넣기
3. 운영에서 `ASSUME_YES=1` · `verify` · `attack` · `db:seed` · `open-prep.sh apply`
4. 법무 확인 전 약관 · 처리방침 게시 · `publish-terms.sh`(킷 원문으로 덮음 — 게시는 운영 화면 약관에서)
5. 결제대행사 연결 전 「주문 받기」 켜기
6. 목록을 보기 전 `cleanup.sh --apply`(먼저 `bash ~/sgb/deploy/aws/cleanup.sh` 로 읽기만)
7. 운영 `.env` · Nginx 를 판별 절차서에 없는데 고치기(Nginx 는 `sites-enabled/sgb` 가 실제 파일)
8. `~/kits/out` 의 킷 쓰기(점검용 · 덮어써짐)

## 8. 판별 절차서에 적는 것 (Claude 가 쓰는 틀)

| 절 | 내용 |
|---|---|
| 머리 | 지금 운영 판(마지막 적용 시각 · 절차서 · postcheck 수) → 올릴 판 · 바뀐 것 한 줄씩 · 마이그레이션 수(스냅샷 필수 여부) |

| 리허설 | 두 킷 차이 · 버리는 DB 에 마이그레이션 전체 + 새 것 두 번(재실행 안전) |
| 2. 무엇이 바뀌나 | 운영자 · 회원이 보는 변화 |
| 3. 순서 | 이 문서 3절을 판 번호 · sha 로 채운 블록(한 블록씩 칠 수 있게 그대로 둠) |
| 4. 적용 직후 | 화면 확인 표 · 적용 뒤 할 일(스위치 · 채우기 등) |
