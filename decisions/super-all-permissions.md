# 소개뱅크 결정 정리 — SUPER 는 모든 권한

- 기준일: 2026-10-21
- 범위: 최고 관리자(SUPER) 역할의 권한 · 정산 지급 · 앞으로 생기는 권한 · 감사 기록 · 그대로 두는 통제
- 상태: **유효** / **대체됨**

## 요약

1. **SUPER 는 모든 권한을 가진다** — 정산 지급(settlement:pay) 포함, 앞으로 새로 생기는 권한도 자동 포함(2026-10-21 대표 결정).
2. 구현은 권한을 하나하나 적지 않고 **「SUPER 는 권한 검사를 항상 통과」** — 서버 `hasRole` · `AuthGuard`, DB `fn_has_role`(D104), 운영 화면 `canSee`.
3. **감사 기록은 SUPER 도 그대로** 남긴다 — 누가(actor_account_id) · 언제 · 무엇을, 역할은 `SUPER` 로.
4. v10.51 (sgb-core docs/104) 에서 반영. 고치기 전에는 SUPER 만 가진 계정이 운영 API 26개(지급 · 입금 기록 · 광고 청구 · 자료 수집 · 신고 · 이벤트 · 관 관리)와 퍼블리셔 명세서 집행(DB)에서 막혀 있었다.

## 2. 새 권한을 만들 때 지킬 것

1. 서버 — `@Roles('새역할')` 만 적는다. SUPER 는 AuthGuard 가 통과시킨다.
2. 서버 코드 안 역할 비교 — `hasRole(roles, '역할')` (src/core/auth.ts). `roles.includes` 직접 사용 금지.
3. DB — `fn_has_role(계정, '역할')`. account_roles 직접 조회 금지.
4. 운영 화면 — 단추 · 탭 조건 앞에 `roles.includes('SUPER') ||`.

## 3. 미정 사항

- 위 #4 · #5 (게이트 · 2인 원칙을 SUPER 에게도 적용) — 대표 확인 필요. 풀려면 별도 결정과 DB 트리거 변경이 필요.
- 운영 서버의 SUPER 계정 역할 구성(SUPER 만인지, ADMIN 도 함께인지) — sgbdev 가 볼 수 없어 확인 필요.
