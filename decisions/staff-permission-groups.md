# 소개뱅크 결정 정리 — 회원 관리 · 직원 권한 관리 분리 · 권한그룹 체계

- 기준일: 2026-11-21
- 범위: 운영 화면에서 회원과 직원(운영자)을 다루는 화면 · 규칙, 업무별 권한(업무 · 업무그룹 · 권한그룹), 운영 역할을 주고 거두는 규칙
- 함께 볼 것: `super-all-permissions.md`(SUPER 는 모든 권한 · 2인 원칙) · `partner-center-account-basis.md`(파트너 · 판매자 계정)
- 상태: **유효** / **대체됨** / **개발 중**

## 요약

1. **계정은 하나 그대로**, 회원 관리와 직원 권한 관리는 **화면 · 규칙만 나눈다(A안 · 2026-11-21 대표)**. 운영자 계정을 따로 만드는 B안은 나중.
2. 직원 쪽 화면은 운영 화면 **「직원 · 권한」 그룹** 한 곳에 모으고, 운영 역할을 주는 곳도 한 곳만 둔다. **운영자 정지는 SUPER 만**, 회원 목록은 **운영자를 기본으로 뺀다**, 새 운영 역할은 **직원 대장 연결이 필수**(외부 계정은 기한 필수).
3. 권한은 **업무 목록 → 업무그룹 → 권한그룹 → 사원** 순서로 준다. **회원은 기존 규칙 그대로.**
4. 새 체계로 바꾸는 스위치 `perm.mode` 는 **ROLE → COMPARE → GROUPS** 순서로, **대표가 켠다** — 비교 결과 **빠진 주소 0 · 다름 0** 일 때만 다음 단계로.
5. 개발: v10.561 ~ 564 · 마이그레이션 D291(#329) · sgb-core docs/702 ~ 705(계약 기준 번호 · 합친 뒤 확인 필요) — **11/21 개발 중 · 운영 적용 전**.

## 2. 검토에서 찾은 문제 6가지 (2026-11-21 · A안의 근거)

| # | 문제 | A안에서 |
|---|---|---|
| 1 | 운영 역할을 주는 곳이 **두 곳**(회원 상세 · 권한 계층) | 「직원 · 권한 › 역할 주기」 한 곳 · 회원 상세는 보기만 |
| 2 | 「권한 관리」라는 **탭 이름이 두 개**(권한 계층 · 사무) | 「역할 주기」 · 「업무별 권한」으로 나눔 |
| 3 | 직원 관련 화면이 **메뉴 4곳에 흩어짐** | 「직원 · 권한」 그룹으로 모음 |
| 4 | **회원 목록에 운영자가 섞임** | 운영자 기본 제외 · 「운영자 포함」 거르기 |
| 5 | **ADMIN 이 다른 운영자를 정지**할 수 있음 | 운영 역할 있는 계정의 상태 바꾸기는 SUPER 만 |
| 6 | 직원 대장 ↔ 계정 **연결이 선택** | 새 운영 역할은 연결 필수 · 외부 계정은 기한 필수 · 퇴사 뒤 남은 역할 알림 |
