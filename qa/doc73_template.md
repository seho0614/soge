# 소개뱅크 v10.25 — 소개몰(쇼핑몰)을 시안 기준으로: 틀 · 화면 · 시안 값 3가지 (시안 + 실제 웹 + 서버) (2026-10-08)

> 10/7 지시 — 「소개몰(쇼핑몰) 제시 디자인 적용 · 메뉴 이름 소개몰」 → 비교 그림을 먼저 드림
>
> 10/8 지시 — 「개발분과 시안을 비교하여 줘 · 반영 전에 확인 후 반영 · 처음부터 다시 진행 · **다른 점이 있으면 시안을 기준으로 작성**」
>
> 10/8 답(두 번에 나눠 받음) — ① **4판으로 나눔** ② 배송비 · 의료기기 · 건강기능식품 = **시안 값으로** ③ 입점 판매자 = **넣음(마지막 판)** ④ 개발분에만 있는 10건 = **모두 남김** ⑤ 시안의 임시 값 3건 = **모두 개발분 값으로**
>
> 일하는 순서 — **비교 그림 → 확인 → 반영**. 비교 그림 4장과 차이표(`소개뱅크_소개몰_시안기준_개발분_비교_반영전확인_v10.25_20261008.md`)를 먼저 드리고 위 답을 받은 뒤 킷에 반영했습니다.

## 0. 결론

**소개몰 22쪽(시안 21화면 + 결제 승인 쪽)의 틀과 화면 구성을 시안에 맞췄고, 시안 값 3가지(배송비 전 상품 무료 · 의료기기는 팔지 않음 · 건강기능식품은 잠금)를 서버 규칙으로 넣었습니다.**
남기기로 하신 개발분 10건과 개발분 값 3건은 시안에도 넣어, 두 쪽이 같은 내용을 보입니다. 네 판 가운데 **첫 판(v10.25 — 틀 · 화면)** 입니다.

|---|---|---|

### 먼저 알려 드릴 것 7가지

1. **개발 DB 에서 팔리는 상품이 3종으로 줄었습니다.** 건강기능식품 3종 · 의료기기 2종이 「판매 중지」가 됐습니다(지우지 않음). 그래서 성분별 · 고민별의 대부분이 「취급 준비 중」으로 보입니다. v10.26 에서 시안 견본 16종(건강식품)을 시드로 넣으면 채워집니다.
2. **서버에 올리면 일어나는 일 2가지** — ① 건강기능식품 · 의료기기 갈래에 「판매 중」 상품이 있으면 D025 가 「판매 중지」로 바꿉니다(장바구니에 담긴 것은 그대로 두고, 주문하려 하면 서버가 거절합니다). ② 약관 3종의 옛 이름과 배송 조항이 고쳐집니다 — **약관이 이미 발행된 DB** 에서는 새 버전(1.1)으로 발행되어 동의한 회원도 새 버전에는 「동의 안 함」으로 집계되고(동의하지 않아도 이용은 막지 않습니다 — 지금 규칙), **9/30 서버처럼 아직 발행 전(초안)이면 초안의 글만** 고쳐집니다(리허설에서 확인 — 그 상태의 이용안내에는 「건강상품 판매 약관이 아직 발행되지 않았습니다」가 나옵니다).
3. **시안의 「교환 배송비 6,000원」은 서버에 넣지 않았습니다.** 시안 화면(상품 상세 · 교환 신청)에는 적혀 있지만, 서버에는 교환 비용을 받는 규칙이 없습니다. 받을지 · 어떻게 받을지 정해 주셔야 합니다.
4. **주문서의 동의 ② 문구는 그대로 두었습니다**(실제 웹 「배송사에 제공」). 시안은 「판매자에게 제공」인데 입점 판매를 전제로 한 문구라 v10.28 에서 약관과 함께 바꿉니다.
5. **법률 확인이 필요한 것 2가지** — ① 무료배송 상품을 단순 변심으로 반품할 때 「왕복 6,000원(보내 드린 3,000원 + 돌려받는 3,000원)」을 환불액에서 빼는 것: 돌려보내는 비용을 소비자가 내는 것은 법에 있으나(전자상거래법 제18조 제9항), 처음 보낸 배송비까지 빼는 근거는 이번에 확인하지 못했습니다. ② 식품의 「개봉 시 청약철회 제한」: 제한하려면 그 사실을 포장 등에 분명히 적거나 시용 상품을 주는 조치가 필요한지(같은 법 제17조 제6항) — 조문 원문을 이 작업 환경에서 열지 못해 확인하지 못했습니다.
6. **확인 받은 비교표에 없던 차이 3건을 구현하면서 찾아 시안에 맞췄습니다** — 날짜 표기(「2026. 10. 3.」 → 「2026.10.03」) · 잠긴 갈래 단추(누를 수 있음 → 누를 수 없음) · 고민 상세의 성분 표기(「· 준비 중」 → 「🔒」). 그리고 의료기기를 팔지 않게 되어 청약철회 규칙의 이름 「의료기기 · 건강기기」를 「건강기기」로 바꿨습니다.
7. **개발 DB 의 반품 신청 20건을 한꺼번에 반려 처리했습니다.** 시험을 정리하다 「접수」 상태로 남은 것을 모두 반려했는데, 19건은 옛 시험이 남긴 것이었습니다. 개발 DB 에서만 있었던 일이고 킷 · 운영 자료와는 관계없습니다.

4. **사용자 웹의 자료 기억(G-161)** — 상품을 판매 중지로 바꾼 직후, 오래 열지 않은 상품 쪽을 처음 여는 사람에게는 예전 화면이 한 번 보일 수 있습니다(주문은 서버가 거절). 서버 적용(`apply.sh`) · Docker 는 새 폴더에서 빌드하므로 올린 직후에는 해당 없습니다.
5. **`docs/terms/HLT_SALE.md`** 는 약관 초안 생성기의 글이고, 실제로 게시된 약관은 DB 의 글(C880 + D024)입니다. 두 글의 문장이 다릅니다 — 시안에는 DB 의 글을 실었습니다(`qa/hlt_sale_terms.md`).

| 배송비 0원 | 결제 대기 중인 주문의 금액은 주문 때 값 그대로입니다 |

문제가 생기면

1. `rollback.sh` 로 앞 판 코드로 되돌릴 수 있습니다. **DB 는 되돌아가지 않습니다** — 그 상태에서는 장바구니의 배송비는 0원으로 보이는데(D025 가 바꾼 계산) 앞 판 코드는 3만원 미만 주문에 3,000원을 붙입니다. 되돌린 채로 오래 두지 말고 원인을 고쳐 다시 올리십시오.
2. 잠긴 갈래를 다시 열려면 2절의 `UPDATE` 한 줄입니다.
3. 판매 중지된 상품은 지우지 않았으므로 상태만 되돌리면 됩니다(잠긴 갈래의 상품은 갈래를 먼저 열어야 「판매 중」으로 바뀝니다).
